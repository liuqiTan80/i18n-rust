# 第十五章：集合类型

## 15.0 学习目标

读完这一章，你将能够：

1. 说出**集合**与数组的三大区别（堆上、可变长、单类型）；
2. 用**向量**存一串同类数据：创建、推入、弹出、取下标、移除、遍历；
3. 用**哈希映射**按键查值：插入、获取、判断键存在、遍历键值对；
4. 用 **`条目().或插入()`** 写出词频统计这种经典套路；
5. 理解集合的**所有权**：集合拥有里面的数据；
6. 避开"边遍历边修改"的借用冲突。

---

## 15.1 集合：能伸缩的仓库

第三章的数组有个死规定：**长度写死**。声明 `[整数; 3]` 就只能放 3 个，一个不多一个不少。

💡 **比喻**：数组是一排**固定格数的储物柜**——买了几格就几格；**集合**是**能自动加长的仓库**——来货就扩，出货就缩。

📖 **集合（Collection）**：存放在**堆**（一块按需申请的大内存）上的数据结构，长度可以变化。三大特点：

| 特点 | 数组 | 集合 |
|---|---|---|
| 存放位置 | 栈上（小、快、固定） | 堆上（大、灵活） |
| 长度 | 编译时写死 | 运行时可变 |
| 元素类型 | 必须单一 | 必须单一 |

本章两大主角：**向量**（有序的一串）和**哈希映射**（按键查值的电话簿）。

## 15.2 向量：能长大的数组

📖 **向量（向量）**：有序、可伸缩、同一类型的元素串。对应 `向量`。

### 创建

```rust
// 方式一：先造空仓库，再往里放
让 可变 分数 = 向量::新建();      // 类型由第一次 推入 推断

// 方式二：一口气造好
让 颜色 = 向量宏!["红", "黄", "蓝"];
```

> ⚠️ 向量要往里放东西，必须 **`可变`**（仓库要扩建嘛）。

### 推入与弹出

```rust
分数.推入(88);   // 尾部放入
分数.推入(95);
分数.推入(76);

// 弹出：从尾部取出（拿走），返回 选项
如果让 有些(色) = 颜色.弹出() {
    打印行!("弹出：{}", 色);
}
```

📖 **弹出（pop）**：取出最后一个元素并缩短向量。因为仓库可能已空，返回 `选项<类型>`——`有些(值)` 或 `无`，用 `如果让` 拆开最顺手。

### 读取元素

```rust
打印行!("第一个：{}", 分数[0]);          // 下标法：越界会恐慌！
匹配 分数.截取(0) {                      // 安全法：返回 选项
    有些(值) => 打印行!("取到：{}", 值),
    无 => 打印行!("没有这个位置"),
}
```

两种读法的取舍：**确定下标合法**用 `[下标]`（快）；**不确定**就用 `截取`——它温和地返回 `无` 而不是恐慌。

### 移除与长度

```rust
分数.移除(1);              // 拿走下标 1 的元素，后面的自动前移
打印行!("长度：{}", 分数.长度());
```

### 遍历

```rust
对于 项 在 &分数 {          // 借用遍历：只看不动
    打印行!("成绩：{}", 项);
}
```

`&分数` 表示借用每个元素——向量和里面的元素都不被移走。

## 15.3 向量的所有权：仓库拥有货物

向量**拥有**里面的每一个元素：向量被释放时，元素跟着全部释放。

```rust
{
    让 水果 = 向量宏!["苹果", "香蕉"];
    // 水果 住在这个块里
}
// 块结束：水果 释放，里面的元素全没了
```

往向量里放**字符串**（自己拥有的数据）没问题；放 `字符串引用`（借据）就要标生命周期（第十四章）——所以初学统一放 `字符串`。

## 15.4 哈希映射：按键查值的电话簿

📖 **哈希映射（HashMap）**：存一堆"键 → 值"配对，按键瞬间找到值。对应 `HashMap`。

💡 **比喻**：电话簿——记"人名 → 号码"。你不需要从第一页翻，报名字立刻翻到那一页。

### 使用前要先"引入"

哈希映射不像整数那样随取随用，得先引入：

```rust
使用 标准库::集合::哈希映射;
```

（`使用` = use，`标准库` = std。意思是"把电话簿这类工具搬进当前文件。"）

### 插入与获取

```rust
让 可变 电话簿 = 哈希映射::新建();
电话簿.插入("小明", 100);    // 键 -> 值
电话簿.插入("小红", 95);

匹配 电话簿.获取("小明") {
    有些(值) => 打印行!("小明的分数：{}", 值),
    无 => 打印行!("查无此人"),
}

打印行!("包含小红吗：{}", 电话簿.包含键("小红"));
```

注意：`获取` 返回 `选项<&值>`——键可能不存在，所以用 `匹配` 或 `如果让` 拆开。只想知道在不在、不要值，用 `包含键`。

### 遍历键值对

```rust
对于 (键, 值) 在 &电话簿 {
    打印行!("{} -> {}", 键, 值);
}
```

> ⚠️ 哈希映射的遍历**顺序不保证**——每次运行可能不一样。需要有序，用 `有序映射`（BTreeMap）。

### 词频统计：`条目().或插入()`

统计一串词里每个词出现几次，是哈希映射的经典招式：

```rust
让 词列表 = ["苹果", "香蕉", "苹果", "橘子", "苹果", "香蕉"];
让 可变 词频 = 哈希映射::新建();

对于 词 在 词列表 {
    // 条目：看看这个词在不在；或插入：不在就先记 0
    让 计数 = 词频.条目(词).或插入(0);
    *计数 = *计数 + 1;
}
```

读法：`条目(词)` 站到这个词的"门口"；`或插入(0)` 说"没有就先放个 0"；最后拿到**指向值位置的可变引用**，用 `*计数` 原地加 1。一个词第一次来记 0 加 1 = 1，之后每次加 1。

## 15.5 完整示例：成绩统计册

把向量和哈希映射合体——存一串分数、算总分，再统计每个分数出现几次：

```rust
使用 标准库::集合::哈希映射;

函数 主函数() {
    // —— 向量：收集全班分数 ——
    让 可变 分数 = 向量::新建();
    分数.推入(88);
    分数.推入(95);
    分数.推入(76);
    分数.推入(88);
    分数.推入(95);

    // 算总分
    让 可变 总分 = 0;
    对于 项 在 &分数 {
        总分 = 总分 + *项;
    }
    打印行!("共 {} 人，总分 {}", 分数.长度(), 总分);

    // —— 哈希映射：统计每个分数出现几次 ——
    让 可变 频次 = 哈希映射::新建();
    对于 项 在 &分数 {
        让 计数 = 频次.条目(*项).或插入(0);
        *计数 = *计数 + 1;
    }
    对于 (分, 次) 在 &频次 {
        打印行!("{} 分出现 {} 次", 分, 次);
    }

    // —— 弹出一个看看 ——
    如果让 有些(末位) = 分数.弹出() {
        打印行!("最后一位的成绩是：{}", 末位);
        打印行!("现在还剩 {} 人", 分数.长度());
    }
}
```

## 15.6 逐行解释

- **第 5–10 行**：空向量连推 5 个分数——仓库自动扩容，不用提前报数。
- **第 13–16 行**：借用遍历（`&分数`），`项` 是 `&整数`，用 `*项` 取值相加。
- **第 20–24 行**：词频套路——`条目(*项)` 站到该分数的门口，`或插入(0)` 兜底，`*计数` 累加。`*项` 把借来的整数拆出来当键。
- **第 25–27 行**：遍历频次表。键是分数、值是次数。
- **第 30–33 行**：`弹出` 拿走最后一位的成绩，`如果让` 处理"万一为空"。

## 15.7 运行结果

```
共 5 人，总分 442
88 分出现 2 次
95 分出现 2 次
76 分出现 1 次
最后一位的成绩是：95
现在还剩 4 人
```

（频次表的三行顺序可能变化——哈希映射不保证遍历顺序，属正常现象。）

## 15.8 常见错误与解决

### 错误一：向量里混装类型

```
错误：类型不匹配
```

`向量宏![1, "你好"]` 不行——集合只装**一种**类型。要混装，用第十一章的枚举把不同类型包进一个变体。

### 错误二：向不可变向量推入

```
错误：无法借用为可变
```

`推入`、`移除`、`弹出` 都要 **`可变`**。改 `让 可变 列表 = ...`。

### 错误三：边遍历边修改

```
错误：不能同时拥有可变借用和不可变借用
```

`对于 项 在 &分数` 循环里写 `分数.推入(...)` 会撞上第八章的铁律。**解决**：遍历前把要加的东西先收集起来，遍历完再统一推入。

### 错误四：下标越界恐慌

```
线程 '主函数' 恐慌于索引越界
```

`分数[99]` 而向量没这么长。**解决**：不确定长度时用 `截取(下标)` + `匹配`。

### 错误五：忘记引入哈希映射

报"找不到 `哈希映射`"。**解决**：文件顶部加 `使用 标准库::集合::哈希映射;`。

## 15.9 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 集合 | 堆上存放、长度可变的数据结构 |
| 向量 | 有序、可伸缩、单类型的元素串（向量） |
| 向量宏 | `向量宏![...]` 一口气造好向量 |
| 推入 | 在向量尾部添加元素 |
| 弹出 | 取出并移除向量尾部元素，返回选项 |
| 截取 | 按下标安全读取，返回选项 |
| 移除 | 按下标拿走元素，后面前移 |
| 哈希映射 | 按键查值的键值对集合（HashMap） |
| 条目 | 哈希映射的"门口"，配合或插入实现"没有就初始化" |
| 或插入 | 键不存在就插入默认值，返回指向值的可变引用 |
| 包含键 | 判断键是否存在，返回布尔 |
| 有序映射 | 按键排序的映射（BTreeMap） |

> 📖 **提醒**：遇到不懂的词，随时回查全书开头的《总术语表》。

## 15.11 常见问题（FAQ）

**问：向量为什么放堆上？栈不是更快吗？**

答：栈上空间小且大小必须编译时已知。向量"能长大"——10 个元素还是 10 万个元素都能装，这种弹性只有堆能给。访问元素的速度两者其实一样（向量内部也是一段连续内存）。

**问：向量满了会怎样？**

答：不存在"满"。空间不够时它自动申请一块更大的、把旧数据搬过去，全程自动。这就是"能伸缩的仓库"。

**问：哈希映射的键必须是什么类型？**

答：能**比较相等**、能**算哈希**的类型——整数、布尔、字符串都没问题。自定义结构体当键要贴两张贴纸：`#[派生(PartialEq, Eq, Hash)]`。

**问：`分数[0]` 和 `分数.截取(0)` 怎么选？**

答：写竞赛、确信下标合法用前者（代码短）；用户输入的下标、不确定时用后者（永不恐慌）。

**问：遍历哈希映射想同时修改值怎么办？**

答：`对于 (键, 值) 在 &可变 映射` ——`值` 就是可变引用，直接改。但注意不能同时增删键（又撞借用铁律），要增删就分两步走。

**问：集合里能装集合吗？**

答：能。`向量<向量<整数>>`（二维表）、哈希映射的值装向量都行。写类型时从里往外读。
