# 第二十一章：测试

## 21.0 学习目标

读完这一章，你将能够：

1. 用**校对员**比喻解释自动化测试的价值；
2. 写出标准的**测试模块**（`#[配置(测试)]` + `模块`）；
3. 用 **`断言!`、`断言相等!`、`断言不等!`** 让程序自己检查自己；
4. 用 **`#[should_panic]`** 验证"该恐慌的地方确实恐慌"；
5. 跑通中文项目的测试流水线（eject → `cargo test`）；
6. 读懂测试报告（通过/失败/忽略）。

---

## 21.1 为什么要写测试

你改了 `加法` 函数，怎么知道 `减法` 没被连带改坏？人眼检查迟早漏。

💡 **比喻**：出版社出书前请**校对员**逐页核对。自动化测试就是你雇的一支校对队伍——每次改稿，一声令下全体复查，一秒交报告。

📖 **测试（test）**：一段专门用来"检查另一段代码对不对"的代码。写好了放在代码旁边，机器自动运行。

## 21.2 测试住哪里：测试模块

惯例：在同一个文件底部，建一个贴着特殊贴纸的模块：

```rust
#[配置(测试)]
模块 测试们 {
    使用 超级::*;

    #[测试]
    函数 加法正确() {
        断言相等!(加法(2, 3), 5);
    }
}
```

逐块拆解：

- **`#[配置(测试)]`**（= `#[cfg(test)]`）：告诉编译器"这块只在跑测试时编译"。平时 `rzc run` 它根本不参与，零开销；
- **`模块 测试们`**：测试函数的专属抽屉（名字随意，`测试们` 是惯例）；
- **`使用 超级::*;`**（`超级` = super）：把上层模块的东西全搬进来，这样才能直接喊 `加法`；
- **`#[测试]`**：给函数贴"我是测试"的标签，测试运行器会找到并执行它。

## 21.3 断言：校对员的红笔

📖 **断言**：声明"这件事必须为真，不为真就是 bug"。

| 宏 | 含义 | 例子 |
|---|---|---|
| `断言!(条件)` | 条件必须为真 | `断言!(5 > 3);` |
| `断言相等!(甲, 乙)` | 两者必须相等 | `断言相等!(加法(2,3), 5);` |
| `断言不等!(甲, 乙)` | 两者必须不等 | `断言不等!(加法(2,3), 6);` |

断言通过：安安静静。断言失败：**测试当场失败**，并打印两边实际的值——所以比较类检查优先用 `断言相等!`，失败报告一目了然。

## 21.4 验证恐慌：`#[should_panic]`

有的函数**本来就该恐慌**（比如"参数非法必须当场报警"）。测试也要覆盖这种"正确地恐慌"：

```rust
#[测试]
#[should_panic]
函数 越界会恐慌() {
    让 列表 = [1, 2, 3];
    让 下标 = 列表.长度() + 96;   // 运行时算出 99
    让 _ = 列表[下标];
}
```

贴上 `#[should_panic]`，这函数**恐慌了才算通过**。

> ⚠️ 两个细节：① 属性名是**英文** `#[should_panic]`（属性参数不走翻译）；② 下标要**运行时才确定**——写常量 `列表[99]`，编译器直接判"这必然恐慌"拒绝编译，测试根本跑不起来。

## 21.5 怎么跑：中文项目的测试流水线

rzc 没有独立的测试命令，流水线是：

```bash
# 1. 把中文源码导出为标准 Rust
rzc eject src/main.zh

# 2. 用 Cargo 跑测试
cargo test
```

`cargo test` 会：编译（带上测试贴纸的代码）→ 找出所有 `#[测试]` 函数 → 逐个运行 → 打印报告。**它不会执行 `主函数`**——测试和正式运行互不打扰。

## 21.6 完整示例：给计算器写体检表

被测代码 + 三个测试，一个文件全包：

```rust
函数 加法(甲: 整数, 乙: 整数) -> 整数 {
    甲 + 乙
}

函数 绝对值(数: 整数) -> 整数 {
    如果 数 < 0 { 返回 -数; }
    数
}

#[配置(测试)]
模块 测试们 {
    使用 超级::*;

    #[测试]
    函数 加法正确() {
        断言相等!(加法(2, 3), 5);
        断言相等!(加法(-1, 1), 0);
    }

    #[测试]
    函数 绝对值正确() {
        断言相等!(绝对值(-8), 8);
        断言相等!(绝对值(8), 8);
        断言相等!(绝对值(0), 0);
    }

    #[测试]
    #[should_panic]
    函数 越界会恐慌() {
        让 列表 = [1, 2, 3];
        让 下标 = 列表.长度() + 96;
        让 _ = 列表[下标];
    }
}

函数 主函数() {
    打印行!("普通运行不受测试影响：{}", 加法(1, 2));
}
```

## 21.7 逐行解释

- **第 1–8 行**：两个被测函数——`加法` 和 `绝对值`（含负数分支）。
- **第 10–11 行**：测试模块贴纸 + 抽屉。
- **第 12 行**：搬来上层所有定义。
- **第 14–18 行**：加法测试——正数相加、相反数归零两个用例。
- **第 20–25 行**：绝对值测试——负数、正数、零三个边界全查。
- **第 27–33 行**：恐慌测试——运行时算出越界下标，期待恐慌发生。
- **第 35–37 行**：主函数只干自己的事，`cargo test` 时它不会被执行。

## 21.8 运行结果

```
$ cargo test

running 3 tests
test 测试们::加法正确 ... ok
test 测试们::绝对值正确 ... ok
test 测试们::越界会恐慌 - should panic ... ok

test result: ok. 3 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

三行 `ok` + 汇总 `3 passed; 0 failed`——全绿。中文测试名原样显示，报告很好读。

## 21.9 常见错误与解决

### 错误一：测试里找不到被测函数

忘记 `使用 超级::*;`。**解决**：测试模块第一行补上。

### 错误二：常量恐慌被编译器拦截

`列表[99]`（常量下标）在测试里也编译不过："this operation will panic at runtime"。**解决**：下标改用运行时计算的值。

### 错误三：`#[应当恐慌]` 不识别

属性参数不走翻译。**解决**：写英文 `#[should_panic]`；还可加期望语 `#[should_panic(expected = "不能除以零")]` 精确匹配恐慌留言。

### 错误四：改了代码忘了重新导出

跑的是旧 `.rs`。**解决**：养成习惯——`rzc eject` 完再 `cargo test`，一气呵成。

### 错误五：测试函数带参数

测试函数必须**无参数**。想换多组输入？在一个测试里连写多个断言，或写多个测试函数。

## 21.10 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 测试 | 自动检查代码正确性的小程序 |
| 测试模块 | `#[配置(测试)]` 贴着的抽屉 |
| 测试函数 | 贴 `#[测试]` 的无参数函数 |
| 断言 | "必须为真"的检查 |

## 21.11 练习

### 练习一：测减法

写 `减法(甲, 乙)` 函数和一个测试，覆盖 `减法(5, 3) == 2` 和 `减法(3, 5) == -2`。

<details>
<summary>🔍 查看答案</summary>

```rust
函数 减法(甲: 整数, 乙: 整数) -> 整数 {
    甲 - 乙
}

#[配置(测试)]
模块 测试们 {
    使用 超级::*;

    #[测试]
    函数 减法正确() {
        断言相等!(减法(5, 3), 2);
        断言相等!(减法(3, 5), -2);
    }
}
```

</details>

### 练习二：故意写错

把练习一的断言改成 `断言相等!(减法(5, 3), 3);`，跑测试，观察失败报告长什么样。

<details>
<summary>🔍 查看答案要点</summary>

报告显示 `assertion `left == right` failed`，并列出 left: 2、right: 3——这就是 `断言相等!` 失败时把两边都打出来的价值。

</details>

### 练习三：恐慌测试

写函数 `严格正数(数)`：负数或零时 `恐慌!("必须是正数：{}", 数)`。写一个 `#[should_panic]` 测试验证它。

<details>
<summary>🔍 查看答案</summary>

```rust
函数 严格正数(数: 整数) {
    如果 数 <= 0 {
        恐慌!("必须是正数：{}", 数);
    }
}

#[测试]
#[should_panic(expected = "必须是正数")]
函数 负数会恐慌() {
    严格正数(-1);
}
```

（`expected` 参数确保恐慌是因为对的原因。）

</details>

## 21.12 常见问题（FAQ）

**问：测试代码会让程序变大变慢吗？**

答：不会。`#[配置(测试)]` 让测试只在测试编译时存在，正式构建里它们整个消失。

**问：一个函数要写多少测试？**

答：覆盖三样：**正常路**、**边界**（0、空、最大最小）、**坏路**（该报错的输入）。不用穷举所有数，代表性用例就够。

**问：能先写测试、再写函数吗？**

答：能，这叫**测试驱动开发**：先想清楚"对"长什么样，再去实现。初学很推荐——它逼你先把需求想明白。

**问：测试能访问私有函数吗？**

答：能！测试模块写在同一文件里，属于"内部人"，私有函数照测不误——这正是第十七章说的"同模块可见"。

**问：多个文件的库怎么测？**

答：每个 `.zh` 文件都能挂自己的测试模块；导出后用 `cargo test` 会全部跑。目录结构到综合实战章再见全貌。

**问：`cargo test` 和 `rzc run` 能一起用吗？**

答：各司其职：`rzc run` 日常跑程序；写完/改完代码就 `rzc eject` + `cargo test` 体检。
