# Глава 11: Перечисления и сопоставление с образцом

## 11.0 Цели главы

К концу этой главы вы сможете:

1. Объяснить разницу перечисления и структуры («или» против «и»);
2. Определять **простые перечисления** и **перечисления с данными**;
3. Словом `матч` разбирать перечисление и вынимать附 данные;
4. Прочитать и исправить **E0004** (матч неисчерпателен);
5. Типом **`опция`** выражать «значение может быть, а может не быть»;
6. Объяснить, почему у Rust нет капкана «нулевого указателя».

## 11.1 Перечисление: вопрос с выбором

Структура из Главы 10 — это « **и** »: на карточке ученика **сразу** и имя, и возраст, и балл.

Но в жизни больше « **или** »:

- Светофор **либо** красный, **либо** жёлтый, **либо** зелёный;
- Монета **либо** орёл, **либо** решка;
- Ответ на вопрос **либо** верный, **либо** неверный, **либо** ответа нет.

📖 **Перечисление**: тип, чьё значение бывает лишь **одним из перечисленных случаев**. Ключевое слово — `перечисление`.

💡 **Метафора**: перечисление — **бланк теста с выбором**: можно закрасить только один из данных вариантов; «другое» выбрать нельзя, а закрасить два — тем более.

## 11.2 Простое перечисление: светофор

```rust
перечисление Светофор {
    Красный,
    Жёлтый,
    Зелёный,
}
```

📖 **Вариант**: каждое возможное значение перечисления. У `Светофор` их три.

Пользуемся через `ПеречислениеИмя::Вариант`:

```rust
функция действие_светофора(свет: Светофор) {
    матч свет {
        Светофор::Красный => печатай_строку!("Стой"),
        Светофор::Жёлтый => печатай_строку!("Приготовься"),
        Светофор::Зелёный => печатай_строку!("Иди"),
    }
}

функция главная() {
    действие_светофора(Светофор::Красный);
    действие_светофора(Светофор::Жёлтый);
    действие_светофора(Светофор::Зелёный);
}
```

Вывод:

```
Стой
Приготовься
Иди
```

Чем это лучше чисел 1, 2, 3? **Имя само несёт смысл**, и «четвёртый свет» передать невозможно — компилятор и не примет.

## 11.3 Перечисление с данными

Вариант может **взять багаж с собой**:

```rust
перечисление Оценка {
    Балл(целое),        // с целым числом
    Отсутствовал,              // без ничего
    Освобождён(строка),      // с текстом (причина освобождения)
}
```

Чтение: «оценка — только три случая: либо конкретный балл, либо отсутствие, либо освобождение (с указанием причины)».

Строим значения:

```rust
пусть а = Оценка::Балл(88);
пусть б = Оценка::Отсутствовал;
пусть в = Оценка::Освобождён(строка::Из("уже прошёл курс"));
```

> ⚠️ **Внимание**: в багаже варианта лучше держать `строка`, а не `ссылка_на_строку` — вторая тянет за собой аннотации времени жизни (трудности Главы 14); на старте — в обход.

### Перечисление и структура

| | Структура | Перечисление |
|---|---|---|
| Смысл | эти поля верны **одновременно** | эти случаи **на выбор** |
| Пример | Ученик = имя + возраст + балл | Оценка = Балл / Отсутствовал / Освобождён |

Они ещё и **вкладываются друг в друга** (встретим в Главе 10-бис трейтов и в Главе 15 коллекций) — сила огромная.

## 11.4 Матч: открываем багаж

В Главе 5 был базовый `матч` (числа, диапазоны). С перечислениями `матч` умеет **раскрыть багаж варианта и вытащить данные**:

```rust
функция отчёт_об_оценке(штука: Оценка) {
    матч штука {
        Оценка::Балл(значение) => печатай_строку!("Набрано: {}", значение),
        Оценка::Отсутствовал => печатай_строку!("Отсутствовал, оценки нет"),
        Оценка::Освобождён(причина) => печатай_строку!("Освобождён: {}", причина),
    }
}
```

`Оценка::Балл(значение)` читается: «если это оценка с баллом, вынуть изнутри целое и **назвать его `значение`**». Скобки — и есть действие вскрытия багажа.

Вывод:

```
Набрано: 88
Отсутствовал, оценки нет
Освобождён: уже прошёл курс
```

## 11.5 Исчерпывающе: ни одного пропуска

Железное правило Rust: **матч обязан покрыть все варианты**. Пропустили один — **E0004**:

```rust
перечисление Свет { Красный, Зелёный }

матч сейчас {
    Свет::Красный => печатай_строку!("Стой"),
    // Зелёный пропущен ❌
}
```

Реальная ошибка:

```
Ошибка[E0004]: матч-выражение не исчерпывающе: есть значение без руки
💡 Матч обязан покрывать все случаи. Дополните пропущенную руку или подстелите универсальную руку `_`.
```

**Две починки**: ① дописать каждый вариант; ② подстелить `_` (было в Главе 5):

```rust
матч сейчас {
    Свет::Красный => печатай_строку!("Стой"),
    _ => печатай_строку!("во всех прочих случаях — идти"),
}
```

> 💡 **Почему так строго?** Представьте: завтра в `Светофор` добавят вариант «мигает» — и все точки матча, которые его не обработали, немедленно дадут E0004. Компилятор **гонит** вас обновить каждый угол, ни один не спрячется. В этом главный покой перечислений.

## 11.6 Дополнение: все формы сопоставления с образцом

Пока образцы встречались только внутри `матч`. На деле образцы работают ещё **куче где** и умеют разные трюки. Этот раздел доводит ремесло «образца» до конца — теперь, встретив в коде место «разбираем значение», вы узнаете работающий образец.

### if let: важен только один случай

`матч` требует исчерпать все случаи (только что было). Но если важен **один** случай, а остальные обобщённо — `матч` многословен:

```rust
пусть балл: опция<целое> = некоторое(95);

if let некоторое(значение) = балл {
    печатай_строку!("Балл есть: {}", значение);
} иначе {
    печатай_строку!("Балла нет");
}
```

> 📖 **if let**: `if let образец = значение { ... } иначе { ... }` — пробуем `значение` образцом: **сошлось** — разобрали и выполнили первый блок; **не сошлось** — идём в `иначе`. В русском Rust эти два слова остаются английскими (`if let` / `while let`) — так записано в таблице соответствий.

💡 **Метафора**: `матч` — как автомат, где вы жмёте **все** кнопки подряд; `if let` — как один-единственный жетон: попал — товар выпал, мимо — идём к другому автомату.

`if let некоторое(значение) = балл` читается: «если `балл` — это `некоторое(...)`, вынуть значение и назвать `значение`». То же, что `матч балл { некоторое(значение) => ..., ничто => ... }`, только короче.

### while let: циклический if let

```rust
пусть изменяемый остаток: опция<целое> = некоторое(3);
while let некоторое(значение) = остаток {
    печатай_строку!("Осталось {}", значение);
    остаток = ничто;
}
```

> 📖 **while let**: `while let образец = значение { ... }` — пока `значение` укладывается в `образец`, разбираем и повторяем круг; не уложилось — цикл кончен.

(В примере мы нарочно положили в `остаток` `ничто`, поэтому круг один; в настоящих задачах обычно берут из «меняющегося значения» снова и снова — например из итератора.)

### let иначе: не разобралось — уходим

Бывает, «не разобралось» значит « **дальше выполнять бессмысленно**». С Rust 2021 есть новый синтаксис:

```rust
пусть ввод: опция<целое> = некоторое(7);
пусть некоторое(число) = ввод иначе {
    верни;
};
печатай_строку!("let-else достал {}", число);
```

📖 **let иначе**: `пусть образец = значение иначе { способ_выйти };` — образец **обязан сойтись**; сошлось — продолжаем; не сошлось — выполняется блок `иначе` (внутри обычно `верни` или `прерви`), **дальнейший код не исполняется**.

> ⚠️ **Внимание**: блок `иначе` **обязан завершаться невозвратом** (`верни`, `прерви`, `продолжи`, `паника!` и т. п.) — компилятор гарантирует: «не разобрался — значит дальше не пройдёшь».

### Охрана матча: порог для руки матча

Образец отвечает за «такая ли форма», но иногда нужно ещё **условие**. Охрана — это `если` перед `=>`:

```rust
пусть число = 7;
матч число {
    значение если значение > 5 => печатай_строку!("больше 5: {}", значение),
    _ => печатай_строку!("не больше 5"),
}
```

Чтение: полный порог первой руки — «сошлось с `значение` **и** `значение > 5`». Не выполнено — падаем в следующую руку.

> ⚠️ **Подсказка**: в охране можно писать по-русски (`значение если значение > 5`) — `если` переводится в `if`. Заметьте: у `если` внутри образцов есть иная роль (`if let`), но как охрана это обычный `if`.

### Привязка @: и сматчил, и оставил себе

Хотите «диапазон сработал, и само попавшее значение у меня в руках»? Для этого `@`:

```rust
пусть число = 7;
матч число {
    значение @ 1..=5 => печатай_строку!("от 1 до 5: {}", значение),
    _ => печатай_строку!("вне диапазона"),
}
```

📖 **Привязка @**: `имя @ образец` — сработавшее значение **одновременно** кладётся в `имя`. `значение @ 1..=5` читается «если число между 1 и 5, назвать само число `значение`».

Без `@` запись `1..=5` лишь отвечает «в диапазоне или нет», а само число не отдаёт — `@` закрывает эту брешь.

### Образец «или»: одна рука на несколько случаев

Несколько **однотипных** значений должны идти одной дорогой? Склейте их `|` (вертикальной чертой) в одну руку:

```rust
пусть число = 7;
матч число {
    1 | 2 => печатай_строку!("единица или двойка"),
    _ => печатай_строку!("другое"),
}
```

С перечислениями так же: `Оценка::Отсутствовал | Оценка::Освобождён(_) => печатай_строку!("конкретного балла нет")` — оба «безбалльных» случая в одной руке.

### Структуры и кортежи: разбираем и упакованное

Образец разбирает не только перечисления, но и структуры с кортежами:

```rust
структура Точка {
    х: целое,
    y: целое,
}

пусть точка_а = Точка { х: 10, y: 20 };
матч точка_а {
    Точка { х, y } => печатай_строку!("х={} y={}", х, y),
}

пусть (а, б) = (1, 2);
печатай_строку!("{} {}", а, б);
```

- Образец структуры `Точка { х, y }`: разбирает **по имени поля**, порядок безразличен;
- Образец кортежа `(а, б)`: разбирает **по позиции**, один к одному.

💡 **Метафора**: образец перечисления — вскрыть посылку (посмотреть от кого, вынуть что внутри); образец структуры — взять вещь **по бирке**; образец кортежа — перекличка **по номеру места**.

### Полный пример раз: if let, while let и let иначе

```rust
функция главная() {
    // if let
    пусть балл: опция<целое> = некоторое(95);
    if let некоторое(значение) = балл {
        печатай_строку!("Балл есть: {}", значение);
    } иначе {
        печатай_строку!("Балла нет");
    }

    // while let
    пусть изменяемый остаток: опция<целое> = некоторое(3);
    while let некоторое(значение) = остаток {
        печатай_строку!("Осталось {}", значение);
        остаток = ничто;
    }

    // let иначе
    пусть ввод: опция<целое> = некоторое(7);
    пусть некоторое(число) = ввод иначе {
        верни;
    };
    печатай_строку!("let-else достал {}", число);
}
```

Вывод:

```
Балл есть: 95
Осталось 3
let-else достал 7
```

### Полный пример два: охрана, @ и разбор

Охрана, `@`, `|`, разбор структуры и кортежа — в одной программе:

```rust
структура Точка {
    х: целое,
    y: целое,
}

функция главная() {
    // охрана матча
    пусть число = 7;
    матч число {
        значение если значение > 5 => печатай_строку!("больше 5: {}", значение),
        _ => печатай_строку!("не больше 5"),
    }

    // привязка @
    матч число {
        значение @ 1..=5 => печатай_строку!("от 1 до 5: {}", значение),
        _ => печатай_строку!("вне диапазона"),
    }

    // образец «или»
    матч число {
        1 | 2 => печатай_строку!("единица или двойка"),
        _ => печатай_строку!("другое"),
    }

    // разбор структуры
    пусть точка_а = Точка { х: 10, y: 20 };
    матч точка_а {
        Точка { х, y } => печатай_строку!("х={} y={}", х, y),
    }

    // разбор кортежа
    пусть (а, б) = (1, 2);
    печатай_строку!("{} {}", а, б);
}
```

Вывод:

```
больше 5: 7
вне диапазона
другое
х=10 y=20
1 2
```

Первые три — `7`, по очереди прошедший охрану, диапазон и `|`; последние два — как структура и кортеж разбираются одним махом.

### Опровержимые и неопровержимые: два лица образца

Последнее понятие. Образцы двух родов:

📖 **Опровержимый**: может не сойтись. Например `некоторое(значение)` — а вдруг внутри `ничто`.
📖 **Неопровержимый**: **обязательно** сойдётся. Например `число`, `(а, б)` — разбирается что угодно.

**Где какой дозволен**:

- Связывание `пусть`, параметры функций, цикл `для`: требуют **неопровержимых** образцов (компилятор проверит);
- Руки `матч`, `if let`, `while let`: **годятся оба** (не сошлось — другая дорога или конец).

И наоборот тоже нельзя — неопровержимый образец внутри `if let` компилятор ругнёт за излишество (подскажет «этот образец всегда успешен, if let не нужен»).

**Самая частая ловушка**: написать в `пусть` `пусть некоторое(значение) = балл;` — компилятор сразу даст **E0005**:

```
Ошибка[E0005]: этот образец может не сойтись, а здесь требуется неопровержимый образец
💡 Связывания `пусть` и параметры функций требуют обязательно сходящихся образцов. Опровержимые образцы обрабатывайте через `матч` или `if let`.
```

**Решение**: «может не сойтись» разбор — отдайте `матч` / `if let` / `let иначе`; `пусть` держите только для «точно есть».

## 11.7 Опция: против «может не быть»

В программах частое дело: **значения может не существовать**. Например «максимум по классу» — а если в классе никого?

Многие языки выражают «нет» «нулевым указателем», и родился «дефект на миллиард долларов»: забыл проверить пустоту — программа рухнула на месте. Ответ Rust — встроенное перечисление:

```rust
перечисление Опция<Вещь> {
    Некоторое(Вещь),    // есть, значение внутри
    Ничто,          // значения нет
}
```

(`<Вещь>` — обобщённый тип, подробности в Главе 12; пока читайте «опция, хранящая значения такого-то типа».)

📖 **Опция**: тип «значение может быть, может не быть». `некоторое` = есть, `ничто` = нет.

```rust
пусть есть_балл: опция<целое> = некоторое(95);
пусть нет_балла: опция<целое> = ничто;

матч есть_балл {
    некоторое(значение) => печатай_строку!("Балл: {}", значение),
    ничто => печатай_строку!("Балла нет"),
}
матч нет_балла {
    некоторое(значение) => печатай_строку!("Балл: {}", значение),
    ничто => печатай_строку!("Балла нет"),
}
```

Вывод:

```
Балл: 95
Балла нет
```

Ключевая мысль: **«значения нет» — тоже значение, и обработать его обязаны явно**. Притвориться, что `ничто` не существует, не выйдет — чтобы достать значение из опции, придётся `матч`-ем обслужить оба случая (или удобствами из Главы 16). С этих пор «забыл проверить пустоту» в Rust **невозможно в принципе**.

## 11.8 Полный пример: проверка бланка ответов

Массив перечислений + матч + цикл — проверяем бланк из 10 вопросов:

```rust
// ответ на каждый вопрос (производи Копировать: перечисление без данных копируется даром)
#[производи(Копировать, Клонировать)]
перечисление Ответ {
    Верно,
    Неверно,
    Пусто,
}

// очки за вопрос
функция баллы_за(вопрос: Ответ) -> целое {
    матч вопрос {
        Ответ::Верно => 5,
        Ответ::Неверно => 0,
        Ответ::Пусто => 0,
    }
}

// итоговая оценка
перечисление Оценка { Отлично, Хорошо, Удовлетворительно, Плохо }

функция оценка_по(сумма: целое) -> Оценка {
    если сумма >= 45 { верни Оценка::Отлично; }
    если сумма >= 35 { верни Оценка::Хорошо; }
    если сумма >= 20 { верни Оценка::Удовлетворительно; }
    Оценка::Плохо
}

функция главная() {
    // бланк из 10 ответов
    пусть бланк = [
        Ответ::Верно, Ответ::Верно, Ответ::Неверно, Ответ::Верно, Ответ::Пусто,
        Ответ::Верно, Ответ::Верно, Ответ::Неверно, Ответ::Верно, Ответ::Верно,
    ];

    пусть изменяемый сумма = 0;
    пусть изменяемый верных = 0;
    для номер в 0..10 {
        сумма = сумма + баллы_за(бланк[номер]);
        матч бланк[номер] {
            Ответ::Верно => верных = верных + 1,
            Ответ::Неверно => {}
            Ответ::Пусто => {}
        }
    }
    печатай_строку!("Верных {}, сумма {}", верных, сумма);

    матч оценка_по(сумма) {
        Оценка::Отлично => печатай_строку!("Итог: отлично, блестяще!"),
        Оценка::Хорошо => печатай_строку!("Итог: хорошо, неплохо!"),
        Оценка::Удовлетворительно => печатай_строку!("Итог: удовлетворительно, ещё чуть-чуть"),
        Оценка::Плохо => печатай_строку!("Итог: плохо, надо стараться"),
    }
}
// 预期输出: Верных 7, сумма 35
// Итог: хорошо, неплохо!
```

## 11.9 По строкам

- **Строка 2**: `#[производи(Копировать, Клонировать)]` — `Ответ` не несёт данных, его можно **копировать даром**, как целое. Это важно: элементы массива по умолчанию не вынимаются (будет E0508); с `Копировать` выражение `бланк[номер]` автоматически копируется и свободно идёт в функцию.
- **Строки 10–16**: `баллы_за` матчем переводит три случая в числа. Справа от рук — прямо выражения `5`, `0`.
- **Строка 19**: `Оценка` — чисто ярлычное перечисление.
- **Строки 21–26**: `оценка_по` цепочкой `если` из Главы 5 меняет сумму на оценку, в конце — `Оценка::Плохо` как подстраховка.
- **Строки 30–33**: массив перечислений, 10 элементов.
- **Строки 37–43**: один цикл делает два дела — копит сумму и считает верные. `Ответ::Неверно => {}` и `Ответ::Пусто => {}` — пустые скобки: руки матча **обязаны** покрыть все три случая, даже эти «ничего не делаем» надо вписать для порядка.
- **Строки 46–51**: перечисление оценок снова матчится в пожелания — четыре варианта, ни один не забыт.

## 11.10 Вывод

```
Верных 7, сумма 35
Итог: хорошо, неплохо!
```

7 верных × 5 = 35 очков; полоса 35–44 → хорошо.

## 11.11 Частые ошибки и как их исправить

### Ошибка 1: E0004 матч неисчерпателен

Пропущен вариант. **Решение**: допишите или подстелите `_`. В ошибке перечислены «непокрытые образцы» — просто перепишите их.

### Ошибка 2: E0508 нельзя вынести элемент из массива

`функция(массив[номер])` хочет **забрать** элемент — массив не отдаёт. **Решение**: произведите `Копировать` (для перечислений без данных), или передайте ссылку `&массив[номер]` (поменяв параметр), или `.клонируй()`.

### Ошибка 3: в варианте `ссылка_на_строку` — E0106

Вариант `Освобождён(ссылка_на_строку)` требует аннотацию времени жизни. **Решение**: возьмите `строка`: `Освобождён(строка)`, а значение стройте `строка::Из("...")`.

### Ошибка 4: печать перечисления напрямую

`печатай_строку!("{}", Ответ::Верно)` — ошибка. **Решение**: `#[производи(Отлаживать)]` + `{:?}` (старый приём Главы 10).

### Ошибка 5: значение опции берём как должное

`некоторое(95)` нельзя использовать как `95` — снаружи ещё оболочка. **Решение**: разобрать оболочку `матч`-ем, либо методы из Главы 16 вроде `ожидай`.

## 11.12 Словарик главы

| Термин | Значение одной строкой |
|---|---|
| Перечисление | Тип «одно из многих» |
| Вариант | Каждое возможное значение перечисления |
| Приложенные данные | Данные внутри варианта; вынимаются при матче |
| Исчерпывающе | Матч обязан покрыть все возможности, ни одна не пропущена |
| E0004 | Код ошибки неисчерпательного матча |
| E0508 | Код ошибки «вынести элемент из массива» |
| Опция | Тип «есть или нет» |
| некоторое | Вариант опции «значение есть» |
| ничто | Вариант опции «значения нет» |
| Нулевой указатель | Опасный способ чужих языков обозначать «нет»; Rust заменяет опцией |

## 11.14 Частые вопросы

**В: В чём перечисление выигрывает у строк?**

Строка пишется как угодно: `"отлично"`, `"отлично "`, `"отлично!"` — все разные значения, опечатку компилятор не заметит. Перечисление — фиксированный набор значений; ошиблись — не скомпилируется, а матчем с проверкой исчерпанности гарантированно обработано каждое. **Гораздо безопаснее**.

**В: Почему перечислению без данных нужен `Копировать`, чтобы выниматься из массива?**

Элемент массива по умолчанию — «посмотреть можно, забрать нельзя». `Копировать` сообщает компилятору «копия этого типа смешная по цене (просто ярлык)» — при взятии автоматически копируется, массив нетронут. У перечислений с данными копия может стоить дорого, потому требуется ваше явное слово (`клонируй` или производи `Клонировать`).

**В: `опция` такая морока — почему не разрешить просто «нет значения»?**

Потому что «забыл проверить пустоту» — самый дорогой источник дефектов в истории. Rust сделал «нет» **типом, требующим явной обработки**: морока перенесена на момент написания кода, а крах перед пользователем не случится никогда. Набьёте руку — вскроете оболочку двумя строками.

**В: `матч` или цепочка `если` — как выбрать?**

Отдельные случаи (перечисления, немного фиксированных значений) — `матч`; непрерывные отрезки (диапазоны баллов) — привычнее цепочка `если`. Оба законны; берите, что яснее.

**В: Можно вложить структуру в перечисление?**

Можно! Багаж варианта — любой тип, включая структуры и другие перечисления. В боевых проектах следующих глав этот «комбо-приём» будет повсюду.

**В: Тип `результат` — тоже перечисление?**

Да! `результат` = `успех(значение)` / `неудача(причина)` — та же схема, что у `опции`, специально для «операций, которые могут провалиться». Его главная сцена — Глава 16 «Обработка ошибок».
