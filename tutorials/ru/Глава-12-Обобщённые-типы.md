# Глава 12: Обобщённые типы

## 12.0 Цели главы

К концу этой главы вы сможете:

1. Объяснить, что решают обобщённые типы: **один код — много типов**;
2. Писать **обобщённые функции** `<T>`;

## 12.1 Муки переписывания кода

Нужно взять большее из двух чисел. Версия для целых:

```rust
функция максимум_целых(а: целое, б: целое) -> целое {
    если а > б { верни а; }
    б
}
```

А для дробных? **Почти дословно то же** — сменился только тип:

```rust
функция максимум_дробных(а: вещественное, б: вещественное) -> вещественное {
    если а > б { верни а; }
    б
}
```

Дальше будут версии для длинных целых, символов… Когда кончится переписывание? Поменяете логику — правьте N копий; пропустили одну — дефект.

💡 **Метафора**: у вас есть форма для печенья. Раньше — **под каждый сорт печенья отдельный станок** (для целых, для дробных…); теперь хочется **один универсальный станок** — какое тесто положишь, такое печенье и выйдет.

📖 **Обобщённый тип**: писать код с «заполнителем типа», а конкретный тип подставлять при использовании. Заполнитель по обычаю пишут `<T>` (T — от слова «тип»).

## 12.2 Обобщённая функция: универсальный станок

```rust
функция максимум<число>(а: число, б: число) -> число {
    если а > б {
        верни а;
    }
    б
}
```

Чтение: «`максимум` принимает некий тип `число` (заполнитель), два параметра этого типа и возвращает тот же тип».

Но этот код не скомпилируется! Смысл ошибки: у типа `число` не найден оператор `>`. Всё просто: **универсальный станок не умеет делать всё на свете** — вы сунули внутрь ком «непонятно чего»; откуда станку знать, можно ли это сравнивать по величине? Надо **предъявить требование**.

## 12.3 Ограничение трейтом: требование к типу

```rust
функция максимум<число: частичный_порядок>(а: число, б: число) -> число {
    если а > б {
        верни а;
    }
    б
}

функция главная() {
    печатай_строку!("Больше из целых: {}", максимум(3, 9));
    печатай_строку!("Больше из дробных: {}", максимум(2.5, 1.5));
}
```

Вывод:

```
Больше из целых: 9
Больше из дробных: 2.5
```

📖 **Ограничение трейтом**: требование в угловых скобках вида `<число: частичный_порядок>` — «`число` обязано обладать способностью `частичный_порядок`».

📖 **частичный_порядок** (PartialOrd): стандартный трейт, «умеет сравниваться по величине». Его реализуют целые, вещественные, символы.

Одна функция — и целые, и дробные: при вызове компилятор видит типы аргументов и сам «вписывает пропущенное». Полное понятие трейта — в следующей главе; пока читайте ограничение как « **требование к способности** ».

## 12.4 Обобщённая структура: универсальный ящик

Структура тоже может нести заполнитель типа:

```rust
структура Пара<вещь> {
    передний: вещь,
    задний: вещь,
}
```

`Пара` несёт что угодно, но **обе половины обязаны быть одного типа** (один и тот же `вещь`):

```rust
пусть пара_чисел = Пара { передний: 1, задний: 2 };           // вещь = целое
пусть пара_слов = Пара { передний: строка::Из("небо"), задний: строка::Из("земля") };   // вещь = строка
// Пара { передний: 1, задний: "два" }   ❌ типы спереди и сзади не совпали — ошибка
```

## 12.5 Обобщённый блок реализации

Прикрепляя методы к обобщённой структуре, заполнитель нужно нести и после `реализация`:

```rust
реализация<вещь> Пара<вещь> {
    // потребляет себя, возвращает новый экземпляр с обменом сторон
    функция поменяй(себя) -> Пара<вещь> {
        Пара { передний: себя.задний, задний: себя.передний }
    }
}
```

Три соответствия: `реализация<вещь>` (объявляем заполнитель) + `Пара<вещь>` (кому прикрепляем методы) + `вещь` как тип возврата внутри метода.

> ⚠️ **Внимание**: первый параметр `поменяй` — `себя` (потребление), а не `&себя` (заимствование). Ведь `передний` и `задний` **вынимаются** из экземпляра для обмена — заимствованное лицо работу «на переезд» не потянет (железное правило Главы 8). Потребить старое — вернуть новое: чисто и коротко.

## 12.6 Мономорфизация: почему обобщённое не медленно

«Универсальный станок» звучит так, будто тип угадывается на ходу, при выполнении. Не медленнее ли? **Нет**.

📖 **Мономорфизация**: при компиляции компилятор **отдельно переписывает специализированный код для каждого** реально использованного конкретного типа.

Вы написали одну `максимум<число: частичный_порядок>`, вызвали для целых и дробных — в продукте компиляции на самом деле лежат два куска машинного кода: `максимум_для_целых` и `максимум_для_дробных`.

💡 **Метафора**: вы начертили «чертёж универсального станка», а завод (компилятор) по заказу **построил два специализированных станка** и поставил их на конвейер. На ходу работают специализированные — скорость ровно та же, как если бы вы написали два кода руками. **Пишете — пользуетесь удобством обобщения; работаете — получаете скорость специализированного кода.** Это и есть «абстракция нулевой стоимости» Rust.

## 12.7 Старые знакомые — все обобщённые

Взглянем на `опция` из Главы 11:

```rust
перечисление Опция<Вещь> {
    Некоторое(Вещь),
    Ничто,
}
```

`опция<целое>` несёт целые, `опция<строка>` несёт строки — **одно определение, бесконечность конкретных типов**. Так же устроен `результат<вещь, ошибка>` из Главы 16 (вещь — успех, ошибка — сообщение). Обобщение — не новая наука: вы им давно пользуетесь.

## 12.8 Условие «где» и константные обобщения

### Вынести ограничение наружу: условие «где»

Пока ограничение живёт в угловых скобках: `<число: частичный_порядок>`. Требований много — подпись длинная и тесная:

```
функция максимум<число: частичный_порядок + отображаемый>(а: число, б: число) -> число { ... }
```

Читать тяжело. Rust разрешает **вынести ограничения из угловых скобок** и написать отдельно перед телом функции, начиная словом `где`:

```rust
используй стандарт::форматирование::отображаемый;

// требование к способностям вынесено из угловых скобок в блок где
функция сообщи_большее<число>(а: число, б: число) -> число
где
    число: частичный_порядок + отображаемый,
{
    если а > б { а } иначе { б }
}

функция главная() {
    печатай_строку!("Больше: {}", сообщи_большее(7, 3));
    печатай_строку!("Больше: {}", сообщи_большее(2.5, 1.5));
}
```

Вывод:

```
Больше: 7
Больше: 2.5
```

📖 **где**: условие, переносящее ограничения трейтов из угловых скобок перед тело функции. Два правила: `где` стоит на отдельной строке; ограничения разных типовых параметров разделяются **запятыми**, а несколько ограничений одного параметра связываются `+`.

> ⚠️ Запись в угловых скобках и запись через `где` **полностью равносильны** — компилятору всё едино, разница только в «раскладке». Ограничений мало — удобнее в скобках; много и подпись длинная — уносите в блок `где`: в подписи сразу видно «какие параметры», а требования читаются отдельной строкой не спеша.

### Константное обобщение: длина тоже параметр

Обобщённый параметр бывает не только «типом», но и **константой** — числом, известным уже при компиляции. Самый ходовой случай — длина массива:

```rust
структура Ящик<вещь, константа количество: машинное_натуральное> {
    данные: [вещь; количество],
}

```

Чтение: «у `Ящик` два параметра: `вещь` — **тип** (что кладём), `константа количество` — **число** (сколько кладём)». После перевода это `const N: usize` — ключевое слово `константа` + имя `количество` + тип `машинное_натуральное` (беззнаковое целое размером машинного слова).

💡 **Метафора**: типовое обобщение — «универсальная форма»: какое тесто — такое печенье; константное обобщение — «форма с регулировкой»: повернул ручку (количество) — изменился размер партии.

Рабочий пример — одна структура вмещает 3 целых или 2 строки:

```rust
структура Ящик<вещь, константа количество: машинное_натуральное> {
    данные: [вещь; количество],
}

функция главная() {
    пусть маленький = Ящик::<целое, 3> { данные: [1, 2, 3] };
    пусть большой = Ящик::<строка, 2> { данные: [строка::Из("небо"), строка::Из("земля")] };
    печатай_строку!("Маленький: {} шт, первый {}", маленький.данные.длина(), маленький.данные[0]);
    печатай_строку!("Большой: {} шт, второй {}", большой.данные.длина(), большой.данные[1]);
}
```

Вывод:

```
Маленький: 3 шт, первый 1
Большой: 2 шт, второй земля
```

Обратите внимание на запись `Ящик::<целое, 3>`: в угловых скобках **сперва типы, потом числа**. `количество` обязано быть константой компиляции — переменная в роли длины даст ошибку (см. частые ошибки ниже).

> ⚠️ `машинное_натуральное` (usize) — то самое беззнаковое целое «размером машинного слова», что стоит за длиной массива. `константа количество` ведает только количеством, не типом — в один и тот же `Ящик` кладите хоть целые, хоть строки.

### Частая ошибка: длина массива из переменной времени выполнения

```rust
// 预期错误: E0435
функция главная() {
    пусть ячеек = 3;
    пусть данные: [целое; ячеек] = [1, 2, 3];
    печатай_строку!("{}", данные[0]);
}
```

```
Ошибка[E0435]: В константе использовано неконстантное значение
 --> строка 3: место длины массива
```

**Решение**: длина массива и `количество` константного обобщения обязаны быть **числами, известными при компиляции** — литерал `3` годится, параметр `константа количество: машинное_натуральное` годится, а обычное `пусть ячеек = 3` — нет. Длина приходит из переменной времени выполнения? Берите вектор (Глава 15) или оформите длину константным обобщённым параметром.

## 12.9 Полный пример: универсальный ящик инструментов

Обобщённая функция + обобщённая структура + обобщённые методы — одним взглядом:

```rust
// обобщённая функция: годится всем сравнимым типам
функция максимум<число: частичный_порядок>(а: число, б: число) -> число {
    если а > б {
        верни а;
    }
    б
}

// обобщённая структура
структура Пара<вещь> {
    передний: вещь,
    задний: вещь,
}

// обобщённый блок реализации
реализация<вещь> Пара<вещь> {
    функция поменяй(себя) -> Пара<вещь> {
        Пара { передний: себя.задний, задний: себя.передний }
    }
}

функция главная() {
    // одна функция, два типа
    печатай_строку!("Больше из целых: {}", максимум(3, 9));
    печатай_строку!("Больше из дробных: {}", максимум(2.5, 1.5));

    // одна структура, два наполнения
    пусть пара_чисел = Пара { передний: 1, задний: 2 };
    пусть после = пара_чисел.поменяй();
    печатай_строку!("После обмена: передний={}, задний={}", после.передний, после.задний);

    пусть пара_слов = Пара { передний: строка::Из("небо"), задний: строка::Из("земля") };
    печатай_строку!("Передний: {}", пара_слов.передний);
}
```

## 12.10 По строкам

- **Строки 2–7**: `максимум` с ограничением `частичный_порядок` — вызвать может лишь сравнимый тип.
- **Строки 10–13**: `Пара<вещь>` — оба поля одного типа.
- **Строки 16–20**: обобщённый блок реализации. `поменяй` потребляет себя и строит новый экземпляр.
- **Строки 24–25**: одна функция; в первый вызов компилятор вписал `число = целое`, во второй — `число = вещественное`.
- **Строки 28–30**: у `пара_чисел` тип `вещь = целое`. После вызова `поменяй` `пара_чисел` потреблена (правила владения из Главы 7 действуют на обобщениях точно так же) — новый экземпляр поймали в `после`.
- **Строки 32–33**: у `пара_слов` тип `вещь = строка` — одно определение структуры, совершенно разное наполнение.

## 12.12 Частые ошибки и как их исправить

### Ошибка 1: E0369 оператор не найден для типа

В обобщённой функции прямо применить `>` или `+` к `T` — ошибка. **Решение**: добавить ограничение трейтом — для сравнения `частичный_порядок`, для равенства `Равно`, для печати `отображаемый`. Систематически — в Главе 13.

### Ошибка 2: типы спереди и сзади не совпали

`Пара { передний: 1, задний: "два" }` — ошибка. **Решение**: один заполнитель = один тип. Нужны два типа — берите два заполнителя: `структура Пара<первое, второе> { передний: первое, задний: второе }`.

### Ошибка 3: в блоке реализации забыли заполнитель

Написать `реализация Пара<вещь>` без `реализация<вещь>` — ошибка «типовой параметр `вещь` не найден». **Решение**: `реализация<вещь> Пара<вещь>` — угловые скобки появляются дважды, у каждой своя роль.

### Ошибка 4: E0507 вынести вещь из заимствования

В методе с `&себя` вернуть `себя.поле` (поле строкового рода — перемещаемое) — ошибка «нельзя вынести из заимствованного содержимого». **Решение**: сделать метод потребляющим (`себя`), или возвращать `.клонируй()` поля.

## 12.13 Словарик главы

| Термин | Значение одной строкой |
|---|---|
| Обобщённый тип | Заполнитель типа; один код на много типов, пишется `<T>` |
| Типовой параметр | Заполнитель в угловых скобках, как `<число>` |
| Ограничение трейтом | Требование к способностям типового параметра, как `<число: частичный_порядок>` |
| частичный_порядок | Стандартный трейт «умеет сравниваться по величине» |
| Равно | Стандартный трейт «умеет проверять равенство» |
| Мономорфизация | На компиляции — специализированный код для каждого конкретного типа |
| Абстракция нулевой стоимости | Цель дизайна: удобно писать — без доплаты на ходу |

> 📖 **Напоминание**: незнакомое слово — загляните в «Общий словарь» в начале книги.

## 12.15 Частые вопросы

**В: T в `<T>` обязано зваться T?**

Нет, имя любое. В этой книге русские заполнители (`число`, `вещь`) — для понятности; в реальных проектах чаще всего однобуквенные `T`, `U`.

**В: Куда писать ограничение?**

В объявление: `функция имя<число: частичный_порядок>(...)`. Несколько ограничений — через `+`: `<число: частичный_порядок + отображаемый>` (и сравнивает, и печатается). Несколько типовых параметров — через запятую: `<первое, второе>`.

**В: Обобщённые типы — это то же, что «универсальный интерфейс» (куда в других языках кладут что угодно)?**

Нет. Обобщённые типы фиксируются **на компиляции**, для каждого типа рождается свой код — быстро и типобезопасно; «универсальный интерфейс» распознаёт типы на ходу — медленно и аварино.

**В: Когда стоит брать обобщения?**

Когда ловите себя на **переписывании почти одинакового кода, отличающегося только типом**. Два-три повтора — уже стоит абстрагировать. Но не обобщение ради обобщения: если тип всегда один, конкретный тип и яснее.

**В: `опция<целое>` и `опция<строка>` — один тип?**

Нет. Это два независимых типа, полученных из одного «шаблона» с разными параметрами; присваивать друг другу их нельзя. Как красный и синий ящик из одного проекта: дизайн один, а ящики разные.

**В: «Трейт» следующей главы и «ограничение» этой — как связаны?**

Трейт = **определение самой способности** («что значит уметь сравниваться»); ограничение = **требование к партнёру обладать способностью** при использовании обобщения. В следующей главе вы научитесь определять свои трейты — и мощь обобщений раскроется целиком.

## Что дальше

Обобщения абстрагировали «тип», но не «способность»: `частичный_порядок`, `отображаемый` — способности, данные от рождения. А как их получает **мой собственный тип**? Как определить совершенно новую способность?

**Глава 13 «Трейты»** откроет:

- Определение трейта: `трейт Представься { ... }`;
