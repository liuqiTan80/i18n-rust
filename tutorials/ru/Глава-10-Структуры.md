# Глава 10: Структуры

## 10.0 Цели главы

К концу этой главы вы сможете:

1. Объяснить назначение структур на примере **учётной карточки**;
2. Определить структуру, построить **экземпляр**, читать и менять поля точкой;
3. Блоком **`реализация`** прикрепить к структуре методы (вернём долг Главы 6);
4. Наклейкой **`#[производи(Отлаживать)]`** разрешить печать структуры через `{:?}`;
5. Написать **кортежную структуру**;
6. Синтаксисом обновления **`..старый_экземпляр`** быстро построить новый экземпляр;
7. Управлять группой данных через массив структур.

---

## 10.1 Зачем структуры: муки россыпью

Допустим, надо хранить сведения об ученике: имя, возраст, балл. С текущими знаниями выходит так:

```rust
пусть имя_а = "Соня";
пусть возраст_а = 12;
пусть балл_а = 95;

пусть имя_б = "Гриша";
пусть возраст_б = 13;
пусть балл_б = 76;
```

Проблема налицо: три переменные склеены в группу лишь **договорённостью об именах** (у всех «_а»). Учеников больше — переменные роятся; кто с кем пара — угадывай на глаз.

💡 **Метафора**: это как материалы всего класса, **рассыпанные по полу** — листок с именем, полоска с возрастом, талон с баллом. Нужна **учётная карточка**: одна на ученика, три графы — у каждой своё место.

📖 **Структура**: самодельный тип-«карточка», упаковывающий связанные данные. Ключевое слово — `структура`.

## 10.2 Определяем структуру

```rust
структура Ученик {
    имя_ученика: строка,
    возраст: целое,
    балл: целое,
}
```

Чтение: «есть новый тип `Ученик`, у него три графы: имя_ученика (строка), возраст (целое), балл (целое)».

📖 **Поле**: каждая графа данных внутри структуры. У `Ученик` полей три.

> ⚠️ **Внимание**: определение структуры — лишь **макет карточки**; реальных данных пока нет. Как типография напечатала бланк — но ни на одном бланке ещё ничего не записано.

> 💡 **Почему поле названо `имя_ученика`, а не просто `имя`?** Слово `имя` занято таблицей соответствий — при отладочной печати поле напечаталось бы как `name`, и объявление разошлось бы с показом. Берите незанятые имена!

## 10.3 Строим экземпляр: заполняем карточку

📖 **Экземпляр**: конкретная порция данных, построенная по макету структуры, — заполненная карточка.

### Способ первый: литералом, сразу

```rust
пусть соня = Ученик {
    имя_ученика: строка::Из("Соня"),
    возраст: 12,
    балл: 95,
};
```

Форма: `ИмяТипа { поле: значение, поле: значение, ... }`. **Заполнить обязаны все поля** — пропустили одно, будет ошибка (E0063).

### Способ второй: ассоциированная функция (конструктор)

Видели в Главе 6: функция в блоке `реализация` без `себя` — ассоциированная, она специализируется на строительстве экземпляров:

```rust
реализация Ученик {
    функция создать(имя: строка, балл: целое) -> Ученик {
        Ученик { имя_ученика: имя, возраст: 12, балл: балл }
    }
}

// как пользоваться:
пусть соня = Ученик::создать(строка::Из("Соня"), 95);
```

Плюс: логика построения (например возраст по умолчанию) собрана в одном месте, а в главной функции — чистенькая одна строка.

## 10.4 Читаем и пишем поля: точка

```rust
// читать
печатай_строку!("{} — {} лет", соня.имя_ученика, соня.возраст);

// писать (экземпляр обязан быть пусть изменяемый)
пусть изменяемый соня = Ученик { ... };
соня.балл = 100;
```

> ⚠️ **Внимание**: в Rust нет способа сделать изменяемым «одно поле» — менять любое поле может лишь изменяемый целиком экземпляр: `пусть изменяемый`.

## 10.5 Методы: снабжаем карточку функциями

Функция с параметром `себя` внутри блока `реализация` — **метод**. Возвращаем долг Главы 6:

```rust
реализация Ученик {
    // читающий метод
    функция сдал_ли(&себя) -> логическое {
        себя.балл >= 60
    }

    // изменяющий метод
    функция добавь_баллы(изменяемая_ссылка себя, сколько: целое) {
        себя.балл = себя.балл + сколько;
    }
}

// вызов:
соня.добавь_баллы(5);
печатай_строку!("{}", соня.сдал_ли());
```

Чем метод лучше обычной функции? **Данные и поведение живут вместе**. Проверка «сдал/не сдал» прикреплена к самому типу ученика, а не валяется где-то в стороне как `проверь_сдачу(какой_то_ученик)`.

## 10.6 Отладочная печать: `{:?}` и производи

Попробуем напечатать структуру напрямую:

```rust
печатай_строку!("{}", соня);   // ❌ ошибка: тип Ученик не умеет показываться через {}
```

Для `{}` тип должен уметь «показываться» — у структур по умолчанию этого нет. Два пути; новичкам — первый:

**Клеим наклейку Отлаживать, печатаем через `{:?}`**:

```rust
#[производи(Отлаживать)]
структура Ученик { ... }

печатай_строку!("{:?}", соня);
```

Вывод:

```
Ученик { имя_ученика: "Соня", возраст: 12, балл: 95 }
```

`{:?}` — **отладочный формат**: все поля как на ладони,神器 отладки. Полей много и хочется построчно — `{:#?}`:

```rust
печатай_строку!("{:#?}", небесный_цвет);
```

```
Цвет {
    красный: 0,
    зелёный: 191,
    синий: 255,
}
```

> 📖 **Производи**: заставляет компилятора автоматически породить реализацию某些 способностей; пишется `#[производи(...)]`. В скобках имя трейта можно по-русски (`Отлаживать`, `Клонировать` — так они записаны в таблице соответствий), а можно и английский оригинал (`Debug`, `Clone`).

## 10.7 Кортежная структура: упаковка без имён полей

Бывает, данные просты до того, что каждой графе имя давать жаль:

```rust
структура Точка(целое, целое);

функция главная() {
    пусть точка = Точка(3, 5);
    печатай_строку!("х: {}, y: {}", точка.0, точка.1);
}
// 预期输出: х: 3, y: 5
```

Вывод: `х: 3, y: 5`

Доступ по позиции — `.0`, `.1` (как у кортежей из Главы 4). Годится для одного-двух полей с самоочевидным смыслом (координаты, цвета…). В большинстве случаев читабельнее обычная структура с именами полей.

## 10.8 Синтаксис обновления: поменять пару граф, остальное списать

Хочется построить новую карточку **почти как старую**:

```rust
пусть соня_вторая = Ученик { балл: 88, ..соня };
```

Чтение: «у новой карточки балл 88, **остальные поля списываем у Сони**».

> ⚠️ **Напоминание о владении**: `..соня` **перемещает** поля старой карточки в новую (вспомните Главу 7). Если поля — `строка` и прочие складские данные, `соня` после этого недействительна. Хотите обе карточки живыми — сперва `соня.клонируй()`.

## 10.9 Полный пример: классный журнал

Структура + методы + массив + цикл — управляем целым классом:

```rust
#[производи(Отлаживать, Клонировать)]
структура Ученик {
    имя_ученика: строка,
    балл: целое,
}

реализация Ученик {
    функция создать(имя: строка, балл: целое) -> Ученик {
        Ученик { имя_ученика: имя, балл: балл }
    }

    функция сдал_ли(&себя) -> логическое {
        себя.балл >= 60
    }
}

функция главная() {
    // в массиве три экземпляра-ученика
    пусть класс = [
        Ученик::создать(строка::Из("Соня"), 95),
        Ученик::создать(строка::Из("Гриша"), 58),
        Ученик::создать(строка::Из("Лиза"), 88),
    ];

    // печатаем журнал
    для номер в 0..3 {
        печатай_строку!("{:?}, сдал: {}", класс[номер], класс[номер].сдал_ли());
    }

    // ищем максимум
    пусть изменяемый максимум = 0;
    пусть изменяемый чемпион = Ученик::создать(строка::Из("никто"), 0);
    для номер в 0..3 {
        если класс[номер].балл > максимум {
            максимум = класс[номер].балл;
            чемпион = класс[номер].клонируй();
        }
    }
    печатай_строку!("Чемпион — {}, {} баллов", чемпион.имя_ученика, чемпион.балл);
}
// 预期输出: Ученик { имя_ученика: "Соня", балл: 95 }, сдал: true
// Ученик { имя_ученика: "Гриша", балл: 58 }, сдал: false
// Ученик { имя_ученика: "Лиза", балл: 88 }, сдал: true
// Чемпион — Соня, 95 баллов
```

## 10.10 По строкам

- **Строка 1**: производим сразу две способности — `Отлаживать` (умеет `{:?}`) и `Клонировать` (умеет `.клонируй()`), через запятую.
- **Строки 2–5**: структура `Ученик` с двумя полями.
- **Строки 8–10**: ассоциированная функция `создать` — экземпляр одной строкой.
- **Строки 12–14**: читающий метод `сдал_ли`.
- **Строки 19–23**: **массив структур** — каждый элемент есть карточка ученика. Запись массива та же, что в Главе 3: `[элемент, элемент, ...]`.
- **Строки 26–28**: цикл печати. `{:?}` выплёвывает карточку целиком.
- **Строки 31–32**: в `чемпион` сначала кладём заглушку «никто», чтобы циклу было с чем сравнивать.
- **Строки 33–38**: классический «турнир за первое место». `класс[номер]` достаёт карточку из массива; массив только для чтения (изменяемости нет), **забрать** карточку нельзя — потому `.клонируй()` вручает чемпиону копию.
- **Строка 40**: `чемпион.имя_ученика` — точка достаёт поле.

## 10.11 Вывод

```
Ученик { имя_ученика: "Соня", балл: 95 }, сдал: true
Ученик { имя_ученика: "Гриша", балл: 58 }, сдал: false
Ученик { имя_ученика: "Лиза", балл: 88 }, сдал: true
Чемпион — Соня, 95 баллов
```

## 10.12 Частые ошибки и как их исправить

### Ошибка 1: E0063 поле не заполнено

```
Ошибка[E0063]: в структуре `{имя_структуры}` отсутствует поле `{имя_поля}`
💡 При инициализации структуры нужно задать значения всем полям.
```

**Решение**: допишите поле, или возьмите `..старый_экземпляр`, чтобы остальное списать.

### Ошибка 2: печать структуры через `{}` даёт ошибку

`печатай_строку!("{}", соня)` — ошибка «Ученик не реализует показ». **Решение**: наклейте `#[производи(Отлаживать)]` и перейдите на `{:?}`; либо печатайте конкретное поле `соня.имя_ученика`.

### Ошибка 3: присваивание полю неизменяемого экземпляра

```rust
соня.балл = 100;   // ❌ соня не объявлена пусть изменяемый
```

Ошибка E0594. **Решение**: добавьте `изменяемый` в объявление: `пусть изменяемый соня = ...`.

### Ошибка 4: после синтаксиса обновления старый экземпляр исчез

`..соня` списал поля — строковые поля `сони` перемещены; обращение к `соне` дальше — E0382. **Решение**: сперва `соня.клонируй()`, потом обновляйте; либо переставьте порядок использования.

### Ошибка 5: опечатка в имени трейта производи

`#[производи(Клонировввать)]` — «производящий макрос не найден». **Решение**: сверяйте имена: `Отлаживать`, `Клонировать`, `Копировать`, `Хэш`.

## 10.13 Словарик главы

| Термин | Значение одной строкой |
|---|---|
| Структура | Самодельный упаковочный тип |
| Поле | Каждая графа данных внутри структуры |
| Экземпляр | Конкретная порция данных, построенная по структуре |
| Ассоциированная функция | Функция блока реализации без параметра себя; строит экземпляры |
| Конструктор | См. «ассоциированная функция» |
| Метод | Функция с параметром себя, прикреплённая к типу |
| Производи | Автогенерация реализации трейтов; пишется `#[производи(...)]` |
| Отладочный вывод | Формат `{:?}`; печать структуры вместе с наклейкой Отлаживать |
| Кортежная структура | Структура без имён полей, доступ по позиции |
| Синтаксис обновления | `..старый_экземпляр` — списать остальные поля в новый экземпляр |

> 📖 **Напоминание**: незнакомое слово — загляните в «Общий словарь» в начале книги.

## 10.15 Частые вопросы

**В: Структура и кортеж из Главы 4 — в чём разница?**

Оба упаковывают. Поля кортежа **без имён** (доступ `.0`, `.1`) — для временных мелких связок; поля структуры **с именами** — для настоящих моделей данных. Кортежная структура — между ними.

**В: Можно вложить структуру в структуру?**

Можно. Например в структуре `Класс` — массив учеников. Данные вкладываются слоями, как карточки в шкафу. После Главы 15 (векторы — растущие коллекции) будет ещё гибче.

**В: Что именно передаётся в `себя`?**

Тот экземпляр, что вызвал метод. В `соня.сдал_ли()` параметр `себя` = `соня`. `&себя` — заимствование, `себя` — забрать (потребить). Знания Глав 7–8 работают здесь на полную.

**В: Почему для постройки экземпляра советуют ассоциированную функцию, а не литерал?**

Два плюса — ① можно задать значения по умолчанию (например фиксированный возраст в `создать`); ② можно вставить проверку (страницы не бывают отрицательными). В больших проектах логику постройки держат в ассоциированных функциях.

**В: Наклейка `производи(Отлаживать)` замедляет программу?**

Почти нет. Это печатный код, порождённый на компиляции; пока вы не зовёте `{:?}`, он не исполняется.

**В: Перечисления (Глава 11) и структуры — как соотносятся?**

Структура — « **и** »: на одной карточке сразу имя, возраст и балл; перечисление — « **или** »: значение бывает лишь одним из случаев (сдал / не сдал / отсутствовал). Увидим в следующей главе.

---

## Что дальше

Структура решила «упаковать много данных» (и). Но часты сценарии «одно из двух, одно из трёх» (или): оценка — либо отлично, либо хорошо, либо плохо; монета — либо орёл, либо решка.

**Глава 11 «Перечисления и сопоставление с образцом»** научит:

- Определять «много-из-одного» типы словом `перечисление`;
- Прикладывать данные к каждому варианту;
- Полная сила `матч`: разобрать перечисление и вытащить данные;
- `опция` — стандартный ответ Rust на «значения может не быть».
