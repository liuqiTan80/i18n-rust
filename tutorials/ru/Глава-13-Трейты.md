# Глава 13: Трейты

## 13.0 Цели главы

К концу этой главы вы сможете:

1. Объяснить, что такое трейт, на примере **должностной инструкции**;
2. Определять новые способности ключевым словом **`трейт`** (обязательные методы + методы по умолчанию);
3. Выдавать типам «допуск к работе» записью **`реализация Трейт для Тип`**;
4. Принимать «любого с этой способностью» двумя способами: `<Т: трейт>` и `ссылка реализация Трейт`;
5. Словом **`динамический`** (объект трейта) смешивать разные типы в одной коллекции;
6. Читать и исправлять **E0277** (трейт не реализован);
7. Понять, что наклейка `производи` — это просто автоматическое написание блока реализации.

## 13.1 Трейт: должностная инструкция

💡 **Метафора**: школа готовит вечер знакомств и ищет «умеющих представиться». В объявлении написано:

> **Должность: представимый**
> Требование: обязан уметь выдать текст самопредставления.

Откликнуться может ученик, может учитель — **неважно, кто вы: выполнили требование — допущены**.

📖 **Трейт**: соглашение о наборе подписей методов, определяющее «что умеет тип». Ключевое слово — `трейт`. Как должностная инструкция: пишет только требования, но не имя исполнителя.

`частичный_порядок` и `отображаемый` из Главы 12 — трейты, **заранее определённые** стандартной библиотекой. В этой главе вы научитесь **определять свои**.

## 13.2 Определяем трейт

```rust
трейт Представься {
    функция представься(&себя) -> строка;
}
```

Чтение: «есть должность `Представься`; допущенный обязан предоставить метод `представься`: принимает `&себя`, возвращает строку».

Обратите внимание: после метода — **точка с запятой**, тела нет — инструкция лишь требует, работать за вас не будет.

## 13.3 Реализуем трейт: откликнулись и допущены

```rust
структура Ученик {
    имя_ученика: строка,
    балл: целое,
}

структура Преподаватель {
    имя_ученика: строка,
    предмет: строка,
}

реализация Представься для Ученик {
    функция представься(&себя) -> строка {
        формат!("Ученик {} ({} баллов)", себя.имя_ученика, себя.балл)
    }
}

реализация Представься для Преподаватель {
    функция представься(&себя) -> строка {
        формат!("Преподаватель {}, ведёт {}", себя.имя_ученика, себя.предмет)
    }
}
```

📖 Синтаксис **`реализация ИмяТрейта для ИмяТипа`**: читается «для этого типа реализуем этот трейт». `реализация` и `для` работают в паре.

Теперь и ученик, и преподаватель «допущены с сертификатом» — всюду, где требуют `Представься`, они могут выйти.

> ⚠️ **Внимание**: определить трейт ≠ реализовать. Инструкция без найма — должность пуста; реализовали для одного типа — остальные по-прежнему без допуска.

## 13.4 Методы по умолчанию: инструкция с образцом

Методы трейта могут **нести реализацию по умолчанию** — откликнувшиеся пользуются образцом сразу или переписывают его:

```rust
трейт Представься {
    функция представься(&себя) -> строка;                 // пишем сами

    функция вежливо(&себя) -> строка {             // есть реализация по умолчанию
        формат!("Будем знакомы: {}", себя.представься())
    }
}
```

Ни Ученик, ни Преподаватель не писали `вежливо` — а пользоваться могут: внутри он зовёт их собственный `представься`. Хотите другие любезности — перепишите `вежливо` в своём блоке `реализация`.

## 13.5 Две формы «проверки допуска»

Напишем функцию, принимающую только «умеющих представиться». Две равносильные формы:

### Форма первая: обобщённое ограничение (из Главы 12)

```rust
функция перекличка<человек: Представься>(кто: ссылка человек) {
    печатай_строку!("{}", кто.вежливо());
}
```

### Форма вторая: `ссылка реализация Трейт` (короче)

```rust
функция перекличка(кто: ссылка реализация Представься) {
    печатай_строку!("{}", кто.вежливо());
}
```

Чтение: «параметр — заимствование любого типа, лишь бы тот реализовал `Представься`».

Как выбрать? **Один параметр, простой случай** — форма вторая, нагляднее; **нескольким параметрам нужен один и тот же заполнитель типа** (например «сравнить двух людей одного типа») — форма первая.

## 13.6 Объект трейта: смешиваем разные типы

Массив требует, чтобы все элементы были **одного типа** (железное правило Главы 3). Ученик и Преподаватель — два разных типа; как их поместить в один список?

Ответ: **объект трейта** — смотрим не на конкретный тип, а на «сертификат»:

```rust
пусть список: [ссылка динамический Представься; 2] = [ссылка соня, ссылка преподаватель];

для номер в 0..2 {
    печатай_строку!("Прибыл: {}", список[номер].представься());
}
```

📖 **динамический**: ключевое слово, «конкретный тип узнаётся только при выполнении». `ссылка динамический Представься` читается «заимствование любого представимого».

💡 **Метафора**: обобщённое ограничение — как **запуск потока под должность**: пришли заказы от ученика и преподавателя, и компилятор строит два конвейера (мономорфизация, Глава 12); объект трейта — **один общий конвейер**: что ни придёт, с сертификатом — обработаем. Общий конвейер экономит код, но на каждом шаге сверяет сертификат — чуть-чуть медленнее.

| | Обобщение `<Т: трейт>` | Объект трейта `динамический трейт` |
|---|---|---|
| Когда известен тип | на компиляции | при выполнении |
| Скорость | быстрее (свой код) | чуть медленнее (проверка на месте) |
| Можно смешивать типы | нет | да |

## 13.7 Правда о наклейке производи

Наклейки Главы 10 `#[производи(Отлаживать)]` и Главы 7 `#[производи(Клонировать)]` теперь объяснимы: **производи = компилятор пишет блок `реализация` за вас**.

`#[производи(Отлаживать)]` примерно равен автоматическому:

```rust
реализация Отлаживать для Ученик {
    // ...автоматически выписана логика печати каждого поля
}
```

Одна наклейка — минус десятки переписанных строк. Часто производимые трейты: `Отлаживать` (отладочная печать), `Клонировать` (клон), `Копировать` (копирование даром), `ЧастичноРавно` (сравнение на равенство). **В скобках производи имена пишутся как в таблице** (по-русски — с большой буквы, как определено в языковом пакете; можно и английский оригинал).

## 13.8 Ассоциированные типы и перегрузка операторов

В 13.2 в подписях методов трейта мог появляться «ещё не решённый тип» — вот где работают обобщения. Но есть и другая заглушка: **ассоциированный тип**.

### Ассоциированный тип: «заполнитель типа» внутри трейта

Сперва взглянем на знаменитейший трейт стандартной библиотеки — трейт итератора. Это должностная инструкция «транспортёра»:

```rust
// набросок: ядро трейта итератора стандартной библиотеки выглядит так
трейт Итератор {
    тип ТипЭлемента;                          // ассоциированный тип: вид груза на ленте (заполнитель)
    функция следующий(&изменяемая_ссылка себя) -> опция<ТипЭлемента>;  // взять следующий груз
}
```

Здесь `ТипЭлемента` — **ассоциированный тип**: в инструкции сказано «буду возить груз по имени `ТипЭлемента`», а что это — яблоки или кирпичи, **решает сам каждый откликнувшийся**.

📖 **Ассоциированный тип**: тип-заглушка, объявленный в `трейт` записью `тип Имя;`. При реализации трейта истинное лицо вписывается: `тип ТипЭлемента = конкретный_тип;` (после перевода — `Item`).

> ⚠️ **Подсказка**: `ТипЭлемента` — русское имя ассоциированного типа `Item`, заданное стандартной библиотекой, — наш диалект переводит его обратно в `Item`, так что «переписывайте дословно».

💡 **Метафора**: трейт — спецификация «транспортёра»: «возжу грузы типа `ТипЭлемента`»; реализация трейта — подписание договора: **вторая сторона (ваш тип)** вписывает в договор « `ТипЭлемента` = целое». Один трейт, разные типы вписывают разные `ТипЭлемента` — и не мешают друг другу.

Прикрутим транспортёр к счётчику:

```rust
структура Счётчик {
    текущий: целое,
    предел: целое,
}

// выдаём счётчику допуск «транспортёра»
реализация Итератор для Счётчик {
    тип ТипЭлемента = целое;

    функция следующий(&изменяемая_ссылка себя) -> опция<целое> {
        если себя.текущий < себя.предел {
            себя.текущий = себя.текущий + 1;
            некоторое(себя.текущий - 1)
        } иначе {
            ничто
        }
    }
}

функция главная() {
    пусть счёт = Счётчик { текущий: 0, предел: 4 };
    для число в счёт {
        печатай_строку!("{}", число);
    }
}
```

Вывод:

```
0
1
2
3
```

Реализация `Итератор` требует двух вещей: `тип ТипЭлемента = целое;` (груз — целые) и `функция следующий` (выдаёт по числу). Заполнили — и `Счётчик` стал настоящим транспортёром: `для число в счёт` безостановочно зовёт `следующий` (после перевода — `next`), пока не получит `ничто`.

### Наследование трейтов: родительский трейт

Трейт может «наследовать» другой. Например определим `ПремиумПоказ`: он требует сперва `отображаемый` (умеет описаться), а сверх того даёт «расширенное описание»:

```rust
трейт Описуемый {
    функция опиши(&себя) -> строка;
}

// ПремиумПоказ наследует Описуемый: сперва описание, потом расширенное
трейт ПремиумПоказ: Описуемый {
    функция опиши_расширенно(&себя) -> строка;
}

структура Товар {
    название: строка,
    цена: целое,
}

реализация Описуемый для Товар {
    функция опиши(&себя) -> строка {
        формат!("{} ({} рублей)", себя.название, себя.цена)
    }
}

реализация ПремиумПоказ для Товар {
    функция опиши_расширенно(&себя) -> строка {
        формат!("【рекомендуем】{}", себя.опиши())
    }
}

функция приветствуй(кто: ссылка реализация ПремиумПоказ) {
    печатай_строку!("{}", кто.опиши_расширенно());
}

функция главная() {
    пусть товар = Товар { название: строка::Из("ручка"), цена: 5 };
    приветствуй(ссылка товар);
}
```

Вывод:

```
【рекомендуем】ручка (5 рублей)
```

📖 **Наследование трейтов**: `трейт Потомок: Родитель { ... }` — после двоеточия «предварительное условие». Кто хочет реализовать `ПремиумПоказ`, **обязан одновременно реализовать `Описуемый`**.

Два замечания:

- Для унаследованного `Описуемый` всё равно нужен **отдельный блок реализации** (наследование ≠ автоматическая реализация — на работу устраиваться приходится самому);
- В методах по умолчанию `ПремиумПоказ` можно прямо звать `себя.опиши()` — компилятор знает: «кто реализовал ПремиумПоказ, тот наверняка Описуемый».

### Перегрузка операторов: научим структуру плюсу

Операторы `+`, `-`, `*` — по сути тоже трейты: `+` соответствует трейту `сложение`. Реализуйте его для структуры — и `+` заработает на вашем типе:

```rust
используй стандарт::операции::сложение;

структура Точка {
    х: целое,
    y: целое,
}

// научим Точку плюсу
реализация сложение для Точка {
    тип ТипВывода = Точка;

    функция МетодСложения(себя, другой: Точка) -> Точка {
        Точка { х: себя.х + другой.х, y: себя.y + другой.y }
    }
}

функция главная() {
    пусть а = Точка { х: 1, y: 2 };
    пусть б = Точка { х: 3, y: 4 };
    пусть сумма = а + б;
    печатай_строку!("({}, {})", сумма.х, сумма.y);
}
```

Вывод:

```
(4, 6)
```

Трейт `сложение` требует двух вещей: ассоциированного типа `ТипВывода` (тип результата после сложения) и `функция МетодСложения` (как складывать). С этих пор `а + б` законно — компилятор сам переводит в `сложение::МетодСложения(а, б)`.

> ⚠️ **Подсказка**: имена ассоциированных типов (`ТипВывода`, `ТипЭлемента`) и метода сложения (`МетодСложения`) — зафиксированные слова таблиц соответствий (после перевода `Output`, `Item`, `add`), **переписывайте дословно**. Сложение, умножение, сравнение… весь набор операторных трейтов лежит в `стандарт::операции`, схема одна и та же.

### Частые ошибки

**Ошибка 1: при реализации трейта не заполнили ассоциированный тип**

Реализуете `Итератор`, написали только `функция следующий`, без `тип ТипЭлемента = ...` — ошибка «не хватает ассоциированного типа» (E0191). **Решение**: сверьтесь с определением трейта и допишите `тип ТипЭлемента = конкретный_тип;`.

**Ошибка 2: у наследующего трейта не реализован «родитель»**

Хотите реализовать `ПремиумПоказ`, но не реализовали `Описуемый` — ошибка «`Описуемый` не реализован». **Решение**: реализуйте и родительский трейт; его ограничение жёсткое, не объедешь.

**Ошибка 3: забыли про слово-ключ `для`**

Правильная форма — **`реализация Трейт для Тип`**. Без `для` будет синтаксическая ошибка.

**Ошибка 4: у обязательного метода нет точки с запятой**

Обязательный метод трейта кончается **точкой с запятой** (тела нет); написали `{}` — стал методом по умолчанию. Обе формы законны — просто решите, что вам нужно.

**Ошибка 5: в массив объектов трейта кладут значения**

`[динамический Представься; 2]` не влезет — размер объекта трейта не фиксирован. Берите **заимствования** `[ссылка динамический Представься; 2]` или умные указатели (бокс из Главы 19).

## 13.9 Полный пример: школьная перекличка

Определение трейта, реализация двумя типами, метод по умолчанию, две формы вызова, объект трейта — всё в одной связке:

```rust
// —— должностная инструкция ——
трейт Представься {
    // обязательно: самопредставление
    функция представься(&себя) -> строка;

    // по умолчанию: вежливая версия (внутри зовёт представься выше)
    функция вежливо(&себя) -> строка {
        формат!("Будем знакомы: {}", себя.представься())
    }
}

// —— два рода людей ——
структура Ученик {
    имя_ученика: строка,
    балл: целое,
}

структура Преподаватель {
    имя_ученика: строка,
    предмет: строка,
}

// —— оба откликнулись и допущены ——
реализация Представься для Ученик {
    функция представься(&себя) -> строка {
        формат!("Ученик {} ({} баллов)", себя.имя_ученика, себя.балл)
    }
}

реализация Представься для Преподаватель {
    функция представься(&себя) -> строка {
        формат!("Преподаватель {}, ведёт {}", себя.имя_ученика, себя.предмет)
    }
}

// —— обобщённая функция: только с допуском ——
функция перекличка(кто: ссылка реализация Представься) {
    печатай_строку!("{}", кто.вежливо());
}

// —— объект трейта: разные типы вперемешку ——
функция общая_перекличка(список: [ссылка динамический Представься; 2]) {
    для номер в 0..2 {
        печатай_строку!("Прибыл: {}", список[номер].представься());
    }
}

функция главная() {
    пусть соня = Ученик { имя_ученика: строка::Из("Соня"), балл: 95 };
    пусть преподаватель = Преподаватель { имя_ученика: строка::Из("Пётр Иванович"), предмет: строка::Из("математика") };

    // форма вторая: ссылка реализация Трейт
    перекличка(ссылка соня);
    перекличка(ссылка преподаватель);

    // массив объектов трейта
    пусть список: [ссылка динамический Представься; 2] = [ссылка соня, ссылка преподаватель];
    общая_перекличка(список);
}
// 预期输出: Будем знакомы: Ученик Соня (95 баллов)
// Будем знакомы: Преподаватель Пётр Иванович, ведёт математика
// Прибыл: Ученик Соня (95 баллов)
// Прибыл: Преподаватель Пётр Иванович, ведёт математика
```

## 13.10 По строкам

- **Строки 2–10**: трейт `Представься` — один обязательный метод (кончается точкой с запятой) + один метод по умолчанию (с телом).
- **Строки 13–21**: две структуры, поля разные.
- **Строки 24–34**: два блока `реализация ... для ...`, каждый пишет свой `представься`; `вежливо` оба берут из умолчания.
- **Строки 37–39**: `перекличка` в форме `ссылка реализация Представься` — с сертификатом оба, обоих можно передать.
- **Строки 42–46**: `общая_перекличка` принимает массив «заимствований представимых». `ссылка динамический Представься` делает смешение двух типов законным.
- **Строки 49–50**: строим одного ученика и одного преподавателя.
- **Строки 53–54**: перекличка по одному — идёт метод по умолчанию `вежливо`.
- **Строки 57–58**: складываем в список и проводим общую перекличку. В массиве лежат **заимствования** (`ссылка`) — Соня и преподаватель живы.

Будем знакомы: Преподаватель Пётр Иванович, ведёт математика

Прибыл: Преподаватель Пётр Иванович, ведёт математика

## 13.12 Частые ошибки и как их исправить

### Ошибка 1: E0277 трейт не реализован

```
Ошибка[E0277]: ограничение трейта `камень: умеет_летать` не выполнено
💡 Реализуйте для типа нужный трейт или используйте уже реализовавший его тип.
```

**Решение**: либо дописать `реализация умеет_летать для камень` (дать ему крылья по-настоящему), либо взять уже реализовавший тип.

### Ошибка 2: в блоке реализации пропущен обязательный метод

Трейт требует три метода, в блоке два — ошибка «не хватает метода». **Решение**: допишите по определению трейта; совсем не хочется — поставьте заглушку `не_реализовано!()` (при вызове запаникует).

### Ошибка 3: перепутано слово-ключ в `реализация Трейт для Тип`

Верно — **`реализация Трейт для Тип`**. Пропуск или подмена `для` даст синтаксическую ошибку.

### Ошибка 4: у определения метода забыли точку с запятой

Обязательный метод трейта кончается **точкой с запятой** (тела нет); написали `{}` — это уже метод по умолчанию. Оба законны — осознанно выбирайте.

### Ошибка 5: в массив объектов трейта кладут значения

`[динамический Представься; 2]` не влезет — размер объекта трейта не фиксирован. Берите **заимствования** `[ссылка динамический Представься; 2]` или умные указатели (бокс из Главы 19).

## 13.13 Словарик главы

| Термин | Значение одной строкой |
|---|---|
| Трейт | Соглашение о наборе методов, определяющее «что умеет тип» |
| Блок реализации трейта | `реализация Трейт для Тип` — выдача допуска типу |
| Метод по умолчанию | Метод трейта с готовой реализацией; можно использовать или переписать |
| Ограничение трейтом | `<Т: трейт>` — требование способности от обобщённого типа |
| ссылка реализация Трейт | Короткая форма ограничения трейтом на уровне параметра |
| динамический | Ключевое слово: конкретный тип узнаётся при выполнении |
| Объект трейта | Значение типа `динамический трейт`; смешивает разные типы |
| Производи | Наклейка, по которой компилятор сам пишет блок реализации, `#[производи(...)]` |

> 📖 **Напоминание**: незнакомое слово — загляните в «Общий словарь» в начале книги.

### Упражнение 1: говорящие звери

Определите трейт `Говори { функция говори(&себя) -> строка; }`, реализуйте его для структур `Кошка` и `Собака` (возвращают «мяу» и «гав»), напишите функцию `послушай(кто: ссылка реализация Говори)`, печатающую голос.

<details>
<summary>🔍 Ответ</summary>

```rust
трейт Говори {
    функция говори(&себя) -> строка;
}

структура Кошка;
структура Собака;

реализация Говори для Кошка {
    функция говори(&себя) -> строка {
        строка::Из("мяу")
    }
}

реализация Говори для Собака {
    функция говори(&себя) -> строка {
        строка::Из("гав")
    }
}

функция послушай(кто: ссылка реализация Говори) {
    печатай_строку!("{}", кто.говори());
}

функция главная() {
    послушай(ссылка Кошка);
    послушай(ссылка Собака);
}
```

(`структура Кошка;` — «пустая структура» без полей; удобна, когда тип нужен лишь чтобы вешать на него методы.)

## 13.15 Частые вопросы

**В: Трейт и «интерфейс» — одно и то же?**

Идея одна (соглашение о способностях), но трейты Rust сильнее: умеют нести методы по умолчанию, глубоко配合 с обобщениями и ограничивать «размер типа», «умение копироваться» и прочее. Реализовать трейт могут и прочие типы (целые, строки) — интерфейсы других языков в основном служат «классам».

**В: Один тип может реализовать несколько трейтов?**

Может — по блоку реализации на каждый. И наоборот: один трейт реализуют много типов. Трейты и типы связаны **«многие ко многим»**.

**В: Где можно реализовать трейт — в любом файле?**

Есть правило (правило сироты): либо трейт ваш, либо тип ваш — хотя бы одно из двух. Чтобы две библиотеки не дрались, «чужой тип + чужой трейт» не сочетаются. На старте весь ваш код — в собственном ящике, до этой ловушки не доберётесь.

**В: Обобщённое ограничение или объект трейта — как выбирать в реальных проектах?**

Нужна скорость, набор типов известен → обобщённое ограничение; нужно **смешивать** разные типы (например «список всего печатаемого») → объект трейта. В следующих главах книги встречаются оба помногу.

**В: Стандартные трейты вроде `частичный_порядок`, `отображаемый` — учить наизусть?**

Ходовых немного — `Отлаживать` (печать структур), `Клонировать`/`Копировать` (копирование), `Равно`/`ЧастичныйПорядок` (сравнение), `отображаемый` (печать через `{}`), `Поумолчанию` (значение по умолчанию). Пользуетесь — запоминаются; шпаргалка и в Приложении A.

**В: Можно ли положить в трейт поля?**

Нельзя. Трейт ведает лишь «что умеет» (методы), а не «что имеет» (поля). Нужны поля — структура; нужно «структура + способность» — комбинируйте: структура держит поля, блок реализации вешает трейт.

- Когда в подписи функции аннотировать обязательно, а когда компилятор выведет сам;
