# Глава 14: Времена жизни

## 14.0 Цели главы

К концу этой главы вы сможете:

1. Объяснить, чем на самом деле ведают **времена жизни** (срок действия ссылок);
2. Читать синтаксис пометки **`'a`**;
3. Знать, когда функции аннотация **обязательна**, а когда компилятор выводит сам;
4. Аннотировать **структуру, держащую ссылки**;
5. Читать и исправлять **E0106** (нет аннотации) и **E0597** (заимствование пережило значение);
6. Понять `'статический`: почему строковые литералы действуют вечно.

> ✨ Символы этой главы выглядят грозно, а делают одно: **гарантируют, что расписка в ваших руках никогда не станет фальшивой**. Читайте не спеша, запускайте примеры почаще.

## 14.1 Повторение: у расписки есть срок

В Главе 8 говорилось: ссылка — **расписка**, `&значение` берётся в долг и возвращается.

💡 **Метафора**: у каждой расписки есть **срок действия** — от рождения до освобождения原 значения. Пока срок идёт — пользуйтесь свободно; истёк — расписка недействительна.

```rust
{
    пусть временное = строка::Из("короткий век");
    // «прописка» временное — внутри этого блока
}
// блок кончился: временное освобождено, все расписки на него погашены
```

📖 **Время жизни**: диапазон, в котором ссылка остаётся действительной. Пишется `'имя` (апостроф + имя), например `'живучесть`. Это лишь метка проверки на компиляции — скорости она не трогает.

В компиляторе есть отдел — **заимственный контролёр**, который ежедневно сверяет: когда распиской пользуются, жив ли ещё владелец?

## 14.2 Чаще всего компилятор считает сам

В тринадцати прошлых главах вы ни разу не писали `'живучесть` — компилятор выводит сроки сам:

```rust
пусть привет = строка::Из("Привет");
пусть расписка = ссылка привет;      // срок расписки: от этой строки до освобождения привет
печатай_строку!("{}", расписка);  // ✅ внутри срока
```

У ссылки один источник — срок ясен как день, ваше участие не нужно.

## 14.3 Когда аннотировать обязательно: ссылки из нескольких источников

Напишем функцию: вернуть более длинный из двух текстов.

```rust
// 预期错误: E0106
функция самый_длинный(а: ссылка_на_строку, б: ссылка_на_строку) -> ссылка_на_строку {   // ❌
    а
}
```

Компилятор отвечает ошибкой **E0106**:

```
Ошибка[E0106]: Функции не хватает аннотации времени жизни
💡 Когда у функции несколько ссылочных параметров, компилятор не может вывести связи между ними. Укажите время жизни на параметрах и возвращаемом значении.
```

Почему тут не вывести? Возвращается **одно из двух — а или б**; в подписи функции тела нет, и со стороны подписи компилятор не знает, чей срок унаследует результат. **Сказать обязаны вы своими словами**.

## 14.4 Пометка `'живучесть`: связываем сроки вместе

```rust
функция самый_длинный<'живучесть>(а: ссылка 'живучесть текст, б: ссылка 'живучесть текст) -> ссылка 'живучесть текст {
    если а.длина() >= б.длина() {
        верни а;
    }
    б
}
```

Читаем по кускам:

| Кусок | Чтение |
|---|---|
| `самый_длинный<'живучесть>` | «функция затрагивает один срок, назовём его `'живучесть`» (объявление) |
| `а: ссылка 'живучесть текст` | «а — заимствование текста, живущее минимум `'живучесть`» |
| `б: ссылка 'живучесть текст` | «б — так же» |
| `-> ссылка 'живучесть текст` | «срок возвращаемого считается по тому же `'живучесть`» |

Суть: **возвращённая расписка не переживёт расписки двух параметров**. Вызывающему достаточно держать живыми оба аргумента — результат в безопасности.

> 💡 **Метафора**: `'живучесть` — как **договор о совместной ответственности**: три стороны (а, б и возврат) подписали «наши сроки связаны; у кого первым истечёт — останавливаются все».

> ✨ **Важное уточнение**: пометка `'живучесть` **не меняет** реальный срок жизни ни одного значения — она лишь **рассказывает компилятору об отношениях**. Сроки определяет структура кода; аннотация — только说明书.

## 14.5 Структура держит ссылку: тоже аннотируем

Может ли поле структуры быть ссылкой? Может, но с аннотацией — это заявление « **структура не переживёт одолженные данные** »:

```rust
структура Выдержка<'живучесть> {
    содержимое: ссылка 'живучесть текст,
}

реализация<'живучесть> Выдержка<'живучесть> {
    функция отчёт(&себя) {
        печатай_строку!("Выдержка: {}", себя.содержимое);
    }
}

// пользование:
пусть текст = строка::Из("У лукоморья дуб зелёный");
пусть кусочек = Выдержка { содержимое: ссылка текст };
кусочек.отчёт();
```

Чтение: «`Выдержка` держит заимствованный текст, `'живучесть` — срок этого заимствования. `кусочек` можно использовать, только пока жив `текст`».

> ⚠️ **Частый вопрос**: почему в Главе 11 советовали «не класть в варианты перечислений `ссылка_на_строку`»? Именно потому, что со ссылкой приходит аннотация времени жизни. А со `строка` (данными во владении) — ничего не нужно. **Принцип новичка: структуры и перечисления по возможности держат собственные данные (строка, вектор), расписок — поменьше.**

## 14.6 Когда можно не аннотировать: правила опускания

Три правила автоматического вывода; знать о них достаточно, заучивать не надо:

1. **Каждый ссылочный параметр получает свой собственный срок** — `функция пример(один: ссылка_на_строку, два: ссылка_на_строку)` внутренне считает их двумя независимыми сроками;
2. **Если ссылочный параметр один**, его срок автоматически уходит возвращаемому — `функция первая(слово: ссылка_на_строку) -> ссылка_на_строку` без аннотации;
3. **В методах есть `&себя`** — главным сроком всегда становится `себя`; потому методы шестой главы никогда не аннотируют времена жизни.

Сомневаетесь? **Сперва не пишите — на ошибке компилятор за руку всё допишет** (в совете E0106 готовый правильный вариант, перепишите).

## 14.7 `'статический`: живёт до конца программы

Есть ссылка с самым долгим сроком — равным жизни самой программы: строковый **литерал**.

```rust
пусть лозунг = "Ученье — свет";
```

Эта `"Ученье — свет"` вырезана прямо в программе («камень» из Главы 9) и существует от запуска до выхода. Её время жизни зовётся **`'статический`**.

Вручную писать его не нужно — литералы компилятор признаёт сам. Чаще всего слово встречается в подсказках: «кажется, вам нужно `ссылка 'статический текст`». Увидели — не пугайтесь: это значит «этот текст действителен пожизненно».

## 14.8 Полный пример: самый длинный + карточка выдержки

Два героя главы соединяются:

```rust
// явное время жизни: срок возврата связан с обоими параметрами
функция самый_длинный<'живучесть>(а: ссылка 'живучесть текст, б: ссылка 'живучесть текст) -> ссылка 'живучесть текст {
    если а.длина() >= б.длина() {
        верни а;
    }
    б
}

// структура держит ссылку: аннотация обязательна
структура Выдержка<'живучесть> {
    содержимое: ссылка 'живучесть текст,
}

реализация<'живучесть> Выдержка<'живучесть> {
    функция отчёт(&себя) {
        печатай_строку!("Выдержка: {}", себя.содержимое);
    }
}

функция главная() {
    // —— самый_длинный: две ссылки на входе, одна на выходе ——
    пусть короткая = "Привет";
    пусть длинная = строка::Из("Привет, мир!");
    пусть победитель = самый_длинный(ссылка короткая, ссылка длинная);
    печатай_строку!("Длиннее: {}", победитель);

    // —— Выдержка: структура держит ссылку ——
    пусть текст = строка::Из("У лукоморья дуб зелёный");
    пусть кусочек = Выдержка { содержимое: ссылка текст };
    кусочек.отчёт();
    печатай_строку!("Текст жив: {}", текст);
}
// 预期输出: Длиннее: Привет, мир!
// Выдержка: У лукоморья дуб зелёный
// Текст жив: У лукоморья дуб зелёный
```

## 14.9 По строкам

- **Строки 2–7**: три ссылки `самый_длинный` (два параметра и возврат) помечены `'живучесть` — договор о совместной ответственности в силе.
- **Строки 10–12**: `Выдержка<'живучесть>` — `'живучесть` стоит и после имени структуры: её поле — расписка.
- **Строки 14–18**: в блоке реализации пишется `реализация<'живучесть> Выдержка<'живучесть>` — параметр срока «протаскивается» в блок, оба места обязательны.
- **Строки 22–25**: `короткая` — литерал (`'статический`, от рождения годится под любой срок), `длинная` — строка. Обе одолжены `самый_длинный`; срок `победитель` связан с ними — после этой строки обе живы, безопасно.
- **Строки 28–30**: `кусочек` одолжил текст `текста`. Компилятор следит: ни одно использование `кусочка` не пересечёт точку освобождения `текста`.
- **Строка 31**: `кусочек` отработал, а `текст` печатается сам — заимствование хозяину не мешает.

## 14.10 Вывод

```
Длиннее: Привет, мир!
Выдержка: У лукоморья дуб зелёный
Текст жив: У лукоморья дуб зелёный
```

`длина()` сравнивает байты: «Привет, мир!» (22 байта) против «Привет» (12 байт).

## 14.11 Частые ошибки и как их исправить

### Ошибка 1: E0106 не хватает аннотации времени жизни

Срабатывает, когда функция с несколькими ссылочными параметрами возвращает ссылку. **Решение**: по совету ошибки допишите `'живучесть` — и на параметрах, и на возврате.

### Ошибка 2: E0597 заимствованное живёт недостаточно долго

```
Ошибка[E0597]: заимствованное значение живёт недостаточно долго
💡 Срок ссылки превысил срок жизни значения. Скорректируйте область, чтобы значение жило дольше.
```

Типичный случай: одолжили в блоке, а расписку хотят вынести. **Решение**: ① перенесите объявление оригинала в бóльшую область; ② не одолживайте — постройте свои данные `строка::Из(...)`; ③ возьмите `.клонируй()`.

### Ошибка 3: поле-ссылка без аннотации

`структура Выдержка { содержимое: ссылка_на_строку }` — ошибка. **Решение**: `структура Выдержка<'живучесть> { содержимое: ссылка 'живучесть текст }`; а лучше вовсе `содержимое: строка`.

### Ошибка 4: аннотация не на своём месте

`'живучесть` стоит сразу после `ссылка`: `ссылка 'живучесть текст`. Написать `<'живучесть>` со скобками — синтаксическая ошибка.

## 14.12 Словарик главы

| Время жизни | Диапазон действия ссылки; пишется `'имя` |

| Аннотация времени жизни | Отношения ссылок, показанные компилятору, как `<'живучесть>` |

```rust
// 预期错误: E0597
функция главная() {
    пусть расписка;
    {
        пусть временное = строка::Из("короткий век");

    }

}
```

<summary>🔍 Ответ</summary>

```rust
функция главная() {

функция главная() {

```

</details>

## 14.14 Частые вопросы

**В: Времена жизни тормозят программу?**

Совсем нет. Вся проверка — на компиляции; во время выполнения накладных расходов ноль. `'живучесть` — инструкция для компилятора, после компиляции она «выбрасывается».

**В: Почему в других языках этого нет?**

Там либо позволяют висячие ссылки (риск краха), либо ставят сборщик мусора (накладные расходы на ходу). Rust один раз расчисляет всё на компиляции через аннотации: несколько лишних `'живучесть` при письме — взамен абсолютной безопасности на ходу.

**В: Мне что, каждую ссылку помечать `'живучесть`?**

Нет. В повседневном коде 90% ссылок без пометок (правила опускания покрывают). Вручную пишут лишь два рода: ① функция с несколькими ссылочными параметрами, возвращающая ссылку; ② структура/перечисление, держащие ссылку. Ошибка компилятора точно укажет, где не хватает.

**В: `'живучесть` и `'второй` можно использовать вместе?**

Можно. Разные имена = разные сроки, не связанные между собой. Связь даёт только одинаковая пометка. Например `функция пример<'живучесть, 'кратко>(один: ссылка 'живучесть текст, два: ссылка 'кратко текст) -> ссылка 'живучесть текст` — возврат привязан лишь к сроку `один`.

**В: Прежние советы «обходить времена жизни» ещё действуют?**

Можно ослабить! Теперь вы читаете `ссылка 'живучесть текст`. Но инженерно «тип владеет своими данными» — по-прежнему хороший дизайн: чем проще заимствования, тем легче код в обслуживании.

**В: Времена жизни и владение — как соотносятся?**

Владение ведает «кто хозяин и когда освобождать»; времена жизни — «расписка действительна, лишь пока хозяин жив». Одно — право собственности, другое — срок аренды; вместе они составляют систему безопасности памяти Rust.
