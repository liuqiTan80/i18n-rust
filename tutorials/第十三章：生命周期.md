# 第十三章：生命周期

前面学了很多关于类型和引用的知识。但有一个问题还没解决——**如果引用的东西已经被销毁了，怎么办？**

Rust 用一个叫**生命周期**的机制来解决这个问题。

---

## 13.1 什么是生命周期

> **生活类比**：生命周期就像一个**质检员**。他检查每一本书里的"引用"（书签），确保书签指向的页码还在书里——如果那一页已经被撕掉了，质检员会立刻拦住你。

```
生命周期检查：

书签 → 第 50 页    ✅ 第 50 页还在
书签 → 第 100 页   ❌ 第 100 页被撕掉了！质检员拦住！
```

**为什么要检查生命周期？** 因为"引用一个不存在的东西"会导致非常严重的错误——程序可能读到乱码，甚至崩溃。Rust 宁可让你在写代码时就发现问题，也不让你运行时才出错。

---

## 13.2 悬垂引用问题

先看一个**不合法的例子**：

```rust
函数 获取引用() -> &整数 {
    让 x = 5;
    &x  // ❌ x 在函数结束时就销毁了
}      //    返回的引用指向一个不存在的东西！

函数 主函数() {
    让 r = 获取引用();
    打印行!("{}", r);  // 这里 x 已经不存在了
}
```

逐行解释：

- 第 2 行：创建变量 `x`，值为 5
- 第 3 行：返回 `x` 的引用——但 `x` 马上就要被销毁了
- 第 4 行：函数结束，`x` 被销毁
- 第 8 行：`r` 指向的东西已经不存在了！

```
问题出在哪：

函数开始：
  x = 5         ← x 存在

函数结束：
  x 被销毁       ← x 不存在了
  返回 &x        ← 引用的东西没了！

主函数：
  r = &x         ← r 指向虚空
  打印 r         ← 💥 程序崩溃
```

Rust 的编译器会**直接拒绝编译**这段代码。它会说："`x` 活得不够久"。

---

## 13.3 生命周期标注

有时候编译器自己搞不清楚两个引用的寿命谁长谁短。你需要用**生命周期标注**来告诉它。

> **生活类比**：生命周期标注就像给每个人戴一个**手环**，上面写着"我能活到什么时候"。编译器看到手环就知道——"这个引用能不能活到需要它的时候"。

生命周期标注的语法是**`'a`**（单引号加一个小写字母）：

```
'a  读作"生命周期 a"
'b  读作"生命周期 b"
```

它不代表具体的时间长短，只是一个**标签**——"这个引用和那个东西，谁先消失"。

### 标注语法

```rust
// &'a 整数 意思是：
// "这个引用至少能活 'a 那么久"
函数 取最长<'a>(s1: &'a 文本, s2: &'a 文本) -> &'a 文本 {
    如果 s1.长度() >= s2.长度() {
        s1
    } 否则 {
        s2
    }
}
```

逐行解释：

- 第 3 行：**`<'a>`** 声明了一个生命周期标签 `a`
- 第 3 行：**`s1: &'a 文本`** 意思是"s1 这个引用至少能活 `a` 那么久"
- 第 3 行：**`s2: &'a 文本`** 意思是"s2 也至少能活 `a` 那么久"
- 第 3 行：**`-> &'a 文本`** 意思是"返回的引用也能活 `a` 那么久"

```
生命周期标注告诉编译器：

s1: ────────────────────  ← 至少活 'a
s2:     ────────────────  ← 至少活 'a
返回值: ────────────────  ← 也活 'a

编译器取最短的那个，确保返回值不会比输入活得更久。
```

**为什么需要这个标注？** 因为函数可能返回 `s1` 也可能返回 `s2`，编译器不知道返回的引用到底跟着谁活。标注告诉编译器："不管返回哪个，都至少能活 `a` 那么久"。

## 13.4 结构体中的生命周期

如果结构体里存了引用，你必须标注生命周期：

> **生活类比**：你在日记里抄了一段书上的话。如果书被扔了，日记里的话还有意义吗？结构体存引用也是一样——你必须保证"原书"比"日记"活得久。

```rust
// 这个结构体存了一段文字的引用
结构体 摘录<'a> {
    内容: &'a 文本,
}

函数 主函数() {
    让 原文 = "学而时习之，不亦说乎";  // 原文先存在
    让 我的摘录 = 摘录 { 内容: 原文 };  // 摘录引用原文
    打印行!("摘录：{}", 我的摘录.内容);
    // 原文比摘录活得久 ✅
}
```

逐行解释：

- 第 2 行：**`摘录<'a>`** 声明结构体有一个生命周期标签
- 第 3 行：**`内容: &'a 文本`** 意思是"内容的引用至少活 `a` 那么久"
- 第 7 行：`原文` 先创建
- 第 8 行：`我的摘录` 引用了 `原文`——编译器检查 `原文` 是否比 `我的摘录` 活得久

```
生命周期关系：

原文:    ──────────────────────────  ← 活得久
我的摘录:      ──────────────────    ← 活得短，引用原文
                     ✅ 安全！原文还在
```

## 13.5 静态生命周期

有一种特殊的生命周期叫 **`'静态`**——意思是"整个程序运行期间都存在"：

```rust
// 文字字面量都是 '静态 的
让 问候 = "你好世界";  // 类型是 &'静态 文本
```

**为什么？** 因为文字字面量（写在代码里的文字）被直接嵌在程序文件里。只要程序在运行，这些文字就存在。

```
"你好世界" 存在哪里？

程序文件 ────────────────────────
│ ...                            │
│ "你好世界"   ← 嵌在程序里       │
│ ...                            │
└────────────────────────────────┘
只要程序在运行，这段文字就在 → '静态
```

## 常见错误

### 忘记标注结构体中引用的生命周期

```rust
// ❌ 编译器报错：引用必须标注生命周期
// 结构体 摘录 {
//     内容: &文本,
// }

// ✅ 加上生命周期标注
结构体 摘录<'a> {
    内容: &'a 文本,
}
```

### 引用活得不够久

```rust
函数 主函数() {
    让 r;
    {
        让 x = 5;
        r = &x;  // ❌ x 在括号结束时就销毁了
    }            //    但 r 还想继续用
    // 打印行!("{}", r);  // ❌ x 已经不存在了
}
```

### 返回局部变量的引用

```rust
// ❌ 不能返回函数内部变量的引用
// 函数 获取引用() -> &整数 {
//     让 x = 5;
//     &x  // x 马上就销毁了
// }

// ✅ 返回拥有的值（不是引用）
函数 获取值() -> 整数 {
    让 x = 5;
    x  // 直接返回值，不是引用
}
```

## 练习题

### 练习 1：找最长字符串

写一个函数，接收两段文字引用，返回较长的那段。正确标注生命周期。

<details>
<summary>参考答案</summary>

```rust
函数 取最长<'a>(s1: &'a 文本, s2: &'a 文本) -> &'a 文本 {
    如果 s1.长度() >= s2.长度() {
        s1
    } 否则 {
        s2
    }
}

函数 主函数() {
    让 更长 = 取最长("你好", "世界你好");
    打印行!("较长的是：{}", 更长);  // 世界你好
}
```
</details>

### 练习 2：带生命周期的结构体

定义一个 `文本引用<'a>` 结构体，存一段文字引用。创建实例并打印。

<details>
<summary>参考答案</summary>

```rust
结构体 文本引用<'a> {
    文字: &'a 文本,
}

函数 主函数() {
    让 原文 = "这是原始文字";
    让 r = 文本引用 { 文字: 原文 };
    打印行!("引用内容：{}", r.文字);
}
```
</details>
