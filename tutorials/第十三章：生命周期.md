# 第十三章：生命周期

上一章学了特征——定义类型"能做什么"。这一章，我们回到第七章讲过的**引用**。

回忆一下：引用就像**借书证**——你不拥有这本书，但可以凭借书证去看书。借书证隐藏着一个问题：**如果书被销毁了，借书证还在，怎么办？**

Rust 用一个叫**生命周期**的机制来解决这个问题。

---

## 13.1 什么是生命周期

> **生活类比**：生命周期就像一个**质检员**。他检查每一本书里的"引用"（书签），确保书签指向的页码还在书里——如果那一页已经被撕掉了，质检员会立刻拦住你。

### 每个变量都有"寿命"

先建立两个基础概念：

- **创建**：用 `让` 创建变量时，变量"出生"了（第二章讲过）
- **销毁**：当变量所在的代码块结束时，变量"死亡"了

从出生到死亡这一段"活着"的时间，就叫这个变量的**生命周期**。

```
让 数 = 5;        ← 数 出生（创建）
{                 ← 进入新代码块
    让 其他 = 10;   ← 其他 出生
}                 ← 其他 死亡（代码块结束）
                  ← 数 还活着
```

**引用和生命周期的关系？** 引用是"借书证"，它必须指向一本**还存在的书**。所以 Rust 必须保证：**被引用的东西，比引用本身活得更久**。这个检查就叫**生命周期检查**。

```
生命周期检查：

书签 → 第 50 页    ✅ 第 50 页还在
书签 → 第 100 页   ❌ 第 100 页被撕掉了！质检员拦住！
```

**为什么要检查生命周期？** 因为"引用一个不存在的东西"会导致非常严重的错误——程序可能读到乱码，甚至崩溃。Rust 宁可让你在写代码时就发现问题，也不让你运行时才出错。

---

## 13.2 悬垂引用问题

先看一个**不合法的例子**：

```rust
函数 获取引用() -> &整数 {
    让 数 = 5;
    &数  // ❌ 数 在函数结束时就销毁了
}      //    返回的引用指向一个不存在的东西！

函数 主函数() {
    让 引用值 = 获取引用();
    打印行!("{}", 引用值);  // 这里 数 已经不存在了
}
```

**逐行解释：**

- 第 2 行：创建变量 `数`，值为 5
- 第 3 行：返回 `数` 的引用——但 `数` 马上就要被销毁了
- 第 4 行：函数结束，`数` 被销毁
- 第 7-8 行：`引用值` 指向的东西已经不存在了！

```
问题出在哪：

函数开始：
  数 = 5         ← 数 存在

函数结束：
  数 被销毁       ← 数 不存在了
  返回 &数        ← 引用的东西没了！

主函数：
  引用值 = &数    ← 引用值 指向虚空
  打印 引用值     ← 💥 程序崩溃
```

Rust 的编译器会**直接拒绝编译**这段代码。它会说："`数` 活得不够久"——意思是：你想返回 `数` 的引用，但 `数` 在函数结束时就死了，引用带出去也没用。

## 13.3 生命周期标注

有时候编译器自己搞不清楚两个引用的寿命谁长谁短。你需要用**生命周期标注**来告诉它。

> **生活类比**：生命周期标注就像给每个人戴一个**手环**，上面写着"我能活到什么时候"。编译器看到手环就知道——"这个引用能不能活到需要它的时候"。

生命周期标注的语法是**`'a`**（单引号加一个小写字母）：

```
'a  读作"生命周期 a"
'b  读作"生命周期 b"
```

它不代表具体的时间长短，只是一个**标签**——"这个引用和那个东西，谁先消失"。

### 标注语法

```rust
// &'a 整数 意思是：
// "这个引用至少能活 'a 那么久"
函数 取最长<'a>(甲: &'a 文本, 乙: &'a 文本) -> &'a 文本 {
    如果 甲.长度() >= 乙.长度() {
        甲
    } 否则 {
        乙
    }
}
```

逐行解释：

- 第 3 行：**函数签名里**标了 `<'a>`——`甲: &'a 文本`、`乙: &'a 文本`、`-> &'a 文本` 用的是同一个生命周期标签 `a`，意思是"甲、乙和返回值都至少能活 `a` 那么久"

```
生命周期标注告诉编译器：

甲: ────────────────────  ← 至少活 'a
乙:     ────────────────  ← 至少活 'a
返回值: ────────────────  ← 也活 'a

编译器取最短的那个，确保返回值不会比输入活得更久。
```

**为什么需要这个标注？** 因为函数可能返回 `甲` 也可能返回 `乙`，编译器不知道返回的引用到底跟着谁活。标注告诉编译器："不管返回哪个，都至少能活 `a` 那么久"。

**标注只影响检查，不影响速度**：`'a` 不是程序运行时真的戴了手环——它只在编译时帮编译器检查，编译成机器码后一点痕迹都没有，运行速度和没标注完全一样。

### 省略规则——大多数时候你不用写标注

看到这里你可能会想："难道每个函数都要写 `'a`？"好消息是——**不用**。Rust 编译器非常聪明，它有一套**省略规则**，能在简单情况下自己推断生命周期：

- **只有一个输入引用时**：返回值自动使用这个引用的生命周期，不用标注
- **有 `&自我` 方法时**：返回值自动跟着 `&自我` 走，不用标注

```rust
函数 取第一个字(文字: &文本) -> &文本 {
    &文字[..3]  // ✅ 只有一个输入引用，编译器自己知道寿命
}
```

**什么时候才必须写标注？** 当函数有**多个引用参数**，且返回值可能是其中一个时——比如 13.3 开头的 `取最长`。因为编译器不知道返回值到底跟着 `甲` 活还是跟着 `乙` 活，只能让你明确告诉它。

> ✨ **小提示**：先正常写代码，**报错了再加标注**。大多数函数根本不需要你手动写 `'a`。

## 13.4 结构体中的生命周期

如果结构体里存了引用，你必须标注生命周期：

> **生活类比**：你在日记里抄了一段书上的话。如果书被扔了，日记里的话还有意义吗？结构体存引用也是一样——你必须保证"原书"比"日记"活得久。

> ✨ **小提示**：为什么结构体必须标注，函数却可以省略？因为函数只在"调用那一瞬间"存在，编译器能看清输入输出的关系；而结构体可能被创建后保存很久，编译器无法预知它什么时候被销毁，所以必须由你明确写出"里面的引用能活多久"。

```rust
// 这个结构体存了一段文字的引用
结构体 摘录<'a> {
    内容: &'a 文本,
}

函数 主函数() {
    让 原文 = "学而时习之，不亦说乎";  // 原文先存在
    让 我的摘录 = 摘录 { 内容: 原文 };  // 摘录引用原文
    打印行!("摘录：{}", 我的摘录.内容);
    // 原文比摘录活得久 ✅
}
```

逐行解释：

- 第 2 行：**`摘录<'a>`** 标注结构体有一个生命周期标签
- 第 3 行：**`内容: &'a 文本`** 意思是"内容的引用至少活 `a` 那么久"
- 第 7 行：`原文` 先创建
- 第 8 行：`我的摘录` 引用了 `原文`——编译器检查 `原文` 是否比 `我的摘录` 活得久

```
生命周期关系：

原文:    ──────────────────────────  ← 活得久
我的摘录:      ──────────────────    ← 活得短，引用原文
                     ✅ 安全！原文还在
```

## 13.5 静态生命周期

有一种特殊的生命周期叫 **`'静态`**——意思是"整个程序运行期间都存在"：

```rust
// 文字字面量都是 '静态 的
让 问候 = "你好世界";  // 类型是 &'静态 文本
```

**为什么？** 因为文字字面量（写在代码里的文字）被直接嵌在程序文件里。只要程序在运行，这些文字就存在。

> ✨ **小提示**：`'静态` 也经常出现在函数签名里——比如 `函数 获取名字() -> &'静态 文本`，意思是"返回的文字永远不会消失，你可以放心长期保存"。与普通 `'a` 一样，它也只是编译时的检查标记，不影响运行速度。

```
"你好世界" 存在哪里？

程序文件 ────────────────────────
│ ...                            │
│ "你好世界"   ← 嵌在程序里       │
│ ...                            │
└────────────────────────────────┘
只要程序在运行，这段文字就在 → '静态
```

## 常见错误

### 忘记标注结构体中引用的生命周期

```rust
// ❌ 编译器报错：引用必须标注生命周期
// 结构体 摘录 {
//     内容: &文本,
// }

// ✅ 加上生命周期标注
结构体 摘录<'a> {
    内容: &'a 文本,
}
```

### 引用活得不够久

```rust
函数 主函数() {
    让 引用值;
    {
        让 数 = 5;
        引用值 = &数;  // ❌ 数 在括号结束时就销毁了
    }            //    但 引用值 还想继续用
    打印行!("{}", 引用值);  // ❌ 编译器报错：数 已经不存在了
}
```

> ✨ **小提示**：`让 引用值;` 的意思是"先占一个空盒子，稍后再放东西"。这里的关键是：`引用值` 在花括号**外面**创建，所以它的寿命比花括号里的 `数` 更长——把 `数` 的引用放进去，就必然指向一个已死的东西。

### 返回局部变量的引用

```rust
// ❌ 不能返回函数内部变量的引用
// 函数 获取引用() -> &整数 {
//     让 数 = 5;
//     &数  // 数 马上就销毁了
// }

// ✅ 返回拥有的值（不是引用）
函数 获取值() -> 整数 {
    让 数 = 5;
    数  // 直接返回值，不是引用
}
```

        甲

函数 主函数() {

## 本章小结

| 概念 | 一句话 |
|------|--------|
| 生命周期 | 质检员——确保引用永远指向存在的东西 |
| `'a` | 生命周期标签——"我能活到什么时候" |
| 悬垂引用 | 引用一个不存在的东西——编译器会拦住 |
| 省略规则 | 单一输入引用时编译器自己推断，不用写标注 |
| 结构体中的引用 | 必须标注生命周期，保证"原书"比"日记"活得久 |
| `'静态` | 整个程序运行期间都存在 |
