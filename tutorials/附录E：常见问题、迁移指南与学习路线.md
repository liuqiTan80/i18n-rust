# 附录E：常见问题、迁移指南与学习路线

学完整个教程后，你可能还有很多疑问。本附录回答最常见的问题，讲清如何过渡到标准 Rust，并给你一条继续前进的路线。

---

## E.1 常见问题

### "我完全看不懂怎么办？"

回头重新读前面的章节。每章的比喻和解释是独立的——你可以只看某一章，不用从头开始。

最重要的是**动手写代码**。光看不练永远学不会——就像光看菜谱不会做菜一样。

### "编译器报错了怎么办？"

先别慌。编译器报错不是"你做错了"，而是"编译器在帮你"。

Rust 的编译器是出了名的友好——它会告诉你：
1. 哪里出了错
2. 为什么错了
3. 怎么修

仔细阅读错误信息，大部分问题都能自己解决。错误码的人话解释见**附录 C《常见错误信息字典》**。

### "报错信息是英文的怎么办？"

rzc 会尽量翻译错误信息：**有错误码的错误**（如 `E0308` 类型不匹配）会翻译成中文并附上 💡 修复建议；但**语法错误**（括号不匹配、拼错关键字等）没有错误码，会显示 rustc 的原文。

遇到英文报错时，重点看三个信息：`-->` 后面的**位置**、反引号里的**关键词**、以及 `cannot`/`expected` 等提示词。配合 `rzc eject` 查看翻译后的英文代码，往往能更快发现问题。

### "rzc 支持哪些语言？"

除了中文，rzc 还内置了日语、俄语、德语、西班牙语、法语、葡萄牙语、韩语、阿拉伯语、印地语共 **11 种语言**的语言包，以及英语方言。每种语言都有一套完整的关键字映射——你甚至可以用阿拉伯语或印地语写 Rust。

### "为什么我起的名字有时会编译失败？"

因为中文 Rust 里有一批**关键字和标准库映射词**——它们在语言里有固定含义，拿来当变量名会被"转译"成别的东西。比如：

```rust
枚举 动作 {
    移动,   // ❌ `移动` 是关键字（对应 move），不能当变体名
    跳跃,
}
```

再比如变量起名 `报告`（会被转译成标准库类型 `Report`）、`结果`（转成 `Result`）、变体起名 `空`（转成 `()`）。

**怎么判断一个词能不能用？** 查附录 A 的映射表——表里出现过的词都是"有主"的，尽量避免用作名字；自定义名字优先用**组合词**（`汇报内容`、`计算结果值`）。遇到报错也不用慌，改个名字就行。

### "什么时候用结构体，什么时候用枚举？"

- **结构体**：当你需要把**多个数据打包**时——比如一个人的姓名、年龄、身高
- **枚举**：当一个值**只能是几种情况之一**时——比如方向（东南西北）、选项（有/无）

### "什么时候用引用，什么时候用克隆？"

- **引用**：你只是想"看看"数据，不需要修改——借来看，看完还回去
- **克隆**：你需要一份独立的副本——复印一份，各改各的

克隆会消耗更多内存。如果数据很大，优先考虑引用。

### "什么时候用 `结果`，什么时候用 `恐慌`？"

- **`结果`**：错误是**可以预见的**——文件可能不存在、用户可能输入错误
- **`恐慌`**：错误**不应该发生**——发生了就说明程序有严重问题

经验法则：如果错误是"正常的"（用户经常遇到的），用 `结果`。如果错误是"不可能发生的"（发生了就是 bug），用 `恐慌`。

### "派生宏为什么必须写英文？"

`#[派生(Debug)]`、`#[派生(Clone)]` 的括号里要写英文原名——因为派生宏按英文名查找，这个位置不走翻译。属性参数同理（`#[should_panic]`）。宏内部的片段说明符（`:expr`、`:ident`）也一样。

## E.2 迁移指南：走向标准 Rust

中文 Rust 是学习工具，但最终你可能要过渡到标准 Rust——因为实际的 Rust 项目都是英文的。

好消息是：**你已经学会了 Rust 的核心概念**。迁移只是把中文关键字换成英文。就像你已经学会了做菜，现在只是把中文菜谱翻译成英文菜谱——做法完全一样。

### 为什么要迁移？

1. **实际项目都是英文的**——开源社区、公司代码库都用标准 Rust；
2. **文档和错误信息是英文的**——标准 Rust 的学习资源更丰富；
3. **团队协作**——团队成员可能不熟悉中文方言。

### 迁移三步走

**第一步：导出为标准 Rust。**

```bash
rzc eject src/main.zh
```

生成 `src/main.rs`，内容是标准 Rust：

```rust
// 中文 Rust              // 标准 Rust
函数 主函数() {            fn main() {
    让 名字 = "小明";         let 名字 = "小明";
    打印行!("你好，{}", 名字);  println!("你好，{}", 名字);
}                        }
```

关键字换了名字，变量名、字符串、结构**完全不变**。

**第二步：验证。**

项目此时就是标准 Rust 项目，直接 `cargo run`、`cargo test` 跑起来。

**第三步：对照附录 A 熟悉词汇。**

不用一次全记住——用多了自然就记住了。最常用的对照：

| 中文 Rust | 标准 Rust | 中文 Rust | 标准 Rust |
|-----------|-----------|-----------|-----------|
| `函数` | `fn` | `结构体` | `struct` |
| `让` | `let` | `枚举` | `enum` |
| `可变` | `mut` | `实现` | `impl` |
| `如果/否则` | `if/else` | `特征` | `trait` |
| `匹配` | `match` | `模块` | `mod` |
| `对于...在` | `for...in` | `公开` | `pub` |
| `返回` | `return` | `使用` | `use` |
| `字符串` | `String` | `结果` | `Result` |
| `选项` | `Option` | `向量` | `Vec` |

### 心态调整

1. **概念不变**——所有权、借用、特征、生命周期，两种方言完全相同；
2. **语法几乎不变**——只是关键字换了名字；
3. **你已经有了优势**——你理解了 Rust 的核心，现在只需要学"词汇"。

## E.3 学习路线

### 第一阶段：巩固基础（1-2 周）

- 重新阅读你不确定的章节
- 做每章的练习题
- 完成第二十五章的毕业挑战 1–3

### 第二阶段：实战项目（2-4 周）

选择一个小项目来做：

1. **命令行工具**：文件搜索、文本处理、批量重命名
2. **小游戏**：猜数字、贪吃蛇、21 点
3. **网络工具**：简单的网页服务器、聊天室（此时接触 tokio 异步生态）

### 第三阶段：深入学习（持续）

1. 阅读标准 Rust 的官方教程（The Rust Programming Language）
2. 通过示例学习（Rust by Example）、刷小练习（Rustlings）
3. 学习 Rust 的异步生态或嵌入式开发
4. 参与开源项目

## E.4 编程思维建议

### 先想清楚再写代码

拿到一个问题后，不要急着写代码。先用自然语言描述解决步骤，想清楚后再翻译成代码——第二十五章的记账本就是先设计数据模型再写函数。

### 从小处开始

不要试图一次写 1000 行代码。每次只写一小部分，确认它能运行，再继续。

### 多读错误信息

编译器的错误信息是你的朋友。它告诉你：**哪里**错了（文件名和行号）、**什么**错了（错误类型）、**怎么**修（建议的修复方式）。

### 善用测试

改完代码先跑测试（第二十一章）。有测试兜底，改代码才有底气。

## E.5 编程习惯建议

### 给变量取有意义的名字

```rust
// ❌ 看不出是什么
让 x = 25;

// ✅ 一看就知道（还避开了映射词冲突）
让 学生年龄 = 25;
```

### 写注释解释"为什么"

```rust
// ❌ 没用的注释——代码已经说了
让 总分 = 甲 + 乙;  // 甲加乙

// ✅ 有用的注释——解释了"为什么"
// 因为满分是 100，超过 100 按 100 算
让 总分 = (甲 + 乙).最小(100);
```

### 保持函数简短

一个函数只做一件事。函数太长就拆成多个小函数（第六章）。
