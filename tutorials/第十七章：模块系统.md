# 第十七章：模块系统

## 17.0 学习目标

读完这一章，你将能够：

1. 用**抽屉柜**比喻解释模块的作用（分门别类 + 隐私保护）；
2. 用 **`模块`** 关键字给代码分区，支持嵌套；
3. 用 **`公开`** 控制哪些东西允许外人使用；
4. 用 **`::` 路径**和 **`使用`** 找到目标；
5. 把代码拆成**多个文件**，一个文件一个模块；
6. 看懂 **E0603**（私有访问）并修复。

## 17.1 为什么需要模块

前面所有代码都挤在一个文件里。真实项目动辄几千行——全堆一起，找个函数像大海捞针。

💡 **比喻**：一间大仓库如果什么都乱扔，找把螺丝刀要翻一天。**模块**就是仓库里的**抽屉柜**：厨具放厨房抽屉、餐具放餐厅抽屉，每个抽屉还能上锁（隐私保护）。

模块解决三件事：

1. **分区**——相关的代码住一起；
2. **命名空间**——两个抽屉里都可以有"夹子"，互不冲突；
3. **隐私**——抽屉里没公开的东西，外人碰不到。

## 17.2 定义模块

```rust
模块 厨房 {
    函数 洗菜() {
        打印行!("洗菜");
    }

    公开 函数 上菜() {
        洗菜();
        打印行!("上菜！");
    }
}
```

📖 **模块（mod）**：把函数、结构体、常量等装进一个带名字的空间。模块可以**嵌套**——抽屉里套小抽屉：

```rust
模块 厨房 {
    公开 模块 灶台 {
        公开 函数 炒菜() {
            打印行!("炒菜中...");
        }
    }
}
```

## 17.3 公开与私有：门锁

Rust 的规矩和很多语言**相反**：

> **默认全部私有**。想让外面用，必须显式 **`公开`**。

```rust
模块 厨房 {
    函数 洗菜() { ... }        // 🔒 私有：只有厨房内部能用
    公开 函数 上菜() { ... }   // 🔓 公开：外面可以调用
}
```

外面这样调用：

```rust
厨房::上菜();      // ✅ 公开函数
厨房::洗菜();      // ❌ 报错：私有！
```

💡 **比喻**：餐厅对客人**公开上菜窗口**，但后厨怎么洗菜是内部流程，不对外开放。想改内部流程时，随便改——反正没人能直接依赖它。这就是私有的好处：**内部自由，外部稳定**。

## 17.4 路径：怎么找到抽屉里的东西

📖 **路径**：用 **`::`** 连接的一串名字，像家庭地址："小区 :: 楼栋 :: 门牌"。

```rust
厨房::灶台::炒菜();    // 完整地址：厨房里的灶台里的炒菜
```

**在模块内部**，找邻居可以抄近路——同层的直接点名：

```rust
公开 函数 上菜() {
    洗菜();          // 同层私有函数，直接叫
    灶台::炒菜();    // 内嵌的子模块，相对路径
}
```

## 17.5 `使用`：把常用地址写进通讯录

每次都写全地址太啰嗦。`使用`（use）把路径**引入**当前文件，之后直接点名：

```rust
使用 厨房::上菜;

函数 主函数() {
    上菜();    // 不用再写 厨房::
}
```

第十五章的 `使用 标准库::集合::哈希映射;` 就是这个机制——把标准库深处的哈希映射搬到手边。

> ✨ 小规矩：**引入函数**写到函数名（`使用 厨房::上菜;`）；**引入类型**一般写到类型名（`使用 标准库::集合::哈希映射;`），用它的方法靠点号就行。

## 17.6 文件即模块：多文件项目

代码多了，把模块拆进各自的文件。**文件名 = 模块名**：

```
我的项目/
├── Cargo.toml
└── src/
    ├── 主函数.zh          <- 主入口
    └── 餐具库.zh        <- 新文件 = 新模块
```

`餐具库.zh` 里：

```rust
公开 函数 拿筷子() {
    打印行!("拿好筷子");
}
```

`主函数.zh` 里用 **`模块 餐具库;`**（注意是**分号**，不是花括号）声明"有这么个文件模块"，然后照常使用：

```rust
模块 餐具库;

函数 主函数() {
    餐具库::拿筷子();
}
```

## 17.7 完整示例：小餐厅

分区、嵌套、隐私、路径、引入——全在一间"小餐厅"里：

```rust
模块 厨房 {
    // —— 嵌套的小抽屉 ——
    公开 模块 灶台 {
        公开 函数 炒菜() {
            打印行!("炒菜中...");
        }
    }

    // —— 私有：内部流程 ——
    函数 洗菜() {
        打印行!("洗菜");
    }

    // —— 公开：对外的唯一窗口 ——
    公开 函数 上菜() {
        洗菜();          // 模块内：私有函数随便用
        灶台::炒菜();    // 模块内：嵌套模块直接点名
        打印行!("上菜！");
    }
}

// 把上菜窗口记进通讯录
使用 厨房::上菜;

函数 主函数() {
    上菜();                        // 靠 使用 引入
    厨房::灶台::炒菜();            // 完整路径点名
}
```

## 17.8 逐行解释

- **第 1 行**：`模块 厨房`——拉开第一个抽屉。
- **第 3–7 行**：嵌套模块 `灶台`，两层都 `公开`——外面才够得着 `炒菜`（一层私有，整条路就断）。
- **第 10–12 行**：`洗菜` 没写 `公开`，天生私有。
- **第 15–19 行**：`上菜` 公开，内部用近路调 `洗菜` 和 `灶台::炒菜`。
- **第 23 行**：`使用 厨房::上菜;`——以后直接喊"上菜"。
- **第 26 行**：`上菜()` 一条龙：洗菜 → 炒菜 → 上菜。
- **第 27 行**：绕过上菜窗口，直接进灶台炒菜——路径写得全，公开够得着。

## 17.9 运行结果

```
洗菜
炒菜中...
上菜！
炒菜中...
```

第一组三行来自 `上菜()`，第二行单独来自完整路径调用。

## 17.10 常见错误与解决

### 错误一：E0603 模块是私有的

```
错误[E0603]: 模块是私有的
💡 默认情况下模块是私有的。若需从外部访问，请使用 `公开 模块 xxx;` 声明。
```

**解决**：沿路径检查**每一层**——模块、函数、结构体字段都要 `公开`，缺一不可。

### 错误二：路径写错找不到东西

```
错误：找不到 `炒菜`
```

**解决**：从当前模块出发想地址——同层的直接点名，外部的写全路径或先 `使用`。

### 错误三：文件模块写成了花括号

`模块 餐具库 { }` 是"就地定义"；文件模块必须 **`模块 餐具库;`**（分号）。且文件名要和模块名一致。

### 错误四：结构体公开了、字段没公开

`公开 结构体 学生 { 姓名: 字符串 }`——外面能造 `学生` 这个类型，但**碰不到 `姓名` 字段**。字段要单独 `公开`：

```rust
公开 结构体 学生 {
    公开 姓名: 字符串,
}
```

## 17.11 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 模块 | 代码的抽屉，`模块 名字 { }` |
| 公开 | 关键字，允许外部使用（默认私有） |
| 私有 | 默认状态，只有模块内部能用 |
| 路径 | `::` 连接的地址，指向模块里的东西 |
| 使用 | 把路径引入当前文件，省去重复写地址 |
| 文件模块 | 一个文件一个模块，`模块 名字;` 声明 |

> 📖 **提醒**：遇到不懂的词，随时回查全书开头的《总术语表》。

## 17.13 常见问题（FAQ）

**问：为什么默认私有？别的语言大多默认公开。**

答：默认私有逼你**想清楚接口**——哪些是承诺给外面的，哪些是内部实现。内部改动不破坏外部，代码才好维护。习惯后你会觉得更安全。

**问：模块和文件必须一一对应吗？**

答：不是。一个文件里可以写多个 `模块 { }`，一个模块也可以跨多个文件（子目录）。但"一个文件一个模块"最清晰，推荐新手坚持。

**问：`使用` 会让代码变慢吗？**

答：不会。`使用` 只是编译期的别名，运行时代价为零。放心引入。

**问：标准库那么深的路径（标准库::集合::哈希映射），官方是怎么分区的？**

答：就是本章这套系统的真实运用：`标准库` 是库根，`集合` 是它的模块，`哈希映射` 是模块里的类型。你会的语法和官方一模一样。

**问：能不能 `使用 厨房::*;` 把整个模块全引入？**

答：可以（`*` 通配），但会把里面所有公开的东西倒进来，容易重名。初学建议一个一个显式引入，清楚。

**问：私有函数写测试怎么办？**

答：同模块内部（包括测试代码写在同一模块里）可以访问私有成员。第二十一章《测试》会讲。
