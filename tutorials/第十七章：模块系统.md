# 第十六章：模块系统

前面的代码都写在一个文件里。但项目一大，一个文件就装不下了。

你需要把代码**分门别类**地整理好——就像一个大公司要有不同的部门，每个部门管不同的事。

这就是**模块系统**的作用。

---

## 16.1 什么是模块

> **生活类比**：模块就像一个公司里的**部门**。"人事部"管人事，"财务部"管账目，"技术部"管开发。每个部门有自己的工作内容，其他部门需要合作时，得通过正式渠道沟通。

```
公司（项目）
├── 人事部（模块）── 招聘、培训
├── 财务部（模块）── 记账、报销
└── 技术部（模块）── 开发、运维
```

**为什么要分模块？** 因为代码多了以后，全堆在一起会非常混乱。分模块让你：

- 把相关的代码放在一起（比如所有"厨房"相关的函数放一个模块）
- 隐藏不想让别人看到的细节（比如"成本计算"不对外公开）
- 让代码更容易找到（要找做饭功能？直接去厨房模块找）

**模块里能放什么？** 函数、结构体、枚举、特征……几乎前面学过的所有东西都能放进模块。甚至**模块里还能再放模块**——就像公司里部门下面还有小组：

```
公司（项目）
├── 技术部（模块）
│   ├── 开发组（子模块）── 写代码
│   └── 测试组（子模块）── 查 bug
└── 财务部（模块）
    └── 出纳组（子模块）── 发工资
```

模块套模块，一层层套下去，就形成了一棵"**模块树**"。树根是主文件（`主函数` 所在的地方），树枝是各个模块。

---

## 16.2 定义模块

用 **`模块`** 关键字定义一个模块：

```rust
模块 厨房 {
    公开 函数 做饭() {
        打印行!("正在做饭...");
    }

    公开 函数 洗碗() {
        打印行!("正在洗碗...");
    }
}

函数 主函数() {
    厨房::做饭();   // 调用厨房模块的"做饭"功能
    厨房::洗碗();   // 调用厨房模块的"洗碗"功能
}
```

逐行解释：

- 第 1 行：**`模块 厨房 { ... }`** 定义了一个叫"厨房"的模块。注意：`模块` 后面跟着的是模块的**名字**（你自己起），花括号里是模块的**内容**
- 第 2-4 行：模块内部的 `做饭` 函数
- 第 6-8 行：模块内部的 `洗碗` 函数
- 第 3 行：`做饭` 前面多了个 **`公开`**——先记住"从外面调用模块里的函数，就要加 `公开`"，它具体是什么意思，16.4 马上讲
- 第 12 行：**`厨房::做饭()`** 用 `::` 表示"属于厨房模块的做饭功能"。`::` 可以读作"的"——"厨房的做饭"

```
模块就像一个工具箱：

┌── 厨房 ──────────────────┐
│                           │
│  🔧 做饭()               │
│  🔧 洗碗()               │
│                           │
└───────────────────────────┘
         ↑
    厨房::做饭()  ← 打开工具箱，使用"做饭"
```

> ✨ **小提示**：`::` 在第十五章见过（`结果::成功`），它的意思是"**属于**"——`厨房::做饭` 读作"厨房的做饭"。这一章你会经常见到它。

## 16.3 嵌套模块：模块树

模块里可以再放模块，就像文件夹里还能放文件夹：

```rust
模块 餐厅 {
    公开 模块 厨房 {
        公开 函数 做饭() {
            打印行!("正在做饭...");
        }
    }

    公开 模块 大厅 {
        公开 函数 接待() {
            打印行!("欢迎光临！");
        }
    }
}

函数 主函数() {
    餐厅::厨房::做饭();  // 路径：餐厅 → 厨房 → 做饭
    餐厅::大厅::接待();  // 路径：餐厅 → 大厅 → 接待
}
```

逐行解释：

- 第 1 行：定义"餐厅"模块
- 第 2 行：餐厅里面又定义了一个"厨房"模块——`厨房` 是 `餐厅` 的**子模块**，`餐厅` 是 `厨房` 的**父模块**
- 第 3 行：厨房里的 `做饭` 函数加了 `公开`——为什么？看第 15 行，`主函数` 要调用它。不加 `公开`，主函数就用不了（16.4 会细讲）
- 第 15 行：**`餐厅::厨房::做饭()`** 像不像文件路径？`餐厅/厨房/做饭`——一层一层往下找。这就是"**路径**"：从根出发，沿着模块树一路走到目标函数

```
模块树长这样：

餐厅
├── 厨房
│   └── 做饭()     ← 完整路径：餐厅::厨房::做饭()
└── 大厅
    └── 接待()     ← 完整路径：餐厅::大厅::接待()
```

> ⚠️ **重要**：嵌套的模块每一层都要"开门"——`厨房` 要 `公开`，`做饭` 也要 `公开`，外面才够得着。就像进公司大门要工牌、进办公室还要门禁，每一层都要刷一次卡。

## 16.4 公开与私有

> **生活类比**：公司里有**内部文件**和**公开文件**。内部文件只有本部门的人能看，公开文件其他部门也能看。模块里的代码也一样——默认是"内部"的，加了 **`公开`** 关键字才对外可见。

```rust
模块 餐厅 {
    // 公开的——外面可以用
    公开 函数 点餐() {
        打印行!("您要点什么？");
        计算成本();   // 餐厅内部调用自己的私有函数，没问题
    }

    // 不公开——只有餐厅内部能用
    函数 计算成本() -> 整数 {
        42  // 商业机密！
    }
}

模块 厨房 {
    公开 函数 做饭() {
        打印行!("正在做饭...");
    }
}

函数 主函数() {
    餐厅::点餐();      // ✅ 公开函数，可以用
    厨房::做饭();      // ✅ 厨房的做饭是公开的，也能用
    // 餐厅::计算成本(); // ❌ 私有函数，外面不能用！
}
```

逐行解释：

- 第 3 行：**`公开 函数 点餐()`** 加了 `公开`，外面可以调用
- 第 5 行：`点餐` 内部调用了 `计算成本()`——注意！这是**模块内部**自己调用自己，私有函数在模块内部随便用，不需要 `公开`
- 第 8 行：`计算成本` 没有加 `公开`，默认是私有的
- 第 15-16 行：`餐厅::点餐()` 和 `厨房::做饭()` 可以调用，因为都是公开的
- 第 17 行：`餐厅::计算成本()` 不能调用，因为它是私有的——编译器会报错

```
可见性规则：

┌── 餐厅 ────────────────────┐
│                             │
│  🟢 公开 点餐()    ← 外面能看到、能用
│  🔒 私有 计算成本() ← 外面看不到、不能用
│                             │
└─────────────────────────────┘
```

> ✨ **小提示**：默认"私有"是个贴心的设计——你写代码时可能有些函数只是给自己内部用的"辅助工具"，不想让别人乱调用。不写 `公开`，编译器就帮你守住。

## 16.5 多文件模块

代码多了以后，一个模块可以拆到单独的文件里。比如厨房模块的代码太多，就单独放一个文件：

```
项目结构：
src/
├── main.zh        ← 主文件
├── kitchen.zh     ← 厨房模块的代码
└── 大厅.zh        ← 大厅模块的代码
```

**`main.zh`**：

```rust
模块 kitchen;     // 告诉编译器：去 kitchen.zh 文件找 kitchen 模块

函数 主函数() {
    kitchen::做饭();
}
```

**`kitchen.zh`**：

```rust
公开 函数 做饭() {
    打印行!("正在做饭...");
}
```

逐行解释：

- `main.zh` 第 1 行：**`模块 kitchen;`** 注意！这里**没有花括号**，后面是**分号**。意思是："kitchen 模块的代码不写在这里，去同名文件里找"
- 编译器会自动去找 `kitchen.zh` 文件，把它当成厨房模块的内容
- `kitchen.zh` 第 1 行：函数加了 `公开`，因为主文件要用它

> ⚠️ **为什么模块名用英文（kitchen）而不是中文（厨房）？** 因为编译器找文件时，要求**文件名和模块名完全一致**（`kitchen` 就找 `kitchen.zh`），而编译器只认英文字母的文件名——中文文件名会直接报错。这是编译器（rustc）的限制。所以：**拆到单独文件的模块，模块名用英文**。不过模块里的函数名、变量名仍然可以放心用中文。

**怎么运行？** 把每个文件都转译成标准 Rust，然后一起编译：

```
rzc eject src/main.zh
rzc eject src/kitchen.zh
rustc src/main.rs -o 程序名
./程序名
```

**为什么要拆文件？** 因为所有代码挤在一个文件里，找起来太累了。拆成多个文件，每个文件管一件事，代码就清晰了。不过**初学者阶段**，建议先把所有代码写在一个文件里——用嵌套模块（16.3 的方式）就够了，等代码真的很多了再拆文件。

## 16.6 用 `使用` 简化路径

每次都要写 `餐厅::厨房::做饭()` 太长了。用 **`使用`** 可以简化：

```rust
模块 餐厅 {
    公开 模块 厨房 {
        公开 函数 做饭() {
            打印行!("正在做饭...");
        }
    }
}

函数 主函数() {
    // 不用"使用"：每次都要写完整路径
    餐厅::厨房::做饭();
}
```

逐行解释：

- 第 10 行：`餐厅::厨房::做饭()` 完整路径，一层层写下来，又长又啰嗦

**用 `使用` 之后：**

```rust
模块 餐厅 {
    公开 模块 厨房 {
        公开 函数 做饭() {
            打印行!("正在做饭...");
        }
    }
}

使用 餐厅::厨房;   // 文件顶部引入：以后提到厨房，不用写餐厅了

函数 主函数() {
    厨房::做饭();  // 简化了！
}
```

逐行解释：

- 第 9 行：**`使用 餐厅::厨房;`** 意思是"以后提到厨房时，不用写餐厅了"——把 `厨房` 这个名字"拿到自己面前"
- 第 12 行：直接写 `厨房::做饭()` 就行了

```
路径简化：

不用"使用"：
  餐厅::厨房::做饭()     ← 每次都写这么长

用"使用"后：
  使用 餐厅::厨房;
  厨房::做饭()            ← 短多了！
```

**`使用` 的三种常见用法**：

```rust
模块 餐厅 {
    公开 模块 厨房 {
        公开 函数 做饭() {
            打印行!("正在做饭...");
        }
    }
}

// 用法一：引入"模块"——以后写 厨房::做饭()
使用 餐厅::厨房;

// 用法二：引入"函数"——以后直接写 做饭()
使用 餐厅::厨房::做饭;

// 用法三：引入并起"别名"——以后写 开火()
使用 餐厅::厨房::做饭 作为 开火;

函数 主函数() {
    厨房::做饭();  // 用法一
    做饭();        // 用法二
    开火();        // 用法三
}
```

逐行解释：

- 第 11 行：**`使用 餐厅::厨房;`** 引入的是模块，用的时候还要写 `厨房::`
- 第 14 行：**`使用 餐厅::厨房::做饭;`** 引入的是函数本身，用的时候直接写 `做饭()`——更短，但注意：如果别处也有 `做饭`，就会"撞名"报错
- 第 17 行：**`使用 ... 作为 开火;`** 是"起别名"——`作为` 的意思是"改名叫"。把长长的 `餐厅::厨房::做饭` 改名叫 `开火`，以后用短名字。这样既简短，又不怕撞名

> ✨ **小提示**：`作为`（`as`）就像给人起外号——名字太长就叫外号。不过外号只在当前文件里有效。

## 16.7 `超级`：从子模块往上走

模块树的路径是**从上往下**走的。那子模块里的代码，想调用**父模块**里的函数怎么办？

> **生活类比**：厨房（子模块）的员工月底要报销，得找餐厅（父模块）的财务。他不能往楼下跑，得**往上走一层**——`超级` 就是"往上走一层"的意思。

```rust
模块 餐厅 {
    公开 模块 厨房 {
        公开 函数 做饭() {
            打印行!("正在做饭...");
            超级::结账();   // 往上走一层 = 餐厅，调用餐厅的结账
        }
    }

    公开 函数 结账() {
        打印行!("请到前台付款");
    }
}

函数 主函数() {
    餐厅::厨房::做饭();
}
```

逐行解释：

- 第 4 行：做饭做完了，要提醒客人结账——但 `结账` 不是厨房自己的函数，是**餐厅**（父模块）的函数
- 第 5 行：**`超级::结账()`** ——`超级` 的意思就是"父模块"。厨房往上走一层就是餐厅，`超级::结账` = "餐厅的结账"
- 第 11 行：`结账` 定义在餐厅这一层

```
从子模块往上看：

餐厅（父模块）
├── 结账()          ← 目标在这
└── 厨房（子模块）
    └── 做饭()
          └── 超级::结账()   ← 从厨房往上走一层 → 餐厅 → 找到结账
```

**如果不用 `超级` 会怎样？** 在 `做饭` 里直接写 `结账()`，编译器会认为你在找"厨房自己的结账函数"——找不到，就报错。`超级` 是给编译器指路："别在厨房里找，往上走一层找。"

> ✨ **小提示**：`超级` 和 `使用` 的关系：`使用` 是"把别处的东西拿过来用"，`超级` 是"往上一层去找"。实际写代码时 `超级` 用得不多，但你看到别人代码里的 `超级::`，要知道它是"父模块"的意思。

## 常见错误

### 忘记加 `公开`

```rust
模块 工具箱 {
    函数 内部工具() { 打印行!("内部使用"); }
    // 公开 函数 外部工具() { 打印行!("外部可用"); }
}

函数 主函数() {
    // 工具箱::内部工具();  // ❌ 私有函数，外面不能用
}
```

### 模块路径写错

```rust
模块 外层 {
    公开 模块 内层 {
        公开 函数 你好() { 打印行!("你好！"); }
    }
}

函数 主函数() {
    // 内层::你好();       // ❌ 路径不完整
    外层::内层::你好();    // ✅ 完整路径
}
```

### 嵌套模块中间某层没加 `公开`

```rust
模块 外层 {
    // 忘记写"公开"了！
    模块 内层 {
        公开 函数 你好() { 打印行!("你好！"); }
    }
}

函数 主函数() {
    // 外层::内层::你好();  // ❌ 内层 不是公开的，外面够不着
}
```

> ✨ **小提示**：记住 16.3 的比喻——每一层都要"刷门禁"。`内层` 自己没加 `公开`，就算里面的 `你好` 加了也没用，门都没开，里面的东西再好也拿不到。

### 模块文件名和模块名不一致（或用了中文文件名）

```rust
// ❌ 模块名 kitchen，文件却叫 厨房.zh —— 名字对不上，编译器找不到
// ❌ 模块名 厨房，文件叫 厨房.zh —— 中文文件名，编译器不支持
// ✅ 模块名 kitchen，文件叫 kitchen.zh —— 完全一致且是英文
```

## 练习题

### 练习 1：创建模块

创建一个 `数学` 模块，包含 `加` 和 `乘` 两个公开函数。在 `主函数` 里调用它们。

<details>
<summary>参考答案</summary>

```rust
模块 数学 {
    公开 函数 加(甲: 整数, 乙: 整数) -> 整数 {
        甲 + 乙
    }

    公开 函数 乘(甲: 整数, 乙: 整数) -> 整数 {
        甲 * 乙
    }
}

函数 主函数() {
    打印行!("3 + 5 = {}", 数学::加(3, 5));
    打印行!("3 × 5 = {}", 数学::乘(3, 5));
}
```
</details>

### 练习 2：公开与私有

创建一个 `银行` 模块，有公开的 `查询余额` 函数和私有的 `验证密码` 函数。

<details>
<summary>参考答案</summary>

```rust
模块 银行 {
    公开 函数 查询余额() -> 整数 {
        验证密码("123456");  // 模块内部可以调用私有函数
        1000
    }

    函数 验证密码(密码: &文本) -> 布尔 {
        密码 == "123456"
    }
}

函数 主函数() {
    打印行!("余额：{}", 银行::查询余额());
    // 银行::验证密码("123456");  // ❌ 私有函数，外面不能用
}
```
</details>

### 练习 3：嵌套模块与 `超级`

定义 `学校` 模块，里面有一个 `图书馆` 子模块（公开），`图书馆` 里有公开函数 `借书`。借书时调用父模块的 `登记` 函数（用 `超级`）。

<details>
<summary>参考答案</summary>

```rust
模块 学校 {
    公开 模块 图书馆 {
        公开 函数 借书() {
            打印行!("借走《Rust 入门》");
            超级::登记("《Rust 入门》");  // 超级 = 学校
        }
    }

    公开 函数 登记(书名: &文本) {
        打印行!("已登记：{}", 书名);
    }
}

函数 主函数() {
    学校::图书馆::借书();
}
```
</details>

## 本章小结

| 概念 | 一句话 |
|------|--------|
| 模块 | 公司里的部门——把相关代码放在一起 |
| 模块树 | 模块套模块，像文件夹套文件夹 |
| 嵌套模块 | `模块` 里再写 `模块`，路径一层层往下 |
| `公开` | 公开文件——其他模块也能用 |
| 私有（默认） | 内部文件——只有本模块能用 |
| 多文件模块 | `模块 kitchen;` 把模块拆到 `kitchen.zh` 文件（文件名必须英文） |
| `使用` | 把别处的路径拿过来，省得每次写完整名字 |
| `作为` | 给引入的东西起别名（外号） |
| `超级` | 从子模块往上一层，调用父模块的东西 |
