# 第十一章：枚举与模式匹配

## 11.0 学习目标

读完这一章，你将能够：

1. 解释枚举和结构体的区别（"或"与"且"）；
2. 定义**简单枚举**和**附带数据的枚举**；
3. 用 `匹配` 解构枚举、提取附带数据；
4. 看懂 **E0004**（匹配不完备）并修复；
5. 使用 **`选项`** 类型表示"可能有值，也可能没有"；
6. 知道为什么 Rust 没有"空指针"这个坑。

---

## 11.1 枚举：一道多选题

第十章的结构体是"**且**"：一张学生卡**同时**有姓名、年龄、分数。

但生活中更多的是"**或**"：

- 红绿灯**要么**红、**要么**黄、**要么**绿；
- 一枚硬币**要么**正面、**要么**反面；
- 一道题的作答**要么**对、**要么**错、**要么**没答。

📖 **枚举**：一个值只能是**列出的几种情况之一**的类型。对应关键字 `枚举`。

💡 **比喻**：枚举是一张**多选题的答题卡**——你只能在给定的选项里选一个，不能选"其他"，更不能同时选两个。

## 11.2 简单枚举：红绿灯

```rust
枚举 红绿灯 {
    红,
    黄,
    绿,
}
```

📖 **变体**：枚举的每一种可能取值。`红绿灯` 有三个变体。

使用时用 `枚举名::变体名`：

```rust
函数 红绿灯行动(灯: 红绿灯) {
    匹配 灯 {
        红绿灯::红 => 打印行!("停"),
        红绿灯::黄 => 打印行!("准备"),
        红绿灯::绿 => 打印行!("走"),
    }
}

函数 主函数() {
    红绿灯行动(红绿灯::红);
    红绿灯行动(红绿灯::黄);
    红绿灯行动(红绿灯::绿);
}
```

输出：

```
停
准备
走
```

比用整数 1、2、3 表示红绿灯好在哪？**名字自带含义**，而且你不可能传一个"4 号灯"进去——编译器根本不接受。

## 11.3 附带数据的枚举

变体还能**自带行李**：

```rust
枚举 成绩 {
    分数(整数),        // 带一个整数
    缺考,              // 不带
    免修(字符串),      // 带一段文字（写明免修原因）
}
```

读法："成绩只有三种情况：要么是一个具体分数，要么是缺考，要么是免修（附带原因说明）。"

造值：

```rust
让 甲 = 成绩::分数(88);
让 乙 = 成绩::缺考;
让 丙 = 成绩::免修(字符串::从("已学过"));
```

> ⚠️ **小心**：变体的行李类型里尽量用 `字符串`，不要用 `字符串引用`——后者会牵扯生命周期标注（第十四章的难题），初学避开。

### 枚举与结构体

| | 结构体 | 枚举 |
|---|---|---|
| 含义 | 这些字段**同时**成立 | 这些情况**选其一** |
| 例子 | 学生 = 姓名 + 年龄 + 分数 | 成绩 = 分数 / 缺考 / 免修 |

两者还能**套着用**（下一章特征、第十五章集合会见到），威力无穷。

## 11.4 匹配：拆开行李

第五章学过 `匹配` 的基本用法（匹配整数、范围）。对枚举，`匹配` 还能**拆开变体的行李、取出数据**：

```rust
函数 成绩报告(单: 成绩) {
    匹配 单 {
        成绩::分数(值) => 打印行!("得分：{}", 值),
        成绩::缺考 => 打印行!("缺考，无成绩"),
        成绩::免修(原因) => 打印行!("免修：{}", 原因),
    }
}
```

`成绩::分数(值)` 读作："如果这是一份带分数的成绩，把里面的整数**取出来起名叫 `值`**。"括号里就是拆行李的动作。

输出：

```
得分：88
缺考，无成绩
免修：已学过
```

## 11.5 穷尽：一个都不能漏

Rust 的铁律：**匹配必须覆盖所有变体**。漏一个就报 **E0004**：

```rust
枚举 灯 { 红, 绿 }

匹配 当前 {
    灯::红 => 打印行!("停"),
    // 漏了 绿 ❌
}
```

真实报错：

```
错误[E0004]: 匹配表达式不完备：存在没有匹配分支的可能取值
💡 匹配必须覆盖所有可能的情况。请补齐遗漏的分支，或添加 `_` 通配分支兜底。
```

**两种修法**：① 补齐每个变体；② 用 `_` 兜底（第五章学过）：

```rust
匹配 当前 {
    灯::红 => 打印行!("停"),
    _ => 打印行!("其他情况都走"),
}
```

> 💡 **为什么这么严？** 假设以后给 `红绿灯` 加了"闪烁"变体，所有没处理它的匹配点都会立刻报 E0004——编译器**押着你**把每个角落都更新一遍，一个都跑不掉。这是枚举最大的安全感来源。

## 11.6 补充：模式匹配全形态

到现在，模式只出现在 `匹配` 里。其实模式还能用在一**堆别的地方**，还能配出各种花样。这一节把"模式"这门手艺补完整——以后看代码，凡是出现"拆开一个值"的地方，你都能认出是模式在干活。

### 如果让：只关心一种情况

`匹配` 要求穷尽所有情况（11.5 刚讲过）。但如果我只关心**其中一种**，其他情况统一处理，用 `匹配` 就显得啰嗦：

```rust
让 分数: 选项<整数> = 有些(95);

如果让 有些(值) = 分数 {
    打印行!("有分：{}", 值);
} 否则 {
    打印行!("没分");
}
```

📖 **如果让**：`如果让 模式 = 值 { ... } 否则 { ... }`——拿 `值` 去试 `模式`：**试得上**就拆开执行第一个块，**试不上**就走 `否则`。

💡 **比喻**：`匹配` 像售货机让你按**所有**按钮；`如果让` 像只按**一个**按钮——按中了就出货，按不中就换一台。

`如果让 有些(值) = 分数` 读作："如果 `分数` 是 `有些(...)`，把里面的值拿出来叫 `值`。"它和 `匹配 分数 { 有些(值) => ..., 无 => ... }` 是一回事，只是短。

### 当让：循环版如果让

```rust
让 可变 剩余: 选项<整数> = 有些(3);
当让 有些(值) = 剩余 {
    打印行!("剩余 {}", 值);
    剩余 = 无;
}
```

📖 **当让**：`当让 模式 = 值 { ... }`——只要 `值` 还能试上 `模式`，就拆开执行一遍循环体，然后**重新试**；试不上就结束循环。

（上面的例子故意把 `剩余` 置为 `无`，所以循环只跑一圈；真实场景通常是从一个"会变化的值"里反复取值，比如不停从迭代器里拿。）

### 让 否则：拆不出来就走人

有时候"拆不开"意味着**后面代码没必要跑了**。Rust 2021 起多了个新语法：

```rust
让 输入: 选项<整数> = 有些(7);
让 有些(数) = 输入 否则 {
    返回;
};
打印行!("让否则 拿到 {}", 数);
```

📖 **让 否则**：`让 模式 = 值 否则 { 退出代码 };`——模式**必须试上**，试上就继续；试不上就执行 `否则` 块（里面通常是 `返回` 或 `中断`），**后面的代码不再执行**。

> ⚠️ **注意**：`否则` 块**必须以不返回的方式结束**（`返回`、`中断`、`继续`、`恐慌!` 等）——因为编译器要保证"没拆开就一定走不到后面"。

### 匹配守卫：给匹配臂加个门槛

模式管"是不是这种形状"，但有时候还要加一个**条件**。守卫就是加在 `=>` 前面的 `if`：

```rust
让 数 = 7;
匹配 数 {
    值 如果 值 > 5 => 打印行!("大于5：{}", 值),
    _ => 打印行!("不大于5"),
}
```

读法：第一个臂的完整门槛是"匹配到 `值` **并且** `值 > 5`"。条件不满足就落到下一条臂。

> ⚠️ **提醒**：守卫表达式可以写中文（`值 如果 值 > 5`）——`如果` 会被转译成 `if`。注意 `如果` 在模式里另有含义（`如果让`），但作为守卫条件，转译后就是标准的 `if`。

### @ 绑定：既匹配又留名

想要"范围匹配成功，同时把命中的值拿到手"？`@` 就是干这个的：

```rust
让 数 = 7;
匹配 数 {
    值 @ 1..=5 => 打印行!("1到5：{}", 值),
    _ => 打印行!("范围外"),
}
```

📖 **@ 绑定**：`名字 @ 模式`——把匹配到的值**同时**存进 `名字`。`值 @ 1..=5` 读作"如果数在 1 到 5 之间，把数本身叫 `值`"。

没有 `@` 的话，`1..=5` 只能判断"在不在范围里"，但拿不到具体的数——`@` 补上了这个缺口。

### 或模式：一臂多用

几种**同类型**的取值想走同一条路？用 `|`（竖线）把它们并成一臂：

```rust
让 数 = 7;
匹配 数 {
    1 | 2 => 打印行!("1或2"),
    _ => 打印行!("其他"),
}
```

枚举也同理：`成绩::缺考 | 成绩::免修(_) => 打印行!("没有具体分数")`——两种"没分"的情况共用一条臂。

### 结构体与元组：把打包的数据拆开

模式不仅能拆枚举，还能拆结构体和元组：

```rust
结构体 点 {
    横: 整数,
    纵: 整数,
}

让 点甲 = 点 { 横: 10, 纵: 20 };
匹配 点甲 {
    点 { 横, 纵 } => 打印行!("横={} 纵={}", 横, 纵),
}

让 (甲, 乙) = (1, 2);
打印行!("{} {}", 甲, 乙);
```

- 结构体模式 `点 { 横, 纵 }`：按**字段名**拆，顺序无所谓；
- 元组模式 `(甲, 乙)`：按**位置**拆，一一对应。

💡 **比喻**：枚举模式像拆快递盒（看是哪家快递、拆出什么）；结构体模式像按**标签**取物；元组模式像按**座位号**点名。

### 完整示例一：如果让、当让与让 否则

```rust
函数 主函数() {
    // 如果让
    让 分数: 选项<整数> = 有些(95);
    如果让 有些(值) = 分数 {
        打印行!("有分：{}", 值);
    } 否则 {
        打印行!("没分");
    }

    // 当让
    让 可变 剩余: 选项<整数> = 有些(3);
    当让 有些(值) = 剩余 {
        打印行!("剩余 {}", 值);
        剩余 = 无;
    }

    // 让否则
    让 输入: 选项<整数> = 有些(7);
    让 有些(数) = 输入 否则 {
        返回;
    };
    打印行!("让否则 拿到 {}", 数);
}
```

输出：

```
有分：95
剩余 3
让否则 拿到 7
```

### 完整示例二：守卫、@ 与解构

把守卫、`@`、`|`、结构体解构、元组解构装进一个程序跑一遍：

```rust
结构体 点 {
    横: 整数,
    纵: 整数,
}

函数 主函数() {
    // 匹配守卫
    让 数 = 7;
    匹配 数 {
        值 如果 值 > 5 => 打印行!("大于5：{}", 值),
        _ => 打印行!("不大于5"),
    }

    // @ 绑定
    匹配 数 {
        值 @ 1..=5 => 打印行!("1到5：{}", 值),
        _ => 打印行!("范围外"),
    }

    // 或模式
    匹配 数 {
        1 | 2 => 打印行!("1或2"),
        _ => 打印行!("其他"),
    }

    // 结构体解构
    让 点甲 = 点 { 横: 10, 纵: 20 };
    匹配 点甲 {
        点 { 横, 纵 } => 打印行!("横={} 纵={}", 横, 纵),
    }

    // 元组解构
    让 (甲, 乙) = (1, 2);
    打印行!("{} {}", 甲, 乙);
}
```

输出：

```
大于5：7
范围外
其他
横=10 纵=20
1 2
```

前三条是 `7` 依次过守卫、范围、`|` 的结果；后两条演示结构体、元组怎么一口气拆出所有数据。

### 可反驳与不可反驳：模式的两副面孔

最后补一个概念。模式分两种：

📖 **可反驳**：可能试不上。比如 `有些(值)`——万一值是 `无` 就试不上。
📖 **不可反驳**：**一定**试得上。比如 `x`、`(甲, 乙)`——什么值都能拆。

**使用位置有讲究**：

- `让` 绑定、函数参数、`对于` 循环：要求**不可反驳**模式（编译器会帮你检查）；
- `匹配` 臂、`如果让`、`当让`：**两种都行**（试不上就走别的路或结束）。

反过来也不行——`如果让` 里写不可反驳模式，编译器会嫌你多此一举（提示"这个模式必然成功，没必要用 如果让"）。

**最常见的坑**：在 `让` 里写 `让 有些(值) = 分数;`——编译器直接报 **E0005**：

```
错误[E0005]: 该模式不能保证匹配成功，但此处要求必然匹配成功的模式
💡 `让` 绑定与函数参数等位置要求必然成功的模式。可能失败的模式请改用 `匹配` 或 `如果 让` 处理。
```

**解决**：把"可能试不上"的拆壳交给 `匹配` / `如果让` / `让 否则`；`让` 只用来接收"一定有"的东西。

## 11.7 选项：对付"可能没有"

程序里常见一种情况：**值可能不存在**。比如"全班最高分"——万一班里没人呢？

很多语言用"空指针"表示"没有"，结果诞生了价值十亿美元的缺陷：忘了检查空值，程序当场崩溃。Rust 的答案是一个内置枚举：

```rust
枚举 选项<物> {
    有些(物),    // 有值，值装在里面
    无,          // 没有值
}
```

（`<物>` 是泛型，第十二章细讲；现在读作"装什么类型的值的选项"。）

📖 **选项**：表示"可能有值也可能没有"的类型。`有些` = 有，`无` = 没有。

```rust
让 有分: 选项<整数> = 有些(95);
让 没分: 选项<整数> = 无;

匹配 有分 {
    有些(值) => 打印行!("有分数：{}", 值),
    无 => 打印行!("没有分数"),
}
匹配 没分 {
    有些(值) => 打印行!("有分数：{}", 值),
    无 => 打印行!("没有分数"),
}
```

输出：

```
有分数：95
没有分数
```

关键思想：**"没有值"也是一种值，必须被明确处理**。你没法假装 `无` 不存在——想从选项里拿值，就必须用 `匹配` 同时照顾两种情况（或用第十六章的便捷方法）。从此"忘记检查空值"这种事在 Rust 里**不可能发生**。

## 11.8 完整示例：答题卡评分

枚举数组 + 匹配 + 循环，给一张 10 题答题卡打分：

```rust
// 每道题的作答情况（派生 Copy：无数据的枚举可以随手复制）
#[派生(Copy, Clone)]
枚举 答案 {
    对,
    错,
    未答,
}

// 每题得分规则
函数 得分(题: 答案) -> 整数 {
    匹配 题 {
        答案::对 => 5,
        答案::错 => 0,
        答案::未答 => 0,
    }
}

// 总评等级
枚举 评级 { 优, 良, 中, 差 }

函数 评级根据(总分: 整数) -> 评级 {
    如果 总分 >= 45 { 返回 评级::优; }
    如果 总分 >= 35 { 返回 评级::良; }
    如果 总分 >= 20 { 返回 评级::中; }
    评级::差
}

函数 主函数() {
    // 一张 10 题的答题卡
    让 答题卡 = [
        答案::对, 答案::对, 答案::错, 答案::对, 答案::未答,
        答案::对, 答案::对, 答案::错, 答案::对, 答案::对,
    ];

    让 可变 总分 = 0;
    让 可变 对题数 = 0;
    对于 下标 在 0..10 {
        总分 = 总分 + 得分(答题卡[下标]);
        匹配 答题卡[下标] {
            答案::对 => 对题数 = 对题数 + 1,
            答案::错 => {}
            答案::未答 => {}
        }
    }
    打印行!("对{}题，总分{}", 对题数, 总分);

    匹配 评级根据(总分) {
        评级::优 => 打印行!("总评：优，真棒！"),
        评级::良 => 打印行!("总评：良，不错！"),
        评级::中 => 打印行!("总评：中，继续加油"),
        评级::差 => 打印行!("总评：差，要努力了"),
    }
}
```

## 11.9 逐行解释

- **第 2 行**：`#[派生(Copy, Clone)]`——`答案` 不带任何数据，可以像整数一样**随手复制**。这很关键：数组里的元素默认拿不出来（会报 E0508），有了 `Copy`，`答题卡[下标]` 就自动复制一份，随便传给函数。
- **第 10–16 行**：`得分` 用匹配把三种情况映射成数字。匹配臂右边直接是表达式 `5`、`0`。
- **第 19 行**：`评级` 是纯标签枚举。
- **第 21–26 行**：`评级根据` 用第五章的 `如果` 链把总分换等级，最后 `评级::差` 兜底。
- **第 30–33 行**：枚举数组，10 个元素。
- **第 37–43 行**：一次循环干两件事——累加总分、数对题数。`答案::错 => {}` 和 `答案::未答 => {}` 是空花括号：匹配臂**必须**写全三种情况，这两种"什么都不做"也要写出来占位。
- **第 46–51 行**：把评级枚举再匹配成祝福语，四个变体一个不漏。

## 11.10 运行结果

```
对7题，总分35
总评：良，不错！
```

7 道对题 × 5 分 = 35 分，落在 35–44 区间 → 良。

## 11.11 常见错误与解决

### 错误一：E0004 匹配不完备

漏了变体。**解决**：补齐，或 `_` 兜底。看到报错里列出"未覆盖的模式"，照着抄就行。

### 错误二：E0508 无法移出数组内容

`函数(数组[下标])` 想把元素**拿走**，但数组不答应。**解决**：给枚举派生 `Copy`（无数据时），或传引用 `&数组[下标]`（改函数参数），或 `.克隆()`。

### 错误三：变体装 `字符串引用` 报 E0106

枚举变体里写 `免修(字符串引用)` 要求生命周期标注。**解决**：改用 `字符串`：`免修(字符串)`，造值时 `字符串::从("...")`。

### 错误四：直接打印枚举

`打印行!("{}", 答案::对)` 报错。**解决**：`#[派生(调试)]` + `{:?}`（第十章的老办法）。

### 错误五：拿选项里的值想当然

`有些(95)` 不能直接当 `95` 用——它外面还包着一层壳。**解决**：用 `匹配` 拆壳，或第十六章的 `拆包期望` 等方法。

## 11.14 常见问题

**问：枚举和字符串比，优势在哪？**

答：字符串想写什么写什么，`"优"`、`"优 "`、`"優"` 都是不同值，拼错了编译器不管。枚举只有固定几种取值，写错直接编译不过，而且匹配时穷尽检查保证每种都处理了。**安全得多**。

**问：为什么无数据的枚举要派生 `Copy` 才能从数组里取？**

答：数组元素默认是"借你看可以，拿走不行"。`Copy` 告诉编译器"这个类型复制极其便宜（就是个标签）"，取的时候自动复制一份，原数组不动。带数据的枚举复制可能有成本，所以需要你明确表态（`克隆` 或派生 `Clone`）。

**问：`选项` 这么麻烦，为什么不直接允许"没有值"？**

答：因为"忘了检查没有值"是历史上最贵的缺陷来源。Rust 把"没有"做成**必须显式处理的类型**，麻烦前置到写代码时，崩溃就永远不会发生在用户面前。用熟了你会发现拆壳也就两行。

**问：`匹配` 和 `如果` 链怎么选？**

答：离散情况（枚举、少数固定值）用 `匹配`；连续区间（分数段）用 `如果` 链更顺手。两者都合法，怎么清楚怎么来。

**问：枚举能装结构体吗？**

答：能！变体的行李可以是任何类型，包括结构体、甚至另一个枚举。后面章节的实战项目会大量用到这种"组合拳"。

**问：`结果` 类型也是枚举吗？**

答：是！`结果` = `成功(值)` / `错误(原因)`，和 `选项` 一个套路，专门表示"可能失败的操作"。第十六章《错误处理》是它的主场。
