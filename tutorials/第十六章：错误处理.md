# 第十六章：错误处理

## 16.0 学习目标

读完这一章，你将能够：

1. 分清两类错误：**可恢复**（用 `结果`）与**不可恢复**（用 `恐慌!`）；
2. 用 **`结果<好, 坏>`** 让函数体面地汇报成败；
3. 用 **`匹配`** 和 **`?`** 两种姿势处理结果；
4. 知道 **`解包`/`期望`** 的便利与危险；
5. 看懂运行时**恐慌**的输出；
6. 会用"该恐慌还是该返回结果"决策表。

---

## 16.1 两种错误，两套工具

程序出错不可避免：用户输了字母、文件不存在、网络断了。Rust 把错误分成两类：

| | 可恢复错误 | 不可恢复错误 |
|---|---|---|
| 例子 | 文件没找到、数字格式不对 | 程序逻辑自相矛盾、内存越界 |
| 工具 | `结果` 枚举 | `恐慌!` |
| 态度 | 报告上级，商量着办 | 立即停止，不再继续 |

💡 **比喻**：可恢复错误像**外卖送错了口味**——退回去重做就行；不可恢复错误像**厨房着火了**——别送外卖了，先报警。

## 16.2 结果：一个装着成败的盒子

📖 **结果（Result）**：标准库枚举，两个变体：

```
结果<好, 坏>
├── 成功(好值)    // 事情办成了，成果在这里
└── 错误(坏值)    // 办砸了，原因在这里
```

（`结果` = Result，`成功` = Ok，`错误` = Err。）

写一个解析年龄的函数——成了给数字，砸了给原因：

```rust
函数 解析年龄(文字: &文本) -> 结果<整数, 字符串> {
    匹配 文字.解析::<整数>() {
        成功(数) => {
            如果 数 < 0 {
                返回 错误(字符串::从("年龄不能为负"));
            }
            成功(数)
        }
        错误(_) => 错误(格式化!("无法解析：{}", 文字)),
    }
}
```

几个细节：

- **`文字.解析::<整数>()`**：把文字解析成整数（`解析` = parse）。它本身就返回 `结果`——解析不了 `"二十"` 这种文字。
- **`解析::<整数>`**：尖括号里指定要解析成什么类型，这叫"turbofish"（蝌蚪尾巴），第十一章的枚举拆数据也见过类似的。
- 我们**检查了两种坏情况**：格式不对、数字为负——每个都给出具体原因。

## 16.3 处理结果：拆开看

调用方拿到 `结果`，必须**先拆开**才能用里面的值——这正是 Rust 的设计：逼你面对失败的可能。

```rust
匹配 解析年龄("25") {
    成功(年龄) => 打印行!("年龄是：{}", 年龄),
    错误(原因) => 打印行!("出错了：{}", 原因),
}
```

## 16.4 `?`：失败的接力传送

函数里连续好几步都可能失败，每步都 `匹配` 一遍？太啰嗦。**`?` 号**是快捷传送：

```rust
函数 汇报档案(文字: &文本) -> 结果<字符串, 字符串> {
    让 年龄 = 解析年龄(文字)?;
    成功(格式化!("档案建好，年龄 {}", 年龄))
}
```

`解析年龄(文字)?` 的含义：

- 拿到 `成功(值)` → 拆出值，继续往下走；
- 拿到 `错误(原因)` → **立即从本函数返回这个错误**，后面的代码不执行。

💡 **比喻**：`?` 像**接力赛的交棒规则**——这一棒顺利就继续跑；一旦掉棒（出错），整队立刻停下来报告，不会假装继续跑。

⚠️ **前提**：`?` 只能用在**本身返回 `结果`（或 `选项`）的函数**里。`主函数` 返回 `()`，不能直接用（进阶写法暂且不表）。

## 16.5 恐慌：拉响警报

📖 **恐慌（panic）**：程序遇到无法继续的情况时，打印信息、清理现场、停止运行。

### 被动恐慌：程序自己触发

数组越界（下标是变量时编译器拦不住）会恐慌：

```rust
让 分数 = [1, 2, 3];
让 下标 = 9;
打印行!("{}", 分数[下标]);   // 运行时恐慌
```

> ✨ 有意思的是：如果下标写成**常量** `分数[9]`，编译器会**提前拦截**："这个操作运行时必然恐慌"。Rust 连这种错误都尽量在编译期抓。

### 主动恐慌：自己拉警报

```rust
恐慌!("这不该发生：{}", 42);
```

运行输出：

```
thread 'main' panicked at src/main.rs:2:5:
这不该发生：42
```

什么时候主动恐慌？**程序的不变量被破坏**——比如"这里绝不可能为空，空了说明前面有大 bug"。宁可当场报警，不要带病运行。

## 16.6 解包与期望：偷懒的快进键

确定结果一定是 `成功` 时，可以用快捷方法直接取值：

```rust
让 数 = "42".解析::<整数>().解包();        // 直接取成功值
让 数 = "42".解析::<整数>().期望("应该是数字");  // 取不到就带这句话恐慌
```

（`解包` = unwrap，`期望` = expect。）

⚠️ **危险警告**：它们遇到 `错误` 会**直接恐慌**。学习时玩玩可以，正式代码里请老实 `匹配` 或 `?`。

## 16.7 决策表：该用哪个？

| 情况 | 选择 |
|---|---|
| 用户输入、文件、网络等外部因素可能失败 | `结果` |
| 失败后调用方**能补救**（重试、换方案） | `结果` |
| 程序内部逻辑绝不该出错，出错即 bug | `恐慌!` |
| 写示例/原型，图省事 | `解包`/`期望`（加注释） |

## 16.8 完整示例：档案管理系统

把本章所有招式串起来：解析 + 业务校验 + `?` 接力 + 调用方分发：

```rust
// 解析年龄：成功返回数字，失败返回原因
函数 解析年龄(文字: &文本) -> 结果<整数, 字符串> {
    匹配 文字.解析::<整数>() {
        成功(数) => {
            如果 数 < 0 {
                返回 错误(字符串::从("年龄不能为负"));
            }
            成功(数)
        }
        错误(_) => 错误(格式化!("无法解析：{}", 文字)),
    }
}

// ? 接力：任何一步失败就提前把错误传上去
函数 汇报档案(文字: &文本) -> 结果<字符串, 字符串> {
    让 年龄 = 解析年龄(文字)?;
    成功(格式化!("档案建好，年龄 {}", 年龄))
}

函数 主函数() {
    对于 输入 在 ["25", "-3", "二十"] {
        匹配 汇报档案(输入) {
            成功(汇报内容) => 打印行!("{} -> {}", 输入, 汇报内容),
            错误(原因) => 打印行!("{} -> 失败：{}", 输入, 原因),
        }
    }
}
```

## 16.9 逐行解释

- **第 2–13 行**：`解析年龄` 返回 `结果<整数, 字符串>`。三种结局：格式对且非负 → `成功(数)`；负数 → `错误("年龄不能为负")`；格式不对 → `错误("无法解析：...")`。
- **第 16–19 行**：`汇报档案` 用 `?`——解析失败时错误自动上交，成功则包装成新的 `成功` 继续加工。
- **第 22–28 行**：主函数拿三种输入走流水线：`"25"` 成功；`"-3"` 死在业务校验；`"二十"` 死在解析。调用方用 `匹配` 分流两种结局。

## 16.10 运行结果

```
25 -> 档案建好，年龄 25
-3 -> 失败：年龄不能为负
二十 -> 失败：无法解析：二十
```

三种失败原因各不相同——好错误信息就该这样，**说清楚错在哪、为什么**。

## 16.11 常见错误与解决

### 错误一：`结果` 没拆就直接用

```
错误：类型不匹配：期望 `整数`，实际得到 `结果<...>`
```

**解决**：`匹配` / `如果让` / `?` 拆开再使用。

### 错误二：在不返回 `结果` 的函数里用 `?`

编译报错"不能在返回 `()` 的函数中使用 `?`"。**解决**：把函数返回类型改成 `结果<..., ...>`，或改用 `匹配`。

### 错误三：拿 `错误` 当变体名时拼错

`结果` 的失败变体叫 **`错误`**（= Err）。写 `失败(...)` 会报"未知的元组变体"。

### 错误四：变量名撞上标准库类型

起名 `报告` 会被转译成标准库类型 `Report`，触发命名警告甚至找不到名字。**解决**：变量名避开单一名词映射词，用 `汇报内容` 这类组合词。

### 错误五：解包炸了

```
called `unwrap()` on an `Err` value
```

**解决**：别裸 `解包`——用 `匹配` 或 `期望("说明为什么一定有值")`，至少恐慌时能看懂。

## 16.12 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 可恢复错误 | 可以补救的失败，用 `结果` 表示 |
| 不可恢复错误 | 必须停止的失败，用 `恐慌!` 表示 |
| 结果 | `结果<好, 坏>` 枚举，装成功或失败 |
| 成功/错误 | 结果的两个变体（Ok / Err） |
| ? 操作符 | 成功就拆值继续，失败就立刻上交错误 |
| 恐慌 | 打印信息、清理现场、停止运行 |
| 恐慌! | 主动拉响警报的宏 |
| 解包 | 直接取成功值，遇到错误就恐慌 |
| 期望 | 解包 + 自定义恐慌留言 |
| 解析 | 把文字转换成数字等类型，返回结果 |

> 📖 **提醒**：遇到不懂的词，随时回查全书开头的《总术语表》。

        返回 错误(字符串::从("不能除以零"));

函数 主函数() {

        成功(商) => 打印行!("商是：{}", 商),

## 16.14 常见问题（FAQ）

**问：为什么不学别的语言，到处"抛出异常"？**

答：异常容易被漏接（忘了 try）。Rust 把错误**写在返回类型里**——`结果<好, 坏>` 一眼可见，编译器盯着你必须处理。"错误是值，不是意外"。

**问：`选项` 和 `结果` 怎么选？**

答：`选项` 表示"可能没有，但没有也不算错"（比如查不到某人，正常）；`结果` 表示"失败了，有原因要交代"（比如文件格式坏了）。前者 `有些/无`，后者 `成功/错误`。

**问：`?` 能让错误类型自动转换吗？**

答：本章两个函数都用 `字符串` 当错误类型，省事。真实项目里有 `从`（From）机制自动转换不同错误类型，到第二十五章综合实战你会见到它的影子。

**问：恐慌后数据会丢吗？**

答：默认行为是逐层清理（清理器运行）后退出。总之：**恐慌 = 程序生命终点**，别指望恐慌后继续干活。

**问：什么时候真的该恐慌？**

答：三条经验：① 写测试时（断言失败就该恐慌）；② 程序内部约定被打破（空指针级别的 bug）；③ 示例代码图简洁。面向用户的正式功能，一律 `结果`。

**问：`主函数` 能返回 `结果` 吗？**

答：能！`函数 主函数() -> 结果<(), 字符串>` 是合法写法，出错时程序打印错误退出。等你对 `结果` 更熟了可以试试。
