# 第十六章：错误处理

## 16.0 学习目标

读完这一章，你将能够：

1. 分清两类错误：**可恢复**（用 `结果`）与**不可恢复**（用 `恐慌!`）；
2. 用 **`结果<好, 坏>`** 让函数体面地汇报成败；
3. 用 **`匹配`** 和 **`?`** 两种姿势处理结果；
4. 知道 **`解包`/`期望`** 的便利与危险；
5. 看懂运行时**恐慌**的输出；
6. 会用"该恐慌还是该返回结果"决策表。

---

## 16.1 两种错误，两套工具

程序出错不可避免：用户输了字母、文件不存在、网络断了。Rust 把错误分成两类：

| | 可恢复错误 | 不可恢复错误 |
|---|---|---|
| 例子 | 文件没找到、数字格式不对 | 程序逻辑自相矛盾、内存越界 |
| 工具 | `结果` 枚举 | `恐慌!` |
| 态度 | 报告上级，商量着办 | 立即停止，不再继续 |

💡 **比喻**：可恢复错误像**外卖送错了口味**——退回去重做就行；不可恢复错误像**厨房着火了**——别送外卖了，先报警。

## 16.2 结果：一个装着成败的盒子

📖 **结果**：标准库枚举，两个变体：

```
结果<好, 坏>
├── 成功(好值)    // 事情办成了，成果在这里
└── 错误(坏值)    // 办砸了，原因在这里
```

（`成功` = Ok，`错误` = Err。）

写一个解析年龄的函数——成了给数字，砸了给原因：

```rust
函数 解析年龄(文字: &文本) -> 结果<整数, 字符串> {
    匹配 文字.解析::<整数>() {
        成功(数) => {
            如果 数 < 0 {
                返回 错误(字符串::从("年龄不能为负"));
            }
            成功(数)
        }
        错误(_) => 错误(格式化!("无法解析：{}", 文字)),
    }
}
```

几个细节：

- **`文字.解析::<整数>()`**：把文字解析成整数（`解析` = parse）。它本身就返回 `结果`——解析不了 `"二十"` 这种文字。
- **`解析::<整数>`**：尖括号里指定要解析成什么类型，这叫"turbofish"（蝌蚪尾巴），第十一章的枚举拆数据也见过类似的。
- 我们**检查了两种坏情况**：格式不对、数字为负——每个都给出具体原因。

## 16.3 处理结果：拆开看

调用方拿到 `结果`，必须**先拆开**才能用里面的值——这正是 Rust 的设计：逼你面对失败的可能。

```rust
匹配 解析年龄("25") {
    成功(年龄) => 打印行!("年龄是：{}", 年龄),
    错误(原因) => 打印行!("出错了：{}", 原因),
}
```

## 16.4 `?`：失败的接力传送

函数里连续好几步都可能失败，每步都 `匹配` 一遍？太啰嗦。**`?` 号**是快捷传送：

```rust
函数 汇报档案(文字: &文本) -> 结果<字符串, 字符串> {
    让 年龄 = 解析年龄(文字)?;
    成功(格式化!("档案建好，年龄 {}", 年龄))
}
```

`解析年龄(文字)?` 的含义：

- 拿到 `成功(值)` → 拆出值，继续往下走；
- 拿到 `错误(原因)` → **立即从本函数返回这个错误**，后面的代码不执行。

💡 **比喻**：`?` 像**接力赛的交棒规则**——这一棒顺利就继续跑；一旦掉棒（出错），整队立刻停下来报告，不会假装继续跑。

⚠️ **前提**：`?` 只能用在**本身返回 `结果`（或 `选项`）的函数**里。`主函数` 返回 `()`，不能直接用（进阶写法暂且不表）。

## 16.5 恐慌：拉响警报

📖 **恐慌**：程序遇到无法继续的情况时，打印信息、清理现场、停止运行。

### 被动恐慌：程序自己触发

数组越界（下标是变量时编译器拦不住）会恐慌：

```rust
让 分数 = [1, 2, 3];
让 下标 = 9;
打印行!("{}", 分数[下标]);   // 运行时恐慌
```

> ✨ 有意思的是：如果下标写成**常量** `分数[9]`，编译器会**提前拦截**："这个操作运行时必然恐慌"。Rust 连这种错误都尽量在编译期抓。

### 主动恐慌：自己拉警报

```rust
恐慌!("这不该发生：{}", 42);
```

运行输出：

```
线程 '主函数' 恐慌于 src/主函数.rs:2:5:
这不该发生：42
```

什么时候主动恐慌？**程序的不变量被破坏**——比如"这里绝不可能为空，空了说明前面有大缺陷"。宁可当场报警，不要带病运行。

## 16.6 解包与期望：偷懒的快进键

确定结果一定是 `成功` 时，可以用快捷方法直接取值：

```rust
让 数 = "42".解析::<整数>().解包();        // 直接取成功值
让 数 = "42".解析::<整数>().期望("应该是数字");  // 取不到就带这句话恐慌
```

（`解包` = unwrap，`期望` = expect。）

⚠️ **危险警告**：它们遇到 `错误` 会**直接恐慌**。学习时玩玩可以，正式代码里请老实 `匹配` 或 `?`。

## 16.7 决策表：该用哪个？

| 情况 | 选择 |
|---|---|
| 用户输入、文件、网络等外部因素可能失败 | `结果` |
| 失败后调用方**能补救**（重试、换方案） | `结果` |
| 程序内部逻辑绝不该出错，出错即缺陷 | `恐慌!` |
| 写示例/原型，图省事 | `解包`/`期望`（加注释） |

## 16.8 自定义错误与自动转换

16.2 起我们都用 `字符串` 当错误类型——省事，但很粗糙：错误种类没法枚举，调用方也没法分类处理。真实项目里，正确姿势是**自己定义错误类型**。

### 错误类型长什么样

一个合格的自定义错误 = 三件套：

1. **枚举**：列出所有出错种类（变体就是分类）；
2. **实现 `可显示`**：让 `{}` 能打印出人话；
3. **实现 `错误特征`**：拿到标准错误体系的门票（后面的 `?` 全自动转换要靠它）。

```rust
使用 标准库::格式化::显示;
使用 标准库::格式化::格式化参数;

#[派生(调试)]
枚举 登记错误 {
    名字太短,
    年龄不对,
}

实现 可显示 对于 登记错误 {
    函数 格式化方法(&自我, 格式化器: &可变 格式化参数) -> 结果<空, 标准库::格式化模块::错误特征> {
        让 文字 = 匹配 自我 {
            登记错误::名字太短 => "名字至少两个字",
            登记错误::年龄不对 => "年龄要在 0 到 150 之间",
        };
        写入格式化!(格式化器, "{}", 文字)
    }
}

实现 标准库::错误模块::错误特征 对于 登记错误 {}

函数 主函数() {
    打印行!("{}", 登记错误::名字太短);
    打印行!("{}", 登记错误::年龄不对);
}
```

输出：

```
名字至少两个字
年龄要在 0 到 150 之间
```

几个要点：

- `#[派生(调试)]`：`错误特征` 要求类型能调试打印，顺手贴上（第十章的贴纸）；
- `函数 格式化方法` 的签名是**标准格式**：接收 `&可变 格式化参数`，返回 `结果<空, 标准库::格式化模块::错误特征>`——**照抄即可**，不用问为什么；
- `写入格式化!(格式化器, "...")` 是"往格式化器里写文字"的宏（对应 `write!`）；
- `实现 标准库::错误模块::错误特征 对于 登记错误 {}` 是空实现——特征本身没有必须补的方法，这张"证书"就是让编译器认账。

📖 **错误特征**：Rust 标准库给"错误"发的统一证书。实现了它，你的错误就能和标准库错误（文件、网络、解析……）享受同样的待遇。

### 从转换：? 的自动翻译官

16.4 讲过：`?` 失败时会把错误**从当前函数返回**。但有个隐藏机制：如果函数声明的错误类型和实际产生的错误类型**不一样**，`?` 会尝试用 **`从转换`** 自动翻译！

场景：`文字.解析::<整数>()` 产生的错误是标准库的 `解析整数错误`，而我们的函数返回 `登记错误`——类型对不上。怎么办？实现一个 `从转换` 就行：

```rust
// 告诉编译器：解析整数的失败 = 我们的"格式错误"
实现 从转换<解析整数错误> 对于 登记错误 {
    函数 从(_输入: 解析整数错误) -> 登记错误 {
        登记错误::格式错误
    }
}
```

有了它，`文字.解析::<整数>()?` 里的 `?` 一旦遇到解析失败，就会**自动调用这个 `from`**，把 `解析整数错误` 翻译成 `登记错误::格式错误`，再沿函数返回。

（`从转换` = From，`转换为` = Into：实现了 `从转换`，`转换为` 自动免费获得——`值.转换为()` 直接可用。）

### 完整示例：登记系统

```rust
使用 标准库::格式化::显示;
使用 标准库::格式化::格式化参数;
使用 标准库::数字::解析整数错误;

#[派生(调试)]
枚举 登记错误 {
    名字太短,
    年龄不对,
    格式错误,
}

实现 可显示 对于 登记错误 {
    函数 格式化方法(&自我, 格式化器: &可变 格式化参数) -> 结果<空, 标准库::格式化模块::错误特征> {
        让 文字 = 匹配 自我 {
            登记错误::名字太短 => "名字至少两个字",
            登记错误::年龄不对 => "年龄要在 0 到 150 之间",
            登记错误::格式错误 => "输入格式不对",
        };
        写入格式化!(格式化器, "{}", 文字)
    }
}

实现 标准库::错误模块::错误特征 对于 登记错误 {}

// 关键：解析整数的失败 → 自动翻译成我们的 格式错误
实现 从转换<解析整数错误> 对于 登记错误 {
    函数 从(_输入: 解析整数错误) -> 登记错误 {
        登记错误::格式错误
    }
}

函数 检查名字(名字: &文本) -> 结果<(), 登记错误> {
    如果 名字.逐字符().计数() < 2 {
        返回 错误(登记错误::名字太短);
    }
    成功(())
}

函数 检查年龄(文字: &文本) -> 结果<整数, 登记错误> {
    让 年龄 = 文字.解析::<整数>()?;   // 解析失败时，? 自动调用上面的 from
    如果 年龄 < 0 || 年龄 > 150 {
        返回 错误(登记错误::年龄不对);
    }
    成功(年龄)
}

函数 登记(名字: &文本, 年龄文字: &文本) -> 结果<(), 登记错误> {
    检查名字(名字)?;
    检查年龄(年龄文字)?;
    成功(())
}

函数 主函数() {
    匹配 登记("小", "abc") {
        成功(_) => 打印行!("登记成功"),
        错误(错误原因) => 打印行!("失败：{}", 错误原因),
    }
    匹配 登记("小明", "200") {
        成功(_) => 打印行!("登记成功"),
        错误(错误原因) => 打印行!("失败：{}", 错误原因),
    }
    匹配 登记("小明", "25") {
        成功(_) => 打印行!("登记成功"),
        错误(错误原因) => 打印行!("失败：{}", 错误原因),
    }
}
```

输出：

```
失败：名字至少两个字
失败：年龄要在 0 到 150 之间
登记成功
```

三种失败，三种人话：`"小"` 只有 1 个字（`逐字符().计数()` 数的是**字符**，中文一个字算一个——第九章的 `长度` 数的是**字节**，中文会数成 3）；`"200"` 超龄；`"abc"` 根本解析不成数字（虽然这轮没轮到它——名字先挂了）。

> 💡 **为什么这么设计？** 三个函数（检查名字 / 检查年龄 / 登记）都返回同一个 `登记错误`，全靠 `?` 接力 + `from` 自动翻译。如果每个函数各自返回不同类型的错误，`?` 就没法传了——`从转换` 把"错误体系"统一成一个口径。

### 主函数返回结果

`主函数` 也能返回 `结果`！这样主函数里也能用 `?` 一路接力，把错误一路传到最顶层：

```rust
使用 标准库::格式化::显示;
使用 标准库::格式化::格式化参数;

#[派生(调试)]
枚举 登记错误 {
    名字太短,
}

实现 可显示 对于 登记错误 {
    函数 格式化方法(&自我, 格式化器: &可变 格式化参数) -> 结果<空, 标准库::格式化模块::错误特征> {
        写入格式化!(格式化器, "名字至少两个字")
    }
}

实现 标准库::错误模块::错误特征 对于 登记错误 {}

函数 检查名字(名字: &文本) -> 结果<(), 登记错误> {
    如果 名字.长度() < 2 {
        返回 错误(登记错误::名字太短);
    }
    成功(())
}

函数 主函数() -> 结果<(), 登记错误> {
    检查名字("小明")?;
    打印行!("登记成功");
    成功(())
}
```

输出：

```
登记成功
```

如果检查失败（把 `"小明"` 换成 `"A"`——只有 1 个字节，`长度() < 2` 成立），`主函数` 会带着 `错误` 退出，程序自动打印（这一行走的是**标准错误输出**，且退出码为 1）：

```
Error: 名字太短
```

（`Error: ` 前缀是运行时自动加的，用的是 `{:?}` 调试格式，所以错误类型要派生 `调试`。）

> ⚠️ **提醒**：`主函数` 返回 `结果` 时，错误直接变成"程序以错误码退出"——适合**最顶层**兜底；业务里的错误该 `匹配` / `?` 处理的地方照旧。

### 常见错误

**错误一：`?` 报"无法转换错误类型"**

`?` 遇到类型对不上、又没有 `从转换` 实现时，编译报错。**解决**：给目标错误类型实现 `从转换<来源类型>`（或 `从转换<字符串>` 兜底）。

**错误二：错误类型没派生 `调试`**

`主函数` 返回 `结果`、或实现 `错误特征` 时，要求类型能调试打印。**解决**：`#[派生(调试)]` 贴上（第十章的贴纸又立功了）。

## 16.9 完整示例：档案管理系统

把本章所有招式串起来：解析 + 业务校验 + `?` 接力 + 调用方分发：

```rust
// 解析年龄：成功返回数字，失败返回原因
函数 解析年龄(文字: &文本) -> 结果<整数, 字符串> {
    匹配 文字.解析::<整数>() {
        成功(数) => {
            如果 数 < 0 {
                返回 错误(字符串::从("年龄不能为负"));
            }
            成功(数)
        }
        错误(_) => 错误(格式化!("无法解析：{}", 文字)),
    }
}

// ? 接力：任何一步失败就提前把错误传上去
函数 汇报档案(文字: &文本) -> 结果<字符串, 字符串> {
    让 年龄 = 解析年龄(文字)?;
    成功(格式化!("档案建好，年龄 {}", 年龄))
}

函数 主函数() {
    对于 输入 在 ["25", "-3", "二十"] {
        匹配 汇报档案(输入) {
            成功(汇报内容) => 打印行!("{} -> {}", 输入, 汇报内容),
            错误(原因) => 打印行!("{} -> 失败：{}", 输入, 原因),
        }
    }
}
```

## 16.10 逐行解释

- **第 2–13 行**：`解析年龄` 返回 `结果<整数, 字符串>`。三种结局：格式对且非负 → `成功(数)`；负数 → `错误("年龄不能为负")`；格式不对 → `错误("无法解析：...")`。
- **第 16–19 行**：`汇报档案` 用 `?`——解析失败时错误自动上交，成功则包装成新的 `成功` 继续加工。
- **第 22–28 行**：主函数拿三种输入走流水线：`"25"` 成功；`"-3"` 死在业务校验；`"二十"` 死在解析。调用方用 `匹配` 分流两种结局。

## 16.11 运行结果

```
25 -> 档案建好，年龄 25
-3 -> 失败：年龄不能为负
二十 -> 失败：无法解析：二十
```

三种失败原因各不相同——好错误信息就该这样，**说清楚错在哪、为什么**。

## 16.12 常见错误与解决

### 错误一：`结果` 没拆就直接用

```
错误：类型不匹配：期望 `整数`，实际得到 `结果<...>`
```

**解决**：`匹配` / `如果让` / `?` 拆开再使用。

### 错误二：在不返回 `结果` 的函数里用 `?`

编译报错"不能在返回 `()` 的函数中使用 `?`"。**解决**：把函数返回类型改成 `结果<..., ...>`，或改用 `匹配`。

### 错误三：拿 `错误` 当变体名时拼错

`结果` 的失败变体叫 **`错误`**（= Err）。写 `失败(...)` 会报"未知的元组变体"。

### 错误四：变量名撞上标准库类型

起名 `报告` 会被转译成标准库类型 `Report`，触发命名警告甚至找不到名字。**解决**：变量名避开单一名词映射词，用 `汇报内容` 这类组合词。

### 错误五：解包炸了

```
called `unwrap()` on an `Err` value
```

**解决**：别裸 `解包`——用 `匹配` 或 `期望("说明为什么一定有值")`，至少恐慌时能看懂。

## 16.13 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 可恢复错误 | 可以补救的失败，用 `结果` 表示 |
| 不可恢复错误 | 必须停止的失败，用 `恐慌!` 表示 |
| 结果 | `结果<好, 坏>` 枚举，装成功或失败 |
| 成功/错误 | 结果的两个变体 |
| ? 操作符 | 成功就拆值继续，失败就立刻上交错误 |
| 恐慌 | 打印信息、清理现场、停止运行 |
| 恐慌! | 主动拉响警报的宏 |
| 解包 | 直接取成功值，遇到错误就恐慌 |
| 期望 | 解包 + 自定义恐慌留言 |
| 解析 | 把文字转换成数字等类型，返回结果 |

> 📖 **提醒**：遇到不懂的词，随时回查全书开头的《总术语表》。

```rust
        错误(原因) => 打印行!("失败：{}", 原因),
    }
    匹配 除法(10, 0) {
        成功(商) => 打印行!("商是：{}", 商),
        错误(原因) => 打印行!("失败：{}", 原因),
    }
}
```

## 16.15 常见问题

**问：为什么不学别的语言，到处"抛出异常"？**

答：异常容易被漏接（忘了捕获）。Rust 把错误**写在返回类型里**——`结果<好, 坏>` 一眼可见，编译器盯着你必须处理。"错误是值，不是意外"。

**问：`选项` 和 `结果` 怎么选？**

答：`选项` 表示"可能没有，但没有也不算错"（比如查不到某人，正常）；`结果` 表示"失败了，有原因要交代"（比如文件格式坏了）。前者 `有值/无`，后者 `成功/错误`。

**问：`?` 能让错误类型自动转换吗？**

答：能——靠 `从` 机制。16.8 小节演示过：实现了 `从转换`，`?` 会自动把一种错误翻译成另一种。第二十五章综合实战还会见到它的大规模应用。

**问：恐慌后数据会丢吗？**

答：默认行为是逐层清理（清理器运行）后退出。总之：**恐慌 = 程序生命终点**，别指望恐慌后继续干活。

**问：什么时候真的该恐慌？**

答：三条经验：① 写测试时（断言失败就该恐慌）；② 程序内部约定被打破（空指针级别的缺陷）；③ 示例代码图简洁。面向用户的正式功能，一律 `结果`。

**问：`主函数` 能返回 `结果` 吗？**

答：能！16.8 小节讲过详细写法：`函数 主函数() -> 结果<(), 错误类型>`，出错时程序打印 `Error: ...` 并带错误码退出。
