# 第二十三章：宏与元编程

## 23.0 学习目标

读完这一章，你将能够：

1. 说出**带感叹号**的调用为什么是宏而不是函数；
2. 用**代码复印机**比喻解释宏的本质；
3. 用 **`宏规则!`** 写声明式宏，理解"模式 → 模板"的工作方式；
4. 看懂 **`$名字:expr`** 这类捕获语法；
5. 知道派生宏、属性宏的存在（第十七、十三章已多次用）；
6. 会用"函数优先，宏是最后手段"的判断原则。

## 23.1 感叹号：宏的招牌

你早就天天用宏了：

```rust
打印行!("你好");     // 打印行! 是宏
格式化!("第{}名", 3);  // 格式化! 是宏
恐慌!("出事了");      // 恐慌! 也是宏
```

📖 **宏（macro）**：名字后面带 **`!`** 的，都是宏。它在编译前**展开成真正的代码**，编译器再编译展开后的结果。

💡 **比喻**：函数像**现成的菜**——你点单，它端上来；宏像**代码复印机**——你给它一张模板和素材，它现场印出一段新代码填进你的程序里。

为什么 `打印行!` 非得当宏？因为它接收**任意个数、任意类型**的参数——函数做不到"参数个数不定"，宏可以在展开前数一数你给了什么。

## 23.2 声明式宏：模式匹配式的复印机

📖 **宏规则（macro_rules）**：声明式宏的定义方式。结构像 `匹配`：左边一个模式，右边一段模板。

```rust
宏规则! 打招呼 {
    () => {
        打印行!("你好！");
    };
    ($名字:表达式) => {
        打印行!("你好，{}！", $名字);
    };
}
```

逐块读：

| 片段 | 含义 |
|---|---|
| `宏规则! 打招呼` | 造一个叫 `打招呼` 的宏 |
| `() => { ... }` | 模式一：什么也不传时，展开成这句 |
| `($名字:表达式) => { ... }` | 模式二：传一个表达式，存进 `$名字` |
| `$名字` | 模板里用回捕获到的素材 |

⚠️ **注意**：片段说明符必须写**英文**——`:expr`（表达式）、`:ident`（标识符）、`:ty`（类型）等。写 `:表达式` 编译不过。

使用（模式由编译器自动挑）：

```rust
打招呼!();                // 命中模式一
打招呼!("小华");           // 命中模式二
打招呼!(格式化!("第{}名", 3));  // 表达式也行
```

## 23.3 宏展开：复印的过程

`打招呼!("小华")` 编译前被替换成：

```rust
打印行!("你好，{}！", "小华");
```

编译器看到的从来只有展开后的代码。所以宏**没有类型检查的提前量**——错误出现在展开后的代码里，报错位置有时让人挠头。这是宏的主要代价。

## 23.4 三种宏家族

| 家族 | 长相 | 你在本书见过 |
|---|---|---|
| 声明式宏 | `宏规则!` 定义，`名字!(...)` 调用 | `打印行!`、本章示例 |
| 派生宏 | `#[派生(...)]` 贴纸 | 第七章 `Clone`、第十章 `Debug` |
| 属性宏/过程宏 | `#[...]` 自定义属性 | 第二十一章 `#[测试]` 的近亲 |

后两种靠编译器的过程宏机制实现，通常由库提供。初学**会写声明式宏、会用派生贴纸**就够闯荡了。

## 23.5 什么时候用宏

**函数优先！** 宏只在三种场合出手：

1. **参数个数不定**（`打印行!`）；
2. **编译前就要生成代码**（派生宏替你写实现块）；
3. **造领域小语法**（测试框架的断言、Web 路由定义）。

写宏的代价：调试难、报错绕、可读性下降。能写函数绝不写宏。

## 23.6 完整示例：两个小宏

一个多模式宏 + 一个带循环的宏：

```rust
// 声明式宏：像填表模板，按模式生成代码
宏规则! 打招呼 {
    () => {
        打印行!("你好！");
    };
    ($名字:expr) => {
        打印行!("你好，{}！", $名字);
    };
}

// 一个会重复三遍的宏
宏规则! 说三遍 {
    ($话:expr) => {
        对于 _ 在 0..3 {
            打印行!("{}", $话);
        }
    };
}

函数 主函数() {
    打招呼!();
    打招呼!("小华");
    打招呼!(格式化!("第{}名", 3));
    说三遍!("好好学习");
}
```

## 23.7 逐行解释

- **第 2–9 行**：`打招呼` 两条规则。模式按书写顺序匹配——先试空参数，再试"一个表达式"。
- **第 6 行**：`$名字:expr` 是捕获槽——"这里收一个表达式，起名 `$名字`"。
- **第 12–18 行**：`说三遍` 把传进来的表达式塞进一个 `对于` 循环——宏展开的就是整段代码，循环、判断随便写。
- **第 21–24 行**：四种调用。`打招呼!(格式化!(...))` 演示宏参数可以是别的宏的产物。

## 23.8 运行结果

```
你好！
你好，小华！
你好，第3名！
好好学习
好好学习
好好学习
```

前三个来自 `打招呼` 的两种模式，后三个来自 `说三遍` 的循环展开。

## 23.9 常见错误与解决

### 错误一：片段说明符写中文

```
错误：invalid fragment specifier `表达式`
```

**解决**：用英文：`expr`（表达式）、`ident`（标识符）、`literal`（字面量）、`ty`（类型）。

### 错误二：`no rules expected ...`

传入的参数和所有模式都对不上。**解决**：检查参数个数和形状，对照宏定义的每条规则。

### 错误三：宏找不到名字

宏展开在调用处，展开的代码里引用的名字得在**调用处可见**。**解决**：需要的话在模板里写全路径。

### 错误四：忘记感叹号

`打印行("你好")` 报找不到函数。**解决**：宏调用永远带 `!`。

## 23.10 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 宏 | 编译前展开成代码的语法工具，名字带 `!` |
| 声明式宏 | 用 `宏规则!` 按模式匹配的宏 |
| 模式 | 宏左边：描述接收什么形状的参数 |
| 模板 | 宏右边：展开成什么代码 |
| 捕获槽 | `$名字:expr`，把参数存起来给模板用 |
| 片段说明符 | 槽的类型标注，如 `expr`、`ident` |
| 派生宏 | `#[派生(...)]` 自动写实现块 |
| 展开 | 宏替换成代码的过程 |

> 📖 **提醒**：遇到不懂的词，随时回查全书开头的《总术语表》。

## 23.11 练习

> 💪 先自己试，再看答案。

### 练习一：二选一

写宏 `选大的!`：接收两个表达式，打印较大的。

<details>
<summary>🔍 查看答案</summary>

```rust
宏规则! 选大的 {
    ($甲:expr, $乙:expr) => {
        如果 $甲 > $乙 {
            打印行!("{}", $甲);
        } 否则 {
            打印行!("{}", $乙);
        }
    };
}

// 使用：选大的!(3, 9);
```

</details>

### 练习二：带标签的打印

写宏 `报数!`：接收一个表达式，打印"名字 = 值"（名字就用表达式的字面文本做不到——改收一个标识符）。

<details>
<summary>🔍 查看答案</summary>

```rust
宏规则! 报数 {
    ($名:ident) => {
        打印行!("{} = {}", "变量", $名);
    };
}

// 使用：
让 分数 = 88;
报数!(分数);   // 变量 = 88
```

（想把变量名本身打出来需要"字符串化"操作符 `$名`，进阶话题。）

</details>

### 练习三：数模式

给 `打招呼` 加第三条规则：接收一个整数字面量（`:literal`），打印"你好，第 N 位客人"。

<details>
<summary>🔍 查看答案</summary>

```rust
宏规则! 打招呼 {
    () => { 打印行!("你好！"); };
    ($数:literal) => { 打印行!("你好，第{}位客人", $数); };
    ($名字:expr) => { 打印行!("你好，{}！", $名字); };
}

// 打招呼!(3);   -> 你好，第3位客人
```

（字面量规则放在 `expr` 规则前，优先命中。）

</details>

## 23.12 常见问题（FAQ）

**问：宏和泛型都是"一份代码多种用法"，区别在哪？**

答：泛型对**类型**抽象（编译后各造一份，但只收同形状参数）；宏对**代码形状**抽象（参数个数、结构都能变）。`打印行!` 那种"参数任意个"只有宏做得到。

**问：宏会影响运行速度吗？**

答：展开发生在编译前，展开后就是普通代码，运行时零开销。影响的是**编译时间**和**可读性**。

**问：为什么报错总在宏附近绕来绕去？**

答：因为错误出在**展开后的代码**里，位置信息常常指向调用处或宏内部混合。对策：把宏写小、模式写简单；调试时先手动展开看看生成物。

**问：标准库的 `向量宏![1,2,3]` 是怎么实现的？**

答：就是一个声明式宏，收一串逗号分隔的表达式，展开成"建向量 + 逐个推入"。你现在完全读得懂它的原理了。

**问：我以后会需要自己写宏吗？**

答：大概率很少。业务代码里函数+泛型+特征足够。但**读懂宏**很重要——断言、日志、路由等库全是宏。能读能改，就是好水平。

**问：`宏规则!` 能递归吗？**

答：能——宏可以用自己展开自己（处理任意长度的列表就是靠递归模式）。这是高阶玩法，需要时再学。
