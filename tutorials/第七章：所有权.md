# 第七章：所有权

## 7.0 学习目标

读完这一章，你将能够：

1. 说出**所有权的三条规则**；
2. 解释**作用域**结束时值会发生什么；
3. 分清**复制**（整数等小数据）和**移动**（字符串等堆数据）；
4. 看懂 **E0382**（值在移动后被使用）错误并修复它；
5. 用 **`克隆()`** 复制一份独立的数据；
6. 说出值**传进函数、从函数返回**时所有权去了哪里。

> ✨ 这一章是 Rust 最特别的地方，别的语言大多没有。第一次读不懂很正常，多读两遍、把例子都跑一遍，就会豁然开朗。

---

## 7.1 为什么需要所有权：谁来打扫卫生

💡 **故事**：学校组织大扫除。如果**没有分工**，会发生两种灾难：

1. **没人打扫**：某块地没人负责，垃圾越堆越多——程序里叫**内存泄漏**（申请了内存却不归还，内存越用越多，最后卡死）；
2. **两人同时打扫同一处**：一个刚擦完另一个又按自己的理解改，乱套——程序里叫**数据竞争**（后两章讲多线程时详细说）。

Rust 的办法很简单粗暴：**每一样东西，必须有且只有一个主人。主人负责它，主人走了，东西自动收拾掉。**

📖 **所有权（Ownership）**：Rust 的核心规则——每个值都有唯一的"主人"（变量），主人离开时值被自动释放。

这就是 Rust 不用"垃圾回收器"（别的语言雇的自动清洁工）也能保证内存安全的原因：**人人有责，责任到人**。

---

## 7.2 所有权的三条规则

背下这三条，本章就成功了一半：

| 编号 | 规则 | 大白话 |
|---|---|---|
| 规则一 | 每个值都有一个**所有者**（变量） | 每样东西都有主人 |
| 规则二 | 同一时刻，所有者**只能有一个** | 一物不能二主 |
| 规则三 | 所有者离开**作用域**，值被**自动释放** | 主人走了，东西自动收拾 |

📖 **作用域（Scope）**：一个名字"有效"的代码范围。通常就是一对花括号 `{ }` 之内。就像"操场"是你活动的范围——出了操场，你管不了操场上的事。

---

## 7.3 作用域：值的一生

看这段代码：

```rust
函数 主函数() {
    {
        让 临时 = 字符串::从("只活在块里");
        打印行!("块内：{}", 临时);
    }
    // 临时 在这里已经不存在了
    打印行!("块外继续");
}
```

输出：

```
块内：只活在块里
块外继续
```

`临时` 在内层花括号里出生，花括号一结束，它就**消失**了——占用的内存自动归还。你在块外再用 `临时`，编译器会报"找不到这个变量"。

> 💡 **比喻**：值的一生像住酒店：**入住**（声明）→ 使用 → **退房**（离开作用域）。退房时房间自动打扫干净（内存释放），不用你操心，也不会有人赖着不走。

> 📖 **释放（Drop）**：值离开作用域时自动执行的清理，内存还给系统。英文叫 drop。

---

## 7.4 两种存放地：口袋和仓库

为什么有的数据会"复制"、有的会"移动"？先要知道数据存放的两个地方：

📖 **栈（Stack）**：速度飞快、容量小的内存区。像**随身口袋**——掏取方便，但装不了大件。
📖 **堆（Heap）**：速度稍慢、容量大的内存区。像**仓库**——能放大件，但取东西要跑一趟，还得登记。

| 存放地 | 装什么 | 比喻 |
|---|---|---|
| 栈（口袋） | 整数、浮点数、布尔、字符——大小固定的小东西 | 钥匙、橡皮 |
| 堆（仓库） | 字符串、向量等——内容多少不定的大东西 | 一整箱书 |

`字符串`（字符串）的内容就存在**堆**上：仓库里放着一排字，变量本身（口袋里）只攥着一张**提货单**（记录仓库位置、长度）。

理解了这个，下面的复制和移动就顺理成章了。

---

## 7.5 复制：口袋里的东西随手抄一份

```rust
让 甲 = 5;
让 乙 = 甲;
打印行!("甲：{}，乙：{}", 甲, 乙);
```

输出：`甲：5，乙：5`

整数住在**口袋**里，抄一份几乎不花时间。所以 `让 乙 = 甲` 是**复制**：甲还在，乙是独立的另一份。两个变量都能随便用。

📖 **复制（Copy）**：值离开作用域时自动逐位复制的性质。整数、浮点数、布尔、字符都具备。

**哪些类型会复制？** 记住口诀：**"数字、真假、单字符"**——整数（`整数`、`长整数`…）、浮点数（`浮点数`）、布尔（`真`/`假`）、字符。这些统统住在口袋里，赋值就是抄一份。

---

## 7.6 移动：提货单只有一张

字符串住在**仓库**里，变量手里只有提货单。这时：

```rust
让 句子甲 = 字符串::从("你好");
让 句子乙 = 句子甲;
打印行!("句子乙：{}", 句子乙);
```

`让 句子乙 = 句子甲` 不是复制，而是**移动**：提货单从句子甲手里**递给了**句子乙。提货单只有一张——现在主人是句子乙。

💡 **比喻**：一张电影票给了朋友，你手里就没了。想进场？要么朋友还你，要么再买一张（7.7 节的克隆）。

如果移动之后还想用旧的变量名：

```rust
让 句子甲 = 字符串::从("你好");
让 句子乙 = 句子甲;
打印行!("句子甲：{}", 句子甲);   // ❌
```

编译器毫不留情地报错：

```
错误[E0382]: 值在移动后被使用：`句子甲`
📌 变量 `句子甲` 在第 3 行被移动，第 4 行尝试再次使用。
💡 Rust 中值被移动后不能再使用。考虑使用 `引用`（&）或 `克隆()` 来避免移动。
```

📖 **移动（Move）**：把堆上数据的所有权从一个变量交给另一个变量，原变量立即失效。

> 📖 **E0382**：错误码，意思是"值在移动后被使用"。看到它就知道：某个值已经换了主人，你却还在找旧主人要。

**为什么 Rust 这么"抠"？** 如果复制整箱书（可能几百兆），程序会变慢；如果两人共享一张提货单，退房时（离开作用域）会打扫两次同一间房——直接崩溃。Rust 选择最干脆的方案：**一物一主，给出去就没了**。

---

## 7.7 克隆：再买一张票

想要两份独立的？用 **`克隆()`**（英文 clone，"克隆、复制"）：

```rust
让 原件 = 字符串::从("藏宝图");
让 复制件 = 原件.克隆();
打印行!("原件：{}，复制件：{}", 原件, 复制件);
```

输出：`原件：藏宝图，复制件：藏宝图`

克隆把**仓库里的东西真真切切复制一份**，两张提货单各指各的仓库。改一份，另一份不受影响。

> ⚠️ **小心**：克隆要花时间（仓库里整箱复印）。能移动解决就别克隆。初学阶段放心用，性能优化是以后的事。

**对比记忆表**：

| 操作 | 口袋数据（整数等） | 仓库数据（字符串等） |
|---|---|---|
| `让 乙 = 甲` | 复制，都能用 | 移动，甲失效 |
| `让 乙 = 甲.克隆()` | 也能克隆（没必要） | 复制，都能用 |

## 7.8 所有权与函数：进出都要"过户"

值**传进函数**和**从函数返回**，同样发生所有权转移。

### 传参：值搬进函数

```rust
函数 收下(句子: 字符串) {
    打印行!("函数里收到：{}", 句子);
}

函数 主函数() {
    让 祝福 = 字符串::从("生日快乐");
    收下(祝福);
    // 祝福 已经搬进函数，这里不能再用
}
```

`收下(祝福)` 把祝福**整个过户**给了函数的参数 `句子`。调用结束后 `句子` 离开作用域，值被释放。主函数里的 `祝福` 从此失效。

### 返回：值搬回调用者

```rust
函数 制作问候(名字: 字符串引用) -> 字符串 {
    字符串::从(名字)
}

函数 主函数() {
    让 问候 = 制作问候("小明");
    打印行!("拿到：{}", 问候);
}
```

输出：`拿到：小明`

函数里新造的字符串，通过 `返回` **过户**给了 `问候`——它的新主人。

> 💡 **比喻**：函数是一间快递站。传参 = 你把包裹**寄进去**（你手里就没了）；返回 = 快递站把新包裹**寄给你**（从此归你）。

> ✨ **现在你可能会觉得麻烦：借东西都不行吗？** 行！第八章《引用与借用》就是专门讲"怎么借"的——借了要还，不转移所有权。

## 7.9 完整示例：快递站

把所有权的所有知识串成一个"寄快递"的故事：

```rust
// 派生(克隆)：让结构体自动获得 克隆 能力
// 派生括号里的特征名可以用中文（克隆 → Clone）
#[派生(克隆)]
结构体 包裹 {
    内容: 字符串,
    重量: 整数,
}

实现 包裹 {
    函数 创建(内容: 字符串, 重量: 整数) -> 包裹 {
        包裹 { 内容: 内容, 重量: 重量 }
    }

    函数 介绍(&自我) {
        打印行!("包裹：{}，{}克", 自我.内容, 自我.重量);
    }
}

// 签收 = 把包裹的所有权收进来，签收完包裹就"用掉"了
函数 签收(件: 包裹) {
    件.介绍();
    打印行!("已签收！");
}

函数 主函数() {
    // 造一个包裹
    让 甲 = 包裹::创建(字符串::从("玩具"), 500);
    甲.介绍();

    // 克隆一份寄出，原件自己留着
    让 副本 = 甲.克隆();
    签收(副本);

    // 原件还在，继续用
    甲.介绍();

    // 最后把原件也寄出去
    签收(甲);
    // 从此 甲 失效
}
```

---

## 7.10 逐行解释

- **第 3 行**：`#[派生(克隆)]` 是一行"贴纸"（专业叫**属性**），让编译器自动为 `包裹` 生成 `克隆()` 方法。括号里可以写中文特征名（`克隆` → `Clone`、`调试` → `Debug`），也可直接写英文原名。
- **第 4–7 行**：结构体 `包裹` 有两个字段。`内容` 是 `字符串`（住在仓库），`重量` 是整数（住在口袋）。
- **第 10–13 行**：关联函数 `创建`，返回新包裹（所有权交给调用者）。
- **第 15–17 行**：`介绍` 用 `&自我`——**只借用**看一眼，不拿走，所以调用后包裹还在（借用细节第八章细讲）。
- **第 21–24 行**：`签收` 的参数类型是 `包裹`（不带 `&`）——传进来的包裹所有权归了 `件`，函数结束 `件` 被释放。寄件人从此失去这个包裹。
- **第 28 行**：`字符串::从("玩具")` 造一个字符串，随包裹一起归 `甲` 所有。
- **第 32 行**：`甲.克隆()` 复制出完全独立的 `副本`（连同里面的字符串一起复制）。
- **第 33 行**：`签收(副本)`——副本被收走、释放。
- **第 36 行**：`甲` 完好无损，还能介绍自己。
- **第 39 行**：`签收(甲)`——原件也被收走。这行之后若再写 `甲.介绍()`，就是 E0382。

---

## 7.11 运行结果

```
包裹：玩具，500克
包裹：玩具，500克
已签收！
包裹：玩具，500克
包裹：玩具，500克
已签收！
```

对照：第 1 行是造好后自我介绍；第 2–3 行是克隆的副本被签收；第 4–6 行是原件介绍自己、然后也被签收。两个包裹内容一样，但它们是**独立的两个值**。

## 7.12 常见错误与解决

### 错误一：E0382 移动后使用

```
错误[E0382]: 值在移动后被使用：`句子甲`
💡 Rust 中值被移动后不能再使用。考虑使用 `引用`（&）或 `克隆()` 来避免移动。
```

**三条修复路线**：

1. **只是想看看** → 传引用 `&句子甲`（第八章）；
2. **想双方都留一份** → `句子甲.克隆()`；
3. **真的只想给一个人** → 调整代码顺序，让最后一次使用在移动之前。

### 错误二：把整数的行为套在字符串上

"为什么 `甲` 不能用了？`乙 = 甲` 之后整数都能用啊！"——因为整数是**复制**，字符串是**移动**。回头看 7.4 的口诀："数字、真假、单字符"才复制。

### 错误三：克隆了却报错"方法不存在"

自定义结构体调用 `.克隆()` 报错，是因为结构体默认**不会**克隆。要在结构体定义前加贴纸 `#[派生(克隆)]`。

### 错误四：派生特征名写错

`#[派生(克降)]` 会报"找不到派生宏"——注意别把 `克隆` 写成 `克降` 之类的同音错别字。中文特征名支持：`克隆`→`Clone`、`调试`→`Debug`、`复制`→`Copy`、`哈希`→`Hash` 等。

## 7.15 常见问题（FAQ）

**问：所有权检查是运行时还是编译时？**

答：**编译时**。编译器在你运行之前就查清了所有权的来龙去脉，不合格的程序根本编译不过去。所以 Rust 程序运行时没有所有权检查的开销——这就是"零成本"思想的体现。

**问：整数真的永远不会移动吗？**

答：对。整数、浮点数、布尔、字符这些"口袋数据"赋值时永远复制。以后你会学到精确的判定方式：实现了 `Copy` 特征的类型都复制。

**问：字符串字面量 `"你好"` 也是移动吗？**

答：字面量是**字符串引用**（`&文本`），它是"借用"——借用的东西赋值时只是把借据再抄一份，双方都还能用。真正会移动的是 `字符串`（字符串）类型，比如 `字符串::从("你好")` 造出来的。第九章会详细区分两者。

**问：克隆和复制到底差在哪？**

答：复制是编译器**自动、廉价**的（只抄口袋里的几个字节）；克隆是**你手动、较贵**的（要去仓库整箱复印）。能复制的类型克隆也行但没必要；会移动的类型想要两份就必须克隆。

**问：每个变量都要想着所有权，不会很累吗？**

答：开始确实累，这是学 Rust 最大的门槛。好消息是：等你写完两三章的项目，"谁拥有谁"会变成直觉。而且编译器是免费搭档——你忘了，它立刻提醒你，还附修复建议。

**问：别的语言（比如 Python、JavaScript）为什么没有这些？**

答：它们大多用"垃圾回收器"：程序运行时雇一个后台清洁工，定期巡逻打扫没人用的值。方便，但要付出运行时的性能开销和不确定性。Rust 用所有权在编译期解决问题，运行时就快而稳。
