# 第十六章：模块系统

前面的代码都写在一个文件里。但项目一大，一个文件就装不下了。

你需要把代码**分门别类**地整理好——就像一个大公司要有不同的部门，每个部门管不同的事。

这就是**模块系统**的作用。

---

## 16.1 什么是模块

> **生活类比**：模块就像一个公司里的**部门**。"人事部"管人事，"财务部"管账目，"技术部"管开发。每个部门有自己的工作内容，其他部门需要合作时，得通过正式渠道沟通。

```
公司（项目）
├── 人事部（模块）── 招聘、培训
├── 财务部（模块）── 记账、报销
└── 技术部（模块）── 开发、运维
```

**为什么要分模块？** 因为代码多了以后，全堆在一起会非常混乱。分模块让你：
- 把相关的代码放在一起
- 隐藏不想让别人看到的细节
- 让代码更容易找到

---

## 16.2 定义模块

用 **`模块`** 关键字定义一个模块：

```rust
模块 厨房 {
    函数 做饭() {
        打印行!("正在做饭...");
    }

    函数 洗碗() {
        打印行!("正在洗碗...");
    }
}

函数 主函数() {
    厨房::做饭();   // 调用厨房模块的"做饭"功能
    厨房::洗碗();   // 调用厨房模块的"洗碗"功能
}
```

逐行解释：

- 第 1 行：**`模块 厨房 { ... }`** 定义了一个叫"厨房"的模块
- 第 2-4 行：模块内部的 `做饭` 函数
- 第 6-8 行：模块内部的 `洗碗` 函数
- 第 12 行：**`厨房::做饭()`** 用 `::` 表示"属于厨房模块的做饭功能"

```
模块就像一个工具箱：

┌── 厨房 ──────────────────┐
│                           │
│  🔧 做饭()               │
│  🔧 洗碗()               │
│                           │
└───────────────────────────┘
         ↑
    厨房::做饭()  ← 打开工具箱，使用"做饭"
```

## 16.3 公开与私有

> **生活类比**：公司里有**内部文件**和**公开文件**。内部文件只有本部门的人能看，公开文件其他部门也能看。模块里的代码也一样——默认是"内部"的，加了 **`公开`** 关键字才对外可见。

```rust
模块 餐厅 {
    // 公开的——外面可以用
    公开 函数 点餐() {
        打印行!("您要点什么？");
        厨房::做饭();
    }

    // 不公开——只有餐厅内部能用
    函数 计算成本() -> 整数 {
        42  // 商业机密！
    }
}

模块 厨房 {
    公开 函数 做饭() {
        打印行!("正在做饭...");
    }
}

函数 主函数() {
    餐厅::点餐();      // ✅ 公开函数，可以用
    // 餐厅::计算成本(); // ❌ 私有函数，外面不能用！
}
```

逐行解释：

- 第 3 行：**`公开 函数 点餐()`** 加了 `公开`，外面可以调用
- 第 8 行：`计算成本` 没有加 `公开`，默认是私有的
- 第 19 行：`餐厅::点餐()` 可以调用，因为它是公开的
- 第 20 行：`餐厅::计算成本()` 不能调用，因为它是私有的——编译器会报错

```
可见性规则：

┌── 餐厅 ────────────────────┐
│                             │
│  🟢 公开 点餐()    ← 外面能看到、能用
│  🔒 私有 计算成本() ← 外面看不到、不能用
│                             │
└─────────────────────────────┘
```

## 16.4 多文件模块

代码多了以后，一个模块可以拆到单独的文件里：

```
项目结构：
src/
├── main.rs        ← 主文件
├── 厨房.rs        ← 厨房模块的代码
└── 餐厅.rs        ← 餐厅模块的代码
```

**`main.rs`**：

```rust
模块 厨房;     // 告诉编译器：去"厨房.rs"文件找厨房模块
模块 餐厅;

函数 主函数() {
    餐厅::点餐();
}
```

**`厨房.rs`**：

```rust
公开 函数 做饭() {
    打印行!("正在做饭...");
}
```

逐行解释：

- `main.rs` 第 1 行：**`模块 厨房;`** 没有花括号，意思是"去同名文件找这个模块"
- 编译器会自动去找 `厨房.rs` 文件
- `厨房.rs` 第 1 行：函数加了 `公开`，因为其他文件要用它

**为什么要拆文件？** 因为所有代码挤在一个文件里，找起来太累了。拆成多个文件，每个文件管一件事，代码就清晰了。

## 16.5 用 `使用` 简化路径

每次都要写 `餐厅::厨房::做饭()` 太长了。用 **`使用`** 可以简化：

```rust
模块 餐厅 {
    公开 模块 厨房 {
        公开 函数 做饭() {
            打印行!("正在做饭...");
        }
    }
}

// 不用"使用"：每次都要写完整路径
餐厅::厨房::做饭();

// 用"使用"引入：以后可以简写
使用 餐厅::厨房;

函数 主函数() {
    厨房::做饭();  // 简化了！
}
```

逐行解释：

- 第 11 行：**`使用 餐厅::厨房;`** 意思是"以后提到厨房时，不用写餐厅了"
- 第 14 行：直接写 `厨房::做饭()` 就行了

```
路径简化：

不用"使用"：
  餐厅::厨房::做饭()     ← 每次都写这么长

用"使用"后：
  使用 餐厅::厨房;
  厨房::做饭()            ← 短多了！
```

## 常见错误

### 忘记加 `公开`

```rust
模块 工具箱 {
    函数 内部工具() { 打印行!("内部使用"); }
    // 公开 函数 外部工具() { 打印行!("外部可用"); }
}

函数 主函数() {
    // 工具箱::内部工具();  // ❌ 私有函数，外面不能用
}
```

### 模块路径写错

```rust
模块 外层 {
    公开 模块 内层 {
        公开 函数 你好() { 打印行!("你好！"); }
    }
}

函数 主函数() {
    // 内层::你好();       // ❌ 路径不完整
    外层::内层::你好();    // ✅ 完整路径
}
```

## 练习题

### 练习 1：创建模块

创建一个 `数学` 模块，包含 `加` 和 `乘` 两个公开函数。

<details>
<summary>参考答案</summary>

```rust
模块 数学 {
    公开 函数 加(甲: 整数, 乙: 整数) -> 整数 {
        甲 + 乙
    }

    公开 函数 乘(甲: 整数, 乙: 整数) -> 整数 {
        甲 * 乙
    }
}

函数 主函数() {
    打印行!("3 + 5 = {}", 数学::加(3, 5));
    打印行!("3 × 5 = {}", 数学::乘(3, 5));
}
```
</details>

### 练习 2：公开与私有

创建一个 `银行` 模块，有公开的 `查询余额` 函数和私有的 `验证密码` 函数。

<details>
<summary>参考答案</summary>

```rust
模块 银行 {
    公开 函数 查询余额() -> 整数 {
        1000  // 模拟余额
    }

    函数 验证密码(密码: &文本) -> 布尔 {
        密码 == "123456"
    }
}

函数 主函数() {
    打印行!("余额：{}", 银行::查询余额());
    // 银行::验证密码("123456");  // ❌ 私有函数，外面不能用
}
```
</details>

## 本章小结

| 概念 | 一句话 |
|------|--------|
| 模块 | 公司里的部门——把相关代码放在一起 |
| `公开` | 公开文件——其他模块也能用 |
| 私有（默认） | 内部文件——只有本模块能用 |
| 多文件模块 | 大模块拆到单独文件 |
| `使用` | 简化路径，不用每次写完整名字 |
