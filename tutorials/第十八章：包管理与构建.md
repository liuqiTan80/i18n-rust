# 第十八章：包管理与构建

## 18.0 学习目标

读完这一章，你将能够：

1. 说出 **`Cargo.toml`** 的三大板块（身份、依赖、配置）；
2. 用命令给项目**添加第三方库**；
3. 分清 **debug 构建**与 **release 构建**的用途；
4. 分清**可执行文件**（bin）与**库**（lib）；
5. 知道构建产物藏在哪个目录；
6. 看懂版本号的三段式（主.次.补丁）。

---

## 18.1 项目也要办身份证

一个项目就是一堆文件——编译器怎么知道：叫什么名字？用了哪些别人的库？怎么编译？

💡 **比喻**：项目像开一家公司，得先**办营业执照**。Rust 世界的营业执照叫 **`Cargo.toml`**，而发证机关叫 **Cargo**（rzc 内部就带着它干活）。

第一章我们用 `rzc init 我的项目` 造项目，它生成的文件是：

```
我的项目/
├── Cargo.toml     <- 营业执照
└── src/
    └── 主函数.zh    <- 源代码
```

## 18.2 Cargo.toml 逐行读

`rzc init` 生成的真实内容：

```toml
[package]
name = "我的项目"
version = "0.1.0"
edition = "2024"

[dependencies]
```

| 字段 | 含义 |
|---|---|
| `[package]` | 身份信息板块 |
| `name` | 项目名（发布后别人靠它找你） |
| `version` | 版本号，三段式，见下文 |
| `edition` | Rust 版本纪元，决定语言规则，`2024` 是新版 |
| `[dependencies]` | 依赖清单——用到哪些第三方库，写在这里 |

📖 **依赖（dependency）**：你项目引用的别人的库。写进清单后，构建时自动下载、编译、链接。

### 版本号三段式

`0.1.0` 读作"主版本.次版本.补丁版本"：

- **补丁**（第三位）：修 bug，不改变用法；
- **次**（第二位）：加功能，老用法照旧；
- **主**（第一位）：大改，老用法可能失效。

约定：`0.` 开头的库还算年轻，随时可能变脸；`1.` 以上算成熟稳定。

## 18.3 添加第三方库

想用一个现成的库（比如序列化库 `serde`），两种办法：

### 办法一：命令行添加

```bash
cargo add serde
```

它自动在 `Cargo.toml` 里写上：

```toml
[dependencies]
serde = "1.0"
```

rzc 也提供同样的快捷命令（VS Code 扩展里也有"添加依赖"命令）：

```bash
rzc cargo add serde
```

### 办法二：手写

直接编辑 `Cargo.toml`，把依赖抄进 `[dependencies]`。下次构建时自动下载。

> ⚠️ 下载依赖需要联网。公司内网、教室机房记得提前备好。

## 18.4 构建：两种口味

### 日常开发：默认构建

```bash
cargo build
```

产物在 `target/debug/` 下。编译快、带调试信息，**适合写代码时反复跑**。`rzc run` 背后就是它。

### 发布上线：优化构建

```bash
cargo build --release
```

产物在 `target/release/` 下。编译器花时间做**优化**（跑得更快），编译本身慢一些。**给用户用的最终版本**一定用它。

💡 **比喻**：debug 版是**试做版**——做得快，方便随时改；release 版是**精装版**——慢工出细活，拿来上架。

> ✨ `target/` 目录可以随便删——都是构建产物，删了重新编译就回来。所以 `.gitignore` 里总写着它。

## 18.5 可执行文件还是库？

一个项目可以产出两种东西：

| 类型 | 入口文件 | 产出 |
|---|---|---|
| 可执行文件（bin） | `src/主函数.zh` | 能直接运行的程序 |
| 库（lib） | `src/lib.zh` | 给别人引用的代码 |

`rzc init` 默认造可执行文件。想造库，加参数（`rzc init 名字 --lib`）。很多项目两个都要：库给别人用，可执行文件当命令行工具。

## 18.6 常用命令速查

| 命令 | 作用 |
|---|---|
| `rzc init 名字` | 新建中文项目 |
| `rzc run src/主函数.zh` | 编译并运行 |
| `rzc check src/主函数.zh` | 只检查不运行（快） |
| `cargo build` | 构建（debug） |
| `cargo build --release` | 构建（优化版） |
| `cargo test` | 运行测试（第二十一章见） |
| `cargo add 库名` | 添加依赖 |

## 18.7 完整示例：从零到发布

把本章流程完整走一遍（以真实终端为准）：

```bash
# 1. 办营业执照
rzc init 问候器
cd 问候器

# 2. 写代码（src/主函数.zh）
```

`src/主函数.zh`：

```rust
函数 主函数() {
    打印行!("你好，世界！");
}
```

```bash
# 3. 开发期：反复运行调试
rzc run src/主函数.zh

# 4. 只检查，不运行（更快）
rzc check src/主函数.zh

# 5. 发布：编译优化版
cargo build --release

# 6. 运行成品
./target/release/问候器
```

## 18.8 逐行解释

- **步骤 1**：`rzc init` 生成 `Cargo.toml` 和 `src/主函数.zh`，语言包已内置；
- **步骤 3**：`rzc run` = 转译 + 编译 + 运行一条龙，写完就跑；
- **步骤 4**：`check` 跳过生成可执行文件，只做类型检查——改代码后先 check，省时间；
- **步骤 5**：`--release` 触发优化编译，产物进 `target/release/`；
- **步骤 6**：直接执行成品，不经过任何工具链。

## 18.9 运行结果

步骤 1 的输出：

```
✅ 项目 '问候器' 创建成功！
   语言包已内置，无需手动复制。如需自定义，可创建 lang-packs/zh/ 目录覆盖。
   使用 `rzc run src/主函数.zh` 运行。
```

步骤 3 的输出：

```
你好，世界！
```

## 18.10 常见错误与解决

### 错误一：依赖下载失败

```
错误：无法连接 crates.io
```

**解决**：检查网络；公司内网可配置镜像源（问管理员要地址写进 `~/.cargo/config.toml`）。

### 错误二：版本号写错

```
错误：找不到匹配 库名 = "99.0" 的版本
```

**解决**：去库的主页查最新版本号，或者干脆 `cargo add 库名` 让它自动选。

### 错误三：找不到可执行文件

`./target/release/主函数` 不存在？**解决**：可执行文件名 = `Cargo.toml` 里的 `name`（中文项目名可能已被净化成合法字符），去 `target/release/` 下 `ls` 看看真名。

### 错误四：改了 Cargo.toml 没生效

依赖改了但代码报"找不到库"。**解决**：重新构建一次，让 Cargo 重新解析依赖清单。

## 18.13 常见问题（FAQ）

**问：Cargo 和 rzc 是什么关系？**

答：rzc 是中文前门——把 `.zh` 转译成 Rust、把错误翻成中文；真正编译、下载依赖、管理构建的是背后的 Cargo 与 rustc。两者分工合作。

**问：`Cargo.lock` 是什么？**

答：依赖的"快照"——记录了这次构建用到的**每个库的确切版本**。团队共享它，保证所有人编译出的东西一模一样。

**问：依赖库也能是中文写的吗？**

答：依赖库本身用标准 Rust 写（`.rs`）。你的中文代码引用它们没问题——rzc 只转译你的 `.zh` 文件。

**问：为什么 `target/` 那么大？**

答：里面存着每次构建的中间产物和产物，多个构建口味各存一份。正常现象，几十上百兆都可能。定期 `cargo clean` 清空。

**问：发布给别人用，该发什么？**

答：可执行程序 → 发 `target/release/` 下的可执行文件（注意对方操作系统要对应）；代码库 → 发布到仓库（如 crates.io）或直接把源码给对方。

**问：`edition = "2024"` 能改旧吗？**

答：能，但没必要。新纪元规则更完善，本书所有代码都按它写。
