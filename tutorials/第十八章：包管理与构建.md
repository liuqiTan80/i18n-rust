# 第十七章：包管理与构建

前面的代码都是一个个小程序。但真正的项目需要用到别人写好的工具库，也需要把自己的代码组织好。

这一章学习如何**管理项目**和**使用第三方库**。

---

## 17.1 什么是包管理器

> **生活类比**：包管理器就像一个**购物平台**。你想做蛋糕，但家里没有烤箱——你不用自己造一个，直接"下单买"就行。包管理器帮你"下载"别人写好的工具库，安装到你的项目里。

```
做蛋糕需要烤箱 ──→ 不用自己造 ──→ 在购物平台下单 ──→ 快递送到家
写程序需要随机数 ──→ 不用自己写 ──→ 在包管理器添加 ──→ 自动下载到项目
```

Rust 的包管理器叫 **Cargo**。它同时负责：

- 下载第三方库（购物）
- 编译你的代码（组装）
- 运行你的程序（启动）

**什么是"第三方库"？** 就是别人写好的、可以拿来直接用的代码包。比如你想生成随机数——随机数算法挺麻烦的，但早就有人写好了，你下载下来直接用就行。在 Rust 里，这些代码包叫 **crate**（读音"克瑞特"），全世界共享的 crate 仓库叫 **crates.io**。

## 17.2 项目配置文件 `Cargo.toml`

> **生活类比**：`Cargo.toml` 就像一份**快递单**——告诉快递公司（编译器）你是谁、你要寄什么、需要哪些配件。

每个 Rust 项目都有一个 `Cargo.toml` 文件。你不需要手写它——用 `rzc init 项目名` 创建项目时，它会自动帮你生成。生成出来长这样：

```toml
[package]
name = "我的项目"
version = "0.1.0"
edition = "2024"

[dependencies]
```

逐行解释：

- 第 1 行：**`[package]`** 是"项目的基本信息"部分
- 第 2 行：项目的名字
- 第 3 行：版本号——`0.1.0` 表示"还在早期开发"
- 第 4 行：**`edition`** 是用哪套语法规则（"2024" 是最新的一套）
- 第 6 行：**`[dependencies]`** 是"我需要哪些第三方库"部分，现在还是空的

> ⚠️ **注意**：`Cargo.toml` 的内容是**固定的英文格式**（`[package]`、`name`、`version` 这些），不能用中文替换。这是 Cargo 自己认的格式，就像快递单上的栏目名是印好的。**中文 Rust 只翻译代码，不翻译配置文件**——不过别担心，这些配置基本不用手写，`rzc init` 都帮你生成好了。

```
Cargo.toml 就像快递单：

┌── Cargo.toml ──────────────────────┐
│  [package]                         │
│  name = "我的项目"     ← 你是谁     │
│  version = "0.1.0"     ← 版本号     │
│  edition = "2024"      ← 语法规则   │
│                                    │
│  [dependencies]                    │
│  rand = "0.8"          ← 需要哪些库 │
└────────────────────────────────────┘
```

## 17.3 添加第三方库

> **生活类比**：添加第三方库就像在购物平台**下单**——告诉包管理器"我要这个东西"，它就会自动下载并安装。

### 方法一：用命令添加（推荐）

在项目目录的终端输入：

```bash
cargo add rand
```

`rand` 就是"随机数"这个库在仓库里的**英文名字**。包管理器会自动：
1. 去仓库（crates.io）找到这个库
2. 在 `Cargo.toml` 的 `[dependencies]` 里记上一笔
3. 下次编译时自动下载

### 方法二：直接编辑配置文件

打开 `Cargo.toml`，在 `[dependencies]` 下面手动添加一行：

```toml
[dependencies]
rand = "0.8"
```

两种方法效果一样。

> ⚠️ **为什么写 `rand` 不写"随机数"？** 因为 crate 仓库（购物平台）里的商品名字是英文的——所有 crate 都用英文名注册。中文名是 zrRust 的"翻译"，只用在**代码里**：配置文件里写英文名 `rand`，代码里写中文"随机数"，rzc 会自动对应起来。

### 使用第三方库

添加好依赖后，就可以在代码中使用了：

```rust
使用 随机数::随机特征;       // 引入"随机"能力
使用 随机数::随机数生成器;   // 引入"生成器"函数

函数 主函数() {
    让 可变 生成器 = 随机数生成器();
    让 随机数 = 生成器.随机范围(1..=100);
    打印行!("随机数：{}", 随机数);
}
```

逐行解释：

- 第 1 行：**`使用 随机数::随机特征;`** ——`随机数` 是 `rand` 库的中文名，`随机特征` 是它里面的 `Rng`（一个"能力清单"）。这一行的意思是"把随机数的能力借过来用"
- 第 2 行：**`随机数生成器`** 是 `thread_rng` 的中文名——一个专门生成随机数的"机器"
- 第 5 行：**`让 可变 生成器 = 随机数生成器();`** 开动这台机器，拿到生成器
- 第 6 行：**`生成器.随机范围(1..=100)`** 让机器生成 1 到 100 之间的随机整数（`..=` 是"闭区间"，包含两边，第四章讲过）
- 第 7 行：打印出来

```
执行流程：

随机数生成器() ──→ 一台"随机机器"
    ↓
机器.随机范围(1..=100) ──→ 摇一摇，出 1~100 之间的数
    ↓
随机数：73
```

> ✨ **小提示**：`随机特征`（`Rng`）为什么要单独 `使用`？因为 `随机范围` 这个方法写在"能力清单"（特征）里，你要先借到这份清单，才能使用清单上的方法。这就像你要用会员权益，得先出示会员卡——第十六章学的 `使用` 在这里派上用场了。

## 17.4 常用命令

| 命令 | 作用 | 生活类比 |
|------|------|---------|
| `cargo add 库名` | 添加依赖 | 下单买东西 |
| `cargo build` | 编译项目 | 把材料组装好 |
| `cargo run` | 编译并运行 | 组装好并启动 |
| `cargo check` | 只检查不编译 | 检查图纸有没有错 |
| `cargo test` | 运行测试 | 质量检验 |
| `cargo clean` | 清除编译产物 | 清空工作台 |
| `cargo update` | 更新依赖 | 更换新配件 |

```
cargo check  vs  cargo build
┌──────────────┐    ┌──────────────┐
│ check        │    │ build        │
│ 检查语法     │    │ 检查语法     │
│ 检查类型     │    │ 检查类型     │
│ ✅ 到此为止  │    │ 生成程序     │
│              │    │ ✅ 可以运行  │
└──────────────┘    └──────────────┘
  更快（不生成）       较慢（生成文件）
```

**为什么要区分 `check` 和 `build`？** 因为 `check` 只检查代码有没有错，不生成最终程序。它比 `build` 快很多。写代码时经常用 `check` 来快速检查，确认没问题了再用 `build`。

## 17.5 中文 Rust 的构建流程

中文 Rust 在 Cargo 的基础上增加了一个**翻译步骤**：

```
你写的中文代码 (.zh 文件)
    ↓
翻译器把中文关键字翻译成英文
    ↓
标准 Rust 代码 (.rs 文件)
    ↓
编译器编译成程序
    ↓
可以运行的程序
```

```
┌── 构建流程 ──────────────────────────┐
│                                      │
│  中文源码 (.zh)                       │
│      ↓                               │
│  ┌─────────────┐                     │
│  │ 翻译器       │  中文关键字 → 英文  │
│  └─────────────┘                     │
│      ↓                               │
│  标准代码 (.rs)                       │
│      ↓                               │
│  ┌─────────────┐                     │
│  │ 编译器       │  编译为程序         │
│  └─────────────┘                     │
│      ↓                               │
│  可执行文件                           │
│                                      │
└──────────────────────────────────────┘
```

### 中文 Rust 命令

| 命令 | 作用 |
|------|------|
| `rzc init 项目名` | 创建新项目（自动生成 Cargo.toml 和主文件） |
| `rzc run 文件.zh` | 翻译并运行（最常用） |
| `rzc check 文件.zh` | 翻译并检查错误 |
| `rzc eject 文件.zh` | 导出为标准 Rust 代码（生成 .rs 文件） |

> ✨ **小提示**：`rzc run` 会自动完成"翻译 → 编译 → 运行"三步。平时的学习阶段，你只需要记住 `rzc run 文件.zh` 一个命令就够了。

## 17.6 项目结构

用 `rzc init 我的项目` 创建出来的项目长这样：

```
我的项目/
├── Cargo.toml          ← 项目配置（快递单）
├── rust-toolchain.toml ← 编译器版本（不用管它）
├── README.md           ← 项目说明（可以自己写介绍）
└── src/
    └── main.zh         ← 你的中文代码（主文件）
```

**`rust-toolchain.toml` 是什么？** 它指定了用哪个版本的编译器。rzc 已经帮你写好了，平时不用管它。

**为什么没有语言包文件夹？** 翻译规则（哪个中文关键字对应哪个英文关键字）已经**内置在 rzc 程序里**了，不需要项目里再放一份。

> ✨ **小提示**：如果你需要自定义翻译规则（比如公司内部专用词），可以在项目里创建 `lang-packs/zh/` 目录放自己的 `关键字.toml`，rzc 会优先使用你的版本。

## 常见错误

### 忘记初始化项目

```bash
cargo build
# ❌ 找不到 Cargo.toml
# 修复：先 cd 到项目目录（rzc init 创建的那个），再运行命令
```

> ✨ **小提示**：所有 `cargo` 命令（`cargo run`、`cargo add` 等）都必须在项目目录里运行——因为 Cargo 要靠 `Cargo.toml` 找到你的项目。就像你下单买东西，得先站在快递点（项目目录）里。

### 在 `Cargo.toml` 里写了中文库名

```toml
# ❌ 错误：仓库里没有叫"随机数"的库
[dependencies]
随机数 = "0.8"

# ✅ 正确：写英文名
[dependencies]
rand = "0.8"
```

### 代码里忘了加 `使用` 就把库当自己家

```rust
// ❌ 没有"使用 随机数::..." 就直接用
函数 主函数() {
    让 生成器 = 随机数生成器();  // 编译器不认识这个名字
}
```

```rust
// ✅ 先用"使用"引入
使用 随机数::随机数生成器;

函数 主函数() {
    让 生成器 = 随机数生成器();
}
```
