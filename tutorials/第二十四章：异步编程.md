## 24.1 一个厨师照看多口锅

第二十章的多线程像**多招几个厨师**——每人一口锅，各干各的。

异步是另一条路：

💡 **比喻**：只有**一个厨师**，但照看三口锅。饭在焖着（等水开）的时候，厨师不傻站着——转身去洗菜。等饭锅"叮"一声，再回来盛饭。**一个线程，多任务交错推进。**

📖 **异步（async）**：任务遇到等待（网络响应、磁盘读写、定时器）时**让位**，把线程让给别的任务；等待结束再回来继续。

| | 多线程 | 异步 |
|---|---|---|
| 思路 | 多招人 | 一人多任务 |
| 开销 | 每个线程一份栈内存 | 任务很小，轻松上万 |
| 擅长 | 计算密集 | 大量等待（网络、IO） |

## 24.2 异步函数：贴个"会让位"的标签

```rust
异步 函数 洗菜() {
    打印行!("菜洗好了");
}
```

`异步`（= async）放在 `函数` 前面，声明这个函数**可能中途让位**。

⚠️ **关键认知**：调用异步函数**不会立刻干活**！

```rust
洗菜();   // 什么都没发生？！
```

它只返回一张**取餐号**。真正开工要靠下一节的 `.等待`。

## 24.3 期物：取餐号

📖 **期物（Future）**：异步调用的返回值——"承诺将来完成的任务凭证"。拿着号等叫号（`.等待`），没叫到就不算完。

## 24.4 `.等待`：叫号取餐

```rust
异步 函数 开饭() {
    洗菜().等待;
    煮饭().等待;
    打印行!("开饭！");
}
```

`任务.等待`（= .await）的含义：

- 任务完成 → 拿走结果，继续下一行；
- 任务还在等 → **让位**，调度员先去推进别的任务，好了再回来。

⚠️ `.等待` 只能出现在**异步函数（或异步块）内部**——等号两边得是同一类世界。

## 24.5 运行时：调度员

期物不会自己跑——需要一个**运行时**不停地推进它们。

💡 **比喻**：餐厅得有**调度员**盯着叫号屏：谁的号到了就喊谁，谁在等就跳过。

标准库不带运行时，要用库。最简单的入门款（加依赖：`cargo add futures`）：

```rust
函数 主函数() {
    futures::executor::block_on(开饭());
}
```

`block_on` = "把这件事跑完再继续"——主线程堵住等异步任务完成。真实大项目用更强大的运行时（如 tokio），套路相同。

## 24.6 完整示例：做饭流水线

两个异步任务、一个汇合点、一个调度员：

```rust
使用 标准库::线程::线程休眠;
使用 标准库::时间::持续时间;

// 异步函数：声明"我可以中途让位"
异步 函数 洗菜() {
    线程休眠(持续时间::从毫秒(50));
    打印行!("菜洗好了");
}

异步 函数 煮饭() {
    线程休眠(持续时间::从毫秒(80));
    打印行!("饭煮好了");
}

// 汇合点：两件事都完成后才能开饭
异步 函数 开饭() {
    洗菜().等待;
    煮饭().等待;
    打印行!("开饭！");
}

函数 主函数() {
    // 运行时（调度员）驱动异步任务跑完
    futures::executor::block_on(开饭());
    打印行!("全部完成");
}
```

## 24.7 逐行解释

- **第 5–8、10–13 行**：两个异步任务。`线程休眠` 模拟"需要等待的时间"（真正的异步会用异步定时器，见常见错误第三条）。
- **第 16–20 行**：`开饭` 也是异步函数——它把两个任务**按顺序**串起来：先洗菜后煮饭，都完成才喊开饭。
- **第 17、18 行**：`.等待` 让每一步"跑完再走"。不写 `.等待`，调用就只是攥着取餐号不干活。
- **第 23–25 行**：`block_on` 当调度员，把 `开饭()` 从第一个期物推进到终点。

## 24.8 运行结果

```
菜洗好了
饭煮好了
开饭！
全部完成
```

顺序铁定——因为两处 `.等待` 把任务串成了先后关系。想让洗菜煮饭**并行交错**，需要"并发驱动"（如 `join!` 宏），那是进阶玩法。

## 24.9 常见错误与解决

### 错误一：忘了 `.等待`

```
警告：未使用的期物——异步调用不等待就不会执行
```

编译器盯着呢。**解决**：调用处补 `.等待`，或者故意丢弃时加 `让 _ = ...`。

### 错误二：在普通函数里写 `.等待`

```
错误：只能在异步上下文中使用 `等待`
```

**解决**：把函数声明成 `异步 函数`，一路向上传播到 `block_on` 为止。

### 错误三：异步函数里睡大觉

本章用 `线程休眠` 只是**模拟**。真项目里它会霸住整个调度员——别的任务全卡住。**解决**：用运行时提供的异步版休眠（如 tokio 的异步睡）。

### 错误四：忘记加运行时依赖

`futures::executor::block_on` 找不到。**解决**：`cargo add futures`（本项目已验证可用）。

## 24.10 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 异步 | 任务遇等待就让位的编程方式 |
| 异步函数 | `异步 函数` 声明、可能让位的函数 |
| 期物 | 异步调用的取餐号（Future） |
| 等待 | `.等待`，推进期物直到完成 |
| 让位 | 把线程暂时让给别的任务 |
| 运行时 | 推进所有期物的调度员 |

## 24.12 常见问题（FAQ）

**问：异步比多线程快吗？**

答：不是"快"，是"省"。同样等一万次网络响应，异步用一条线程就能扛，多线程得开一堆线程。计算密集活儿多线程更合适；等待密集活儿异步更合适。

**问：为什么不把运行时做进标准库？**

答：众口难调——有的场景要极致性能，有的要简单。Rust 让你自己选调度员，代价是入门要装一个库。

**问：`.等待` 会让当前线程睡着吗？**

答：不会。让位是把任务挂起，线程立刻去干别的期物——这正是异步的精髓。只有 `block_on` 这种入口会堵住它所在的线程。

**问：异步和多线程能一起用吗？**

答：能，而且常见：运行时内部就是用线程池推进期物。你写异步代码，调度员底下几条线程由运行时管。

**问：初学要不要深入异步？**

答：本章的"心智模型"够用很久：异步函数 + `.等待` + 运行时。真到写网络服务（大概率用 tokio 框架），再按它的文档进阶。

**问：期物可以传来传去吗？**

答：可以——期物也是值，能存变量、能当参数传、能从函数返回（返回类型要标成期物）。但记住：**不 `.等待` 就不干活**。
