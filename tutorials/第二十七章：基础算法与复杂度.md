## 27.1 函数自己调用自己

以前的函数都是"往下叫"：A 叫 B。递归是**函数叫自己**——把大问题削成一个小一号的同款问题，直到小到能直接回答。

经典例子：阶乘。`5! = 5 × 4 × 3 × 2 × 1`，也可以写成 `5! = 5 × 4!`——这就是递归的句式：

```rust
使用 标准库::集合::哈希映射;

函数 阶乘(n: 整数) -> 整数 {
    如果 n <= 1 {
        返回 1;              // 递归基：小到不能再小，直接答
    }
    n * 阶乘(n - 1)          // 递归步：叫自己，把问题削小一号
}

函数 主函数() {
    让 结果 = 阶乘(5);
    打印行!("阶乘(5) = {}", 结果);
}
// 预期输出: 阶乘(5) = 120
```

跑一遍 `阶乘(5)`，调用像套娃一层层打开、又一层层合上：

```
阶乘(5) = 5 × 阶乘(4)
        = 5 × 4 × 阶乘(3)
        = 5 × 4 × 3 × 阶乘(2)
        = 5 × 4 × 3 × 2 × 阶乘(1)
        = 5 × 4 × 3 × 2 × 1        ← 碰到递归基，返回 1
        = 120                       ← 逐层合上，答案传回来
```

📖 **递归**：函数在自己体内调用自己的写法。每个递归函数都需要两样东西：

- **递归基**：最小的情形，直接给答案、不再叫自己（上面的 `n <= 1`）；
- **递归步**：把问题削小一号，再交给"更小号的自己"。

�� **比喻**：查字典遇到生词，解释里又有生词，你又去查——总得有一本解释全用你认识的词，那就是递归基。没有递归基，套娃永远掀不到底：

```text
错误：线程 'main' 具有栈溢出（stack overflow）
```

**每层调用都要占一份栈**。忘写递归基、或者问题没在变小，就会无限往下撑爆栈。

## 27.2 递归的代价与补救：备忘录

斐波那契数列是递归的宣传画：`F(0)=0，F(1)=1，F(n)=F(n-1)+F(n-2)`，数列 0, 1, 1, 2, 3, 5, 8, 13……

```rust
函数 斐波那契(n: 整数) -> 整数 {
    匹配 n {
        0 => 0,
        1 => 1,
        _ => 斐波那契(n - 1) + 斐波那契(n - 2),
    }
}

函数 主函数() {
    让 第十项 = 斐波那契(10);
    打印行!("斐波那契(10) = {}", 第十项);
}
// 预期输出: 斐波那契(10) = 55
```

能跑，但藏着大浪费：算 `斐波那契(40)` 时，`斐波那契(35)` 会被**重算几十万次**——调用不是一条链，是一棵展开的树，同一个节点在枝丫里反复出现。

补救办法朴素得像个好习惯：**算过的答案记下来，下次先翻记录**。记录本就用第十五章的 `哈希映射`：

```rust
使用 标准库::集合::哈希映射;

函数 斐波那契带记(n: 整数, 备忘录: &mut 哈希映射<整数, 整数>) -> 整数 {
    如果 n <= 1 {
        返回 n;
    }
    如果让 有值(已存) = 备忘录.获取(&n) {
        返回 *已存;              // 翻记录本：算过就直接抄答案
    }
    让 值 = 斐波那契带记(n - 1, 备忘录) + 斐波那契带记(n - 2, 备忘录);
    备忘录.插入(n, 值);
    值
}

函数 主函数() {
    让 mut 备忘录 = 哈希映射::新建();
    让 第四十项 = 斐波那契带记(40, &mut 备忘录);
    打印行!("斐波那契(40) = {}", 第四十项);
}
// 预期输出: 斐波那契(40) = 102334155
```

📖 **记忆化**：把昂贵计算的结果存进缓存，重复请求直接查表。每个 `n` 只算一次，调用次数从**指数**掉到**线性**——同样的递归，快了几百万倍。

💡 这个思想到处有替身：浏览器**缓存**、编译项目的 `target/` 目录（第十八章）、游戏**存档**。"空间换时间"是程序员的通用武器。

## 27.3 排序第一站：气泡排序

把一堆数排好序是算法世界的 "hello world"。最直白的做法是**气泡排序**：从头到尾扫描，见到相邻一对**左边比右边大**就交换——一轮走完，最大的稳稳沉到最后：

```rust
函数 气泡(数们: &mut 向量<整数>) {
    让 mut 已排 = 假;
    当 !已排 {
        已排 = 真;
        让 mut i: 无符号机器整数 = 0;
        当 i + 1 < 数们.长度() {
            如果 数们[i] > 数们[i + 1] {
                数们.交换(i, i + 1);
                已排 = 假;
            }
            i += 1;
        }
    }
}

函数 主函数() {
    让 mut 成绩 = 向量::从([85, 92, 78, 90]);
    气泡(&mut 成绩);
    打印行!("排序后 = {:?}", 成绩);
}
// 预期输出: 排序后 = [78, 85, 90, 92]
```

两个细节：

- 下标 `i` 标成 `无符号机器整数`——**切片下标只认它**（`长度()` 返回的也是它）；
- `已排` 开关让数据本来有序时一轮就收工（"最好情况 O(n)"的由来）。

标准库早备好了工业级版本——第二十二章流水线里用过的 `排序()`：

```rust
函数 主函数() {
    让 mut 名单 = 向量::从(["小亮", "阿伟", "小林"]);
    名单.排序();
    打印行!("按字节序 = {:?}", 名单);
}
// 预期输出: 按字节序 = ["小亮", "小林", "阿伟"]
```

💡 中文字符串排出来是 ["小亮", "小林", "阿伟"]，不是按拼音——标准库对文本按**字节序**（Unicode 编码顺序）比较，跟拼音无关。要按别的规矩排，就得自定义比较闭包（第二十二章的 `映射` 同族方法）。

`排序()` 是高度优化的混合排序，平均 O(n log n)。**工程铁律：生产代码用 `排序()`，手写气泡只为理解原理。**

## 27.4 查找第一站：二分查找

在 10 万人的名单里找一个名字，笨办法是从头翻到尾、平均翻一半——**线性查找**。但如果名单**已经排好序**，你可以像查字典：翻到中间，看目标在前半本还是后半本，扔掉另一半——**二分查找**。

```rust
函数 二分(数们: &向量<整数>, 目标: 整数) -> 无符号机器整数 {
    让 mut 左: 无符号机器整数 = 0;
    让 mut 右: 无符号机器整数 = 数们.长度();
    当 左 < 右 {
        让 中 = 左 + (右 - 左) / 2;
        如果 数们[中] == 目标 {
            返回 中;
        } 否则 如果 数们[中] < 目标 {
            左 = 中 + 1;              // 目标在右半边
        } 否则 {
            右 = 中;                  // 目标在左半边
        }
    }
    数们.长度()                        // 没找到：这个长度就是"不存在"的暗号
}

函数 主函数() {
    让 号码 = 向量::从([1, 3, 5, 7, 9]);
    让 位置 = 二分(&号码, 7);
    打印行!("{} 在第 {} 位", 7, 位置);
}
// 预期输出: 7 在第 3 位
```

📖 **二分查找**：每步比较都扔掉一半候选，规模按 `n → n/2 → n/4 → …` 缩小，缩到 1 需要 **log₂n** 步。

标准库也有现成的快捷方法（注意：**先排序，再二分**）：

```rust
函数 主函数() {
    让 mut 待查 = 向量::从([1, 3, 5, 7, 9]);
    待查.排序();
    让 查找结果 = 待查.二分查找(&5);
    打印行!("查找 5 = {:?}", 查找结果);
}
// 预期输出: 查找 5 = Ok(2)
```

返回的 `结果`（第十六章老朋友）里：`Ok(下标)` 表示找到；`Err(插入点)` 表示没找到，并告诉你"想插进来放这儿"。

�� **二分的门槛只有一条：数据必须有序。** 在未排序的数据上二分，结果不可预期——这不是性能问题，是**正确性前提**。

## 27.5 快慢不是感觉，是数步数

写代码之前怎么判断快慢？看规模上去后**步数怎么涨**：

```rust
函数 折半步数(规模: 整数) -> 整数 {
    让 mut 剩余 = 规模;
    让 mut 步 = 0;
    当 剩余 > 1 {
        剩余 = 剩余 / 2;
        步 += 1;
    }
    步
}

函数 主函数() {
    让 数列 = 向量::从([1, 2, 3, 4, 5]);

    让 一遍步数 = 数列.迭代().计数();
    打印行!("扫一遍 = {} 步", 一遍步数);

    让 个数 = 数列.长度() 作为 整数;
    让 mut 嵌套步数: 整数 = 0;
    让 mut a: 整数 = 0;
    当 a < 个数 {
        让 mut b: 整数 = 0;
        当 b < 个数 {
            嵌套步数 += 1;
            b += 1;
        }
        a += 1;
    }
    打印行!("两层嵌套 = {} 步", 嵌套步数);

    打印行!("折半到剩 1 = {} 步", 折半步数(5));
}
// 预期输出: 扫一遍 = 5 步
// 两层嵌套 = 25 步
// 折半到剩 1 = 2 步
```

- 对每个元素干一次活：**n 步**；
- 嵌套两层循环：**n × n 步**（5 个数干 25 次）；
- 每步扔掉一半：**log₂n 步**（5 个数只要折 2 次就剩 1）。

数据翻倍时，三种涨法的代价完全不同：

| 结构 | n = 1,000 | n = 1,000,000 | 步数涨法 |
|---|---|---|---|
| 一层循环 / 线性查找 | 约 1 千步 | 约 1 百万步 | 跟着 n 涨 |
| 两层嵌套 / 气泡排序 | 约 1 百万步 | **约 1 万亿步** | 跟着 n² 涨 |
| 二分 / 折半 | 10 步 | **20 步** | 跟着 log₂n 涨 |

n = 100 万时，"万亿步"和"20 步"的差距，就是**等不等得到**的差距。

## 27.6 大 O：只跟最大的涨法

上表的"涨法"，行业里用统一记号写：**大 O 记号**。

📖 **大 O 记号**：`O(步数随 n 的涨法)`。规则只有两条——**忽略常数系数、忽略低阶项**：

- 扫两遍数据（2n 步）→ `O(n)`；
- 气泡排序内层走 n + (n-1) + … + 1 ≈ n²/2 步 → `O(n²)`；
- 归并排序"拆一半、排一半、合起来"：每层合并总共 n 步，共 log₂n 层 → `O(n log n)`。

常见档位从快到慢排座次（n = 100 万时的量级感受）：

| 复杂度 | 名字 | n = 100 万时大约要 | 典型场景 |
|---|---|---|---|
| O(1) | 常数 | 1 步 | 向量按下标取元素 |
| O(log n) | 对数 | 20 步 | 二分查找、有序映射 `获取` |
| O(n) | 线性 | 100 万步 | 一遍扫描、求和、`过滤` |
| O(n log n) | 线性对数 | 约 2 千万步 | 标准库 `排序()`、归并排序 |
| O(n²) | 平方 | 1 万亿步 | 气泡排序、两层嵌套 |
| O(2ⁿ) | 指数 | 宇宙热寂也跑不完 | 不加记忆化的斐波那契递归 |

💡 为什么敢忽略常数和低阶？因为大 O 比较的是**规模变大时的涨法**：n 翻十倍，O(n) 的代价跟着翻十倍，O(n²) 翻一百倍——常数系数改变不了这个本质差距。

**数复杂度的口诀**：看循环嵌套和它们各自的长度。一条折叠流水线是 O(n)；折叠里再套一个"对每个元素做一次线性查找"，就悄悄变成 O(n²)——这是性能问题最常见的藏身方式。

## 27.7 工程纪律：先测，再优化

复杂度分析不是背表，是**决策工具**。标准姿势三步：

1. **先写对**：用最直白的写法，该用 `排序()`、`二分查找()` 就用现成的；
2. **再量**：真慢吗？把规模翻倍看时间——跟着翻倍是 O(n) 的健康态，变四倍是 O(n²) 的警报；
3. **后优化**：只动量表上最贵的那处。多数性能问题出在 O(n²) 混进了本该 O(n) 的地方（往往是"循环里套查找"）。

💡 没有测量就重构，多半白忙——"先测再优化"是工程纪律，也是这一章想塞进你兜里的最重要一件工具。

## 27.8 完整示例：成绩单工作台

递归、记忆化、排序、二分，全用上——给一份班级成绩单做四件日常事：

```rust
使用 标准库::集合::哈希映射;

函数 斐波那契带记(n: 整数, 备忘录: &mut 哈希映射<整数, 整数>) -> 整数 {
    如果 n <= 1 {
        返回 n;
    }
    如果让 有值(已存) = 备忘录.获取(&n) {
        返回 *已存;
    }
    让 值 = 斐波那契带记(n - 1, 备忘录) + 斐波那契带记(n - 2, 备忘录);
    备忘录.插入(n, 值);
    值
}

函数 主函数() {
    让 mut 分数 = 向量::从([88, 92, 75, 92, 88, 60]);

    // 1) 排序：生产写法直接调标准库
    分数.排序();
    打印行!("排序后：{:?}", 分数);

    // 2) 二分：先有序，后查找
    让 有92 = 分数.二分查找(&92).是否为成功();
    打印行!("查有 92 分？{}", 有92);

    // 3) 计数用折叠：累加器走一遍流水线
    让 人数 = 分数.迭代().折叠(0, |总, _| 总 + 1);
    打印行!("人数 = {}", 人数);

    // 4) 递归 + 记忆化：算第 15 个斐波那契数
    让 mut 成绩备忘录 = 哈希映射::新建();
    打印行!("斐波那契(15) = {}", 斐波那契带记(15, &mut 成绩备忘录));
}
```

（这里只把带记忆的 `斐波那契` 内联进来让示例能独立跑；`阶乘`、`二分` 仍是前文那两个函数。）

## 27.9 逐行解释

- **`分数.排序()`**：标准库混合排序，O(n log n)；排完变 `[60, 75, 88, 88, 92, 92]`。
- **`二分查找(&92).是否为成功()`**：二分返回 `结果`，`是否为成功()` 把"找没找到"折成布尔。
- **`折叠(0, |总, _| 总 + 1)`**：第二十二章的终点站——累加器从 0 起，每来一个元素加 1；`_` 表示元素本身不看。
- **`斐波那契带记(15, &mut 成绩备忘录)`**：备忘录让每个 `n` 只算一次，递归树塌成一条链。

## 27.10 运行结果

```
排序后：[60, 75, 88, 88, 92, 92]
查有 92 分？true
人数 = 6
斐波那契(15) = 610
```

## 27.11 常见错误与解决

### 错误一：忘了递归基，或问题没在变小

```text
错误：线程 'main' 具有栈溢出（stack overflow）
```

**解决**：检查两件事——有没有"小到直接回答"的分支；每次叫自己时参数是否**严格变小**。

### 错误二：气泡排序里忘了 `可变`

```text
错误：无法借用为可变（cannot borrow as mutable）
```

**解决**：交换元素就是改数据，参数写 `&mut 向量<整数>`，调用处传 `&mut 成绩`（第七章的可变借用）。

### 错误三：在未排序的数据上二分

**症状**：明明有，却说找不到。二分**只对有序数据成立**——先 `排序()` 再 `二分查找()`。这条没有编译报错，靠你自己守住前提。

### 错误四：下标类型不匹配

```text
错误：期望 `usize`，实际得到 `i32`
```

**解决**：切片下标必须是 `无符号机器整数`。循环变量标成它，或用 `作为` 转一下。

### 错误五：`收集` 不标类型

第二十二章讲过：`收集()` 前给变量写 `: 向量<整数>` 一类的标注，编译器才知道往哪种容器装。

## 27.12 本章术语表

| 术语 | 一句白话 |
|---|---|
| 递归 | 函数自己调用自己，把大问题削成小一号的同款问题 |
| 递归基 | 最小情形、直接给答案、不再叫自己的分支——没有它栈会爆 |
| 记忆化 | 算过的结果存进缓存，重复请求直接查表（空间换时间） |
| 气泡排序 | 相邻两位乱就交换，一轮一轮把大的沉到底——教学用 |
| 二分查找 | 每步比较扔掉一半候选，log₂n 步收尾——前提是有序 |
| 原地算法 | 几乎不额外占空间，在数据本身上干活（气泡是，归并多半不是） |
| 稳定排序 | 相等元素保持原来的先后顺序（标准库 `排序()` 是稳定的） |
| 时间复杂度 | 步数随数据规模 n 的涨法 |
| 大 O 记号 | 只记最大涨法的通用速记：忽略常数和低阶 |

## 27.13 练习

**练习一（★）** 用递归写 `求和`：空向量返回 0（递归基），否则"第一个 + 剩下所有的和"（递归步）。用 `[1, 2, 3, 4]` 测，答案 10。

**练习二（★★）** 统计词频：一堆词放进 `哈希映射`，数出每个词出现几次，再找出最多的那个。提示：`或插入(0)` 然后加一。做完想想"先排序再数"和"一遍折叠"两种路子，各自的复杂度是多少。

**练习三（★★★）** 归并排序手写版："拆一半 → 递归排左右 → 合并两条有序带"。合并像拉拉链：每次从两条带的头部挑小的放进新向量。写完问自己：合并一层总共搬多少元素？有几层？——这就是 O(n log n) 名字的由来。

## 27.14 常见问题

**问：递归和循环，到底选哪个？**

答：能一眼看穿"把问题削小"就用递归（树、嵌套结构、分治天然如此）；只是"重复干活"就用循环。深度可能上千的场合别用递归——栈会爆；拿不准时，循环更稳。

**问：标准库 `排序()` 为什么比手写快那么多？**

答：它是多年调优的混合排序，常数极小、还避开最坏情况。手写排序的价值是**理解**，生产一律用现成——算法知识的一半用处，就是知道什么已经有人做到最好。

**问：大 O 一样，实际就一样快吗？**

答：不一定。大 O 忽略的常数恰恰是小数据时的主角。大 O 回答的是"**规模变大后会不会出事**"，这正是它的设计目的。

**问：在 10 万条数据里找一个名字，线性查找和二分差多少？**

答：约 5 万步 vs 17 步（log₂100000 ≈ 17）。前提是数据有序——只查一次，排序本身比查找还贵；**排好一次、反复去查**，二分才把本赚回来。

**问：为什么忽略"2n"里的 2？**

答：n 翻十倍时 2n 和 n 都翻十倍，涨法一样；而 n² 翻一百倍。大 O 比较涨法，不比单价。
