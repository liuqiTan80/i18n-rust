# 第十八章：智能指针

前面的章节里，数据要么放在变量里（栈上），要么用向量、字符串动态增长（堆上）。但你不知道的是——Rust 在背后帮你管理内存。

这一章要揭开谜底：数据到底存在哪里？怎么控制它存在哪里？

---

## 18.1 栈和堆——两种仓库

> **生活类比**：栈就像你**书桌上的便签纸**——拿取很快，但空间有限。堆就像**仓库**——空间很大，但存取要花时间找位置。

```
┌── 栈（便签纸）──────────┐
│  速度快，空间小          │
│  存放：整数、浮点数、布尔 │
│  大小固定的东西           │
└─────────────────────────┘

┌── 堆（仓库）──────────────┐
│  速度慢，空间大            │
│  存放：不确定大小的东西    │
│  比如：用户输入的文字      │
│  比如：不确定有多少项的列表│
└───────────────────────────┘
```

**为什么要分两种？** 因为有些东西编译时就知道大小（比如整数永远是 4 字节），放栈上最快。但有些东西编译时不知道大小（比如用户会输入多少字），只能放堆上。

**常见的数据都放在哪？**

| 数据 | 放哪 | 为什么 |
|------|------|--------|
| 整数、浮点数、布尔、字符 | 栈 | 大小固定，放便签纸最快 |
| `字符串`（`String`） | 栈 + 堆 | 文字本身在堆上，栈上存"地址+长度" |
| `向量`（`Vec`） | 栈 + 堆 | 列表数据在堆上，栈上存"地址+长度+容量" |
| `盒子`（`Box`） | 栈 + 堆 | 盒子（取货单）在栈上，内容在堆上 |

> ✨ **小提示**：你不需要刻意记这些——编译器会自动安排。你只需要知道：**栈是默认的、快的；堆是大的、用来放不确定大小的东西**。`字符串` 和 `向量` 其实已经在偷偷用堆了（所以它们能随意增长），这一章是把这个机制摊开给你看。

## 18.2 盒子——把东西放到堆上

> **生活类比**：**`盒子`** 就像一张**仓库取货单**。你把东西存在仓库里，手里拿着取货单。需要用的时候，凭取货单去仓库取。

```rust
函数 主函数() {
    // 普通变量——放在栈上
    让 栈上数字 = 5;

    // 用盒子——放在堆上
    让 堆上数字 = 盒子::新建(5);

    打印行!("栈上：{}", 栈上数字);
    打印行!("堆上：{}", 堆上数字);  // 自动从仓库取出来
}
```

逐行解释：

- 第 3 行：普通变量，存在栈上——便签纸上写着 5
- 第 6 行：**`盒子::新建(5)`** 把 5 存到堆上（仓库），手里拿着取货单
- 第 9 行：直接打印堆上的值——Rust 自动帮你用取货单去仓库取

```
盒子的工作原理：

栈上（便签纸）：
  堆上数字 → 指向堆上的地址

堆上（仓库）：
  [地址xxx] = 5

打印时：堆上数字 → 找到地址 → 取出 5
```

**为什么要用盒子？** 主要场景是：
- 数据太大，不想放在栈上
- 编译时不知道数据大小
- 想让数据在多个地方共享

## 18.3 递归类型——盒子的重要用途

有一种东西必须用盒子——**递归类型**（自己包含自己的类型）：

**为什么必须要盒子？** 因为编译器在编译时必须知道每个类型**占用多少内存**。如果 `列表` 直接包含自己：

```
❌ 节点(整数, 列表)：

节点 → [整数][列表]
              ↓
         [整数][列表]
                    ↓
               [整数][列表]  ← 永远没完没了！
                      ∞ 无限循环，编译器没法算大小

✅ 节点(整数, 盒子<列表>)：

节点 → [整数][取货单]        ← 取货单只有一张名片那么大（一个地址）
              ↓ 指向仓库
         [整数][取货单]  ← 内容在仓库里
```

> **生活类比**：想象一面镜子对着另一面镜子——无限嵌套。编译器不知道这个结构有多大。用盒子就能解决——"先留一个取货单的位置，实际内容存在仓库里"。

```rust
枚举 列表 {
    节点(整数, 盒子<列表>),
    结束,
}

函数 主函数() {
    // 创建一个列表：1 → 2 → 3 → 结束
    让 我的列表 = 列表::节点(1,
        盒子::新建(列表::节点(2,
            盒子::新建(列表::节点(3,
                盒子::新建(列表::结束)
            ))
        ))
    );
}
```

逐行解释：

- 第 1-4 行：定义"列表"——每个节点包含一个整数和指向下一个节点的盒子
- 第 2 行：**`盒子<列表>`** 意思是"盒子里装的是下一个节点"——这样编译器就知道每个节点多大了（固定大小 + 一个取货单）
- 第 7-12 行：创建 1 → 2 → 3 的链式列表

**为什么编译器必须知道大小？** 因为编译器要给每个变量分配内存。它得像仓库管理员一样，提前知道"这个格子要多宽"。如果类型大小不确定（像上面那样无限嵌套），它就没法分配，只能拒绝编译。

```
链式列表在内存中：

节点1 (栈上)         节点2 (堆上)         节点3 (堆上)
┌──────────┐        ┌──────────┐        ┌──────────┐
│ 值: 1    │        │ 值: 2    │        │ 值: 3    │
│ 下一个 ──┼──→     │ 下一个 ──┼──→     │ 下一个 ──┼──→ 结束
└──────────┘        └──────────┘        └──────────┘
```

## 18.4 引用计数——多人共享

> **生活类比**：**`引用计数`** 就像一本**公共图书**。图书馆买一本书（数据），多个人可以借来看。每有一个人借走，计数器加 1；还回来时，计数器减 1。计数器归零时，书就被销毁。

> ⚠️ **注意**：这里的"克隆"不是复制数据！普通类型（比如整数）的克隆是**复制一份新的**；`引用计数` 的克隆是**多借一本同样内容的书**——数据只有一份，只是计数器加 1。看下面的例子：

```rust
使用 标准库::引用计数::引用计数;

函数 主函数() {
    // 创建一个共享的值
    让 共享值 = 引用计数::新建("大家好".转字符串());

    打印行!("引用计数：{}", 引用计数::强引用计数(&共享值));  // 1

    // 复制引用（不是复制数据！）
    让 引用1 = 引用计数::克隆(&共享值);
    打印行!("引用计数：{}", 引用计数::强引用计数(&共享值));  // 2

    让 引用2 = 引用计数::克隆(&共享值);
    打印行!("引用计数：{}", 引用计数::强引用计数(&共享值));  // 3

    // 引用1 离开作用域，计数减 1
    // 引用2 离开作用域，计数减 1
    // 共享值 离开作用域，计数减 1 → 归零 → 数据被销毁
}
```

逐行解释：

- 第 5 行：创建一个共享值，初始引用计数为 1
- 第 9 行：`.克隆()` 不是复制数据，而是增加一个引用——计数变成 2
- 第 12 行：再克隆一次——计数变成 3
- 当计数归零时，数据自动被销毁

```
引用计数的变化：

新建 → 计数 = 1     [数据]
克隆 → 计数 = 2     [数据] ← 两个人共享
克隆 → 计数 = 3     [数据] ← 三个人共享
销毁 → 计数 = 2     [数据] 还在
销毁 → 计数 = 1     [数据] 还在
销毁 → 计数 = 0     [数据] 被清理！
```

**为什么要用引用计数？** 因为有时候多个地方需要访问同一份数据，但你不想复制它（太浪费内存）。引用计数让你安全地共享数据。

> ✨ **小提示**：`引用计数` 的"克隆"（`引用计数::克隆`）和普通数据的克隆（比如 `字符串.克隆()`）不一样——前者只是多加一个借书人（计数+1，数据还是那一份），后者才是真的复制了一份新数据。

## 18.5 弱引用——打破循环

前面说"计数归零时销毁"。但如果两个引用计数**互相引用**，计数就永远归不了零：

> **生活类比**：小明和小红互相握着对方的手不放——谁也不先松手，谁也走不了。引用计数互相引用时也一样：A 数着 B，B 数着 A，谁都没法归零，数据就永远赖在内存里不走。这叫**循环引用**，会造成**内存泄漏**（内存被白白占着）。

**怎么解决？** 用 **`弱引用`**。弱引用是"看看而已，不计数"的引用：

```rust
使用 标准库::引用计数::引用计数;
使用 标准库::引用计数::弱引用;

函数 主函数() {
    让 强引用 = 引用计数::新建(5);
    // 弱引用：只观察，不计数
    让 弱引用句柄: 弱引用<整数> = 引用计数::降级(&强引用);
    打印行!("强引用计数：{}", 引用计数::强引用计数(&强引用));  // 1（弱引用不增加）

    // 弱引用想拿数据，要先"升级"试试：数据还在就能拿到，没了就拿到"无"
    让 拿到 = 弱引用句柄.升级();
    打印行!("{:?}", 拿到);  // 有些(5)——数据还在
}
```

逐行解释：

- 第 2 行：`使用 标准库::引用计数::弱引用;` 引入弱引用类型
- 第 6 行：**`引用计数::降级(&强引用)`** 把一个强引用"降级"成弱引用——就像从"借书人"变成"只在门口看的人"，不进借书登记簿（不计数）
- 第 7 行：计数还是 1——弱引用**不增加计数**
- 第 10 行：**`弱引用句柄.升级()`** 弱引用想用数据，要先"升级"试试——数据还在就返回 `有些(值)`，数据没了就返回 `无`

```
强引用 vs 弱引用：

强引用： 像借书人    → 计数+1，保证书不丢
弱引用： 像门口看看  → 不计数，书丢了也不管
```

> ✨ **小提示**：实际写代码时，弱引用最常见的使用场景就是打破循环引用：让一边用强引用、另一边用弱引用，循环就断了。你不需要现在就写复杂的循环引用代码，只要知道"**弱引用 = 不计数**"就够了。

## 18.6 内部可变性——只读外表，可变内心

> **生活类比**：**`单元格`** 就像一个**上了锁的日记本**。从外面看，日记本是"不可变"的（别人不能随便拿）。但日记本自带一把钥匙，打开锁就能在里面修改内容。

```rust
使用 标准库::cell::单元格;

函数 主函数() {
    // 外表不可变
    让 数据 = 单元格::新建(5);

    // 但可以从内部修改！
    数据.设置(10);
    打印行!("{}", 数据.获取());  // 10
}
```

逐行解释：

- 第 5 行：`数据` 没有标记 `可变`——外表看起来不可变
- 第 8 行：`.设置(10)` 修改了内部值——但这是允许的，因为单元格内部有"锁"来保护
- 第 9 行：`.获取()` 取出当前值

**为什么要用这个？** 有时候你需要在"不可变"的地方修改数据。比如缓存——从外面看数据没变，但内部偷偷更新了缓存。

**`单元格` 和 `引用单元格`**：`单元格`（`Cell`）适合"整个换掉"（`设置` 一个新值）；`引用单元格`（`RefCell`）适合"借出来改"（可变借用）。零基础阶段，你只需要记住：**`单元格` 能让你在"不可变"的地方偷偷改值**，`引用单元格` 是它的进阶版，用到时再查文档。

## 常见错误

### 忘记用盒子导致类型无限大

```rust
// ❌ 编译器不知道这个类型有多大
// 枚举 列表 {
//     节点(整数, 列表),  // 无限嵌套！
//     结束,
// }

// ✅ 用盒子限制大小
枚举 列表 {
    节点(整数, 盒子<列表>),  // 盒子大小固定
    结束,
}
```

### 引用计数循环引用

```rust
使用 标准库::引用计数::引用计数;
使用 标准库::cell::单元格;

// ❌ 如果 A 引用 B，B 又引用 A，计数永远不归零
// 内存泄漏！
// 修复：用"弱引用"打破循环（18.5 讲过）
```

### 把"引用计数克隆"当成"数据克隆"

```rust
使用 标准库::引用计数::引用计数;

函数 主函数() {
    让 甲 = 引用计数::新建("你好".转字符串());
    让 乙 = 引用计数::克隆(&甲);  // 不是复制数据！

    // 甲 和 乙 指向同一份数据，只是计数变成了 2
    打印行!("计数：{}", 引用计数::强引用计数(&甲));  // 2
}
```

> ✨ **小提示**：怎么判断是"复制数据"还是"共享数据"？看克隆出来的东西——`字符串.克隆()` 会给你一份独立的新文字（改它不影响原文字）；`引用计数::克隆()` 只是多一个"持有者"，数据还是同一份。

## 本章小结

| 概念 | 一句话 |
|------|--------|
| 栈 vs 堆 | 便签纸（快但小）vs 仓库（慢但大） |

| `引用计数` | 公共图书——多人共享，计数归零时销毁 |
