# 第十九章：智能指针

## 19.0 学习目标

读完这一章，你将能够：

1. 说出智能指针比普通引用**多**在哪（拥有数据 + 自动善后）；
2. 用**盒子**把数据装进堆上；
3. 解释为什么**递归类型**必须有盒子（E0072）；
4. 用**引用计数**让多个主人共享一份数据，看懂计数的增减；
5. 知道 `Arc`（原子引用计数）是并发版，留给第二十章。

## 19.1 指针是什么，智能在哪

第八章的引用 `&值` 是**借据**：只指向数据，不拥有数据。

📖 **指针**：存的是"地址"的变量——指向别处的数据。

💡 **比喻**：引用像**朋友的家庭住址**——你知道去哪找他，但房子不是你的；**智能指针**像**你名下的储物间钥匙**——钥匙指向储物间，储物间里的东西**归你管**，而且到期自动退租（自动清理）。

智能指针 = 指针 + 额外能力：

| 能力 | 普通引用 | 智能指针 |
|---|---|---|
| 指向数据 | ✅ | ✅ |
| 拥有数据 | ❌ | ✅ |
| 自动清理 | ❌（主人负责） | ✅（指针没了就清理） |
| 存堆上 | 不一定 | 通常 |

本章两大主角：**盒子**（单人储物间）和**引用计数**（多人合租，记账退房）。

## 19.2 盒子：一人一箱

📖 **盒子（盒子）**：把一份数据装进堆上的箱子，你自己拿着箱子的钥匙。对应 `盒子`。

```rust
让 大数 = 盒子::新建(1000000);
打印行!("盒子里的数：{}", 大数);
```

`盒子::新建(值)` 把值装进堆上的箱子。用的时候**直接当值用**（打印、计算都行），Rust 自动"开箱"。

什么时候用盒子？三大场景：

1. **数据太大**，不想堆在栈上；
2. **类型大小不确定**（下一节的递归类型）；
3. 想拥有数据又不在乎具体类型（特征对象的盒子版）。

## 19.3 没有盒子就写不出的类型：递归

想描述一串数字"1 → 2 → 结束"，自然的想法：

```rust
枚举 链表 {
    节点(整数, 链表),    // ❌ 编译报错
    结束,
}
```

编译器报 **E0072**：

```
错误[E0072]: 递归类型缺少间接层，导致大小无限
💡 类型直接包含自身会无限膨胀。请用 `盒子` 间接包含，使大小固定。
```

为什么？`节点` 里装着一个完整的 `链表`，那个 `链表` 又可能是 `节点`，再套一个……编译器算大小就陷入无限套娃。

💡 **比喻**：俄罗斯套娃要能造出来，**最里面必须有一个实心的**。盒子就是那个实心层——它的大小固定（就是一把钥匙的地址），套娃到此为止。

```rust
枚举 链表 {
    节点(整数, 盒子<链表>),   // ✅ 盒子里才装下一个链表
    结束,
}

让 表 = 链表::节点(1, 盒子::新建(链表::节点(2, 盒子::新建(链表::结束))));
```

（⚠️ 变体名别起 `空`——它被语言包映射成 `()`，不是合法名字。用 `结束`、`尾部` 之类。）

## 19.4 引用计数：多人共享，记账退房

一份数据，好几个人都要用，谁负责最后释放？

💡 **比喻**：三个室友**合租**一台电视。门口挂个计数牌：入住一人加 1，搬走一人减 1。**牌子上归零那天，电视被搬走**。

📖 **引用计数（Rc）**：给数据挂计数牌的智能指针。对应 `Rc`。

```rust
使用 标准库::rc::Rc 作为 Rc别名;

让 共享 = Rc别名::新建(字符串::从("共同财产"));
打印行!("引用数：{}", Rc别名::强引用计数(&共享));   // 1

{
    让 副本 = 共享.克隆();                        // 计数 +1
    打印行!("引用数：{}", Rc别名::强引用计数(&共享)); // 2
}                                                  // 副本离场，计数 -1

打印行!("引用数：{}", Rc别名::强引用计数(&共享));   // 1
```

注意引入的写法：`使用 标准库::rc::Rc 作为 Rc别名;`——标准库深处的类型，用 `作为`（as）起个顺口的别名。`克隆()` 在这里**不是复制数据**，而是"多领一把钥匙、牌子加一"。

> ⚠️ **Rc 只允许多人读，不允许改**——共享的东西随手改会打架。真需要共享着改，还有配套工具（引用单元格），进阶再用。

## 19.5 选哪个？速查表

| 需求 | 工具 |
|---|---|
| 数据放堆上、一个主人 | 盒子 |
| 递归类型（树、链表） | 盒子 |
| 多个主人共享、只读 | 引用计数 |
| 多个主人共享 + 多线程 | 原子引用计数（第二十章） |
| 只是借来用用 | 普通引用 `&` |

## 19.6 完整示例：盒子 + 链表 + 合租

本章三件兵器同台：

```rust
使用 标准库::rc::Rc 作为 Rc别名;

// 递归枚举：链表——没有盒子就写不出来
枚举 链表 {
    节点(整数, 盒子<链表>),
    结束,
}

函数 主函数() {
    // —— 盒子：把数据装进堆上的箱子 ——
    让 大数 = 盒子::新建(1000000);
    打印行!("盒子里的数：{}", 大数);

    // —— 递归结构：1 -> 2 -> 结束 ——
    让 表 = 链表::节点(1, 盒子::新建(链表::节点(2, 盒子::新建(链表::结束))));
    匹配 &表 {
        链表::节点(首, _其余) => 打印行!("首元素：{}", 首),
        链表::结束 => 打印行!("空表"),
    }

    // —— 引用计数：多人共用，记账释放 ——
    让 共享 = Rc别名::新建(字符串::从("共同财产"));
    打印行!("内容：{}，引用数：{}", 共享, Rc别名::强引用计数(&共享));
    {
        让 副本 = 共享.克隆();
        打印行!("克隆后引用数：{}", Rc别名::强引用计数(&共享));
        打印行!("副本也能读：{}", 副本);
    }
    打印行!("副本走后引用数：{}", Rc别名::强引用计数(&共享));
}
```

## 19.7 逐行解释

- **第 1 行**：引入 `Rc` 并起名 `Rc别名`，后面写起来短。
- **第 4–7 行**：`链表` 的 `节点` 变体用 `盒子<链表>` 间接包含自身——大小由此固定。
- **第 11–12 行**：造一个盒子。打印时自动开箱。
- **第 15 行**：一层层造链表：最里是 `结束`，向外包两个节点。读法从内往外：`结束` ← 装进盒子 ← 配 2 成节点 ← 装进盒子 ← 配 1 成节点。
- **第 16–19 行**：借用匹配看首个元素；`_其余` 加下划线表示"拿到但不看"（不然编译器提醒）。
- **第 22–30 行**：引用计数三连——造（计 1）→ 克隆进内层块（计 2）→ 内层结束副本离场（计回 1）。

## 19.8 运行结果

```
盒子里的数：1000000
首元素：1
内容：共同财产，引用数：1
克隆后引用数：2
副本也能读：共同财产
副本走后引用数：1
```

计数牌的变化（1 → 2 → 1）正是引用计数的核心机制，肉眼可见。

## 19.9 常见错误与解决

### 错误一：E0072 递归类型大小无限

直接 `节点(整数, 链表)` 触发。**解决**：套一层盒子 `节点(整数, 盒子<链表>)`。

### 错误二：想改 Rc 里的数据

```
错误：无法借用为可变
```

`Rc` 天生只读共享。**解决**：确认真的需要共享 + 修改；多数初学者场景改用"一个主人 + 借据"就够了。

### 错误三：Rc 用 `让 乙 = 甲;` 移交

`Rc` 没实现 `复制`，直接赋值会移走。**解决**：`让 乙 = 甲.克隆();`——克隆的是钥匙，便宜得很。

### 错误四：变体名起 `空`

`空` 被映射成 `()`，写进枚举报语法错。**解决**：换名字（`结束`、`无项`）。

## 19.12 常见问题（FAQ）

**问：我是不是应该到处用盒子？**

答：不是。简单值放栈上又快又省事。盒子用在三处：大数据、递归结构、特征对象装箱。其余场景普通变量和引用就够。

**问：Rc 和"到处克隆字符串"比，好在哪？**

答：字符串克隆是**复制整段数据**；Rc 克隆只复制一把钥匙（一个地址 + 计数加一），数据只有一份。数据大、主人多时省内存。

**问：引用计数会漏账吗？两个 Rc 互相引用怎么办？**

答：会！这叫**循环引用**——两个数据互相指着，计数永远不归零，内存泄漏。解法是 `弱引用`（只看不计数的钥匙），进阶话题，初学碰不到。

**问：智能指针用起来怎么和普通值一样？**

答：因为它们实现了自动"开箱"机制（解引用）。你写 `大数 + 1`，Rust 悄悄帮你开箱取数再算。这份"无感"正是设计目标。

**问：盒子、Rc 之外还有谁？**

答：`原子引用计数`（多线程共享，下一章）、`单元格`/`引用单元格`（内部可变性，进阶）。初学三件套够用：**引用、盒子、引用计数**。
