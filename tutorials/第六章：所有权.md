# 第六章：所有权

欢迎来到 Rust 最独特的概念——**所有权**。

这是 Rust 区别于其他语言的核心特性。理解了所有权，你就理解了 Rust 的灵魂。

> 这一章的概念可能比较抽象。别急，我会用大量图解和生活类比帮你理解。如果第一遍没看懂，多看几遍——所有权值得你花时间。

---

## 6.1 什么是所有权？

### 生活类比：玩具只能有一个主人

想象你和朋友各有一个玩具。规则很简单：

```
┌──────────────────────────────────────────────────┐
│ 规则 1：每个玩具只能有一个主人                     │
│   → 每个值只有一个所有者                          │
│                                                  │
│ 规则 2：你可以把玩具送给别人                       │
│   → 可以转移所有权                                │
│                                                  │
│ 规则 3：你离开时，玩具自动归还                     │
│   → 所有者离开作用域，值被释放                      │
└──────────────────────────────────────────────────┘
```

**为什么需要这些规则？** 因为如果两个都认为自己拥有同一个玩具，当你想扔掉它时，另一个人可能还在玩——这就乱套了。Rust 通过"一个玩具只能有一个主人"来避免这种混乱。

### 为什么需要所有权？

在其他语言中，内存管理有两种方式：

```
方式 A：垃圾回收（Java、Python）
  → 有专门的"清洁工"定期清理不用的数据
  → 方便，但清洁工需要时间，影响性能

方式 B：手动管理（C、C++）
  → 程序员自己申请和释放内存
  → 高效，但容易忘记释放（内存泄漏）

方式 C：所有权系统（Rust）✅
  → 编译器在编译时自动插入释放代码
  → 既安全又高效，不需要"清洁工"
```

## 6.2 作用域

先理解**作用域**——一个变量"有效"的范围。

**为什么需要理解作用域？** 因为变量不是在任何地方都能用的。就像你的门禁卡只能打开你这栋楼的门——它只在你的楼里"有效"。

```rust
函数 主函数() {
    // 这里 句子 还不存在

    {
        让 句子 = "你好";  // 句子 从这里开始有效
        打印行!("{}", 句子);
    }  // 句子 的作用域到此结束，被销毁

    // 这里 句子 已经无效了
    // 打印行!("{}", 句子);  // ❌ 编译报错
}
```

逐行解释：

- 第 4-7 行：花括号 `{}` 定义了一个"代码块"——句子 只在这个代码块里有效
- 第 5 行：句子 从这里开始存在
- 第 7 行：代码块结束，句子 被销毁——就像你搬走了，门禁卡就失效了

图解：

```
函数 主函数() {
    ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─   ← s 不存在
    {
        ┌─────────────────────┐
        │ s = "你好"          │  ← s 从这里开始有效
        │ 打印行!("{}", s);   │
        └─────────────────────┘
    }                          ← s 到此结束，被销毁
    ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─   ← s 不存在
}
```

## 6.3 栈与堆

要理解所有权，先了解**栈**和**堆**——计算机存储数据的两种方式。

**为什么要区分栈和堆？** 因为不同类型的值存在不同的地方，而所有权规则对它们的影响不同。

### 栈——一摞盘子

栈像一摞**盘子**——后进先出，只能从顶部放和取：

```
        ┌─────┐
        │  C  │  ← 最后放入，最先取出
        ├─────┤
        │  B  │
        ├─────┤
        │  A  │  ← 最先放入
        └─────┘
          栈
```

特点：
- 数据大小必须**提前知道**（编译时就知道）
- 访问速度**非常快**（因为排列整齐，一拿就到）
- 空间有限

### 堆——一个大仓库

堆像一个**大仓库**——数据散乱存放，需要时再找：

```
        ┌─────────────────────────┐
        │                         │
        │    ┌───┐     ┌───────┐  │
        │    │数据│     │ 数据  │  │
        │    └───┘     └───────┘  │
        │         ┌─────┐         │
        │         │数据 │         │
        │         └─────┘         │
        └─────────────────────────┘
                  堆
```

特点：
- 数据大小可以**随时变化**
- 访问速度**较慢**（需要在仓库里找）
- 空间很大

### 什么数据存在哪里？

```
┌────────────────────────────────────────────┐
│ 存在栈上（小、固定）  │ 存在堆上（大、动态） │
├────────────────────────────────────────────┤
│ 整数、浮点数、布尔     │ 字符串（String）    │
│ 字符                   │ 向量（Vec）         │
│ 元组（元素都在栈上时） │ 哈希表（HashMap）   │
└────────────────────────────────────────────┘
```

## 6.4 移动：所有权转移

当你把一个变量赋值给另一个变量时，**所有权会转移**。

### 堆数据的移动

**为什么所有权要转移？** 想象你把你的玩具送给朋友。玩具到了朋友手里，你就不再拥有它了。如果你还认为自己拥有它，当你"扔掉"它时，朋友手里的玩具也没了——这就会出问题。

```rust
函数 主函数() {
    让 句子1 = "你好".转字符串();
    让 句子2 = 句子1;  // 所有权从 句子1 转移到 句子2

    // 打印行!("{}", 句子1);  // ❌ 报错！句子1 已经无效
    打印行!("{}", 句子2);  // ✅ 句子2 有效
}
```

逐行解释：

- 第 2 行：创建一个字符串，句子1 拥有它
- 第 3 行：把 句子1 赋给 句子2——所有权从 句子1 转移到 句子2。句子1 不再有效
- 第 6 行：用 句子2 没问题——它现在拥有这个字符串

图解：

```
赋值前：
句子1 ──→ [堆上的字符串 "你好"]
        ↑ 句子1 拥有这块数据

赋值后（让 句子2 = 句子1）：
句子1 ──×   （句子1 失效，不再指向任何数据）
句子2 ──→ [堆上的字符串 "你好"]
        ↑ 句子2 拥有这块数据（所有权转移了）
```

> **为什么 Rust 要让 句子1 失效？** 因为如果 句子1 和 句子2 都指向同一块数据，当它们离开作用域时，都会尝试释放同一块内存——这会导致**双重释放**错误。Rust 通过让 句子1 失效来防止这个问题。

### 栈数据不会移动

```rust
// 栈上的数据：复制，不移动
让 甲 = 42;
让 乙 = 甲;  // 直接复制值（整数在栈上，很小）
打印行!("甲 = {}, 乙 = {}", 甲, 乙);  // ✅ 两个都有效
```

**为什么栈数据不移动？** 因为整数很小（只有 4 个字节），直接复制一份比"转移所有权"更简单。就像你告诉朋友一个数字——你不需要"失去"这个数字，朋友也能知道它。

图解：

```
栈数据：
甲 = 42  →  甲: [42]
乙 = 甲  →  甲: [42]  乙: [42]   ← 直接复制，两个独立副本
```

> **规则**：栈上的小数据会自动复制；堆上的大数据只转移所有权。

## 6.5 克隆：显式复制

如果你确实想复制一份堆上的数据，用 **`.克隆()`**：

**为什么需要克隆？** 因为有时候你确实需要两份独立的数据——比如你想修改一份，但保留原始的那份。

```rust
函数 主函数() {
    让 句子1 = "你好".转字符串();
    让 句子2 = 句子1.克隆();  // 深拷贝——创建一份完整副本

    打印行!("句子1 = {}", 句子1);  // ✅ 仍然有效
    打印行!("句子2 = {}", 句子2);  // ✅ 也有效
}
```

逐行解释：

- 第 2 行：创建字符串，句子1 拥有它
- 第 3 行：`.克隆()` 在堆上创建一份完全一样的副本，句子2 拥有这份副本
- 第 5-6 行：两个变量都有效——它们各自拥有独立的数据

图解：

```
克隆前：
句子1 ──→ [堆上的字符串 "你好"]

克隆后（句子2 = 句子1.克隆()）：
句子1 ──→ [堆上的字符串 "你好"]   ← 原始数据
句子2 ──→ [堆上的字符串 "你好"]   ← 复制的数据（独立副本）
```

> **`.克隆()` 的代价**：它会完整复制数据。数据量大时，复制会消耗时间和内存。所以只在确实需要两份数据时才用。就像复印一本书——页数越多，复印越慢。

## 6.6 函数传参也会移动

**为什么传参也会移动？** 因为把变量传给函数，就像把玩具送给别人——玩具到了函数手里，你就不再拥有它了。

```rust
函数 打印文本(内容: 字符串) {
    打印行!("{}", 内容);
}  // 内容 在这里被释放（离开作用域）

函数 主函数() {
    让 句子 = "你好".转字符串();
    打印文本(句子);  // 句子的所有权移动到函数参数

    // 打印行!("{}", 句子);  // ❌ 句子已经无效
}
```

逐行解释：

- 第 1 行：函数接受一个字符串参数
- 第 6 行：调用函数时，句子的所有权移动到 `内容` 参数
- 第 7 行之后：句子已经无效了——你不能使用已经送出去的东西

图解：

```
调用前：
句子 ──→ [堆上的字符串 "你好"]

调用 打印文本(句子) 时：
句子 ──×   （句子 失效）
内容 ──→ [堆上的字符串 "你好"]   ← 所有权转移到参数

函数结束后：
内容 ──×   （内容 离开作用域，数据被释放）
```

## 6.7 返回值可以转移回来

```rust
函数 接收并返回(内容: 字符串) -> 字符串 {
    打印行!("{}", 内容);
    内容  // 返回，所有权转移回去
}

函数 主函数() {
    让 句子 = "你好".转字符串();
    让 句子 = 接收并返回(句子);  // 拿回所有权
    打印行!("{}", 句子);  // ✅ 有效
}
```

> 解释：调用 `接收并返回(句子)` 时，旧的 `句子` 已被移交；用 `让 句子 = ...` 重新创建同名变量接住返回值——这就是第二章学过的**遮蔽**。

> 但这太笨拙了——送出去再要回来。下一章我们会学更好的方式——**引用与借用**。就像你不需要把书送给朋友才能让他看——你可以借给他。

## 6.8 所有权规则总结

```
┌──────────────────────────────────────────────────────┐
│ 规则 1：每个值有且只有一个所有者                       │
│ 规则 2：所有者离开作用域时，值被释放                    │
│ 规则 3：赋值或传参会转移所有权（移动）                  │
│ 规则 4：栈上的小数据自动复制，不受移动影响              │
│ 规则 5：用 .克隆() 显式复制堆数据                      │
└──────────────────────────────────────────────────────┘
```

## 6.9 常见错误

### 错误 1：移动后继续使用

```rust
让 句子1 = "你好".转字符串();
让 句子2 = 句子1;
打印行!("{}", 句子1);  // ❌ 句子1 已移动
```

**修复**：用 `.克隆()` → `让 句子2 = 句子1.克隆();`

### 错误 2：函数参数移动

```rust
函数 处理(内容: 字符串) { ... }
让 句子 = "你好".转字符串();
处理(句子);
打印行!("{}", 句子);  // ❌ 句子已移动到函数参数
```

**修复**：传引用（下一章学）→ `处理(&句子);`

### 错误 3：循环中移动

```rust
让 可变 列表 = 向量!["你好".转字符串()];
对于 项 在 列表 {
    打印行!("{}", 项);
}
// ❌ 列表已移动（被消费迭代）
```

**修复**：用引用遍历 → `对于 项 在 &列表 {`

## 6.10 动手实验

### 实验 1：观察移动

**为什么要做这个实验？** 因为亲眼看到移动的效果，比读十遍规则都有用。

```rust
函数 主函数() {
    让 列表1 = 向量![1, 2, 3];
    让 列表2 = 列表1;

    // 打印行!("{:?}", 列表1);  // ❌ 已移动
    打印行!("{:?}", 列表2);  // ✅ 有效
}
```

### 实验 2：使用克隆

```rust
函数 主函数() {
    让 列表1 = 向量![1, 2, 3];
    让 列表2 = 列表1.克隆();

    打印行!("列表1：{:?}", 列表1);  // ✅ 有效
    打印行!("列表2：{:?}", 列表2);  // ✅ 有效
}
```

### 实验 3：栈数据自动复制

```rust
函数 主函数() {
    让 甲 = 42;
    让 乙 = 甲;

    打印行!("甲 = {}, 乙 = {}", 甲, 乙);  // ✅ 两个都有效

    让 丙 = 真;
    让 丁 = 丙;
    打印行!("丙 = {}, 丁 = {}", 丙, 丁);  // ✅ 布尔也是栈数据
}
```

## 6.11 练习题

### 练习 1：判断哪些代码能编译

不运行代码，判断以下哪些能通过编译：

```rust
// A
让 句子1 = "你好".转字符串();
让 句子2 = 句子1;
打印行!("{}", 句子1);

// B
让 句子1 = "你好".转字符串();
让 句子2 = 句子1.克隆();
打印行!("{} {}", 句子1, 句子2);

// C
让 甲 = 42;
让 乙 = 甲;
打印行!("{}", 甲, 乙);
```

<details>
<summary>答案</summary>

- **A** ❌ 不能编译——句子1 已移动
- **B** ✅ 可以编译——克隆后两个都有效
- **C** ✅ 可以编译——整数是栈数据，自动复制

</details>

## 本章小结

1. **所有权** 是 Rust 内存安全的核心机制
2. 每个值有且只有一个所有者，所有者离开作用域时值被释放
3. 赋值/传参会**移动**堆上的数据，原变量失效
4. 用 **`.克隆()`** 显式复制数据
5. 栈上的小数据（整数、布尔等）自动复制，不受移动影响
6. **栈**：小、快、固定大小；**堆**：大、慢、动态大小
