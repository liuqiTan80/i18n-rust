# 第十三章：特征

## 13.0 学习目标

读完这一章，你将能够：

1. 用**岗位说明书**比喻解释特征是什么；
2. 用 **`特征`** 关键字定义新能力（必选方法 + 默认方法）；
3. 用 **`实现 特征 对于 类型`** 给类型发"上岗证"；
4. 用 `<T: 特征>` 约束和 `&实现 特征` 两种写法接收"任何有这能力的人"；
5. 用 **`动态 特征`**（特征对象）把不同类型混装进一个集合；
6. 看懂 **E0277**（未实现特征）并修复；
7. 明白 `派生` 贴纸背后其实就是自动实现特征。

---

## 13.1 特征：岗位说明书

💡 **比喻**：学校要办联欢会，需要招募"会自我介绍的人"。招聘启事上写着：

> **岗位：可介绍**
> 要求：必须能提供一段自我介绍文字。

学生可以来应聘，老师也可以来应聘——**不管你是什么身份，满足要求就能上岗**。

📖 **特征（Trait）**：一组方法签名的约定，定义"某个类型能做什么"。对应英文关键字 `特征`。就像岗位说明书：只写要求，不写具体谁来做。

第十二章的 `可排序`、`可显示` 都是标准库**预先定义好**的特征。这一章，你学会**自己定义**。

## 13.2 定义特征

```rust
特征 可介绍 {
    函数 介绍(&自我) -> 字符串;
}
```

读法："有一个岗位叫 `可介绍`，上岗者必须提供 `介绍` 方法：接收 `&自我`，返回字符串。"

注意：方法后面是**分号**，没有方法体——说明书只写要求，不替你干活。

## 13.3 实现特征：应聘上岗

```rust
结构体 学生 {
    姓名: 字符串,
    分数: 整数,
}

结构体 老师 {
    姓名: 字符串,
    科目: 字符串,
}

实现 可介绍 对于 学生 {
    函数 介绍(&自我) -> 字符串 {
        格式化!("学生{}（{}分）", 自我.姓名, 自我.分数)
    }
}

实现 可介绍 对于 老师 {
    函数 介绍(&自我) -> 字符串 {
        格式化!("{}老师，教{}", 自我.姓名, 自我.科目)
    }
}
```

📖 语法 **`实现 特征名 对于 类型名`**：读作"为这个类型实现这个特征"。`实现`（实现）和 `对于`（for）配合使用。

从此学生、老师都"持证上岗"——任何要求 `可介绍` 的地方，它们都能出场。

> ⚠️ **小心**：定义特征 ≠ 实现特征。只写说明书不招人，岗位还是空的；只给一个类型实现，其他类型依然没资格。

## 13.4 默认方法：说明书自带范本

特征里的方法可以**自带默认实现**——应聘者可以直接用范本，也可以重写：

```rust
特征 可介绍 {
    函数 介绍(&自我) -> 字符串;                 // 必须自己写

    函数 礼貌介绍(&自我) -> 字符串 {             // 有默认实现
        格式化!("请多关照：{}", 自我.介绍())
    }
}
```

学生、老师都没写 `礼貌介绍`，但都能直接用——它内部调用了各自的 `介绍`。想要不同的礼貌语，自己在 `实现` 块里重写即可。

## 13.5 两种"持证检查"写法

写一个函数，只收"会自我介绍的人"。有两种等价风格：

### 风格一：泛型约束（第十二章学过）

```rust
函数 点名<人: 可介绍>(谁: &人) {
    打印行!("{}", 谁.礼貌介绍());
}
```

### 风格二：`&实现 特征`（更简洁）

```rust
函数 点名(谁: &实现 可介绍) {
    打印行!("{}", 谁.礼貌介绍());
}
```

读法："参数是任何类型的借用，只要那个类型实现了 `可介绍`。"

两种风格怎么选？**单参数、简单场景**用风格二，直观；**多个参数要共用同一个类型占位符**（比如"比较两个同类型的人"）用风格一。

## 13.6 特征对象：把不同类型混装

数组要求所有元素**同一类型**（第三章的铁律）。学生和老师在类型上是两家人，怎么装进同一个名单？

答案：**特征对象**——不看具体类型，只看"证书"：

```rust
让 名单: [&动态 可介绍; 2] = [&小华, &老王];

对于 下标 在 0..2 {
    打印行!("到场：{}", 名单[下标].介绍());
}
```

📖 **动态（dyn）**：关键字，表示"运行时才认具体类型"。`&动态 可介绍` 读作"对任何可介绍者的借用"。

💡 **比喻**：泛型约束像**按岗位批量开工**——来了学生和老师的订单，编译器分别造两条流水线（单态化，第十二章）；特征对象像**一条通用流水线**——来的不管是啥，只要有证书就处理。通用流水线省代码，但每次要现场查证，略慢一点点。

| | 泛型 `<T: 特征>` | 特征对象 `动态 特征` |
|---|---|---|
| 何时确定类型 | 编译时 | 运行时 |
| 性能 | 更快（专用代码） | 略慢（现场查证） |
| 能混装不同类型 | 不能 | 能 |

## 13.7 派生贴纸的真相

第十章贴的 `#[派生(Debug)]`、第七章的 `#[派生(Clone)]`，现在能解释清楚了：**派生 = 编译器替你写 `实现` 块**。

`#[派生(Debug)]` 约等于编译器自动生成：

```rust
实现 可调试 对于 学生 {
    // ...自动写出每个字段的打印逻辑
}
```

你贴一张贴纸，少抄几十行。能派生的常见特征：`Debug`（调试打印）、`Clone`（克隆）、`Copy`（随手复制）、`PartialEq`（相等比较）。**派生括号里用英文**（第七章提醒过），因为派生宏按英文原名查找。

## 13.8 完整示例：学校点名系统

把特征定义、双类型实现、默认方法、两种调用风格、特征对象全串起来：

```rust
// —— 岗位说明书 ——
特征 可介绍 {
    // 必选：自我介绍
    函数 介绍(&自我) -> 字符串;

    // 默认：礼貌版介绍（内部调用上面的 介绍）
    函数 礼貌介绍(&自我) -> 字符串 {
        格式化!("请多关照：{}", 自我.介绍())
    }
}

// —— 两类人 ——
结构体 学生 {
    姓名: 字符串,
    分数: 整数,
}

结构体 老师 {
    姓名: 字符串,
    科目: 字符串,
}

// —— 双双应聘上岗 ——
实现 可介绍 对于 学生 {
    函数 介绍(&自我) -> 字符串 {
        格式化!("学生{}（{}分）", 自我.姓名, 自我.分数)
    }
}

实现 可介绍 对于 老师 {
    函数 介绍(&自我) -> 字符串 {
        格式化!("{}老师，教{}", 自我.姓名, 自我.科目)
    }
}

// —— 泛型函数：只收持证者 ——
函数 点名(谁: &实现 可介绍) {
    打印行!("{}", 谁.礼貌介绍());
}

// —— 特征对象：不同类型混装 ——
函数 全员点名(名单: [&动态 可介绍; 2]) {
    对于 下标 在 0..2 {
        打印行!("到场：{}", 名单[下标].介绍());
    }
}

函数 主函数() {
    让 小华 = 学生 { 姓名: 字符串::从("小华"), 分数: 95 };
    让 老王 = 老师 { 姓名: 字符串::从("王"), 科目: 字符串::从("数学") };

    // 风格二：&实现 特征
    点名(&小华);
    点名(&老王);

    // 特征对象数组
    让 名单: [&动态 可介绍; 2] = [&小华, &老王];
    全员点名(名单);
}
```

## 13.9 逐行解释

- **第 2–10 行**：特征 `可介绍`——一个必选方法（分号结尾）+ 一个默认方法（带方法体）。
- **第 13–21 行**：两个结构体，字段各不相同。
- **第 24–34 行**：两个 `实现 ... 对于 ...` 块，各自填写自己的 `介绍` 内容；`礼貌介绍` 都用默认版。
- **第 37–39 行**：`点名` 用 `&实现 可介绍` 风格——学生、老师都持证，都能传入。
- **第 42–46 行**：`全员点名` 收一个"可介绍者借用"数组。`&动态 可介绍` 让两种类型混装合法。
- **第 49–50 行**：造一师一生。
- **第 53–54 行**：分别点名，走默认方法 `礼貌介绍`。
- **第 57–58 行**：装进名单数组、全员点名。数组里存的是**借用**（`&`），小华老王本人还在。

## 13.10 运行结果

```
请多关照：学生小华（95分）
请多关照：王老师，教数学
到场：学生小华（95分）
到场：王老师，教数学
```

前两行走默认方法（"请多关照"前缀），后两行直接 `介绍`——同一个特征，两种调用姿势。

## 13.11 常见错误与解决

### 错误一：E0277 未实现特征

```
错误[E0277]: the 特征 bound `石头: 会飞` is not satisfied
💡 请为该类型实现所需的特征，或使用已实现该特征的类型。
```

**解决**：要么补一个 `实现 会飞 对于 石头`（给它真装上翅膀），要么换个已实现的类型。

### 错误二：实现块里漏了必选方法

特征要求三个方法，实现块只写两个——编译报错"缺少方法"。**解决**：对照特征定义补齐；实在不想写，用 `未实现!()` 占位（运行时用到会恐慌）。

### 错误三：`实现 特征 为 类型` 写错关键字

正确的是 **`实现 特征 对于 类型`**（`对于` = for）。写 `为` 会报语法错误。

### 错误四：方法定义忘写分号

特征里的必选方法以**分号**结尾（没有方法体）；写了 `{}` 就变成默认方法了。两种都合法，想清楚你要哪种。

### 错误五：特征对象数组想装值

`[动态 可介绍; 2]` 装不了——特征对象大小不固定。用**借用** `[&动态 可介绍; 2]` 或智能指针（第十九章的盒子）。

## 13.12 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 特征 | 一组方法签名的约定，定义类型"能做什么"，英文 特征 |
| 实现块（特征） | `实现 特征 对于 类型`，给类型发上岗证 |
| 默认方法 | 特征里自带实现的方法，可以直接用或重写 |
| 特征约束 | `<T: 特征>`，要求泛型类型具备某能力 |
| &实现 特征 | 参数级的特征约束简写 |
| 动态 | 关键字 dyn，表示运行时才认具体类型 |
| 特征对象 | `动态 特征` 类型的值，让不同类型混装 |
| 派生 | 编译器自动写实现块的贴纸，`#[派生(...)]` |

> 📖 **提醒**：遇到不懂的词，随时回查全书开头的《总术语表》。

## 13.14 常见问题（FAQ）

**问：特征和"接口"（interface）是一回事吗？**

答：思想一样（定义能力约定），但 Rust 特征更强：能带默认方法、能和泛型深度配合、还能约束"类型大小""能否复制"等。别的数据类型（整数、字符串）也能实现特征——别的语言的接口大多只服务"类"。

**问：一个类型能实现多个特征吗？**

答：能，各写一个实现块就行。反过来，多个类型实现同一特征也行。特征和类型是**多对多**的关系。

**问：在哪里能实现特征？任何文件都行吗？**

答：有条规则（孤儿规则）：要么特征是你定义的，要么类型是你定义的，二者至少占一个。防止两个库给"别人的类型 + 别人的特征"乱配对打架。初学阶段你的代码都在自己的包里，碰不到这个坑。

**问：泛型约束和特征对象，实际项目怎么选？**

答：追求速度、类型种类固定 → 泛型约束；要**混装**不同类型（比如"把所有可打印的东西放一个列表"）→ 特征对象。本书后面章节两种都会大量出现。

**问：`可排序`、`可显示` 这些标准特征，以后要背吗？**

答：常用的就那几个——`可调试`（打印结构）、`可克隆`/`复制`（复制）、`相等`/`可排序`（比较）、`可显示`（`{}` 打印）、`默认`（造默认值）。用到自然记住，附录 A 也有速查。

**问：特征里能放字段吗？**

答：不能。特征只管"能做什么"（方法），不管"有什么"（字段）。要字段用结构体；要"结构体 + 能力"就组合：结构体装字段，实现块挂特征。
