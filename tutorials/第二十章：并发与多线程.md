# 第二十章：并发与多线程

## 20.0 学习目标

读完这一章，你将能够：

1. 用**多灶台厨房**比喻解释线程；
2. 用 **`线程::生成`** 开新线程、用 **`等待线程`** 收尾；
3. 理解 **`移动`** 闭包为什么要把数据搬进线程；
4. 用**通道**在线程间安全传话；
5. 用 **原子引用计数 + 互斥锁** 共享一份可修改的数据；
6. 记住并发铁律："**共享 + 可变**必须上锁或走通道"。

## 20.1 一个灶台不够快

一个程序默认从头到尾一条线执行——**一个灶台炒菜**，后面的菜全排队。

💡 **比喻**：饭店高峰期，一个灶台忙不过来。**线程**就是多开几个灶台，同时炒几道菜。

📖 **线程**：程序里一条独立执行的指令流。操作系统让它们在多个处理器核心上真正同时跑。

并发写错会出大事（两个厨师同时往锅里放盐）。别怕——**Rust 编译器就是你的后厨主管**，谁没按规矩来，编译阶段就拦下。

## 20.2 生成线程

```rust
使用 标准库::线程;

让 句柄 = 线程::生成(|| {
    打印行!("子线程：开工！");
});
句柄.等待线程().解包();
```

- **`线程::生成(|| { ... })`**：开一个新灶台，把闭包里的代码交给它做（闭包是什么？第二十二章细讲，这里当作"打包好的一段活"）；
- **`句柄`**：生成后拿到的"取餐号"，靠它跟踪这个线程；
- **`等待线程()`**：主线程停下来，等它干完再继续。不等的话，主程序可能先结束，子线程的活白干。

## 20.3 让线程歇一会儿

```rust
使用 标准库::时间::持续时间;

线程休眠(持续时间::从毫秒(50));
```

（需先 `使用 标准库::线程::线程休眠;` 引入。）模拟"干活要花时间"，演示顺序时有用。

## 20.4 通道：线程间传话的对讲机

多个线程之间怎么交流？**不许随便碰同一块数据**——用**通道**传消息：

💡 **比喻**：对讲机——一头说，另一头听。说完的话**所有权交给对方**，说话人就不能再改口了。

```rust
使用 标准库::同步::消息传递;

让 (发话口, 听话口) = 消息传递::通道();

发话口.发送(字符串::从("任务完成，共 42 件")).解包();
让 收到 = 听话口.接收().解包();
```

- `通道()` 一次造出**一对**：发话口（发送端）+ 听话口（接收端）；
- `发送` 把数据**移进**通道——发完你就没份了（所有权转移！）；
- `接收` 会**阻塞等待**：没消息就一直等，有消息立刻拿。这保证"收到的一定是已发出的"。

> ⚠️ 发话口可以克隆出多份（多人对一人说），听话口只有一份——所以叫"多生产者，单消费者"（mpsc，也就是消息通道）。

## 20.5 共享数据：原子引用计数 + 互斥锁

确实需要多人改同一份数据时（比如统计总数），两件套上阵：

```rust
使用 标准库::同步::原子引用计数;
使用 标准库::同步::互斥锁;

让 计数器 = 原子引用计数::新建(互斥锁::新建(0));
```

📖 **互斥锁**：公共厕所的门锁——**进去先锁门**，出来自动开。拿到锁（`加锁()`）才能读写数据，别人只能等。

📖 **原子引用计数**：第十九章引用计数的线程安全版。多线程共享钥匙必须用它（引用计数的记账不够稳，编译器拒绝它进线程）。

💡 **记忆口诀**：**原子引用计数管"几个人有钥匙"，锁管"一次只能进一人"。**

## 20.6 完整示例：工作间汇报

子线程干活、用通道汇报，主线程收报告——本章主菜：

```rust
使用 标准库::线程;
使用 标准库::线程::线程休眠;
使用 标准库::时间::持续时间;
使用 标准库::同步::消息传递;

函数 主函数() {
    // —— 生成子线程 ——
    让 句柄 = 线程::生成(|| {
        打印行!("子线程：开工！");
        线程休眠(持续时间::从毫秒(50));
        打印行!("子线程：收工！");
    });

    // —— 通道：线程间传话 ——
    让 (发话口, 听话口) = 消息传递::通道();
    发话口.发送(字符串::从("任务完成，共 42 件")).解包();

    // 主线程先等消息，再等线程收尾
    让 收到 = 听话口.接收().解包();
    打印行!("主线程收到：{}", 收到);

    句柄.等待线程().解包();
    打印行!("主线程：全员收工");
}
```

## 20.7 逐行解释

- **第 1–4 行**：四件工具引入——线程、休眠函数、时长类型、通道模块。
- **第 7–11 行**：`线程::生成` 开出子线程：打印开工 → 睡 50 毫秒（模拟干活）→ 打印收工。
- **第 14–15 行**：造通道的一对端口，立刻发一条汇报消息。`发送` 把字符串移进通道。
- **第 18–19 行**：`接收` 等到消息（这里是秒到）后打印。
- **第 21 行**：`等待线程` 确保子线程的"收工"打印完成后，主线程才说"全员收工"。

## 20.8 运行结果

```
主线程收到：任务完成，共 42 件
子线程：开工！
子线程：收工！
主线程：全员收工
```

有意思的顺序：主线程**没等**子线程就收到了消息（通道独立于线程），但最后一句"全员收工"**一定**在最后——`等待线程` 兜住了底。

## 20.9 进阶示例：原子引用计数 + 锁的计数器

```rust
使用 标准库::线程;
使用 标准库::同步::原子引用计数;
使用 标准库::同步::互斥锁;

函数 主函数() {
    让 计数器 = 原子引用计数::新建(互斥锁::新建(0));
    让 副本 = 计数器.克隆();
    让 句柄 = 线程::生成(移动 || {
        让 可变 守卫 = 副本.加锁().解包();
        *守卫 = *守卫 + 1;
    });
    句柄.等待线程().解包();
    打印行!("计数：{}", *计数器.加锁().解包());
}
```

输出：`计数：1`

要点：

- `副本 = 计数器.克隆()`——给子线程一把钥匙（原子引用计数克隆便宜）；
- `移动 ||`——把 `副本` **搬进**闭包，线程才能拥有它（下一节讲）；
- `加锁()` 得到 `守卫`——守卫活着期间门锁着，`*守卫` 读写数据；守卫离开作用域自动开锁；
- 主线程打印也要先 `加锁`——锁内数据不能直接 `{}` 打印。

## 20.10 `移动` 闭包：把行李带进线程

子线程可能比主函数活得久。如果闭包只是"借"了外面的变量，线程跑到一半主人没了怎么办？

Rust 的规矩简单粗暴：**`移动`**——把数据的所有权整个搬进闭包：

```rust
让 副本 = 计数器.克隆();
线程::生成(移动 || {
    // 副本 现在是线程自己的了
});
// 这里不能再碰 副本（但 计数器 本人还在）
```

所以正确姿势是：**先克隆（或多造几份），再移动**——每人一份，谁也不欠谁。

## 20.11 原子操作与发送/同步特征

### 原子类型：无锁的线程安全变量

第二十章里共享数据靠 `互斥锁` 加锁。但有个更轻的选择：**原子类型**——加加减减不需要锁，因为硬件保证"读-改-写"是一条不可分割的原子操作。

📖 **原子类型**：线程间安全的数值/布尔类型，操作由处理器保证原子性。常见的有 `原子布尔`、`原子无符号整数`、`原子整数` 等。

💡 **比喻**：互斥锁像"考试时只有一支笔，谁要用都要排队拿"；原子操作像"每人发一个计算器，按键瞬间完成"——计数器这种简单场景，原子类型更轻快。

```rust
使用 标准库::同步::原子引用计数 作为 共享原子;
使用 标准库::同步::原子::原子无符号整数 作为 原子计数;
使用 标准库::线程;
使用 标准库::同步::原子::内存顺序::松弛序 作为 宽松顺序;

函数 主函数() {
    // 共享原子 包住一个从 0 开始的原子计数器，让两个线程共享
    让 计数 = 共享原子::新建(原子计数::从(0));

    // 每个线程要一份共享引用：克隆出两份（原子引用计数克隆只加计数，不复制数据），
    // 原 计数 留在主线程用于最后打印
    让 计数一 = 计数.克隆();
    让 计数二 = 计数.克隆();

    // 线程 1：加 1000 次
    让 处理器一 = 线程::生成(移动 || {
        对于 _ 在 0..1000 {
            计数一.获取并修改(1, 宽松顺序);
        }
    });
    // 线程 2：再加 1000 次
    让 处理器二 = 线程::生成(移动 || {
        对于 _ 在 0..1000 {
            计数二.获取并修改(1, 宽松顺序);
        }
    });

    处理器一.等待线程().期望("线程一异常");
    处理器二.等待线程().期望("线程二异常");
    打印行!("计数 = {}", 计数.加载(宽松顺序));
}
```

输出：

```
计数 = 2000
```

如果用普通 `整数`（i32）做这个计数，两个线程同时"读旧值、加一、写回"会互相覆盖，结果经常小于 2000——这就是**数据竞争**。`获取并修改`（转译后是 `fetch_add`）把"读-加-写"合并成硬件级的一条原子指令，谁也别想插队。

> `松弛序`（Relaxed）是内存顺序的一种，表示"只保证原子性，不额外约束排序"；`标准库::同步::原子::内存顺序` 还有 `获取序`/`释放序`/`全顺序` 等更严格的顺序。教学场景记住：简单计数器用 `松弛序` 就够了。

### 发送与同步：哪些类型能跨线程

为什么 `引用计数` 不能传给线程，而 `原子引用计数` 能？秘密藏在两个特征里：

- 📖 **发送**：这个类型的值**可以安全地移动到另一个线程**。绝大多数类型都实现了发送特征，除了 `引用计数` 这类不是。
- 📖 **同步**：这个类型可以**被多个线程同时共享引用**。`互斥锁`、`原子引用计数` 实现了同步特征，`单元格` 没有。

这两个特征由编译器**自动推导**：你几乎不用手写。规则很简单——你的类型里的字段全都实现了发送/同步特征，它就自动实现；`引用计数` 故意不实现发送特征（它不保证线程安全，两个线程同时克隆会让计数出错）：

```rust
使用 标准库::线程;
使用 标准库::引用计数模块::引用计数;   // 引用计数

函数 主函数() {
    让 数据 = 引用计数::新建(5);
    线程::生成(移动 || {      // ❌ E0277：引用计数<整数> 不能在线程间发送
        打印行!("{}", 数据);
    });
}
```

报错信息大意是：**`引用计数<整数>` 未实现 `发送` 特征**。修复方法：把 `引用计数` 换成 `原子引用计数`——它是"线程安全版的引用计数"，实现方式是在计数上加锁/原子操作。

💡 **比喻**：发送特征像"行李托运牌"——没有它，行李（值）不能上飞机（跨线程）；同步特征像"多人可同时翻阅的公共书架"——`互斥锁` 把书锁好让多人轮流看，`单元格` 则像私人物品不许外借。

## 20.12 常见错误与解决

### 错误一：E0382 值在移动后被使用

线程生成时没克隆就 `移动`，之后还想用原值。**解决**：先 `克隆()`（或另造一份）再进线程。

### 错误二：把引用计数传进线程

```
错误：`引用计数` 不能在线程间安全传送
```

**解决**：换成原子引用计数。

### 错误三：忘 `等待线程`，输出残缺

子线程没打印完程序就退出了。**解决**：收尾前逐个 `句柄.等待线程()`。

### 错误四：锁着数据直接打印/比较

互斥锁里的值要先 `加锁()` 再 `*守卫` 取用。**解决**：一切操作都放进拿到守卫之后。

### 错误五：忘记引入工具

`线程`、`线程休眠`、`持续时间`、`mpsc` 都要 `使用` 引入。报错找不到名字时，先查 20.6 开头的四行。

## 20.15 常见问题

**问：开越多线程越快吗？**

答：不是。线程数超过处理器核心数就变成"换班跑"，反而浪费。而且线程创建本身也有开销。经验：处理器有几核就大致开几条，或者用线程池（库来管）。

**问：为什么 Rust 的并发"以难著称"？**

答：难在**编译期就拒绝数据竞争**——别的语言把这类缺陷留到运行时撞大运。写的时候多挨几下编译器教育，换的是上线后半夜不被叫醒。

**问：通道和锁怎么选？**

答：数据像"接力棒"一样在线程间传递 → 通道；多个线程要**就地修改同一份状态** → 锁。有句行话："别用共享内存来通信，用通信来共享内存"——优先通道。

**问：`解包()` 在并发代码里到处出现，不会出事吗？**

答：本章为简洁用了 `解包`。生产代码里：`等待线程` 失败说明线程恐慌了，`接收` 失败说明发送端全没了——都该用 `匹配` 认真处理。

**问：线程里能用第九章的字符串吗？**

答：能，`字符串` 可以安全移动进线程（它实现了传送特征）。`移动` 闭包带它进去完全没问题——这正是示例里通道发送字符串能成功的原因。

**问：异步和线程是一回事吗？**

答：不是一回事。线程是操作系统级的并行；异步是一个线程内"等活儿时先干别的"的调度技巧。第二十四章《异步编程》详讲。
