# 第十九章：并发与多线程

现代程序经常需要同时做多件事——下载文件的同时显示进度，处理请求的同时记录日志。

Rust 提供了强大的并发工具，而且**在写代码时就能发现并发问题**——不用等到运行时才出错。

---

## 19.1 什么是并发

到目前为止，你写的所有程序都是**单线程**的——程序从第一行开始，一行一行往下执行，做完一件事再做下一件事。就像只有一个厨师，切完菜才去炒菜，炒完菜才去煲汤。

> **生活类比**：并发就像**厨房里的多个厨师**。一个厨师切菜，另一个炒菜，第三个煲汤——他们同时工作，但需要协调（比如不能同时用同一个灶台）。

```
同步（一个人做所有事）：
时间 ──────────────────────────→
厨师：切菜 → 炒菜 → 煲汤 → 完成
                     总时间 = 切菜 + 炒菜 + 煲汤

并发（多个人同时做）：
时间 ──────────────────────────→
厨师A：切菜 ──────→ 帮忙
厨师B：    炒菜 ──────→ 完成
厨师C：煲汤 ──────────────→ 完成
           总时间 ≈ 最慢的那道菜
```

**为什么要用并发？** 因为快。如果三件事互不依赖，同时做比一个一个做快得多。

**并发和并行有什么区别？**

- **并发**：多个任务**同时进行**，但可能只有一个灶台，大家轮流用（一个厨师切菜时，另一个厨师等待）。
- **并行**：多个任务**真的一起做**，因为有好几个灶台（多核 CPU）。

```
单核 CPU（并发）：        多核 CPU（并行）：
┌─ 一个灶台 ─┐            ┌─ 灶台1 ─┐  ┌─ 灶台2 ─┐
│ 切菜 → 炒菜 │            │ 切菜    │  │ 炒菜    │
│ 轮流进行   │            │ 同时进行 │  │ 同时进行 │
└────────────┘            └─────────┘  └─────────┘
```

现在的电脑基本都是多核的，但写代码时不用太纠结区别——**你只需要知道：让多件事同时开工，能更快完成任务**。

## 19.2 创建线程

**线程**就是"一个厨师"。你的程序一启动，就自动有一个线程在干活——叫**主线程**（main 函数所在的线程）。你可以让主线程"雇更多厨师"，也就是**创建新线程**。

```rust
使用 标准库::线程;
使用 标准库::time::持续时间;

函数 主函数() {
    // 创建一个新线程
    让 句柄 = 线程::生成(|| {
        对于 i 在 1..=5 {
            打印行!("工作线程：{}", i);
            线程::线程休眠(持续时间::从毫秒(100));
        }
    });

    // 主线程也在做事
    对于 i 在 1..=3 {
        打印行!("主线程：{}", i);
        线程::线程休眠(持续时间::从毫秒(100));
    }

    // 等工作线程完成
    句柄.等待线程().解包();
    打印行!("全部完成");
}
```

逐行解释：

- 第 1-2 行：引入线程和时间相关的工具（`持续时间` 用来表示"等多久"）
- 第 6 行：**`线程::生成(|| { ... })`** 创建一个新线程——"雇了一个新厨师"。注意它返回一个值，我们把它存进变量 `句柄`
- 第 6 行：**`||`** 是闭包（匿名函数，第五章讲过）——"这个厨师要做的事情"。`||` 里写的就是新线程要执行的代码
- 第 7-10 行：新线程的工作内容——从 1 打印到 5，每打印一次休息 100 毫秒
- 第 9 行：**`线程休眠`** 让这个线程"睡一小会儿"——就像厨师干完一步歇口气，让别的厨师有机会用灶台
- 第 14-17 行：主线程同时也在做事——打印 3 次。**注意：主线程和新线程是同时跑的**
- 第 20 行：**`.等待线程()`** 意思是"等新厨师做完再走"。**`解包()`** 是"取出成功的结果"（第十五章讲过，如果失败程序就崩溃并报告错误）
- 第 21 行：等新线程完成后，打印"全部完成"

**`句柄` 是什么？** `线程::生成` 创建线程后，会给你一张"收据"（在 Rust 里叫句柄）。拿着收据才能"等人做完"（`.等待线程()`）。如果不用变量接住这张收据，线程照样会运行，但你就没法等它了。

```
主线程 ──────────────────────────→
│ 打印 "主线程：1"
│ 打印 "主线程：2"         ┌── 工作线程 ──────→
│ 打印 "主线程：3"         │ 打印 "工作：1"
│ 等待线程...              │ 打印 "工作：2"
│                          │ 打印 "工作：3"
│                          │ ...
│ 打印 "全部完成"          └── 完成
└── 完成
```

**为什么需要 `.等待线程()`？** 因为如果不等，主线程可能先结束了，工作线程还没做完——程序就结束了，工作线程的结果就丢了。

> ⚠️ **注意：输出顺序不固定！** 线程是"同时"跑的，谁先打印谁后打印完全看运气（取决于操作系统怎么调度）。你可能看到：
>
> ```
> 工作线程：1
> 主线程：1
> 主线程：2
> 工作线程：2
> ...
> ```
>
> 也可能看到别的顺序。这很正常，**不要期待"一定是主线程先"**。这也是并发编程和普通编程最大的不同：结果可能每次都不完全一样。

## 19.3 移动——把食材交给新厨师

> **生活类比**：新厨师来了，你得把食材交给他——交出去之后你就不能用了。**`移动`** 关键字就是这个意思——"把数据交给新线程"。

```rust
使用 标准库::线程;

函数 主函数() {
    让 数据 = 向量![1, 2, 3];

    // 用"移动"把数据交给新线程
    让 句柄 = 线程::生成(移动 || {
        打印行!("线程中的数据：{:?}", 数据);
    });

    句柄.等待线程().解包();
    // 打印行!("{:?}", 数据);  // ❌ 数据已经交给线程了，主线程不能用了
}
```

逐行解释：

- 第 4 行：创建数据（向量里有 3 个整数）
- 第 7 行：**`移动 ||`** 意思是"把外面用到的数据都交给这个线程"。这里要交的就是 `数据`
- 第 8 行：线程内部可以使用 `数据`——因为它已经是线程自己的了
- 第 11 行：等线程做完（还记得 `.等待线程()` 吗？）
- 第 12 行：这一行被注释掉了（`//`）——主线程不能再使用 `数据`，因为它已经"送"给新线程了。如果取消注释，编译器会报错

**为什么必须用 `移动`？** 还记得第六章的所有权吗——**每个数据只能有一个主人**。新线程要用 `数据`，就必须把"所有权"（主人身份）从主线程转交给新线程。`移动` 关键字就是完成这个转让的：

- 用了 `移动`：数据的所有权**整个交给新线程**，主线程从此碰不得
- 不用 `移动`：编译器会拒绝编译——"新线程可能比主线程活得久，你借出去的东西可能已经没了"（借用规则，第七章讲过）

```
移动前：                    移动后：
主线程拥有数据              线程拥有数据
┌──────┐                  ┌──────┐
│ 数据 │ ──── 移动 ────→  │ 线程 │
│[1,2,3]│                 │[1,2,3]│
└──────┘                  └──────┘
主线程不能再使用数据
```

> ✨ **小提示**：如果主线程还需要这份数据怎么办？两个办法：① 在移动之前先 `.克隆()` 一份副本给新线程（数据会复制成两份）；② 用 19.5 会讲的 `原子引用计数`，让多个线程共享同一份数据。

## 19.4 通道——厨师之间的传送带

> **生活类比**：通道就像**传送带**——一个厨师通过传送带把菜递给另一个厨师。消息从发送端流入，从接收端流出。

```
发件箱 ──────→ 通道 ──────→ 收件箱
  线程A        (管道)        主线程
```

**为什么要用通道？** 因为线程之间不能直接共享数据（太危险了，19.5 会讲原因），但可以通过"传话"来交流。通道就是那条"传话的管道"。

```rust
使用 标准库::sync::mpsc;
使用 标准库::线程;

函数 主函数() {
    // 创建一条传送带
    让 (发件箱, 收件箱) = mpsc::通道();

    // 新线程发送消息
    线程::生成(移动 || {
        发件箱.发送("你好，主线程！".转字符串()).解包();
    });

    // 主线程接收消息
    让 消息 = 收件箱.接收().解包();
    打印行!("收到：{}", 消息);
}
```

逐行解释：

- 第 6 行：**`mpsc::通道()`** 创建一条通道——"一条传送带"。它返回**一对**东西：`发件箱`（负责发消息）和 `收件箱`（负责收消息）
- 第 6 行：`mpsc` 意思是"多生产者，单消费者"——**可以有很多个发件箱（多个人往里放），但只能有一个收件箱（一个人往外拿）**
- 第 9-11 行：新线程通过 `发件箱` 发送消息——"把菜放到传送带上"。注意这里也用了 `移动`：发件箱被送进新线程
- 第 14 行：主线程通过 `收件箱` 接收消息——"从传送带拿菜"。**`接收()` 会一直等**：如果传送带上暂时没东西，它就停在那里等（专业说法叫"阻塞"），直到有消息来
- 第 14 行：`.解包()` 取出消息——因为 `接收()` 有可能失败（比如发件箱全部被丢弃、再也没人发消息了），所以返回的是"可能成功可能失败"的结果，用 `解包()` 取出成功的值

> ⚠️ **为什么变量叫 `发件箱`、`收件箱`？** `mpsc::通道()` 返回的其实是一对"箱子"：一个专门发货，一个专门收货。`发件箱` 可以被克隆成很多份（每个线程拿一份，这就是"多生产者"）；`收件箱` 只有一份（这就是"单消费者"）。

### 发送多条消息

```rust
使用 标准库::sync::mpsc;
使用 标准库::线程;

函数 主函数() {
    让 (发件箱, 收件箱) = mpsc::通道();

    线程::生成(移动 || {
        对于 i 在 1..=5 {
            发件箱.发送(格式化!("消息 {}", i)).解包();
        }
    });

    // 逐条接收
    对于 消息 在 收件箱 {
        打印行!("收到：{}", 消息);
    }
}
```

逐行解释：

- 第 7 行：新线程在循环里发送 5 条消息
- 第 9 行：`格式化!` 把文字拼起来（第八章讲过）——第 1 次循环生成"消息 1"，第 2 次生成"消息 2"……
- 第 14 行：**`对于 消息 在 收件箱`** 把收件箱当成一个"消息流"，一条一条拿出来。它会一直等：来一条收一条，直到**所有发件箱都被丢弃**才结束（这是循环退出的条件，不用你操心）

## 19.5 互斥锁——浴室的门锁

> **生活类比**：互斥锁就像**浴室的门锁**——一次只能有一个人进去。其他人必须等门开了才能用。

```
┌── 浴室（共享数据）──┐
│                     │
│  🔒 锁住了          │  ← 线程A 正在使用
│  线程A 在里面       │
│                     │
│  线程B 在等...      │  ← 等待锁释放
│  线程C 在等...      │
└─────────────────────┘
```

**为什么需要互斥锁？** 因为如果两个线程同时修改同一个数据，可能会出问题。比如两个人同时编辑同一个文件——一个人刚写的东西可能被另一个人覆盖。

```rust
使用 标准库::sync::{互斥锁, 原子引用计数};
使用 标准库::线程;

函数 主函数() {
    // 创建一个共享计数器
    // 原子引用计数 = 多人安全共享
    // 互斥锁 = 一次只有一个人能用
    让 计数器 = 原子引用计数::新建(互斥锁::新建(0));
    让 可变 句柄们 = 向量![];

    对于 _ 在 0..10 {
        让 计数器克隆 = 原子引用计数::克隆(&计数器);
        让 句柄 = 线程::生成(移动 || {
            // 开锁，拿到数据
            让 可变 数字 = 计数器克隆.加锁().解包();
            *数字 += 1;
            // 锁自动释放（离开作用域时）
        });
        句柄们.推(句柄);
    }

    // 等所有线程完成
    对于 句柄 在 句柄们 {
        句柄.等待线程().解包();
    }

    打印行!("最终计数：{}", *计数器.加锁().解包());  // 10
}
```

逐行解释：

- 第 1 行：**`标准库::sync::{互斥锁, 原子引用计数}`** 一次引入两个工具：`互斥锁` 和 `原子引用计数`（`{ }` 是"大括号分组"，第十六章讲过）
- 第 8 行：**`原子引用计数::新建(互斥锁::新建(0))`** 从里往外读：`互斥锁::新建(0)` 先把计数器 0 锁进"浴室"，再用 `原子引用计数::新建(...)` 给浴室装上"多人共享门卡"。结果是：一个 10 个线程都能进去、但一次只能进一个的计数器
- 第 9 行：`句柄们` 这个向量用来收集 10 张"收据"（线程句柄），最后统一等待
- 第 11 行：**`对于 _ 在 0..10`** 循环 10 次。`_` 是"我不关心这个值"的占位符——我们只需要循环 10 次，用不到循环变量本身（第四章讲过 `对于` 循环）
- 第 12 行：**`.克隆()` 克隆的是"门卡"（多一个人能共享），不是复制数据**——计数器还是同一个
- 第 13 行：把克隆好的门卡送进新线程（`移动`）
- 第 15 行：**`.加锁()`** 拿门卡开门进入"浴室"——如果有人在里面，就站在门口等
- 第 16 行：`*数字 += 1` 修改共享数据（`*` 是解引用，第七章讲过——通过"遥控器"操作真正的数据）
- 第 17 行：**锁自动释放**——`数字` 离开作用域时，"浴室门"自动锁上，下一个线程可以进来了。不需要你手动"解锁"，这正是 Rust 的贴心之处
- 第 23-25 行：等 10 个线程全部完成
- 第 27 行：主线程自己开锁看一眼最终计数，打印出来

**为什么用 `原子引用计数` 而不是第十八章的 `引用计数`？** 第十八章的 `引用计数` 是**单线程专用**的——如果多个线程同时给它"计数 +1"，可能出问题（两个线程同时加，结果只加了一次，这叫**数据竞争**）。`原子引用计数` 是"防竞争版本"，内部保证计数加减是安全的，专门给多线程用。

**为什么不能直接共享一个 `可变` 变量？** 还记得第六章的所有权规则吗——**一个数据只能有一个主人**。10 个线程都想用计数器，就需要 10 份"使用权限"，`原子引用计数` 就是发权限卡的（克隆一次多一张卡）。但卡发出去了，又有新问题：两个线程同时修改计数器怎么办？——所以外面再套一层 `互斥锁`，保证**一次只有一个人能进去改**。

> ✨ **小提示**：拿锁之后要快点干活！锁占得越久，其他线程等得越久。好习惯是：**开锁 → 尽快改完 → 让锁自动释放**（别在锁里面做耗时的事情）。

```
原子引用计数 + 互斥锁 的组合：

┌────────────────────────────────┐
│ 原子引用计数（多人共享）        │
│  └── 互斥锁（一次一人使用）    │
│       └── 数据（共享的计数器）  │
│                                │
│  多个线程通过"原子引用计数"共享 │
│  通过"互斥锁"保证一次只有一个  │
│  线程修改数据                  │
└────────────────────────────────┘
```

## 19.6 Rust 的并发安全保证

Rust 最厉害的地方——**在写代码时就能发现并发问题**，不用等到程序跑起来才出错：

1. **数据竞争**：两个线程同时访问同一数据，至少一个是修改——编译器直接拒绝
2. **跨线程共享不安全的东西**：编译器会拦住

```rust
使用 标准库::线程;

函数 主函数() {
    // ✅ 字符串可以送进线程（字符串自带"跨线程通行证"）
    让 文字 = "你好".转字符串();
    线程::生成(移动 || {
        打印行!("{} ", 文字);
    }).等待线程().解包();

    // ❌ 可变借用不能送进线程（编译器直接拒绝）
    让 可变 数据 = 0;
    // 线程::生成(|| { 数据 += 1; });  // 编译错误！
}
```

**什么能送进线程、什么不能？** Rust 给类型发了两张"通行证"：

- **`发送特征`**（Send）：拥有这张证的类型，可以**安全地从一个线程搬到另一个线程**（比如整数、字符串、向量）。
- **`同步特征`**（Sync）：拥有这张证的类型，可以**安全地被多个线程同时使用**（比如 `互斥锁`、`原子引用计数`、整数）。

| 类型 | 发送特征 | 同步特征 | 说明 |
|------|:---:|:---:|------|
| 整数、布尔、浮点数 | ✅ | ✅ | 纯数据，随便搬随便用 |
| 字符串、向量 | ✅ | ✅ | 里面是堆数据，搬运安全 |
| `引用计数`（第十八章） | ❌ | ❌ | 单线程专用，计数不是防竞争的 |
| `原子引用计数`、`互斥锁` | ✅ | ✅ | 专门为多线程设计的 |
| 可变借用 `&可变` | ❌ | ❌ | 借出去的东西不能跨线程乱跑 |

你不需要背这张表——**编译器会在你犯错时自动提醒你**：写错了，编译过不去；能编译过去，就说明安全。

**为什么这很重要？** 因为在其他语言里，数据竞争是最难发现的错误之一——程序可能运行 100 次都没问题，第 101 次突然崩溃。Rust 在编译时就帮你消灭了这种隐患。

```
Rust 的并发安全：
┌──────────────────────────────────────┐
│  编译时检查：                        │
│  ├── 数据竞争 → 编译错误            │
│  ├── 跨线程移动无效类型 → 编译错误  │
│  └── 生命周期问题 → 编译错误        │
│                                      │
│  运行时保证：                        │
│  ├── 无数据竞争                      │
│  ├── 无悬垂引用                      │
│  └── 无"用完再访问"                  │
└──────────────────────────────────────┘
```

> ✨ **小提示**：你现在只需要记住两句话：**① 往线程里送数据就加 `移动`；② 多线程共享可变数据就用 `原子引用计数` + `互斥锁`**。其余细节交给编译器把关。

## 常见错误

### 忘记等待线程

```rust
使用 标准库::线程;

函数 主函数() {
    线程::生成(|| {
        打印行!("你好");
    });
    // ❌ 忘记 .等待线程()，主线程可能先结束
    // 工作线程可能来不及执行
    // 修复：让 句柄 = ...; 句柄.等待线程();
}
```

### 共享可变数据不用锁

```rust
使用 标准库::线程;

函数 主函数() {
    让 可变 计数 = 0;
    // 线程::生成(|| { 计数 += 1; });  // ❌ 数据竞争！
    // 修复：用 原子引用计数<互斥锁<整数>>
}
```

### 主线程偷偷留了一份发件箱

```rust
使用 标准库::sync::mpsc;
使用 标准库::线程;

函数 主函数() {
    让 (发件箱, 收件箱) = mpsc::通道();
    让 备用 = 发件箱.克隆();  // ❌ 主线程自己留了一份发件箱

    线程::生成(移动 || {
        发件箱.发送("消息".转字符串()).解包();
    });

    // 对于 消息 在 收件箱 { ... }  // ❌ 如果这样收消息，程序会永远等下去！
    // 收件箱只要发现"还有发件箱活着"，就会继续等
    // 而主线程手里的备用发件箱一直活着，永远不会被丢弃
    // 修复：主线程不要保留发件箱，或者用完后 丢弃(备用)
}
```

> ✨ **小提示**：还记得 19.4 说过吗——`对于 消息 在 收件箱` 要等**所有发件箱都被丢弃**才结束。所以写多线程代码时，时刻问自己：**我的发件箱都在谁手里？**

### 练习 1：多线程计数器

创建一个共享计数器，启动 5 个线程，每个线程把计数器加 100。

<details>

### 练习 3：通道汇总

创建 3 个线程，每个线程计算一段数字的和（1~3、4~6、7~9），通过通道把结果发给主线程，主线程汇总后打印总和。

<details>
<summary>参考答案</summary>

```rust
使用 标准库::sync::mpsc;
使用 标准库::线程;

函数 主函数() {
    让 (发件箱, 收件箱) = mpsc::通道();
    让 可变 句柄们 = 向量![];

    // 3 个线程，各算一段：1~3、4~6、7~9
    对于 每段 在 [1..=3, 4..=6, 7..=9] {
        让 发件箱 = 发件箱.克隆();
        让 句柄 = 线程::生成(移动 || {
            让 可变 和 = 0;
            对于 数字 在 每段 {
                和 += 数字;
            }
            发件箱.发送(和).解包();  // 把这一段的答案传回主线程
        });
        句柄们.推(句柄);
    }

    // 主线程把手里的发件箱扔掉：告诉收件箱"不会有人再发了"
    丢弃(发件箱);

    // 等 3 个线程都算完
    对于 句柄 在 句柄们 {
        句柄.等待线程().解包();
    }

    // 从收件箱取出 3 个答案，加起来
    让 可变 总数 = 0;
    对于 部分和 在 收件箱 {
        总数 += 部分和;
    }
    打印行!("总和：{}", 总数);  // 45
}
```

> ✨ **小提示**：注意第 12 行 `让 发件箱 = 发件箱.克隆();`——每次循环克隆一份新的发件箱给新线程，原来的 `发件箱` 主线程留着。第 19 行 `丢弃(发件箱)` 把主线程那份扔掉，这样收件箱才知道"人都走完了"。
</details>

## 本章小结

| 概念 | 一句话 |
|------|--------|
| 线程 | 厨房里的厨师——同时工作 |
| `线程::生成` | 雇一个新厨师（返回"收据"句柄） |
| `等待线程` | 等厨师做完再走 |
| `移动` | 把食材（数据）交给新厨师 |
| 通道 | 厨师之间的传送带 |
| `发送` / `接收` | 往传送带上放菜 / 从传送带上拿菜 |
| 互斥锁 | 浴室门锁——一次一人使用 |
| `原子引用计数` | 多人安全共享（防竞争的引用计数） |
| `发送特征` / `同步特征` | 跨线程通行证 |
