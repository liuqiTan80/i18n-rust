# 附录C：常见错误信息字典

这本字典收录了**全书正文里出现过的错误码**，外加几条 Rust 常见报错与警告，按错误码排序。
每条的「编译器说」一行是 rzc 本地化后的**原句**（句中用「」标出的位置，由编译器填入具体名字），
看见报错先从这一列反查即可；「人话」是它的通俗版解释。

**使用方法**：看到报错先找错误码（方括号里的 `E` 开头编号），翻到对应条目——每条都有"人话翻译 + 常见原因 + 解决办法"。

> 💡 记住编译器的态度：报错不是批评，是**帮你检查作业**。

## 错误码条目

### E0004 匹配不完备

- **编译器说**：匹配表达式不完备：存在没有匹配分支的可能取值
- **人话**：你的 `匹配` 漏了某种情况，万一数据是那种情况，程序不知道怎么办。
- **常见原因**：`匹配` 枚举时少写了变体，又没写 `_` 兜底臂。
- **解决**：补上漏掉的变体，或加 `_ => ...` 兜底。（第十一章）

### E0005 模式不能保证匹配成功

- **编译器说**：该模式不能保证匹配成功，但此处要求必然匹配成功的模式
- **人话**：你把"可能拆不出来"的包装式拆法用在了必须拆得开的地方——`让` 的左边、函数参数位。
- **常见原因**：`让 有值(值) = 分数;`，可 `分数` 完全可能是 `无值`。
- **解决**：改用 `匹配` 摊开两种情况，或用第十一章的 `让 … 否则 { … }` 形式给"拆不上"留退路。（第十一章）
- ⚠️ 该码的 💡 提示里可能出现 `若 让` 这种写法——**它不是本语言的词条**（实测转译后只剩 `若 let`，编译不过）。
  真实写法是 `让 模式 = 值 否则 { … };`，见第十一章「让 否则」一节。

### E0026 结构体模式里写了不存在的字段

- **编译器说**：结构体模式中使用了不存在的字段
- **人话**：拆档案卡时念了一个卡上没有的栏目名。
- **常见原因**：字段名拼错；或从英文代码抄来的字段名与母语改名后的名字不一致（附录 E 讲的正是这种错位）。
- **解决**：对照结构体定义核对字段名；只想用其中几个字段时，模式末尾补 `..` 忽略其余。（附录 E；姊妹码 E0027「未覆盖所有字段」）

### E0027 结构体模式漏了字段

- **编译器说**：结构体模式未覆盖所有字段
- **人话**：拆档案卡只念了部分栏目，剩下的一栏没交代——编译器要求你要么全念，要么明说"其余不管"。
- **解决**：在模式末尾加 `..`：`匹配 小华 { 人 { 姓名, .. } => … }`。（第十章；姊妹码 E0026「写了没有的字段」）

### E0063 结构体缺字段

- **编译器说**：结构体 「结构名」 缺少字段 「字段名」
- **人话**：造结构体时少填了字段——档案卡有空栏。
- **解决**：对照结构体定义补齐字段。（第十章）

### E0072 递归类型大小无限

- **编译器说**：递归类型缺少间接层，导致大小无限
- **人话**：类型直接包含自己，像套娃没有最里层，编译器算不出它多大。
- **解决**：用 `盒子<>` 间接包含：`节点(整数, 盒子<链表>)`。（第十九章）

### E0106 函数缺少生命周期标注

- **编译器说**：函数缺少生命周期标注
- **人话**：函数有多个引用参数还返回引用，编译器不知道返回值的有效期跟谁走。
- **解决**：照报错提示补 `<'a>` 标注——参数和返回值都写上。（第十四章）

### E0133 不安全操作要包进不安全块

- **编译器说**：不安全操作需要 unsafe 块（⚠️ 这句里 `unsafe` 当前未译，属文案残留，你照原样认即可）
- **人话**：你做了编译器保证不了安全的事（碰裸指针、调外部函数），却没把它圈进 `不安全` 块。
- **解决**：把那一行包进 `不安全 { … }`，并在注释里写清为什么它安全。（第二十六章）

### E0191 特征对象没给关联类型的值

- **编译器说**：特征对象未指定关联类型的值
- **人话**：你把带"货物类型"这种关联类型的特征当对象用，却没说货物到底是什么类型。
- **常见原因**：实现 `迭代器特征` 只写了 `函数 下一个`，漏了 `类型 货物类型 = 具体类型;`。
- **解决**：对照特征定义补上关联类型的赋值；或改用泛型参数而非特征对象。（第十三章）

### E0204 类型不能实现复制

- **编译器说**：无法自动派生 Clone
- **人话**：你想让某类型"随手复制"（`复制`/Copy），但它里面有不能随手复制的成员（比如 `字符串`）。
- **解决**：去掉 `复制` 派生，改用 `克隆()`。（第十章）
- ⚠️ **别照着 💡 提示改**：这个码的真实场景是 **`复制`（Copy）** 派生失败，可当前版本这句主句和 💡 提示都在讲 `克隆`（Clone）——那是翻译表这条文案本身的错（已在修）。看到"请为字段类型手动实现 `克隆`"不必动手：`字符串` 早就实现了 `克隆`，它缺的是 `复制`，而它**永远补不上** `复制`。正确做法就是上面那条——不派生 `复制`，改调 `.克隆()`。

### E0261 使用了未声明的生命周期

- **编译器说**：使用了未声明的生命周期
- **人话**：签名里出现了编译器不认识的 `'名字`。
- **解决**：在函数或类型的尖括号里先声明它。（第十四章）

### E0277 特征约束不满足

- **编译器说**：类型 `点` 未实现特征 `标准库::格式化::可显示`（0.9.0 实机输出；旧版曾把后半印成类型名，该缺陷已修）
- **人话**：你让"没有上岗证的类型"去做要求持证的工作。
- **解决**：给该类型实现对应特征，或换已实现的类型。（第十三章）

### E0283 类型推断歧义

- **编译器说**：类型推断歧义：存在多个可满足要求的实现
- **人话**：编译器手里有几个都能用的方案，偏偏不知道该挑哪一个，于是罢工。
- **常见原因**：`收集()` 之类的收尾方法没说明收成什么容器；类型标注全靠推断。
- **解决**：给收下来的变量标出类型：`让 结果: 向量<整数> = …收集();`。（第二十二章 22.11「错误一」）

### E0308 类型不匹配

- **编译器说**：类型不匹配：期望 「期望」，实际得到 「实际」
- **人话**：期望一种类型，实际给了另一种——盒子标签和里面的东西对不上。
- **常见原因**：整数和小数混用、`字符串` 和 `字符串引用` 混用、函数返回值和声明不符；
  解构判断漏写 `让`：`如果 有值(x) = 表达式` 须写成 `如果 让 有值(x) = 表达式`
  （解构模式必须跟 `让`，见第十一章）。
- **解决**：看报错里的"期望/实际"，用类型转换或换值。（第二章起）

### E0369 类型上找不到运算符

- **编译器说**：类型不匹配：无法对 「期望」 和 「实际」 执行运算（⚠️ 实测这两个槽位并不填"期望/实际"两个类型，而是填成**运算符本身**和其中一个操作数，整句常读作「无法对 `==` 和 `点` 执行运算」——该条文案的槽位对不上，正在修；它真正想说的是"这两个类型之间不能这么算"）
- **人话**：你对着一对没定义该运算的类型用了运算符——两个自定义结构体直接 `==`、`+` 都不行。
- **常见原因**：忘了给结构体派生 `部分相等`（转译成 `PartialEq`）就拿 `==` 比；或运算符两侧类型不一致。
- **解决**：比较运算贴 `#[派生(部分相等)]`（派生位用 `部分相等` 才转 `PartialEq`，见附录 A 的"两套词"说明）；
  算术运算改回同一类型或实现 `加法特征`。（第十二章）

### E0382 值在移动后被使用

- **编译器说**：值在移动后被使用：「变量名」
- **人话**：东西已经搬家给了别人，你又伸手去拿原来的位置——抽屉已空。
- **解决**：搬之前先 `克隆()` 一份；或改用借用 `&`。（第七章）

### E0384 不可变变量被重复赋值

- **编译器说**：不可变变量 「变量名」 被重复赋值
- **人话**：你想改一个已经钉死的变量的值——第二次 `分数 = 90;` 它不认。
- **解决**：声明时写 `让 可变 分数 = …;`；若本就不该改，那就别再改。（第三章）

### E0405 找不到特征

- **编译器说**：找不到特征 「特征名」
- **人话**：约束里写的特征名不存在——可能拼错（如把 `可排序` 写成 `偏序`），也可能是**把派生位的词放进了约束位**：`<T: 排序>` `<T: 克隆>` `<T: 复制>` 会被转成方法名 `sort`/`clone`/`copied`，编译就报本码（实测）。
- **解决**：查附录 A 的特征映射表与"特征名分两套词"说明。（第十二章）

### E0425 找不到名称

- **编译器说**：找不到名称 「名称」
- **人话**：用了一个没定义、没引入的名字。
- **常见原因**：拼写错误；忘记 `使用` 引入；作用域不对。
- **解决**：检查拼写 → 补 `使用` → 检查名字定义在哪一层。（第十五章）

### E0432 / E0433 导入解析不了、类型名找不到

- **编译器说**：E0432 无法解析导入路径；E0433 未找到类型 「名称」
- **人话**：`使用` 的地址写错了，找不到那个抽屉。两者分工：E0432 只管 `使用` 行里解析不了的模块名；E0433 还会在**表达式和类型标注**里冒出来（实测 `让 x: 未知类型 = 未知类型::造();` 同时报 E0425 + E0433），它说的是"这个名字既不是已知的类型也不是模块"。
- **解决**：逐段核对路径；模块要先声明；别把类型名写进该写模块名的位置。（第二十章）
- **补充**：表达式与属性里的限定路径前缀（如 `异步运行时::睡眠`）也会按语言包转译。
  若仍报"找不到"，注意词条值为英文原样的名称（如 `MacosLauncher`）遵循 Rust 作用域，
  在表达式中使用前需先用 `使用` 导入。

### E0435 常量里用了非常量值

- **编译器说**：常量中不能使用非常量值
- **人话**：`常量` 要求编译时就算出结果，你给了个运行时才算得出的东西（函数调用、读命令行参数）。
- **解决**：改用 `静态` 或普通 `让`；能把值写成字面量最好。（第十二章）

### E0502 可变与不可变借用冲突

- **编译器说**：无法借用 「变量名」 为可变，因为它同时也被不可变借用
- **人话**：一边有人正在读，另一边有人想改——读写不同席。
- **解决**：让读和写在时间上错开，或调整借用顺序。（第八章）

### E0507 无法移出借用的内容

- **编译器说**：无法移出借用内容
- **人话**：借来的东西不能据为己有——图书馆的书不能撕页带走。
- **解决**：克隆后再拿，或把方法改成消耗 `自我`。（第十二章）

### E0508 无法移出数组元素

- **编译器说**：无法移出数组内容
- **人话**：数组的元素不能单个搬走。
- **解决**：给枚举派生 `复制`，或克隆元素，或改用向量。（第十一章）

### E0531 未知的元组结构体或元组变体

- **编译器说**：未知的元组结构体或元组变体
- **人话**：模式里带括号写了一个**根本不存在**的元组名——名字打错了，或忘了 `枚举名::` 前缀。
- **解决**：核对枚举/结果的正确变体名，写成 `枚举名::变体名(…)`。（第十六章）
- ⚠️ **先查下一条**：实测中"变体形状写错"（给无数据变体加括号、把结构体名当元组变体用）报的是 **E0532**，
  不是本码。看到 E0531 才回来查这条。

### E0532 模式形状与类型不符

- **编译器说**：模式类型与期望不符（如用元组模式匹配结构体）
- **人话**：拆的方式和包装的实际形状不匹配——括号、花括号、纯名字三选一，你选错了。
- **常见原因**：给无数据的变体加了括号（`结果::失败(x)`，可 `失败` 本来不带值）；把结构体当元组拆（`点(_)`）；
  反过来用括号拆花括号变体也一样。
- **解决**：照编译器的提示选形状——结构体用 `结构名 { }`，元组用 `(...)`，无字段用纯名字。（第十一章、第十六章）

### E0573 期望类型但找到了方法

- **编译器说**：此处期望一个类型，但找到了同名的方法
- **人话**：签名里想要一个类型，编译器却在名字里找到了方法（比如把 `自我` 当返回类型）。
- **解决**：返回类型写具体类型名或 `自身`。（第六章）

### E0594 无法对不可变变量赋值

- **编译器说**：无法对不可变变量赋值
- **人话**：想改的东西没标 `可变`——不只是整变量，改它的字段也一样。
- **解决**：声明处加 `可变`：`让 可变 小华 = 人 { … };`。注意别和 E0596 混：这条是**赋值**，那条是**借用成可变**。（第十章）

### E0596 无法借用为可变

- **编译器说**：无法借用为可变
- **人话**：你想改一个没标 `可变` 的东西。
- **解决**：声明处加 `可变`；检查借用链是否每一环都可变。（第八章）

### E0597 借用内容未存活足够久

- **编译器说**：借用内容未存活足够久
- **人话**：借据想活得比原值还久——原值先被释放了。
- **解决**：把原值挪到更大的作用域；或克隆/造自己的数据。（第十四章）

### E0599 类型上找不到该方法

- **编译器说**：类型上找不到该方法
- **人话**：点号后面的方法这个类型没有——可能是名字拼错、类型不对，或忘记引入特征。
- **常见原因**：在 `字符串引用`（字面量那种"石碑"）上调 `.推入(…)`——`推入` 是 `字符串` 的能力，石碑类型上没有（第九章 9.2 正是这一课）；或忘记 `使用` 引入扩展方法所在特征。
- **解决**：查附录 A 方法映射表；补引入。（第九章）

### E0603 路径上的条目是私有的

- **编译器说**：「名称」 是私有的
- **人话**：你伸手进了别人上锁的抽屉——编译器只点名「哪个条目」，不替你断言它是模块、常量还是函数。
- **解决**：沿路径每一层都加 `公开`。（第十七章）

### E0608 该类型不支持索引访问

- **编译器说**：该类型不支持索引访问
- **人话**：你在 `值[下标]` 的位置上放了一个不能用方括号取的东西——比如元组、映射、或者干脆是个函数。
- **常见原因**：拿 `哈希映射` 当数组取（`电话簿["小明"]`）；或以为元组能 `对[0]` 取，实际要写 `对.0`。
- **解决**：映射改用 `.获取(键)`，它回的是 `有值(…)`/`无值`，配合 `匹配` 用（第十五章 15.4 的写法）；元组用 `.0`、`.1` 取位；只有数组、切片、向量支持方括号。（第四章、第十五章）

### E0728 `等待` 只能在异步函数或异步块中使用

- **编译器说**：`等待` 只能在异步函数或异步块中使用
- **人话**：`等待` 是个"只在异步房间里说话"的词，你在普通函数里喊了它。
- **解决**：把所在函数声明成 `异步 函数`，或把那行包进 `异步 { … }` 块（实测转译成 `async { }`，合法）；再往上一路传播，直到交给 `block_on` 这类运行时入口。（第二十四章「错误二」）

## 恐慌（运行时）

### index out of bounds（下标越界）

- **原文**：`index out of bounds: the len is 3 but the index is 9`
- **本地化**：`下标越界：长度是 3，但下标是 9`
- **人话**：数组/向量没有那个位置。
- **解决**：检查下标来源；不确定就用 `.截取(下标)`，它回 `有值(…)`/`无值` 而不恐慌（第十五章 15.2 教过）。（第十五章）

### byte index is not a char boundary（切片落进汉字中间）

- **原文**：`end byte index 1 is not a char boundary; it is inside '你' (bytes 0..3 of string)`
- **本地化**：`字节索引 1 不是字符边界；它位于 '你'（字节 0..3）内部`
- **人话**：汉字占 3 个字节，切片必须落在字符边界上。
- **解决**：切片前按字节边界想清楚，或用 `逐字符()` 处理。（第九章）

### has overflowed its stack（栈溢出）

- **原文**：`thread 'main' has overflowed its stack` + `fatal runtime error: stack overflow, aborting`（`'main'` 后的线程号每次不同）
- **本地化**：无——这条由运行时直接打印，不走界面翻译层，你看到的就是英文原文。
- **人话**：函数没完没了地叫自己，把调用栈用光了。十有八九是**忘了递归基，或问题没在变小**。
- **解决**：检查有没有"小到直接回答"的分支、每次调用参数是否严格变小；运气好的话编译器会在你跑起来之前就给 `unconditional_recursion` 警告（见下方警告表）。（第二十七章，错误一）

## 常见警告（不拦你，但值得看）

警告行的格式是 `警告[键名]: 中文句子`——**认键名比认句子可靠**，键名不随译文变。
下表五行的键名与中文句子均取自 rzc 0.9.0 实机输出（最后一行当前不本地化）。

| 键名 | 编译器说 | 人话 | 解决 |
|---|---|---|---|
| `unused_variables` | 未使用的变量：「名字」 | 变量定义了没用 | 用上它，或把名字改成下划线开头（`_数量`） |
| `unused_imports` | 未使用的导入：「路径」 | 引入了没用到的东西 | 删掉那行 `使用` |
| `dead_code` | 字段 「名字」 从未被读取 | 结构体字段只存不读 | 用起来或删掉（同一个键也报"函数/结构体从未被使用"） |
| `non_snake_case` | 「名字」 应使用蛇形命名（小写字母加下划线） | 名字被转译成了大写开头的词（撞了映射） | 换个不撞映射的名字 |
| `unconditional_recursion` | function cannot return without recursing（**不本地化**，你看到的就是英文） | 函数不递归就永远回不了头——多半缺递归基 | 查递归基和参数是否在变小（第二十七章） |

> 💡 `non_snake_case` 有个近亲：变量名撞上了**枚举变体名**（如 `有值` 转成 `Some`）时，
> 在模式里报的是 **E0530**「匹配绑定与枚举变体冲突」，不是本行的命名警告。改名字即可，两处同理。

## 使用建议

1. **先看 💡 提示**——rzc 翻译后的错误几乎都带修复建议，一半的问题读建议就解决；但**少数条目的译文本身有错**（本字典在 E0204、E0277、E0369 三条已就地标注），拿不准就 `rzc eject` 看英文原句；
2. **再看错误码**——来本字典查人话；
3. **都不行就 `rzc eject`**——看看转译后的英文代码，很多"神秘问题"是映射词撞车，一看便知。
