# 第一章：把程序跑起来

## 1.0 学习目标

读完这一章，你将能够：

1. 装好 **rzc**（中文 Rust 的命令行工具）；
2. 认识你的工作台：**一个代码编辑器 + rzc** 各自负责什么；
3. 用 `rzc run` 运行程序、`rzc check` 检查错误、`rzc eject` 导出标准 Rust；
4. 看懂中文关键字的**语法高亮**，理解 `.zh` 文件后缀的意义；
5. 分清**全角/半角**符号，避开一大类"中文标点"报错；
6. 知道 rzc 的常用命令，哪些现在用、哪些以后再学。

> ✨ 本章不引入新语法，只把环境搭好、把程序跑起来。每节都有"动手试试"，跟着做一遍就会了。

---

## 1.1 你的工作台：编辑器 + rzc

📖 **代码编辑器** 就是你写代码的地方——记事本、VS Code、VSCodium、Cursor、Neovim…… 都行。它只负责把 `.zh` 文件写出来，本身并不认识中文 Rust。

真正干活的是 **rzc**：中文 Rust 的命令行编译器前端。它把你的中文代码**翻译**成标准 Rust，再调用官方 `rustc` 完成编译、运行与检查。所以"用中文写 Rust"不是造了一门新语言，而是给真实的 Rust 换了一层母语皮——你写的每个程序，最终都由货真价实的 Rust 工具链编译运行。

> 💡 想要实时的红色波浪线（诊断）和中文关键字补全，可以给编辑器接入语言服务器 `i18n-rust-lsp`（`rzc install lsp` 一键装），并安装 rust-analyzer（`rzc install toolchain`）。**打包好的图形化 VS Code 扩展**（▶ 运行按钮、代码片段、一键格式化、命令面板、问题面板等）不在本中文专属分支内——它随 `main` 分支提供。本教程全程走命令行，等价能力一样不缺。

## 1.2 安装 rzc

**方式一（推荐）**：已装 Rust 工具链时（没装见第二章 2.4 节方式三），一条命令从 crates.io 安装：

```bash
cargo install rzc        # 从 crates.io 获取源码并在本机编译（首次约 1-3 分钟）
rzc --version            # 显示版本号即成功
```

**方式二（无网络环境）**：从 **GitHub Releases** 下载离线包（Windows 选 `rzc-<版本>-windows-x86_64.zip`）；解压后得到 `rzc` 可执行文件——打开终端（`Win + R` 输入 `cmd` 回车），**进入解压目录**使用它（或把该目录加入 PATH：设置 → 系统 → 高级系统设置 → 环境变量），同样用 `rzc --version` 验证。

> 💡 若 Releases 里暂时没有对应平台的离线包，用方式一安装即可。

> 💡 **离线包已内置 rust-analyzer**（官方发布资产下载不稳定，随包附送）与语言服务器、内置中文语言包；rustc/cargo 需自行安装（见第二章 2.4 节方式三），或联网后执行 `rzc install toolchain`。

### 动手试试：验证装好了

在终端输入：

```bash
rzc --version
```

只要打印出版本号（形如 `rzc 0.8.x`），就说明装好了。

### 环境变量（可选，一般无需配置）

| 变量 | 作用 |
|---|---|
| `RZ_LANG_DIR` | 指定语言包目录（默认使用内置语言包） |
| `RUST_ANALYZER_PATH` | 指定 rust-analyzer 路径（自动检测失败时） |

## 1.3 语法高亮：代码变彩色

📖 **语法高亮**：编辑器把代码里不同作用的词涂成不同颜色。就像课本里**重点词加粗**、**生词标红**，让眼睛一眼分清结构。

新建一个 `main.zh` 文件，敲入下面这个小程序（本教程第二章会从零讲它，这里先拿来练手）：

```rust
函数 主函数() {
    让 名字 = "小明";
    让 年龄 = 20;
    打印行!("我叫{}，今年{}岁。", 名字, 年龄);
}
```

用支持中文 Rust 的语言模式打开后你会发现：

- `函数`、`让` 等**关键字**是一种颜色；
- `"我叫{}，今年{}岁。"` 这样的**字符串**是另一种颜色；
- `20` 这样的**数字**又是另一种颜色。

颜色方案因人而异（取决于你的主题），但**一定不再是清一色的白字**。

> 💡 为什么要上色？代码一长，彩色能帮你一眼看出"哪里是关键字、哪里是文字内容"。就像地图上用绿色标公园、蓝色标河流——比全是灰色的地图好认多了。

### `.zh` 后缀很重要

`.zh` 是中文 Rust 源码的文件后缀。工具与编辑器都靠它判断"这是不是中文 Rust"。如果文件叫 `test.txt` 或没有后缀，就不会被当成中文 Rust 处理。

**检查方法**：看文件名是否以 `.zh` 结尾。

## 1.4 运行与检查：`rzc run` / `rzc check`

第二章我们会从零创建项目。这一节先用上面那个 `main.zh` 练手，跑通"编辑 → 运行 → 检查"这条主线。

在 `main.zh` 所在目录，用命令行：

```bash
rzc run main.zh      # 翻译 → 编译 → 运行，结果直接打在终端
rzc check main.zh    # 只做类型检查，不运行；报错同样中文化
```

- `rzc run` = 把程序跑起来看输出；
- `rzc check` = 只检查有没有错误，快得多（不生成可执行文件）。

运行 `rzc run main.zh`，终端会显示：

```
我叫小明，今年20岁。
```

> 📖 **终端**：屏幕上输入命令、看程序输出的黑底窗口。Windows 可用 `cmd` 或 PowerShell，macOS/Linux 用"终端 Terminal"。

### 动手试试：故意写错，看报错

把 `main.zh` 里加一行类型写错的语句（字符串塞给了整数变量）：

```rust
// 预期错误: E0308
让 年龄: 整数 = "二十";
```

运行 `rzc check main.zh`，会报 **E0308 类型不匹配**，并且——这是 rzc 的看家本领——每条错误都附带 💡 **中文教学提示**，告诉你下一步该怎么办。**不用运行**就能看到错误，这是 `check` 相比 `run` 更快反馈的原因。

> 📖 **诊断**：编译器对代码错误的检查结果。命令行里以文字报出；若接入了语言服务器，也会在编辑器里画成红色波浪线。

## 1.5 让代码排整齐（格式化）

📖 **格式化**：自动调整代码的**缩进和空格**，让排版整齐统一。就像作文写完后老师帮你把段落对齐、标点摆正——**内容一个字不改，只管排版**。

刚上手时缩进容易乱，比如：

```rust
函数 主函数() {
让 名字 = "小明";
        打印行!("你好，{}！", 名字);
}
```

养成好习惯：**写完一段就整理一次排版**。规范后的样子：

```rust
函数 主函数() {
    让 名字 = "小明";
    打印行!("你好，{}！", 名字);
}
```

命令行下最可靠的整理方式，是先导出标准 Rust 再交给官方格式化工具：

```bash
rzc eject main.zh    # 生成等价的 main.rs
cargo fmt            # 用官方 rustfmt 把 .rs 排整齐
```

或者直接让你编辑器的"格式化文档"功能来做（多数编辑器都有）。

> 💡 **比喻**：格式化就像整理书桌。书还是那些书（代码内容没变），但每样东西都回到了该在的位置，找起来快、看着舒服。

> ✨ **好习惯**：整齐的代码更好检查错误，别人（包括未来的你）也更容易读懂。

## 1.6 全角符号：中文输入法最常见的坑

代码里必须用**英文（半角）符号**。但用中文输入法打字时，很容易不小心打出**中文（全角）符号**：

| 全角（错的）  | 半角（对的） |
|--------------|--------------|
| `（）`       | `()`         |
| `；`         | `;`          |
| `“ ”`        | `" "`        |
| `｛｝`       | `{}`         |

💡 **比喻**：全角符号像"穿了棉袄的符号"——看起来差不多，但计算机认不出它，一律报错。

写 `.zh` 代码时，**代码部分**一律切到英文（半角）标点；只有在字符串 `"..."` 里面写中文内容时，才用全角标点（比如 `打印行!("你好！")` 里的感叹号就该是中文的）。

> ⚠️ 全角/半角是初学者报"看不懂的错误"的头号来源。打代码前先确认输入法处在半角状态。

> 💡 `main` 分支的 VS Code 扩展带有"全角自动转半角"的贴心功能，能替你挡掉这类错误；本中文专属分支走命令行，请自己注意。

## 1.7 rzc 命令一览

第二章起会陆续用到这些命令，先混个脸熟：

### 现在就会用的

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `rzc init <项目名>` | 生成完整项目骨架 | 开新项目 |
| `rzc run <文件>` | 翻译并运行 | 每天用 |
| `rzc check <文件>` | 类型检查（不运行） | 每天用 |
| `rzc eject <文件>` | 导出标准 `.rs` | 想看"翻译结果"时 |

### 偶尔会用到的

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `rzc transpile <文件>` | 只转译不编译，标准 Rust 打到屏幕 | 想快速核对翻译 |
| `rzc add <库名>` | 添加第三方依赖 | 需要外部库时 |
| `rzc doctor` | 诊断工具链环境 | 报"找不到 rustc" 时 |

### 以后才学的（现在知道有就行）

| 命令 | 作用 |
|---|---|
| `rzc lang list / install / remove` | 管理语言包（本分支仅内置中文） |
| `rzc mapping ...` | 第三方库母语映射的生成与校验（附录 D） |
| `rzc crate ...` | 检索/安装社区共享映射（附录 D） |

> ✨ 记不住没关系：任何时候 `rzc --help` 就能看全，速查表见附录 D。

## 1.8 常见错误与解决

### 错误一：`rzc: command not found / 不是内部或外部命令`

**原因**：rzc 没装好，或不在 PATH 里。

**解决步骤**：

1. 确认按 1.2 装好了（`rzc --version` 能出版本号）；
2. 若是解压的离线包，确保**当前目录**就是 `rzc` 所在目录，或把该目录加入 PATH；
3. 重开一个终端再试（PATH 改动要新终端才生效）。

> 📖 **PATH**：操作系统查找命令的"目录清单"。命令不在这份清单里，终端就找不到它。

### 错误二：报"找不到 rustc / cargo"

**原因**：只有 rzc，缺官方编译工具链。

**解决**：`rzc install toolchain` 一键装内置工具链（standalone rustc/cargo/rust-analyzer 到 `~/.rz/toolchain`），或自行安装 rustup。装好后 `rzc doctor` 可查状态。

### 错误三：`rzc check` 卡住没反应

**原因**：首次编译要下载并编译依赖，慢属正常。

**解决**：耐心等第一次跑完；之后有缓存会快很多。

### 错误四：中文关键字没上色

**原因**：编辑器没把该文件当中文 Rust。

**解决**：确认文件后缀是 `.zh`；给编辑器装支持中文 Rust 的语言模式，或接入语言服务器（见 1.1 的 💡）。

## 1.9 完整操作流程示例

把本章串起来，这是你以后写代码的**标准流程**：

1. **建项目**：`rzc init 我的项目 && cd 我的项目`；
2. **打开代码**：用编辑器打开 `src/main.zh`；
3. **写代码**：用半角标点敲中文 Rust；
4. **检查**：`rzc check src/main.zh`，看有没有报错（红色波浪线/中文提示）；
5. **排整齐**：`rzc eject` + `cargo fmt`，或编辑器格式化；
6. **运行**：`rzc run src/main.zh`；
7. **看结果**：终端显示程序输出；
8. **出错了**：读中文错误提示与 💡，改正后回到第 4 步。

> 💡 第 4 → 8 步会反复循环很多遍。写程序就是这样：**写一点 → 检查 → 运行 → 改错 → 再写一点**，像滚雪球一样越滚越大。

## 1.12 常见问题

**问：rzc 会不会"翻译"我的代码？我写的中文代码会被改动吗？**

答：不会。`rzc run/check` 只在内存里翻译，你的 `.zh` 文件永远是你写的样子。只有你主动 `rzc eject` 时，才会另外生成一个 `.rs` 文件。

**问：用命令行 `rzc run`，和用 `main` 分支扩展的 ▶ 按钮，结果一样吗？**

答：一样。扩展按钮背后调用的就是 rzc 命令，只是帮你省了打字。

**问：本分支能切换日文、俄文等语言吗？**

答：不能。本分支是**中文专属版**，只内置中文语言包（`.zh`）。多语言编写与图形化 VS Code 扩展都在 `main` 分支。

**问：想边写边看红色波浪线怎么办？**

答：给编辑器接入语言服务器 `i18n-rust-lsp`（`rzc install lsp`）与 rust-analyzer（`rzc install toolchain`）；图形化的即开即用体验见 `main` 分支扩展。命令行下用 `rzc check` 同样能拿到全部错误与中文提示。
