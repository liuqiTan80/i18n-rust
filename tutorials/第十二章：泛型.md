# 第十二章：泛型

## 12.0 学习目标

读完这一章，你将能够：

1. 解释泛型解决的问题：**一份代码，多种类型**；
2. 写出**泛型函数** `<T>`；
3. 看懂**特征约束** `<数: 可排序>` 的意思；
4. 写出**泛型结构体**和**泛型实现块**；
5. 解释**单态化**：为什么泛型不拖慢程序；
6. 认出老朋友：`选项<T>`、`结果<T>` 都是泛型枚举。

---

## 12.1 抄代码的烦恼

要给两个数取较大值。整数版：

```rust
函数 最大值整数(甲: 整数, 乙: 整数) -> 整数 {
    如果 甲 > 乙 { 返回 甲; }
    乙
}
```

小数版呢？**几乎一模一样**，只换了类型：

```rust
函数 最大值小数(甲: 浮点数, 乙: 浮点数) -> 浮点数 {
    如果 甲 > 乙 { 返回 甲; }
    乙
}
```

以后还有长整数版、字符版……抄到什么时候是个头？改逻辑时要改 N 份，漏一份就是 bug。

💡 **比喻**：你有一台模具。以前是**每种饼干配一台专用机器**（整数机器、小数机器……）；现在你想要**一台万能机器**——放什么面团进去，就出什么形状的饼干。

📖 **泛型（Generics）**：用"类型占位符"写代码，使用时再填入具体类型。占位符习惯写成 `<T>`（T = Type，类型）。

## 12.2 泛型函数：万能机器

```rust
函数 最大值<数>(甲: 数, 乙: 数) -> 数 {
    如果 甲 > 乙 {
        返回 甲;
    }
    乙
}
```

读法："`最大值` 接收某个类型 `数`（占位符），两个该类型的参数，返回同类型。"

但这段代码编译不过！报错大意：`数` 类型上找不到 `>` 运算符。道理很简单：**万能机器不是什么都干得了**——你塞进一团"不知道是什么"的面团，机器怎么知道能不能比较大小？必须给它**提要求**。

## 12.3 特征约束：给类型提要求

```rust
函数 最大值<数: 可排序>(甲: 数, 乙: 数) -> 数 {
    如果 甲 > 乙 {
        返回 甲;
    }
    乙
}

函数 主函数() {
    打印行!("整数较大：{}", 最大值(3, 9));
    打印行!("小数较大：{}", 最大值(2.5, 1.5));
}
```

输出：

```
整数较大：9
小数较大：2.5
```

📖 **特征约束（Trait Bound）**：写在尖括号里的要求，形如 `<数: 可排序>`——"`数` 必须具备 `可排序` 能力"。

📖 **可排序（PartialOrd）**：标准特征，表示"能比较大小"。整数、浮点数、字符都实现了它。

同一个函数，整数小数通吃——因为调用时编译器看到实参类型，自动"填空"。特征（英文 trait）的完整概念下一章讲，现在把约束读作"**能力要求**"即可。

## 12.4 泛型结构体：万能收纳盒

结构体也能带类型占位符：

```rust
结构体 一对<物> {
    前: 物,
    后: 物,
}
```

`一对` 能装任何东西，但**两栏必须同类型**（都是同一个 `物`）：

```rust
让 数对 = 一对 { 前: 1, 后: 2 };           // 物 = 整数
让 字对 = 一对 { 前: 字符串::从("天"), 后: 字符串::从("地") };   // 物 = 字符串
// 一对 { 前: 1, 后: "二" }   ❌ 前后类型不一致，报错
```

## 12.5 泛型实现块

给泛型结构体装方法，`实现` 后面也要带上占位符：

```rust
实现<物> 一对<物> {
    // 消耗自我，返回前后对调的新实例
    函数 交换(自我) -> 一对<物> {
        一对 { 前: 自我.后, 后: 自我.前 }
    }
}
```

三处对应：`实现<物>`（声明占位符）+ `一对<物>`（给谁装方法）+ 方法体里用 `物` 作返回类型。

> ⚠️ **小心**：`交换` 的第一个参数是 `自我`（消耗）而不是 `&自我`（借用）。因为把 `前`、`后` 从实例里**拿出来**对调，借用的身份干不了"搬家"的活（第八章铁律）。消耗掉旧的，返回新的，干净利落。

## 12.6 单态化：为什么泛型不慢

"万能机器"听起来运行时现猜类型，会不会很慢？**不会**。

📖 **单态化（Monomorphization）**：编译时，编译器把你用到的每种具体类型**各抄一份专用代码**。

你写了一份 `最大值<数: 可排序>`，调用了整数和小数两种——编译产物里其实有 `最大值_整数版` 和 `最大值_小数版` 两份机器码。

💡 **比喻**：你写的是"万能机器图纸"，工厂（编译器）按订单**造了两台专用机器**上流水线。运行时跑的还是专用机器，速度和你手写两份一模一样。**写代码享泛型的省事，跑程序拿专用代码的速度**——这就是 Rust 的"零成本抽象"。

## 12.7 老朋友都是泛型

回头看第十一章的 `选项`：

```rust
枚举 选项<T> {
    有些(T),
    无,
}
```

`选项<整数>` 装整数，`选项<字符串>` 装字符串——**同一个枚举定义，无限种具体类型**。第十六章的 `结果<T, E>` 也一样（T 装成功值，E 装错误信息）。泛型不是新知识，你早就在用了。

## 12.8 完整示例：万能工具箱

泛型函数 + 泛型结构体 + 泛型方法，一次看齐：

```rust
// 泛型函数：能比较大小的类型都适用
函数 最大值<数: 可排序>(甲: 数, 乙: 数) -> 数 {
    如果 甲 > 乙 {
        返回 甲;
    }
    乙
}

// 泛型结构体
结构体 一对<物> {
    前: 物,
    后: 物,
}

// 泛型实现块
实现<物> 一对<物> {
    函数 交换(自我) -> 一对<物> {
        一对 { 前: 自我.后, 后: 自我.前 }
    }
}

函数 主函数() {
    // 一个函数，两种类型
    打印行!("整数较大：{}", 最大值(3, 9));
    打印行!("小数较大：{}", 最大值(2.5, 1.5));

    // 一个结构体，两种装法
    让 一对数 = 一对 { 前: 1, 后: 2 };
    让 换后 = 一对数.交换();
    打印行!("交换后：前={}, 后={}", 换后.前, 换后.后);

    让 一对字 = 一对 { 前: 字符串::从("天"), 后: 字符串::从("地") };
    打印行!("前：{}", 一对字.前);
}
```

## 12.9 逐行解释

- **第 2–7 行**：`最大值` 带约束 `可排序`——只有能比较大小的类型才能调用。
- **第 10–13 行**：`一对<物>` 两个字段同类型。
- **第 16–20 行**：泛型实现块。`交换` 消耗自我、造新实例。
- **第 24–25 行**：同一函数，第一次调用编译器填 `数 = 整数`，第二次填 `数 = 浮点数`。
- **第 28–30 行**：`一对数` 的 `物 = 整数`。调用 `交换` 后 `一对数` 被消耗（第七章的所有权规则在泛型上一模一样），用 `换后` 接住新实例。
- **第 32–33 行**：`一对字` 的 `物 = 字符串`——同一个结构体定义，装完全不同的东西。

## 12.10 运行结果

```
整数较大：9
小数较大：2.5
交换后：前=2, 后=1
前：天
```

## 12.11 常见错误与解决

### 错误一：E0369 类型上找不到运算符

泛型函数里对 `T` 直接 `>`、`+` 报错。**解决**：加特征约束——比较用 `可排序`，相等判断用 `相等`，打印用 `可显示`。第十三章会系统讲。

### 错误二：泛型结构体前后类型不一致

`一对 { 前: 1, 后: "二" }` 报错。**解决**：同一个占位符 = 同一个类型。想要两种类型混装，用两个占位符：`结构体 一对<甲, 乙> { 前: 甲, 后: 乙 }`。

### 错误三：实现块忘了写占位符

`实现 一对<物>` 少了前面的 `实现<物>`，报"找不到类型参数 `物`"。**解决**：`实现<物> 一对<物>`——尖括号出现两次，各有职责。

### 错误四：E0507 想从借用里搬东西

`&自我` 的方法里返回 `自我.字段`（字段是字符串这类会移动的类型）报"无法移出借用内容"。**解决**：方法改成消耗 `自我`，或返回字段的 `.克隆()`。

## 12.12 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 泛型 | 类型占位符，一份代码适用多种类型，写作 `<T>` |
| 类型参数 | 尖括号里的占位符，如 `<数>` |
| 特征约束 | 对类型参数的能力要求，如 `<数: 可排序>` |
| 可排序 | 标准特征 PartialOrd，能比较大小 |
| 相等 | 标准特征 PartialEq，能判断相等 |
| 单态化 | 编译期为每种具体类型生成专用代码 |
| 零成本抽象 | 用起来方便、跑起来不加价的语言设计目标 |

> 📖 **提醒**：遇到不懂的词，随时回查全书开头的《总术语表》。

## 12.14 常见问题（FAQ）

**问：`<T>` 里的 T 必须叫 T 吗？**

答：不是，任何名字都行。本书用中文占位符（`数`、`物`）方便理解，真实项目里单字母 `T`、`U` 最常见。

**问：约束写在哪里？**

答：声明处：`函数 名<数: 可排序>(...)`。多个约束用 `+`：`<数: 可排序 + 可显示>`（既能比较又能打印）。多个类型参数逗号隔开：`<甲, 乙>`。

**问：泛型和"万能接口"（比如别的语言的 object / any）一样吗？**

答：不一样。泛型在**编译期**确定类型、各生成专用代码，又快又类型安全；any 式接口在运行时才认类型，慢且容易出错。

**问：什么时候该用泛型？**

答：发现自己在**抄几乎一样的代码、只有类型不同**时。两三次重复就值得抽象。但别为泛型而泛型——只有一种类型的场景，直接写具体类型更清楚。

**问：`选项<整数>` 和 `选项<字符串>` 是同一个类型吗？**

答：不是。它们是同一个"模板"填不同参数得到的两个独立类型，互相不能赋值。就像"红色收纳盒"和"蓝色收纳盒"出自同一款设计，但毕竟是两个盒子。

**问：下一章的"特征"和这章的"约束"是什么关系？**

答：特征 = **能力本身的定义**（"什么叫可排序"）；约束 = **使用泛型时要求对方具备某能力**。下一章教你定义自己的特征，泛型的威力才算完整解锁。

## 下一章预告

泛型把"类型"抽象了，但"能力"还没抽象：`可排序`、`可显示` 这些标准能力是天生的，那**我自己的类型**怎么获得"能打印""能比较"的能力？怎么定义全新的能力？

第十三章 **《特征》** 揭晓：

- 定义特征：`特征 可介绍 { ... }`；
- 为类型实现特征（`实现 特征名 为 类型`）；
- 默认方法、特征约束的完整写法；
- `派生` 贴纸背后的真相。
