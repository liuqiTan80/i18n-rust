# 第十九章：并发与多线程

现代程序经常需要同时做多件事——下载文件的同时显示进度，处理请求的同时记录日志。

Rust 提供了强大的并发工具，而且**在写代码时就能发现并发问题**——不用等到运行时才出错。

---

## 19.1 什么是并发

> **生活类比**：并发就像**厨房里的多个厨师**。一个厨师切菜，另一个炒菜，第三个煲汤——他们同时工作，但需要协调（比如不能同时用同一个灶台）。

```
同步（一个人做所有事）：
时间 ──────────────────────────→
厨师：切菜 → 炒菜 → 煲汤 → 完成
                     总时间 = 切菜 + 炒菜 + 煲汤

并发（多个人同时做）：
时间 ──────────────────────────→
厨师A：切菜 ──────→ 帮忙
厨师B：    炒菜 ──────→ 完成
厨师C：煲汤 ──────────────→ 完成
           总时间 ≈ 最慢的那道菜
```

**为什么要用并发？** 因为快。如果三件事互不依赖，同时做比一个一个做快得多。

## 19.2 创建线程

**线程**就是"一个厨师"。程序默认只有一个线程（叫"主线程"），你可以创建更多。

```rust
使用 标准库::线程;
使用 标准库::time::持续时间;

函数 主函数() {
    // 创建一个新线程
    让 句柄 = 线程::生成(|| {
        对于 i 在 1..=5 {
            打印行!("工作线程：{}", i);
            线程::线程休眠(持续时间::从毫秒(100));
        }
    });

    // 主线程也在做事
    对于 i 在 1..=3 {
        打印行!("主线程：{}", i);
        线程::线程休眠(持续时间::从毫秒(100));
    }

    // 等工作线程完成
    句柄.等待().解包();
    打印行!("全部完成");
}
```

逐行解释：

- 第 5 行：**`线程::生成(|| { ... })`** 创建一个新线程——"雇了一个新厨师"
- 第 5 行：**`||`** 是闭包（匿名函数）——"这个厨师要做的事情"
- 第 6-9 行：新线程的工作内容——打印 5 次
- 第 12-15 行：主线程同时也在做事——打印 3 次
- 第 18 行：**`.等待()`** 意思是"等新厨师做完再走"

```
主线程 ──────────────────────────→
│ 打印 "主线程：1"
│ 打印 "主线程：2"         ┌── 工作线程 ──────→
│ 打印 "主线程：3"         │ 打印 "工作：1"
│ 等待...                  │ 打印 "工作：2"
│                          │ 打印 "工作：3"
│                          │ ...
│ 打印 "全部完成"          └── 完成
└── 完成
```

**为什么需要 `.等待()`？** 因为如果不等，主线程可能先结束了，工作线程还没做完——程序就结束了，工作线程的结果就丢了。

## 19.3 移动——把食材交给新厨师

> **生活类比**：新厨师来了，你得把食材交给他——交出去之后你就不能用了。**`移动`** 关键字就是这个意思——"把数据交给新线程"。

```rust
使用 标准库::线程;

函数 主函数() {
    让 数据 = 向量![1, 2, 3];

    // 用"移动"把数据交给新线程
    让 句柄 = 线程::生成(移动 || {
        打印行!("线程中的数据：{:?}", 数据);
    });

    句柄.等待().解包();
    // 打印行!("{:?}", 数据);  // ❌ 数据已经交给线程了，主线程不能用了
}
```

逐行解释：

- 第 3 行：创建数据
- 第 6 行：**`移动 ||`** 意思是"把外面用到的数据都交给这个线程"
- 第 7 行：线程内部可以使用 `数据`
- 第 11 行：主线程不能再使用 `数据`——因为它已经"送"给新线程了

```
移动前：                    移动后：
主线程拥有数据              线程拥有数据
┌──────┐                  ┌──────┐
│ 数据 │ ──── 移动 ────→  │ 线程 │
│[1,2,3]│                 │[1,2,3]│
└──────┘                  └──────┘
主线程不能再使用数据
```

## 19.4 通道——厨师之间的传送带

> **生活类比**：通道就像**传送带**——一个厨师通过传送带把菜递给另一个厨师。消息从发送端流入，从接收端流出。

```
发送端 ──────→ 通道 ──────→ 接收端
  线程A        (管道)        主线程
```

**为什么要用通道？** 因为线程之间不能直接共享数据（太危险了），但可以通过"传话"来交流。

```rust
使用 标准库::sync::mpsc;
使用 标准库::线程;

函数 主函数() {
    // 创建一条传送带
    让 (发送端, 接收端) = mpsc::通道();

    // 新线程发送消息
    线程::生成(移动 || {
        发送端.发送("你好，主线程！".转字符串()).解包();
    });

    // 主线程接收消息
    让 消息 = 接收端.接收().解包();
    打印行!("收到：{}", 消息);
}
```

逐行解释：

- 第 6 行：**`mpsc::通道()`** 创建一条通道——"一条传送带"
- 第 6 行：`mpsc` 意思是"多生产者，单消费者"——可以多人发，但只能一个人收
- 第 9 行：新线程通过 `发送端` 发送消息
- 第 13 行：主线程通过 `接收端` 接收消息

### 发送多条消息

```rust
使用 标准库::sync::mpsc;
使用 标准库::线程;

函数 主函数() {
    让 (发送端, 接收端) = mpsc::通道();

    线程::生成(移动 || {
        对于 i 在 1..=5 {
            发送端.发送(格式化!("消息 {}", i)).解包();
        }
    });

    // 逐条接收
    对于 消息 在 接收端 {
        打印行!("收到：{}", 消息);
    }
}
```

逐行解释：

- 第 8-10 行：新线程发送 5 条消息
- 第 13-15 行：主线程逐条接收——`对于 消息 在 接收端` 会一直等，直到发送端关闭

## 19.5 互斥锁——浴室的门锁

> **生活类比**：互斥锁就像**浴室的门锁**——一次只能有一个人进去。其他人必须等门开了才能用。

```
┌── 浴室（共享数据）──┐
│                     │
│  🔒 锁住了          │  ← 线程A 正在使用
│  线程A 在里面       │
│                     │
│  线程B 在等...      │  ← 等待锁释放
│  线程C 在等...      │
└─────────────────────┘
```

**为什么需要互斥锁？** 因为如果两个线程同时修改同一个数据，可能会出问题。比如两个人同时编辑同一个文件——一个人刚写的东西可能被另一个人覆盖。

```rust
使用 标准库::sync::{互斥锁, 原子引用计数};
使用 标准库::线程;

函数 主函数() {
    // 创建一个共享计数器
    // 原子引用计数 = 多人安全共享
    // 互斥锁 = 一次只有一个人能用
    让 计数器 = 原子引用计数::新建(互斥锁::新建(0));
    让 可变 句柄们 = 向量![];

    对于 _ 在 0..10 {
        让 计数器克隆 = 原子引用计数::克隆(&计数器);
        让 句柄 = 线程::生成(移动 || {
            // 开锁，拿到数据
            让 可变 数字 = 计数器克隆.加锁().解包();
            *数字 += 1;
            // 锁自动释放（离开作用域时）
        });
        句柄们.推(句柄);
    }

    // 等所有线程完成
    对于 句柄 在 句柄们 {
        句柄.等待().解包();
    }

    打印行!("最终计数：{}", *计数器.加锁().解包());  // 10
}
```

逐行解释：

- 第 8 行：**`原子引用计数::新建(互斥锁::新建(0))`** 创建一个被锁保护的计数器，可以多线程安全共享
- 第 12 行：`.克隆()` 克隆的是"引用计数"（多一个人共享），不是复制数据
- 第 15 行：**`.加锁()`** 开锁进入"浴室"——如果有人在里面，就等着
- 第 16 行：`*数字 += 1` 修改共享数据
- 第 17 行：离开作用域时锁自动释放——"出浴室，门锁解开"

```
原子引用计数 + 互斥锁 的组合：

┌────────────────────────────────┐
│ 原子引用计数（多人共享）        │
│  └── 互斥锁（一次一人使用）    │
│       └── 数据（共享的计数器）  │
│                                │
│  多个线程通过"原子引用计数"共享 │
│  通过"互斥锁"保证一次只有一个  │
│  线程修改数据                  │
└────────────────────────────────┘
```

## 19.6 Rust 的并发安全保证

Rust 最厉害的地方——**在写代码时就能发现并发问题**：

1. **数据竞争**：两个线程同时访问同一数据，至少一个是修改——编译器直接拒绝
2. **跨线程共享不安全的东西**：编译器会拦住

```rust
使用 标准库::线程;

函数 主函数() {
    让 可变 数据 = 0;

    让 h1 = 线程::生成(|| {
        // 数据 += 1;  // ❌ 编译器拒绝：不能把可变借用移到线程里
    });

    让 h2 = 线程::生成(|| {
        // 数据 += 2;  // ❌ 编译器拒绝：同上
    });
}
```

**为什么这很重要？** 因为在其他语言里，数据竞争是最难发现的错误之一——程序可能运行 100 次都没问题，第 101 次突然崩溃。Rust 在编译时就帮你消灭了这种隐患。

```
Rust 的并发安全：
┌──────────────────────────────────────┐
│  编译时检查：                        │
│  ├── 数据竞争 → 编译错误            │
│  ├── 跨线程移动无效类型 → 编译错误  │
│  └── 生命周期问题 → 编译错误        │
│                                      │
│  运行时保证：                        │
│  ├── 无数据竞争                      │
│  ├── 无悬垂引用                      │
│  └── 无"用完再访问"                  │
└──────────────────────────────────────┘
```

## 常见错误

### 忘记等待线程

```rust
使用 标准库::线程;

函数 主函数() {
    线程::生成(|| {
        打印行!("你好");
    });
    // ❌ 忘记 .等待()，主线程可能先结束
    // 工作线程可能来不及执行
    // 修复：让 句柄 = ...; 句柄.等待();
}
```

### 共享可变数据不用锁

```rust
使用 标准库::线程;

函数 主函数() {
    让 可变 计数 = 0;
    // 线程::生成(|| { 计数 += 1; });  // ❌ 数据竞争！
    // 修复：用 原子引用计数<互斥锁<整数>>
}
```
