## 25.1 需求：记账本

我们写一个命令行记账本：

> 输入若干条账目（如"餐饮 25 午饭"），程序逐条入账；遇到格式或类别错误就跳过并说明；最后输出**总花费**和**分类统计**。

麻雀虽小五脏俱全——文本解析、错误处理、集合、迭代器，全要上场。

## 25.2 第一步：设计数据

先想"账目长什么样"。类别是有限选项 → **枚举**（第十一章）；一条账目有类别、金额、备注 → **结构体**（第十章）：

```rust
枚举 类别 {
    餐饮,
    交通,
    娱乐,
    其他,
}

结构体 记账条目 {
    类别: 类别,
    金额: 整数,
    备注: 字符串,
}
```

> 💡 **设计心得**：数据模型先行。模型想清楚，函数只是围绕它干活。

## 25.3 第二步：解析——把文字变数据

一行 `"餐饮 25 午饭"` 要过三关：切成三段 → 类别名转枚举 → 金额转数字。任何一关失败都返回**`结果` 的错误**（第十六章）：

```rust
函数 解析类别(名: &文本) -> 结果<类别, 字符串> {
    匹配 名 {
        "餐饮" => 成功(类别::餐饮),
        "交通" => 成功(类别::交通),
        "娱乐" => 成功(类别::娱乐),
        "其他" => 成功(类别::其他),
        别的 => 错误(格式化!("未知类别：{}", 别的)),
    }
}

函数 解析条目(行: &文本) -> 结果<记账条目, 字符串> {
    让 各段: 向量<&文本> = 行.分割(' ').收集();
    如果 各段.长度() != 3 {
        返回 错误(格式化!("格式应为'类别 金额 备注'：{}", 行));
    }
    让 类 = 解析类别(各段[0])?;
    让 金额 = 各段[1].解析::<整数>().解包();
    成功(记账条目 {
        类别: 类,
        金额: 金额,
        备注: 字符串::从(各段[2]),
    })
}
```

注意 `解析类别(各段[0])?`——一个 `?` 就把"类别不认得"的错误接力上去了（第十六章 16.4）。

## 25.4 第三步：统计——哈希映射 + 条目套路

分类累计就是第十五章的**词频套路**：

```rust
函数 分类统计(条目们: &[记账条目]) -> 哈希映射<&文本, 整数> {
    让 可变 统计 = 哈希映射::新建();
    对于 条 在 条目们 {
        让 键 = 匹配 条.类别 {
            类别::餐饮 => "餐饮",
            类别::交通 => "交通",
            类别::娱乐 => "娱乐",
            类别::其他 => "其他",
        };
        让 累计 = 统计.条目(键).或插入(0);
        *累计 = *累计 + 条.金额;
    }
    统计
}
```

枚举转文字键用了一个小技巧：`匹配` 本身是表达式，可以直接赋值（第四章伏笔回收）。

## 25.5 完整代码

```rust
使用 标准库::集合::哈希映射;

// —— 数据设计 ——
枚举 类别 {
    餐饮,
    交通,
    娱乐,
    其他,
}

结构体 记账条目 {
    类别: 类别,
    金额: 整数,
    备注: 字符串,
}

// —— 类别名转枚举（带错误处理） ——
函数 解析类别(名: &文本) -> 结果<类别, 字符串> {
    匹配 名 {
        "餐饮" => 成功(类别::餐饮),
        "交通" => 成功(类别::交通),
        "娱乐" => 成功(类别::娱乐),
        "其他" => 成功(类别::其他),
        别的 => 错误(格式化!("未知类别：{}", 别的)),
    }
}

// —— 一行文本 -> 记账条目："餐饮 25 午饭" ——
函数 解析条目(行: &文本) -> 结果<记账条目, 字符串> {
    让 各段: 向量<&文本> = 行.分割(' ').收集();
    如果 各段.长度() != 3 {
        返回 错误(格式化!("格式应为'类别 金额 备注'：{}", 行));
    }
    让 类 = 解析类别(各段[0])?;
    让 金额 = 各段[1].解析::<整数>().解包();
    成功(记账条目 {
        类别: 类,
        金额: 金额,
        备注: 字符串::从(各段[2]),
    })
}

// —— 统计各类总额 ——
函数 分类统计(条目们: &[记账条目]) -> 哈希映射<&文本, 整数> {
    让 可变 统计 = 哈希映射::新建();
    对于 条 在 条目们 {
        让 键 = 匹配 条.类别 {
            类别::餐饮 => "餐饮",
            类别::交通 => "交通",
            类别::娱乐 => "娱乐",
            类别::其他 => "其他",
        };
        让 累计 = 统计.条目(键).或插入(0);
        *累计 = *累计 + 条.金额;
    }
    统计
}

函数 主函数() {
    让 原始账本 = [
        "餐饮 25 午饭",
        "交通 4 地铁",
        "餐饮 18 奶茶",
        "娱乐 60 电影",
        "买菜 30 超市",
        "交通 2 公交",
    ];

    让 可变 账本 = 向量::新建();
    对于 行 在 原始账本 {
        匹配 解析条目(行) {
            成功(条) => {
                打印行!("入账：{}元（{}）", 条.金额, 条.备注);
                账本.推入(条);
            }
            错误(原因) => 打印行!("跳过（{}）", 原因),
        }
    }

    // 迭代器一步算总额
    让 总花费: 整数 = 账本.迭代().映射(|条| 条.金额).求和();
    打印行!("共 {} 条记录，总花费 {} 元", 账本.长度(), 总花费);

    // 分类统计
    让 统计 = 分类统计(&账本);
    对于 (类, 额) 在 &统计 {
        打印行!("{} 类共 {} 元", 类, 额);
    }
}
```

## 25.6 逐行解释

- **数据区（第 4–16 行）**：枚举圈定四种合法类别；结构体装一条账目的三要素。
- **`解析类别`（第 19–28 行）**：文字 → 枚举。最后一个臂 `别的` 兜住所有未知输入，给出具体原因。
- **`解析条目`（第 31–42 行）**：三关解析。`分割(' ')` 切段、长度校验、`?` 接力类别错误、`解析::<整数>` 转数字、最后组装结构体。
- **`分类统计`（第 45–60 行）**：借词频套路累计每类金额；返回哈希映射给调用方。
- **主函数第一段（第 63–71 行）**：原始数据故意埋一条坏账（"买菜"不是合法类别）。
- **主函数第二段（第 73–82 行）**：逐条解析——成功就打印入账并推入账本，失败就打印跳过原因。**程序没有因为一条坏数据崩溃**——这就是错误处理的价值。
- **主函数第三段（第 85–86 行）**：迭代器链 `迭代 → 映射 → 求和` 一行算出总额（第二十二章）。
- **主函数第四段（第 89–92 行）**：遍历统计表输出。

## 25.9 常见错误与解决（本项目实录）

### 错误一：字段定义了却没用

`备注` 只存不读，编译器提醒"字段从未被读取"。**解决**：要么真用起来（我们在入账打印中用上了），要么删掉。**警告不是噪音，是提醒**。

### 错误二：`解析::<整数>` 忘了尖括号

不知道要转成什么类型就报推断失败。**解决**：永远写全 `解析::<整数>`。

### 错误三：统计遍历顺序"乱"了

以为程序出错了？不是——哈希映射不保证顺序（第十五章）。**解决**：需要有序换 `有序映射`。

### 25.11.1 为什么选它

后端 `engine` 里有一个 `module_path.rs`（模块路径替换），负责把 `use` 语句里的中文路径段替换成英文（`使用 标准集合::哈希映射` → `使用 std::collections::哈希映射`）。它被选中是因为：

1. **逻辑真实**：它是转译管线的一环，每天处理真实代码，不是教学玩具；
2. **依赖少**：只用到标准库和词法分析库 `rustc_lexer`；
3. **知识点密集**：结构体、`实现`、枚举、`匹配`、状态机、字符串、`哈希映射`、`如果让`、切片——一次复习一整本书。

下面是改写后的完整代码。它在仓库根目录的 `.zh-demo/src/主函数.zh`，与原模块逐行对应，转译后可以直接编译运行。

### 25.11.2 完整代码：`主函数.zh`

```rust
// 模块路径替换（真实后端 crates/engine/src/module_path.rs 的方言改写）

使用 标准库::集合::哈希映射; // use std::collections::HashMap
使用 rustc_lexer::{TokenKind, tokenize}; // 第三方库暂无母语映射，保留英文

/// 单阶段替换结果：输出与编辑表
结构体 替换结果 {
    输出: 字符串,
    编辑表: 向量<源码映射项>,
}

/// 源码映射项：记录一次替换的位置与前后文本
结构体 源码映射项 {
    来源偏移: 无符号机器整数, // usize
    长度: 无符号机器整数,
    原文: 字符串,
    译文: 字符串,
}

实现 源码映射项 {
    // 方法名写英文 `new`：中文方法名在 `类型::中文名` 调用处会被
    // 别名映射转译（`新建` → `new`），与声明位保留的中文不一致，
    // 直接写英文即可绕开（方言允许中英文标识符混用）
    函数 new(
        source_offset: 无符号机器整数,
        length: 无符号机器整数,
        original: 字符串引用,
        replacement: 字符串引用,
    ) -> 自身 {
        自身 {
            来源偏移: source_offset,
            长度: length,
            原文: original.转字符串(),
            译文: replacement.转字符串(),
        }
    }
}

/// 替换 use 语句中的中文模块路径段
函数 替换模块路径带表(源码文本: 字符串引用, 路径映射表: 哈希映射<字符串, 字符串>) -> 替换结果 {
    如果 路径映射表.是否为空() {
        返回 替换结果 { 输出: 字符串::从(源码文本), 编辑表: 向量::新建() };
    }
    让 令牌们: 向量<_> = tokenize(源码文本).收集();
    让 mut 输出 = 字符串::新建();
    让 mut 编辑表 = 向量::新建();
    让 mut 当前偏移 = 0;
    // use 语句内的路径段才启用模块路径映射；表达式中的
    // `类型::关联函数`（如 引用计数::新建）留给别名映射处理
    让 mut 在_use_语句 = 假;

    对于 令牌 in 令牌们.迭代() {
        让 令牌长 = 令牌.len;
        让 令牌文本 = &源码文本[当前偏移..当前偏移 + 令牌长];
        匹配 令牌.kind {
            TokenKind::Ident => {
                // use 语句内所有路径段（含末段/单段）都查映射：
                // use 中不可能出现用户变量，替换安全；
                // 末段若不在路径映射（如 `服务器` 属于标识符别名），
                // 保持原样交给别名替换处理
                如果 在_use_语句 {
                    如果让 有值(英语) = 路径映射表.获取(令牌文本) {
                        编辑表.推入(源码映射项::新建(当前偏移, 令牌长, 令牌文本, 英语));
                        输出.推入字符串(英语);
                    } 否则 {
                        输出.推入字符串(令牌文本);
                    }
                } 否则 {
                    输出.推入字符串(令牌文本);
                }
                // 检测 use 语句起点（`使用` 已被词法转译为 `use`，
                // 两种写法都支持）
                如果 令牌文本 == "use" || 令牌文本 == "使用" {
                    在_use_语句 = 真;
                }
            }
            TokenKind::Semi => {
                // use 语句以分号结束
                在_use_语句 = 假;
                输出.推入字符串(令牌文本);
            }
            _ => 输出.推入字符串(令牌文本),
        }
        当前偏移 += 令牌长;
    }
    替换结果 { 输出, 编辑表 }
}

/// 演示：替换一段包含中英文混用的 use 语句
函数 主函数() {
    让 mut 映射表 = 哈希映射::新建();
    映射表.插入(字符串::从("标准集合"), 字符串::从("std::collections"));
    映射表.插入(字符串::从("文件系统"), 字符串::从("std::fs"));
    让 最终结果 = 替换模块路径带表(
        "使用 标准集合::哈希映射; 使用 文件系统;",
        映射表,
    );
    打印行!("{}", 最终结果.输出);
    打印行!("编辑表共 {} 条", 最终结果.编辑表.长度());
    对于 编辑 in 最终结果.编辑表.迭代() {
        打印行!("  [{}..{}] {} → {}", 编辑.来源偏移, 编辑.长度, 编辑.原文, 编辑.译文);
    }
}
```

### 25.11.3 一行代码的三段旅程

以 `使用 标准集合::哈希映射;` 为例，看它被处理的三个阶段：

| 阶段 | 处理的内容 | 结果 |
| --- | --- | --- |
| 词法阶段 | 关键字与类型 | `使用` → `use`（`哈希映射` 是类型名，词法阶段不处理） |
| 模块路径阶段 | `use` 语句内的路径段 | `标准集合` → `std::collections`（上面的示例函数就是本阶段） |
| 别名阶段 | 库 API 标识符 | `哈希映射` → `HashMap`、`新建` → `new`（本阶段由 rzc 内置完成） |

最终产出：`use std::collections::HashMap;`。整个转译管线就像流水线，每一段只改自己负责的东西，互不越界。

### 25.11.4 踩坑实录：方言的边界

写这个真实模块时，我们踩了几个方言的边界——它们不是 bug，是设计使然。**知道了边界，代码就不会撞墙。**

**坑 1：变量名别撞映射词。** 最初把参数命名为 `源`，转译后变成了 `Source`——因为内置映射合并了第三方库 `salvo` 的 `"源" = "Source"`。同样地，`文本` 会变成 `str`，`结果` 会变成 `Result`，`长度` 会变成 `len`。这不是错误，但会让你的中文名悄悄变成另一个名字。**建议**：自定义名字尽量用两字以上的组合词（如 `源码文本`、`令牌长`），或者直接用英文。

**坑 2：自定义方法名与库方法撞名。** 自定义方法叫 `新建`，调用处写 `源码映射项::新建(...)`——声明位保留中文 `新建`，但 `::` 后的调用处被映射转译成 `new`，两者对不上，编译报“找不到关联函数”。**建议**：自定义方法名直接写英文（`new`、`替换`），字段名不受此影响可以放心用中文。

**坑 3：参数名没有豁免。** 函数名、变量名、结构体名、字段名在声明位都会保留中文，但**参数名不在豁免名单**。参数写 `长度` 会被转成 `len`，与字段名 `长度`（保留中文）失配。**建议**：参数名统一写英文（真实后端的参数本来就是英文，照着写最稳）。

**坑 4：映射没覆盖的名字直接写英文。** `rustc_lexer` 的 `TokenKind`、`tokenize`、字段 `kind`/`len` 都没有母语映射，原样保留英文即可——方言从不强制全中文，**映射覆盖不到的，写英文是合法且推荐的**。这也解释了 `主函数` 里 `令牌.kind`、`令牌.len` 为什么是英文。

### 25.11.5 小结

这一节用生产代码验证了三件事：

1. **方言能写真实工程代码**——结构体、状态机、错误处理、标准库调用全都能跑；
2. **转译是流水线**——词法、模块路径、别名各管一段，理解管线就能预判转译结果；
3. **边界清楚反而自由**——知道哪些词会被映射，哪些会保留，就能放心混用中英文。

仓库里的 `.zh-demo/` 就是这节示例的完整项目。现在，去挑战毕业任务吧。
