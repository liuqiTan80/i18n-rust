# 第二十二章：宏与元编程

前面我们一直在"写代码"。现在我们要学一种更高级的技能——**用代码写代码**。

这听起来很神奇，但其实你已经在用了——`打印行!`、`向量!` 这些都是宏。

---

## 22.1 什么是宏

> **生活类比**：宏就像一个**文字模板**。你告诉它"帮我写一封给 XX 的信"，它就按照模板自动生成一封完整的信。你不需要每次手写，只需要换个名字就行。

```
宏的工作方式：

你写：打印行!("你好")
  ↓ 宏展开
编译器看到：标准库::io::_print(格式化参数::新字符串("你好\n"))

你不用写后面那一长串——宏帮你"展开"了
```

**为什么要用宏？** 因为有些代码模式你经常写，但写起来很啰嗦。宏帮你把啰嗦的代码"缩写"成简短的形式。

Rust 有两种宏：

| 类型 | 比喻 | 用途 |
|------|------|------|
| **声明式宏** | 填空题模板 | 基于模式匹配的文字替换 |
| **过程宏** | 智能写作助手 | 理解代码，生成新代码 |

---

## 22.2 声明式宏

> **生活类比**：声明式宏就像**高级查找替换**。你在文字处理软件里设一个模板——"每次我写'称呼：XX'，就自动展开成一封信"。

### 最简单的宏

```rust
// 定义一个宏：创建包含指定值的向量
宏 创建向量 {
    // 规则：接受逗号分隔的表达式
    ($($元素:expr),*) => {
        {
            让 可变 临时 = 向量::新建();
            $(临时.推($元素);)*
            临时
        }
    };
}

函数 主函数() {
    让 v = 创建向量!(1, 2, 3);
    打印行!("{:?}", v);  // [1, 2, 3]
}
```

逐行解释：

- 第 2 行：**`宏 创建向量 { ... }`** 定义了一个新宏
- 第 4 行：**`($($元素:expr),*)`** 是"输入格式"——接受逗号分隔的表达式
  - `$元素` 是一个变量名
  - `:expr` 表示它必须是"表达式"（任何能算出值的东西）
  - `$(...),*` 表示"重复 0 次或多次，用逗号分隔"
- 第 5 行：**`=>`** 后面是"输出代码"——展开后变成什么
- 第 7 行：创建一个临时向量
- 第 8 行：**`$(临时.推($元素);)*`** 对每个元素生成一行"推入"代码
- 第 9 行：返回临时向量

```
宏展开过程：

你写：创建向量!(1, 2, 3)
  ↓ 宏展开
让 可变 临时 = 向量::新建();
临时.推(1);
临时.推(2);
临时.推(3);
临时
```

### 匹配符号速查

| 符号 | 含义 | 例子 |
|------|------|------|
| `$变量:片段类型` | 匹配一个指定类型的代码 | `$名字:ident` 匹配标识符 |
| `$( ... )*` | 重复 0 次或多次 | `$($x:expr),*` |
| `$( ... )+` | 重复 1 次或多次 | `$(+ $x:expr)+` |

### 片段类型速查

| 片段类型 | 匹配什么 | 例子 |
|----------|---------|------|
| `expr` | 表达式 | `1+2`、`x.字段` |
| `ident` | 标识符（名字） | `变量名`、`函数名` |
| `ty` | 类型 | `整数`、`字符串` |
| `tt` | 几乎任何东西 | 最灵活 |

### 实用宏示例

```rust
// 快速创建哈希映射
宏 哈希映射 {
    ($($键:expr => $值:expr),* $(,)?) => {
        {
            让 可变 map = 标准库::集合::哈希映射::新建();
            $(map.插入($键, $值);)*
            map
        }
    };
}

函数 主函数() {
    让 分数 = 哈希映射!{
        "小明" => 85,
        "小红" => 92,
        "小刚" => 78,
    };
    打印行!("{:?}", 分数);
}
```

逐行解释：

- 第 2-11 行：定义宏——输入格式是 `键 => 值`，用逗号分隔
- 第 5 行：创建空的哈希映射
- 第 6 行：对每个"键 => 值"对，生成一行 `插入` 代码
- 第 14-18 行：使用宏——比手动一个个插入方便多了

## 22.3 过程宏

> **生活类比**：如果声明式宏是"填空题模板"，那过程宏就是**智能写作助手**——它理解你的代码，然后自动生成新代码。

过程宏最常用于 `#[派生(...)]`——自动为结构体实现特征。你在第十二章已经见过了。

### 属性宏

属性宏可以"包装"一个函数，给它添加额外功能：

```rust
// 假设有一个"计时"属性宏
// 它会自动在函数前后加上计时代码
#[计时]
函数 慢速计算() -> 整数 {
    // ... 耗时操作
    42
}

// 宏展开后大致相当于：
函数 慢速计算() -> 整数 {
    让 开始 = 即时::现在();       // ← 自动加的
    让 计算结果 = { 42 };         // ← 你的原始代码
    让 耗时 = 开始.经过时间();    // ← 自动加的
    打印行!("耗时: {:?}", 耗时);  // ← 自动加的
    计算结果                      // ← 自动加的
}
```

**为什么要用属性宏？** 因为"给函数加计时"这种需求很常见。有了属性宏，你只需要加一行 `#[计时]`，不用每次手动写计时代码。

## 22.4 宏和函数的区别

什么时候用宏，什么时候用函数？

| 场景 | 用宏 | 用函数 |
|------|------|--------|
| 参数数量不固定 | ✅ | ❌ |
| 需要生成新代码 | ✅ | ❌ |
| 只是封装逻辑 | ❌ | ✅ |
| 需要类型检查 | ❌ | ✅ |
| 错误信息友好 | ❌ | ✅ |

**经验法则**：能用函数就用函数。函数更简单、错误信息更清楚。只有当函数做不到时（比如参数数量不固定、需要生成新代码），才用宏。

## 22.5 宏的卫生性

> **生活类比**：宏是**卫生的**——宏内部的变量名不会和外面的变量名冲突。就像两个同名的人在不同公司工作，互不影响。

```rust
宏 创建变量 {
    () => {
        让 x = 42;  // 这个 x 是宏"内部"的
    };
}

函数 主函数() {
    让 x = 10;      // 这个 x 是"外部"的
    创建变量!();
    打印行!("{}", x);  // 10，不是 42！
}
```

逐行解释：

- 第 4 行：宏内部创建了一个 `x = 42`
- 第 8 行：外部有一个 `x = 10`
- 第 9 行：调用宏——但外部的 `x` 不受影响
- 第 10 行：打印的仍然是 10

## 常见错误

### 重复分隔符不匹配

```rust
宏 错误宏 {
    // 定义用逗号分隔
    ($($x:expr),*) => { };
}

// ❌ 调用时用分号——不匹配！
// 错误宏!(1; 2; 3);

// ✅ 修复：用逗号
错误宏!(1, 2, 3);
```

### 忘记触发迭代器

```rust
// ❌ 迭代器是"懒"的
数字.迭代().映射(|x| x * 2);  // 什么也没做！

// ✅ 必须用收集方法触发
让 收集结果 = 数字.迭代().映射(|x| x * 2).收集();
```

### 练习 2：计时宏

写一个宏 `计时!`，执行一段代码并打印耗时。

<details>
<summary>参考答案</summary>

```rust
宏 计时 {
    ($代码:block) => {
        {
            让 开始 = 即时::现在();
            让 计算结果 = { $代码 };
            让 耗时 = 开始.经过时间();
            打印行!("耗时 {:?}", 耗时);
            计算结果
        }
    };
}

函数 主函数() {
    计时!({
        让 可变 总和 = 0;
        对于 i 在 0..1000000 { 总和 += i; }
        总和
    });
}
```
</details>
