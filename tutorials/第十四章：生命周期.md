# 第十四章：生命周期

## 14.0 学习目标

读完这一章，你将能够：

1. 解释**生命周期**到底在管什么（引用的有效期）；
2. 看懂 **`'a`** 标注的语法和读法；
3. 知道函数什么时候**必须**标生命周期、什么时候编译器自动推断；
4. 给**持有引用的结构体**标注生命周期；
5. 看懂 **E0106**（缺少标注）和 **E0597**（引用活得比原值久）；
6. 理解 `'静态`：字符串字面量为什么永远有效。

> ✨ 这一章的符号看着唬人，其实只做一件事：**保证你手里的借据永远有效**。慢慢读，多跑例子。

---

## 14.1 回顾：借据有有效期

第八章讲过：引用是**借据**，`&值` 借来用、用完还。

💡 **比喻**：每张借据都有**有效期**——从诞生到原值被释放。有效期内，借据随便用；有效期一过，借据作废。

```rust
{
    让 临时 = 字符串::从("短命");
    // 临时 的"户口"在这个块里
}
// 块结束：临时 被释放，指向它的借据全部作废
```

📖 **生命周期（Lifetime）**：一个引用保持有效的作用范围。写作 `'名字`（一撇加名字），如 `'a`。它只是编译期的检查标记，不影响运行速度。

编译器里有个专门的部门叫**借用检查器**，天天核对：每张借据用的时候，原值还活着吗？

## 14.2 大多数时候，编译器自己算

前面十几章的代码你从没写过 `'a`，因为编译器能自己推断出有效期：

```rust
让 问候 = 字符串::从("你好");
让 借据 = &问候;      // 借据的有效期：从这行到 问候 被释放
打印行!("{}", 借据);  // ✅ 有效期内
```

只有一个来源的引用，有效期清清楚楚，不用你操心。

## 14.3 什么时候必须标：多个来源的引用

写一个函数：返回两段文字里较长的那段。

```rust
函数 最长(甲: &文本, 乙: &文本) -> &文本 {   // ❌
    甲
}
```

编译器报错 **E0106**：

```
错误[E0106]: 函数缺少生命周期标注
💡 当函数有多个引用参数时，编译器无法推断引用之间的关系。
   请在参数和返回值上标注生命周期，例如：
   函数 最长<'a>(x: &'a 文本, y: &'a 文本) -> &'a 文本
```

为什么这里推断不了？返回值是**甲和乙中的一个**——函数签名里只写类型，不写函数体逻辑，编译器站在签名的角度根本不知道返回值跟谁的有效期走。**需要你亲口说清楚**。

## 14.4 `'a` 标注：把有效期绑在一起

```rust
函数 最长<'a>(甲: &'a 文本, 乙: &'a 文本) -> &'a 文本 {
    如果 甲.长度() >= 乙.长度() {
        返回 甲;
    }
    乙
}
```

逐块读：

| 片段 | 读法 |
|---|---|
| `最长<'a>` | "本函数涉及一个有效期，起名叫 `'a`"（声明） |
| `甲: &'a 文本` | "甲是一段文字的借用，有效期至少是 `'a`" |
| `乙: &'a 文本` | "乙也一样" |
| `-> &'a 文本` | "返回值的有效期也按 `'a` 算" |

核心含义：**返回的借据，不会比两个参数的借据活得更久**。调用方只要保证两个入参都活着，返回值就安全。

> 💡 **比喻**：`'a` 像一份**联保协议**——甲、乙、返回值三方签字："我们的有效期绑定在一起，谁先到期大家一起停。"

> ✨ **重要澄清**：`'a` 标注**不改变**任何值的实际寿命，它只是把"关系"**说给编译器听**。寿命由代码结构决定，标注只是说明书。

## 14.5 结构体持有引用：也要标

结构体的字段可以是引用吗？可以，但必须标注——等于声明"**这个结构体不能活得比被借的数据久**"：

```rust
结构体 摘录<'a> {
    内容: &'a 文本,
}

实现<'a> 摘录<'a> {
    函数 汇报(&自我) {
        打印行!("摘录：{}", 自我.内容);
    }
}

// 用法：
让 原文 = 字符串::从("春眠不觉晓，处处闻啼鸟");
让 片段 = 摘录 { 内容: &原文 };
片段.汇报();
```

读法："`摘录` 持有一段借用来的文字，`'a` 是这段借用的有效期。`片段` 只能在 `原文` 活着的时候用。"

> ⚠️ **常见疑问**：为什么第十一章说"枚举变体里别装 `字符串引用`"？就是因为一旦装引用，就得写生命周期标注。装 `字符串`（自己拥有的数据）则完全不用。**初学原则：结构体、枚举尽量装自己拥有的数据（字符串、向量），少装借据。**

## 14.6 什么时候可以不标：省略规则

三条自动推断规则，知道有就行，不用背：

1. **每个引用参数各得一个自己的 `'a`**——`函数 甲(一: &文本, 二: &文本)` 内部当作两个独立有效期；
2. **只有一个引用参数时**，它的有效期自动给返回值——`函数 第一(词: &文本) -> &文本` 不用标；
3. **方法里有 `&自我`** 时，有效期的"主角"永远是 `自我`——所以第六章的方法从来不标生命周期。

拿不准？**先不写，编译器报错会手把手教你补**（E0106 的建议里直接给出正确写法，照着抄）。

## 14.7 `'静态`：活到程序结束

有一种引用的有效期最长——和程序本身一样长：字符串**字面量**。

```rust
让 标语 = "好好学习，天天向上";
```

这个 `"好好学习，天天向上"` 直接刻在程序里（第九章的"石碑"），程序从启动到退出它都在。它的生命周期叫 **`'静态`**（英文 'static）。

你平时不用手写它——字面量编译器自动认。它最常出现的地方是错误提示："我猜你要的是 `&'静态 文本`"。见到别怕，就是"这段文字终身有效"的意思。

## 14.8 完整示例：最长文字 + 摘录卡

本章两个主角合体：

```rust
// 显式生命周期：返回值的有效期和两个参数绑定
函数 最长<'a>(甲: &'a 文本, 乙: &'a 文本) -> &'a 文本 {
    如果 甲.长度() >= 乙.长度() {
        返回 甲;
    }
    乙
}

// 结构体持有引用：必须标注生命周期
结构体 摘录<'a> {
    内容: &'a 文本,
}

实现<'a> 摘录<'a> {
    函数 汇报(&自我) {
        打印行!("摘录：{}", 自我.内容);
    }
}

函数 主函数() {
    // —— 最长：两个引用进，一个引用出 ——
    让 短句 = "你好";
    让 长句 = 字符串::从("你好，世界！");
    让 赢家 = 最长(&短句, &长句);
    打印行!("更长的是：{}", 赢家);

    // —— 摘录：结构体持有引用 ——
    让 原文 = 字符串::从("春眠不觉晓，处处闻啼鸟");
    让 片段 = 摘录 { 内容: &原文 };
    片段.汇报();
    打印行!("原文还在：{}", 原文);
}
```

## 14.9 逐行解释

- **第 2–7 行**：`最长` 的三个引用（两个参数、一个返回值）全部标注 `'a`——联保协议生效。
- **第 10–12 行**：`摘录<'a>`——结构体名字后面也带 `<'a>`，因为它的字段是借据。
- **第 14–18 行**：实现块要写 `实现<'a> 摘录<'a>`——把有效期参数"传"进实现块，两处都要。
- **第 22–25 行**：`短句` 是字面量（`'静态`，天生满足任何 `'a`），`长句` 是字符串。两者借给 `最长`，返回的 `赢家` 有效期与二者绑定——这一行之后两者都还活着，安全。
- **第 28–30 行**：`片段` 借了 `原文` 的文字。编译器盯着：`片段` 的任何使用都不能越过 `原文` 的释放点。
- **第 31 行**：`片段` 用完，`原文` 自己还能打印——借用不影响主人。

## 14.10 运行结果

```
更长的是：你好，世界！
摘录：春眠不觉晓，处处闻啼鸟
原文还在：春眠不觉晓，处处闻啼鸟
```

`长度()` 比的是字节："你好，世界！"（16 字节）胜"你好"（6 字节）。

## 14.11 常见错误与解决

### 错误一：E0106 缺少生命周期标注

多引用参数的函数返回引用时触发。**解决**：照报错提示补 `'a`——参数和返回值都写上。

### 错误二：E0597 借用内容未存活足够久

```
错误[E0597]: 借用内容未存活足够久
💡 引用的生命周期超过了被引用值的生命周期。请调整作用域，让被引用值存活更久。
```

典型场景：块里借了值，想让借据活到块外。**解决**：① 把原值的声明挪到更大的作用域；② 不借了，用 `字符串::从(...)` 造自己的数据；③ 用 `克隆()`。

### 错误三：结构体字段写引用忘标注

`结构体 摘录 { 内容: &文本 }` 报错。**解决**：`结构体 摘录<'a> { 内容: &'a 文本 }`；或干脆换成 `内容: 字符串`。

### 错误四：标注写错位置

`'a` 必须紧跟 `&`：`&'a 文本`。写成 `& 文本 'a` 会语法错误。

## 14.14 常见问题（FAQ）

**问：生命周期会拖慢程序吗？**

答：完全不会。所有检查在编译期完成，运行时没有任何开销——`'a` 只是写给编译器的说明书，编译完就"扔掉"了。

**问：为什么别的语言没有这套东西？**

答：别的语言要么允许悬垂引用（崩溃风险），要么用垃圾回收（运行时开销）。Rust 用生命周期标注在编译期一次性算清——写代码时多打几个 `'a`，换来运行时的绝对安全。

**问：我是不是每个引用都要写 `'a`？**

答：不是。日常代码里 90% 的引用都不用写（省略规则覆盖）。真正要手写的就两类：① 多引用参数且返回引用的函数；② 持有引用的结构体/枚举。编译器报错时会精确告诉你缺在哪。

**问：`'a`、`'b` 可以一起用吗？**

答：可以。不同的名字 = 不同的有效期，互不绑定。只有都写 `'a` 才是"联保"。例如 `函数 甲<'a, 'b>(一: &'a 文本, 二: &'b 文本) -> &'a 文本` 表示返回值只跟 `一` 的有效期挂钩。

**问：学完这章，之前那些"先避开生命周期"的建议还要遵守吗？**

答：可以放宽了！现在你能看懂 `&'a 文本` 了。但工程上"类型拥有自己的数据"依然是好设计——借用关系越简单，代码越好维护。

**问：生命周期和所有权是什么关系？**

答：所有权管"谁是主人、何时释放"；生命周期管"借据在主人在世期间才有效"。一个是产权，一个是租期，配套组成 Rust 的内存安全体系。
