# 第 10 章：構造体

## 10.0 この章の目標

この章を終えると、あなたは次のことができるようになります：

1. **名簿カード** のたとえで構造体の役割を説明できる；
2. 構造体を定義し、 **実体** を造り、ドットでフィールドを読み書きできる；
3. **`実装`** ブロックで構造体にメソッドを取り付けられる（第 6 章の伏線をついに回収）；
4. **`#[派生(デバッグ)]`** で構造体を `{:?}` で印刷できる；
5. **タプル構造体** を書ける；
6. **`..旧実体`** 更新構文で手早く新しい実体を造れる；
7. 構造体の配列で一群のデータを管理できる。

---

## 10.1 なぜ構造体が要るのか：バラ売りデータの悩み

生徒一人の情報を記録したいとします：氏名、年齢、得点。ここまでの知識では、こう書くしかありません：

```rust
宣言 氏名甲 = "花子";
宣言 年齢甲 = 12;
宣言 得点甲 = 95;

宣言 氏名乙 = "太郎";
宣言 年齢乙 = 13;
宣言 得点乙 = 76;
```

問題は一目瞭然：三つの変数が **命名の約束ごと**（どれも「甲」付き）だけでかろうじて一组になっている。生徒が増えれば変数は空を飛び交い、どれとどれが一組かは目力頼みです。

💡 **たとえ**：これはクラス全員の資料が **床に散らばっている** 状態——氏名の紙が一枚、年齢の札が一枚、得点の票が一枚。私たちが本当に要るのは **名簿カード** ：生徒ごとに一枚、カードには三つの枠があり、各々がそれぞれの位置に収まる。

📖 **構造体**：自作できる「名簿カード」型。関連するデータをひとまとめにします。キーワードは `構造体`。

## 10.2 構造体を定義する

```rust
構造体 学生 {
    氏名: 文字列型,
    年齢: 整数,
    得点: 整数,
}
```

読み方：「 `学生` という新しい型があります。三つの欄を持つ——氏名（文字列型）、年齢（整数）、得点（整数）。」

📖 **フィールド**：構造体の中の各欄のデータ。`学生` にはフィールドが三つあります。

> ⚠️ **注意**：構造体を定義しただけでは **カードの様式を設計しただけ** で、実際のデータはまだ一つもありません。印刷所が名簿カードのテンプレートを仕上げたばかり——まだ誰の情報も書き込まれていない状態です。

## 10.3 実体を造る：一枚のカードを埋める

📖 **実体（インスタンス）**：構造体の様式に従って造られた具体的なデータの一份——中身の埋まったカード一枚です。

### 方法一：リテラルで直接埋める

```rust
宣言 花子 = 学生 {
    氏名: 文字列型::から("花子"),
    年齢: 12,
    得点: 95,
};
```

書式：`型名 { フィールド名: 値, フィールド名: 値, ... }`。 **すべてのフィールドを埋める必要があります** 、一つでも漏れるとエラー（E0063）です。

### 方法二：関連関数（コンストラクタ）

第 6 章で見ました：`実装` ブロックの中で `自己` を持たない関数が関連関数で、実体を造る専用です：

```rust
実装 学生 {
    関数 作成(氏名: 文字列型, 得点: 整数) -> 学生 {
        学生 { 氏名: 氏名, 年齢: 12, 得点: 得点 }
    }
}

// 使い方：
宣言 花子 = 学生::作成(文字列型::から("花子"), 95);
```

利点：実体を造るロジック（デフォルトの年齢など）が一つの場所に集まり、主関数はすっきり一行。

## 10.4 フィールドの読み書き：ドット

```rust
// 読む
表示行!("{}は今年{}歳", 花子.氏名, 花子.年齢);

// 書く（実体は 宣言 可変 であること）
宣言 可変 花子 = 学生 { ... };
花子.得点 = 100;
```

> ⚠️ **注意**：Rust に「このフィールドだけ可変」という書き方はありません——どんなフィールドでも変えるなら、実体全体を `宣言 可変` と宣言しなければなりません。

## 10.5 メソッド：名簿カードに機能を取り付ける

`実装` ブロックの中の、`自己` 引数を持つ関数が **メソッド** です。第 6 章の伏線をここで正式に回収します：

```rust
実装 学生 {
    // 読み取り専用メソッド
    関数 合格かな(&自己) -> ブール {
        自己.得点 >= 60
    }

    // 変更メソッド
    関数 得点を足す(可変参照 自己, 足す分: 整数) {
        自己.得点 = 自己.得点 + 足す分;
    }
}

// 呼び出し：
花子.得点を足す(5);
表示行!("{}", 花子.合格かな());
```

メソッドは普通の関数に比べて何が良いのか？ **データと振る舞いが一緒にいる** ことです。「合格判定」は学生型自身の身に付いていて、どこかの片隅に散らばった `合格判定(どれかの学生)` にはなりません。

## 10.6 デバッグ印刷：`{:?}` と派生

構造体を直接印刷してみましょう：

```rust
表示行!("{}", 花子);   // ❌ エラー：学生 型は {} 表示に対応していない
```

`{}` を使うには型が「表示」能力を実装している必要がありますが、構造体は標準では持っていません。方法は二つ——入門では最初の方法を使います：

**デバッグのシールを貼り、`{:?}` で印刷**：

```rust
#[派生(デバッグ)]
構造体 学生 { ... }

表示行!("{:?}", 花子);
```

出力：

```
学生 { 氏名: "花子", 年齢: 12, 得点: 95 }
```

`{:?}` は **デバッグ書式** ——全フィールドを一望できます。デバッグの神器です。フィールドが多くて複数行に分けたければ `{:#?}` を使います：

```rust
表示行!("{:#?}", 空色);
```

```
カラー {
    赤: 0,
    緑: 191,
    青: 255,
}
```

> 📖 **派生**：コンパイラに型のための能力の実装を自動生成させること。`#[派生(...)]` と書きます。括弧の中のトレイト名は日本語（`デバッグ`、`クローン`）でも、英語の原名（`Debug`、`Clone`）でも構いません。

## 10.7 タプル構造体：フィールド名のないまとめ方

データが単純すぎて、各欄に名前を付けるまでもないことがあります：

```rust
構造体 座標(整数, 整数);

関数 主関数() {
    宣言 点 = 座標(3, 5);
    表示行!("横：{}、縦：{}", 点.0, 点.1);
}
// 预期输出: 横：3、縦：5
```

出力：`横：3、縦：5`

`.0`、`.1` と位置でアクセスします（第 4 章のタプルと同じ）。二つ以下のフィールドで意味が自明な場面（座標、色など）に向いています。たいていの場合は、フィールド名付きの普通の構造体のほうが読みやすいのでそちらを使います。

## 10.8 更新構文：一部だけ変えて、残りは写す

古いカードを元に、 **ほぼ同じ** 新しいカードを造りたい：

```rust
宣言 花子二号 = 学生 { 得点: 88, ..花子 };
```

読み方：「新しいカードの得点は 88、 **残りのフィールドは花子からそのまま写す** 。」

> ⚠️ **所有権の注意**：`..花子` は古いカードのフィールドを新しいカードへ **移動** させます（第 7 章を思い出して）。フィールドが `文字列型` などのヒープデータだと、`花子` はこの瞬間から無効です。二枚とも使いたければ、先に `花子.クローン()` しましょう。

## 10.9 総合例：クラス名簿

構造体 + メソッド + 配列 + ループで、一クラスを管理します：

```rust
#[派生(デバッグ, クローン)]
構造体 学生 {
    氏名: 文字列型,
    得点: 整数,
}

実装 学生 {
    関数 作成(氏名: 文字列型, 得点: 整数) -> 学生 {
        学生 { 氏名: 氏名, 得点: 得点 }
    }

    関数 合格かな(&自己) -> ブール {
        自己.得点 >= 60
    }
}

関数 主関数() {
    // 配列に生徒の実体を三つしまう
    宣言 クラス = [
        学生::作成(文字列型::から("花子"), 95),
        学生::作成(文字列型::から("太郎"), 58),
        学生::作成(文字列型::から("桜子"), 88),
    ];

    // 名簿を印刷
    各 下番号 中 0..3 {
        表示行!("{:?}、合格：{}", クラス[下番号], クラス[下番号].合格かな());
    }

    // 最高点を探す
    宣言 可変 最高 = 0;
    宣言 可変 チャンピオン = 学生::作成(文字列型::から("なし"), 0);
    各 下番号 中 0..3 {
        もし クラス[下番号].得点 > 最高 {
            最高 = クラス[下番号].得点;
            チャンピオン = クラス[下番号].クローン();
        }
    }
    表示行!("チャンピオンは{}、{}点", チャンピオン.氏名, チャンピオン.得点);
}
// 预期输出: 学生 { 氏名: "花子", 得点: 95 }、合格：true
// 学生 { 氏名: "太郎", 得点: 58 }、合格：false
// 学生 { 氏名: "桜子", 得点: 88 }、合格：true
// チャンピオンは花子、95点
```

## 10.10 一行ずつ

- **1 行目**：能力を二つ同時に派生——`Debug`（`{:?}` で印刷できる）と `Clone`（`.クローン()` できる）。カンマで区切ります。
- **2〜5 行目**：`学生` 構造体はフィールド二つ。
- **8〜10 行目**：関連関数 `作成`、一行で実体を造る。
- **12〜14 行目**：読み取り専用メソッド `合格かな`。
- **19〜23 行目**： **構造体の配列** ——要素の一つ一つが生徒カード。配列の書き方は第 3 章と同じ `[要素, 要素, ...]` です。
- **26〜28 行目**：ループで印刷。`{:?}` がカードの中身をそのまま吐き出します。
- **31〜32 行目**：`チャンピオン` は最初「なし」を入れておき、空回りを防ぎます。
- **33〜38 行目**：定番の「王者決定戦」方式の最大値探し。`クラス[下番号]` で配列からカードを取り出します；配列は読み取り専用（可変と宣言していない）なので、カードを **持ち去る** ことはできず、`.クローン()` で一部コピーして `チャンピオン` に渡します。
- **40 行目**：`チャンピオン.氏名` はドットでフィールドを取ります。

## 10.11 見えるはずのもの

```
学生 { 氏名: "花子", 得点: 95 }、合格：true
学生 { 氏名: "太郎", 得点: 58 }、合格：false
学生 { 氏名: "桜子", 得点: 88 }、合格：true
チャンピオンは花子、95点
```

## 10.12 よくある失敗と直し方

### 失敗一：E0063 フィールドの記入漏れ

```
エラー[E0063]: 構造体 `{構造名}` にフィールド `{フィールド名}` がありません
💡 初期化のときすべてのフィールドに値を与える必要があります。
```

**解決**：フィールドを補うか、`..旧実体` で残りを写す。

### 失敗二：`{}` で構造体を印刷してエラー

`表示行!("{}", 花子)` は「学生 は表示トレイトを実装していない」というエラーに。**解決**：`#[派生(デバッグ)]` を貼って `{:?}` に変える；または特定のフィールド `花子.氏名` を印刷する。

### 失敗三：不変な実体のフィールドに代入

```rust
花子.得点 = 100;   // ❌ 花子 は 宣言 可変 していない
```

E0594 が出ます。**解決**：宣言に `可変` を足す：`宣言 可変 花子 = ...`。

### 失敗四：更新構文のあとで旧実体が消えた

`..花子` がフィールドを写し取り、`花子` の中の `文字列型` フィールドは移動済み——その後 `花子` を使うと E0382。**解決**：先に `花子.クローン()` してから更新するか、使用の順番を調整する。

### 失敗五：派生トレイト名の書き間違い

`#[派生(クーロン)]` は「派生マクロが見つからない」というエラーに——トレイト名の書き間違い（音便の誤字）で起こります。**解決**：トレイト名の綴りを確認：`デバッグ`、`クローン`、`コピー`、`ハッシュ`。

## 10.13 章末用語集

| 用語 | 一言でいうと |
|---|---|
| 構造体 | 自作できるまとめ型 |
| フィールド | 構造体の中の各欄のデータ |
| 実体 | 構造体に従って造られた具体的なデータ一份 |
| 関連関数 | 実装ブロック内の自己引数なしの関数。実体を造るのによく使う |
| コンストラクタ | 「関連関数」参照 |
| メソッド | 自己引数を持ち、型にぶら下がった関数 |
| 派生 | コンパイラにトレイト実装を自動生成させること。`#[派生(...)]` と書く |
| デバッグ出力 | `{:?}` 書式。デバッグ派生と合わせて構造体を印刷 |
| タプル構造体 | フィールド名がなく位置でアクセスする構造体 |
| 更新構文 | `..旧実体` で残りのフィールドを写して手早く新しい実体を造る |

> 📖 **お知らせ**：分からない言葉が出たら、いつでも本の冒頭の《総用語表》に戻って引いてください。

## 10.15 よくある質問

**Q：構造体と第 4 章のタプルは何が違う？**

どちらもまとめ役です。タプルのフィールドは **名前がなく**（`.0`、`.1` でアクセス）、場当たり的な小さな組み合わせ向き；構造体のフィールドは **名前があり** 、正式なデータモデル向き。タプル構造体はその中間です。

**Q：構造体の中に構造体を入れられる？**

入れられます。例えば `クラス` 構造体の中に生徒の配列を一つ入れる、という具合に。データは何層でも入れ子にできます——戸棚の中にカードをしまうようなものです。第 15 章でベクタ（伸び縮みできる集合）を学べば、もっと柔軟になります。

**Q：`自己` に渡されるのは結局何？**

そのメソッドを呼んだ実体そのものです。`花子.合格かな()` の中では、`自己` = `花子`。`&自己` と書けば借用、`自己` と書けば持ち去り（消耗）です。第 8 章の知識がここで丸ごと生きてきます。

**Q：実体を造るとき、リテラルでなく関連関数がおすすめなのはなぜ？**

利点が二つ——① デフォルト値を設定できる（例：`作成` の中で年齢を固定）；② 検査を挟める（例：ページ数は負にできない）。プロジェクトが大きくなったら、構築ロジックは関連関数にまとめて保守します。

**Q：`派生(デバッグ)` のシールはプログラムの速さに影響する？**

ほとんどありません。コンパイル時に生成される印刷コードでしかなく、実行時に `{:?}` を使わなければ動きません。

**Q：このあと学ぶ列挙型（第 11 章）と構造体はどういう関係？**

構造体は「 **かつ** 」——一枚のカードに氏名も年齢も得点も同時にある；列挙型は「 **または** 」——一つの値はいくつかの場合のうちの一つにしかなれない（合格／不合格／欠席）。次の章で明らかになります。

## 次は

構造体は「複数のデータをまとめる」（かつ）を解決しましたが、多くの場面は「二択、三択」（または）です：成績は優か良か可のどれか一つ；硬貨は表か裏か。

第 11 章 **《列挙型とパターンマッチ》** は、次のことを教えます：

- `列挙型` で「多択一」の型を定義する；
- 各選択肢にデータを付ける；
- `マッチ` の完全体：列挙型を解体してデータを取り出す；
- `オプション`——Rust が「値がないかもしれない」に答えた標準解答。
