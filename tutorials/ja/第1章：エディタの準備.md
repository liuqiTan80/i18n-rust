# 第 1 章：エディタの準備

## 1.0 この章の目標

この章を終えると、あなたは次のことができるようになります：

1. **コードエディタ**とは何か、なぜメモ帳では足りないのかを説明できる；
2. **VS Code** と **rust-analyzer**、そしてこの本専用の **i18n-rust** 拡張を導入できる；
3. 練習用フォルダと、最初の `.ja` ファイルを作れる；
4. あなたのコードを「母語のまま」動かす **rzc** という道具と、それがいつ役立つかを知る；
5. あとでどこからでもコマンドを見つけられる——コマンドパレットを使える。

> ✨ この章はプログラミングの知識を一切必要としません。クリックするだけです。各節に「やってみよう」箱があります。一度ついてくれば、あなたのものです。

---

## 1.1 そもそもエディタとは

### 白紙のノートとシール

💡 **たとえ**：メモ帳でコードを書くのは、砂浜に指で作文を書くようなものです——できなくはないけれど、つらい。 **コードエディタ** とは、コードのために設計されたノートです：言葉を色分けし、タイプしながら間違いを見つけ、ワンクリックでプログラムを実行します。

この本が使うエディタは **VS Code** です——無料で、強力で、世界で最も人気のあるエディタです。

📖 **拡張機能（エクステンション）**：エディタに付ける小さな追加機能——自転車のカゴのようなもの。VS Code 単体でも立派なノートですが、拡張を付けると新しい技を覚えます。

この本で大切な拡張は二つ：

- **rust-analyzer** —— 公式の Rust 拡張：シンタックスハイライト、エラーの波線、自動補完。必須。
- **i18n-rust** —— このプロジェクト専用の拡張：Rust のエラーメッセージを 10 言語に翻訳し、教育ヒント付きで表示し、さらに AI による解説を加えます。**日本語で Rust を書く読者にとっては必須**です（`.ja` ファイルを rust-analyzer が理解するのはこの拡張のおかげ）。英語話者向けの標準 Rust 本では省略可能でしたが、この本（日本語版）では欠かせません。

## 1.2 道具の導入

### 手順一：VS Code を導入する

1. https://code.visualstudio.com を開き、お使いの環境向けのインストーラをダウンロードする；
2. インストールする（既定の選択で構わない）そして開く。

ようこそ画面が出ますが、今は無視して構いません。

### 手順二：rust-analyzer 拡張を導入する

1. 左サイドバーの **拡張** アイコン（四つの正方形）をクリック；
2. `rust-analyzer` を検索；
3. 「The Rust Programming Language」（または「rust-lang」）が公開しているものの **インストール** をクリック。

### 手順三：Rust ツールチェーンを導入する

拡張が動くには Rust コンパイラが必要です。まだなら今すぐ導入してください（詳しい手順は第 2 章 2.4 節）：

- **Linux / macOS**： `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`
- **Windows**： https://rustup.rs から rustup-init をダウンロードして実行。

導入後、VS Code を **閉じて再度開く**（新しく導入した道具は新しいプロセスからでないと見つかりません）。そして確認：

1. VS Code で内蔵ターミナルを開く：メニュー **ターミナル → 新しいターミナル**；
2. `rustc --version` と入力して Enter——バージョン番号が出れば成功。

### 手順四：i18n-rust 拡張と rzc

日本語で Rust を書くなら、i18n-rust 拡張は **必須** です。これが `.ja` ファイルを理解し、エラーを日本語に翻訳します。また、コンパイラ本体の **rzc** も必要です：

```bash
cargo install rzc
```

rzc は標準 Rust も理解します（そのまま通ります）が、それに加えて次を加えます：10 言語の翻訳付き教育診断、ネットのない教室向けのオフライン梱包、そして**各学習者が母語で Rust を書けるようする方言キーワード**。日本語読者にとって、これはこの本の中心です。

> 💡 i18n-rust 拡張は rzc と連携し、次を提供します：教育ヒント付きのエラーメッセージ翻訳、AI による解説（各自の API キー）、非英語方言のコードスニペット。日本語で書くなら、これらはすべて「標準装備」です。

## 1.3 はじめてのシンタックスハイライト

📖 **シンタックスハイライト**：エディタがコードの部分ごとに違う色を塗ること。太字の重要語と赤の語彙がある教科書のように——構造が一目で分かれます。

### やってみよう

練習ファイルを作ります：

1. `Ctrl + N` で新しい白紙ファイル；
2. `Ctrl + S` で `test.ja` と名付け、練習フォルダに保存（**拡張子は必ず `.ja`**）；
3. このプログラムを一字一句打ち込む（タイピング練習にもなります）：

```rust
関数 主関数() {
    宣言 名前 = "太郎";
    宣言 年齢 = 20;
    表示行!("私の名前は {} で、{} 歳です。", 名前, 年齢);
}
```

保存（`Ctrl + S`）すると、次に気づきます：

- `関数`、`宣言` —— **予約語** は一つの色；
- `"私の名前は..."` —— **文字列** は別の色；
- `20` —— **数値** はまた別の色。

正確な配色はテーマによりますが、間違いなく **もう真っ白ではなくなります**。

> 💡 なぜ色を付けるのか？ 本当のコードは長くなります。色があれば「予約語か内容か」が一目で分かります。緑の公園と青の川がある地図のように——真っ白な地図よりずっと読みやすい。

### `.ja` 拡張子が効く

i18n-rust 拡張は認識された `.ja` ファイルでのみ働きます。ファイルが `test.txt` なら、色も波線も出ません。

**確認法**：ファイル名は `.ja` で終わるか？ 右下の欄に `Rust (日本語)` とあるか？

## 1.4 プログラムの実行：三つの方法

プログラムを動かす方法は三つあります——一番楽なものから始め、気に入ったものを選んでください。

### 方法一：▶ ボタン

`test.ja` を開いた状態で、エディタタブの **右上** を見てください：▶（再生）ボタンと ✓（チェック）ボタンがあります（i18n-rust 拡張が提供）。

- ▶ = プログラムを実行（`rzc run` と同じ）；
- ✓ = チェックのみ（`rzc check` と同じ）。

出力は下の **ターミナルパネル** に現れます。

> 📖 **ターミナルパネル**：VS Code の下部に埋め込まれたターミナル——黒い命令行窓を中に入れたもの。窓を切り替える必要がなくなります。

### 方法二：右クリックメニュー

コード領域を **右クリック**：コンテキストメニューに「実行」「チェック」そして整形コマンドがあります。

### 方法三：ターミナル（正直な方法）

単一ファイルの場合：

```bash
rzc run test.ja
```

プロジェクトの場合：

```bash
rzc new こんにちは
cd こんにちは
rzc run
```

> 📖 **ショートカット**：動作を完了するキーの組み合わせ——マウス不要。九九を知っているのと同じで、長い足し算より速い。i18n-rust 拡張は `関数 主関数` の上に「実行」というクリック可能なヒントも出します。

### やってみよう：わざと壊して、赤い波線を見る

コードにこの行を加えてください：

```rust
// 预期错误: E0308
宣言 年齢: 整数 = "二十";
```

保存後、その行の下に **赤い波線** が現れます；マウスを乗せると理由がポップアップします——型の不一致が、実行しなくても見えるのです。

> 📖 **診断（ダイアグノスティクス）**：エディタのリアルタイムなエラーチェックを、波線として描くもの。医者の診断書に付く赤い旗のようなもの。

> ⚠️ **注意**：波線が出るには i18n-rust 言語サーバが動いている必要があります。ファイルを開いて数秒経っても波線が出ないなら、1.9 節のトラブルシューティングを見てください。

### クリックできるエラー：問題パネル

`Ctrl + Shift + M` で **問題パネル** を開きます——現在のファイルのすべてのエラーと警告。一つをクリックすれば、カーソルが壊れた行へ飛びます。

## 1.5 ワンキー整形：ぐちゃぐちゃのコードが自分で整う

📖 **整形（フォーマット）**：コードの **字下げと間隔** を自動で整えること——統一され、きちんと。先生が段落を揃え句読点を正すようなもの——**言葉は一文字も変わらず、配置だけが変わる**。

### やってみよう

`test.ja` のコードをわざと乱してください（字下げを消し、適当な空白を足す）：

```rust
関数 主関数() {
宣言 名前 = "太郎";
        表示行!("こんにちは、{}！", 名前);
}
```

それから：

- **右クリック → ドキュメントのフォーマット**；または
- `Shift + Alt + F`（Mac は `Shift + Option + F`）。

コードは瞬時にきちんとした字下げに戻ります：

```rust
関数 主関数() {
    宣言 名前 = "太郎";
    表示行!("こんにちは、{}！", 名前);
}
```

> 💡 **たとえ**：整形は机を片付けるようなもの。本（コード）は変わらないのに、すべてが元の場所に戻る——探しやすく、見やすい。

> ✨ **よい習慣**：ひと区切り書き終えるごとに整形ショートカットを押しましょう。きちんとしたコードはデバッグしやすく、他人（将来のあなたも含む）にも読みやすい。

---

## 1.6 自動補完：エディタが言葉を完成させる

📖 **自動補完（オートコンプリート）**：タイプしていると、エディタが意味ありげなものを提案します。 `主関数` の中で `表` と打てば `表示行!` を含むリストが出ます——`Tab` か `Enter` を押せば完成し、プレースホルダも込みで入ります。

### やってみよう

`主関数` の中で `表` と打ち、リストを見てください。矢印キーで `表示行!` を選び Enter、引用符の中に「こんにちは」と打ちます。

> 💡 **たとえ**：自動補完は親切な助手が文章を完成させるようなもの——最初の音節を言えば、残りを知っている。i18n-rust 拡張は標準ライブラリの関数をすべて知っているので、まだ習っていないものも提案できます：リスト脇の小さな説明箱を読んでください。

## 1.7 コマンドパレット：すべてのコマンドが一つの箱

`Ctrl + Shift + P` で **コマンドパレット** を開きます——コマンド名を打てば実行できます。今すぐ使う三つ：

| コマンド | 役割 |
|---|---|
| ドキュメントのフォーマット | コードを整える（1.5 節） |
| 問題：問題ビューにフォーカス | エラーパネル（1.4 節） |
| Rust Analyzer：サーバーの再起動 | 波線が消えたり補完が死んだりした時 |

あとで使う三つ：

| コマンド | 役割 |
|---|---|
| i18n-rust コマンド | 診断の翻訳、AI 解説（導入時） |
| ターミナル：新しいターミナルの作成 | 内蔵ターミナル |
| ウィンドウの再読み込み | どこでも使える「一度消してつける」 |

> ✨ 覚える必要はありません：`Ctrl + Shift + P` を押して、やりたいことの最初の文字を打つだけ。

## 1.8 一連の作業例

この章をつなげます——これがこれからの **標準的な作業手順** です：

1. **プロジェクトを開く**：VS Code → ファイル → フォルダを開く → プロジェクトを選ぶ；
2. **コードを開く**：ファイルツリーで `src/main.ja` をクリック；
3. **書く**：自動補完に言葉を完成させてもらい、タイプ中に赤い波線に気を配る；
4. **保存**：`Ctrl + S`；
5. **整える**：`Shift + Alt + F` でフォーマット；
6. **実行**：右上の ▶ をクリック（またはターミナルで `rzc run`）；
7. **結果を見る**：ターミナルパネルに出力が出る；
8. **エラー時**：`Ctrl + Shift + M` で問題パネルを開く；エラーをクリックして飛び、直して手順 4 へ戻る。

> 💡 手順 4 → 8 は何度も何度も繰り返されます。それがプログラミングです：**少し書く → チェック → 実行 → 直す → もう少し書く**——坂を転がる雪だるま。

## 1.9 よくある失敗と直し方

### 失敗一：`.ja` ファイルに色も波線も付かない

**原因**：i18n-rust 拡張が動いていないか、ファイルが Rust として認識されていない。

**直し方（順に）**：

1. 右下の欄が `Rust (日本語)` になっているか確認。なっていなければクリックして手動で選ぶ；
2. 拡張子が本当に `.ja` か確認（Windows は拡張子を隠すことがある——実は `test.ja.txt` かも；エクスプローラで「拡張子を表示」を有効に）；
3. `Ctrl + Shift + P` で `ウィンドウの再読み込み` と打ち Enter。

### 失敗二：赤い波線がなく、エラーを見逃す

**原因**：言語サーバが起動していない——たいてい **rustc が導入されていないか、見つからない**。

**直し方（順に）**：

1. VS Code の内蔵ターミナル（メニュー：ターミナル → 新しいターミナル）で `rustc --version` を打つ：
   - 「command not found」→ rustc が導入されていないか PATH にない；1.2 節手順三をやり直し、VS Code を開き直す；
2. `Ctrl + Shift + P` で **Rust Analyzer：サーバーの再起動** を実行；
3. それでも駄目？ `ウィンドウの再読み込み`。

> 📖 **PATH**：コマンドを見つけるための OS の「ディレクトリ一覧」。その一覧に載っていないコマンドは、ターミナルから見つけられません。

### 失敗三：実行ボタンが「rustc not found」でエラー

失敗二と同じ根っこ。rustc が妙な場所にあるなら、システムに教えます：

- rustup が正しく導入されたか確認（1.2 節手順三）；
- VS Code の設定で `rust` を検索し、非標準の配置ならツールチェーン関連のパスを確認。

### 失敗四：整形が何もしない

**原因**：ファイルが Rust として認識されていない。

**直し方**：まず失敗一の手順を済ませてから整形。

### 失敗五：ショートカットが何もしない

**考えられる原因**：別のアプリや入力メソッドがショートカットを奪った（`Ctrl + Shift + C` はある配列では「コピー」、中国語入力では「簡体/繁体変換」の意味になる）。

**直し方**：メニューを使えば同じ動作。あるいは VS Code の設定 → キーボードショートカットで再割り当て。

## 1.12 よくある質問

**Q：拡張は私のファイルを変えますか？ コードが書き換わりますか？**

いいえ。i18n-rust / rust-analyzer がするのは **色付け・チェック・補完** だけです。あなたの `.ja` ファイルは書いた通りのままです。整形は空白を並べ替えるだけです。

**Q：同じプロジェクトにターミナルとエディタボタン、両方使えますか？ 結果は変わりますか？**

変わりません。ボタンは裏で同じ rzc / rustc コマンドを走らせているだけ——タイプの手間を省くだけです。自由に使ってください。

**Q：友だちが別のエディタ（JetBrains 系など）を使っています。この本は当てはまりますか？**

はい。概念（プロジェクト、コンパイラ、エラーメッセージ）は同じです；ボタンの場所が違うだけです。rust-analyzer には JetBrains 版（RustRover）もあります。

**Q：標準 Rust を書くなら rzc は何のためですか？**

日本語で Rust を書くなら、rzc と i18n-rust 拡張があってこそです：学習者が **自分の母語** で Rust を書け（10 言語対応）、エラーメッセージを教育ヒント付きで翻訳し、すべてオフラインで梱包できます。日本語版のこの本は、まさにそのために rzc を使います。

**Q：AI チャットのような機能をクリックしても何も起きません**

AI 機能には各自の AI サービス鍵とアドレス設定が必要です——省略可能なコースです。初心者はまったく必要ありません；飛ばしても書いて走らせることに何も変わりません。

**Q：拡張を上げたら、突然エラーが壁のように出ました？**

まず「Rust Analyzer：サーバーの再起動」を実行し、それから `ウィンドウの再読み込み`。それでも壊れる？ ツールチェーンが無事か確認（`rustc --version`）。
