# 第 11 章：列挙型とパターンマッチ

## 11.0 この章の目標

この章を終えると、あなたは次のことができるようになります：

1. 列挙型と構造体の違い（「または」と「かつ」）を説明できる；
2. **単純な列挙型** と **データ付きの列挙型** を定義できる；
3. `マッチ` で列挙型を解体し、付属データを取り出せる；
4. **E0004**（マッチの非網羅）を読んで直せる；
5. **`オプション`** 型で「値があるかもしれないし、ないかもしれない」を表現できる；
6. なぜ Rust に「ヌルポインタ」という落とし穴がないのか説明できる。

---

## 11.1 列挙型：一つの多肢選択問題

第 10 章の構造体は「 **かつ** 」でした：一枚の生徒カードに氏名も年齢も得点も **同時に** あります。

しかし生活の中には「 **または** 」のほうが多いものです：

- 信号は **赤か**、 **黄か**、 **青か** のどれか一つ；
- 硬貨は **表か**、 **裏か** のどちらか；
- 一つの問題への解答は **正解か**、 **誤答か**、 **無答か** のどれか。

📖 **列挙型**：一つの値が **列挙されたいくつかの場合のうちの一つ** にしかなれない型。キーワードは `列挙型` です。

💡 **たとえ**：列挙型は **マークシートの解答欄** のようなもの——与えられた選択肢から一つだけ塗れる。「その他」は選べないし、二つ同時に塗ることも許されません。

## 11.2 単純な列挙型：信号機

```rust
列挙型 信号機 {
    赤,
    黄,
    青,
}
```

📖 **バリアント（変種）**：列挙型の取り得る値の一つ一つ。`信号機` にはバリアントが三つあります。

使うときは `列挙型名::バリアント名` と書きます：

```rust
関数 信号機の動き(灯: 信号機) {
    マッチ 灯 {
        信号機::赤 => 表示行!("止まれ"),
        信号機::黄 => 表示行!("准备"),
        信号機::青 => 表示行!("進め"),
    }
}

関数 主関数() {
    信号機の動き(信号機::赤);
    信号機の動き(信号機::黄);
    信号機の動き(信号機::青);
}
```

出力：

```
止まれ
准备
進め
```

整数の 1、2、3 で信号を表すより何が良いのか？ **名前自体が意味を持つ** うえ、「4 番目の信号」など渡そうとしても——コンパイラがそもそも受け付けません。

## 11.3 データ付きの列挙型

バリアントは **手荷物を持ち運べます** ：

```rust
列挙型 成績 {
    点数(整数),        // 整数を一つ伴う
    欠席,              // 何も伴わない
    履修免除(文字列型),      // 文字を一節伴う（免除の理由を書く）
}
```

読み方：「成績には三通りしかない——具体的な点数であるか、欠席であるか、履修免除（理由付き）であるか。」

値を作る：

```rust
宣言 甲 = 成績::点数(88);
宣言 乙 = 成績::欠席;
宣言 丙 = 成績::履修免除(文字列型::から("履修済み"));
```

> ⚠️ **注意**：バリアントの手荷物の型には、`文字列参照` でなく `文字列型` を使うようにしましょう——後者は寿命注釈（第 14 章の難所）に絡むので、入門のうちは避けて通ります。

### 列挙型と構造体

| | 構造体 | 列挙型 |
|---|---|---|
| 意味 | これらのフィールドが **同時に** 成立 | これらの場合の **どれか一つ** |
| 例 | 学生 = 氏名 + 年齢 + 得点 | 成績 = 点数 / 欠席 / 履修免除 |

両者は **組み合わせて使える** ので（次章のトレイト、第 15 章の集合で登場します）、威力は無限大です。

## 11.4 マッチ：手荷物を開ける

第 5 章で `マッチ` の基本（整数や範囲とのマッチ）を学びました。列挙型に対しては、`マッチ` はさらに **バリアントの手荷物を開けてデータを取り出せます** ：

```rust
関数 成績報告(件: 成績) {
    マッチ 件 {
        成績::点数(値) => 表示行!("得点：{}", 値),
        成績::欠席 => 表示行!("欠席、成績なし"),
        成績::履修免除(理由) => 表示行!("履修免除：{}", 理由),
    }
}
```

`成績::点数(値)` の読み方：「これが点数付きの成績なら、中の整数を **取り出して `値` と名付ける** 。」括弧の中身が手荷物を開ける動作です。

出力：

```
得点：88
欠席、成績なし
履修免除：履修済み
```

## 11.5 網羅：一つも漏らせない

Rust の鉄律： **マッチはすべてのバリアントを覆わなければならない** 。一つでも漏れると **E0004** が出ます：

```rust
列挙型 信号 { 赤, 青 }

マッチ 今 {
    信号::赤 => 表示行!("止まれ"),
    // 青 が漏れている ❌
}
```

実際のエラー：

```
エラー[E0004]: マッチ式が網羅的ではありません：アームのない値が存在します
💡 マッチはすべての場合をカバーする必要があります。不足しているアームを追加するか、`_` ワイルドカードアームで受け皿を作ってください。
```

**修理は二通り**：① 各バリアントを補う；② `_` で受け皿を作る（第 5 章で学びました）：

```rust
マッチ 今 {
    信号::赤 => 表示行!("止まれ"),
    _ => 表示行!("それ以外はすべて進む"),
}
```

> 💡 **なぜこんなに厳しい？** 将来 `信号機` に「点滅」バリアントを追加したとします。すると、それを処理していないマッチ箇所は全部すぐに E0004 を出します——コンパイラが **背中を押して** あなたに隅々まで更新させ、一箇所も逃げ場を与えません。これが列挙型の最大の安心感です。

## 11.6 補足：パターンマッチの全形態

ここまでパターンは `マッチ` の中にしか現れませんでした。実はパターンは **他にもいろんな場所** で使え、しかも各种のバリエーションがあります。この節で「パターン」という手芸を仕上げましょう——これ以降コードを読むとき、「値を解体している」箇所を見つけたら、そこでパターンが働いていると分かります。

### if let：一つの場合だけ気になる

`マッチ` はすべての場合を網羅する必要があります（11.5 のとおり）。でも **そのうちの一つ** だけ気になって、残りはまとめて処理すればいいとき、`マッチ` ではくどい：

```rust
宣言 点数: オプション<整数> = あり(95);

if let あり(値) = 点数 {
    表示行!("点がある：{}", 値);
} そうでなければ {
    表示行!("点がない");
}
```

> 📖 **if let**：`if let パターン = 値 { ... } そうでなければ { ... }` —— `値` を `パターン` で試します： **当てはまれば** 解体して最初のブロックを実行し、 **当てはまらなければ** `そうでなければ` へ進みます。ja 方言ではこの二語は英語のまま（`if let` / `while let`）——英語話者の母語方言そのものだからです。

💡 **たとえ**：`マッチ` が自動販売機の **全部の** ボタンを押して回るなら、`if let` は **一つの** ボタンだけ押す——当たれば商品が出て、外れたら別の機械へ行く。

`if let あり(値) = 点数` の読み方：「もし `点数` が `あり(...)` なら、中の値を取り出して `値` と呼ぶ。」`マッチ 点数 { あり(値) => ..., なし => ... }` と同じことの、短い書き方です。

### while let：if let のループ版

```rust
宣言 可変 残り: オプション<整数> = あり(3);
while let あり(値) = 残り {
    表示行!("残り {}", 値);
    残り = なし;
}
```

📖 **while let**：`while let パターン = 値 { ... }` —— `値` が `パターン` に当てはまり続けるかぎり、解体してループ本体を一度実行し、 **もう一度試します** ；当てはまらなければループ終了。

（上の例はわざと `残り` を `なし` にしているので一周で終わります。実際の場面では「変化していく値」から繰り返し取る——たとえばイテレータから次々に取り出す——のが定番です。）

### let else：解体できなければ退場

「解体できない＝ここから先のコードは走る意味がない」ことがあります。Rust 2021 からある新構文です：

```rust
宣言 入力: オプション<整数> = あり(7);
宣言 あり(数) = 入力 そうでなければ {
    返す;
};
表示行!("let-else で取得 {}", 数);
```

📖 **let else**：`宣言 パターン = 値 そうでなければ { 抜け方 };` ——パターンは **必ず当てはまらなければならず** 、当たればそのまま続行；当たらなければ `そうでなければ` ブロック（中はたいてい `返す` や `中断`）を実行し、 **この後のコードは実行されません** 。

> ⚠️ **注意**：`そうでなければ` ブロックは **「戻らない」仕方で終わる必要があります** （`返す`、`中断`、`続行`、`パニック!` など）——「解体に失敗したら必ず後ろへ行けない」ことをコンパイラが保証するためです。

### マッチガード：マッチ腕に段差を付ける

パターンが「この形かどうか」を担当するのに対し、追加の **条件** が欲しいこともあります。ガードは `=>` の前に置く `もし` です：

```rust
宣言 数値 = 7;
マッチ 数値 {
    値 もし 値 > 5 => 表示行!("5より大きい：{}", 値),
    _ => 表示行!("5以下"),
}
```

読み方：最初の腕の完全な条件は「 `値` にマッチ **かつ** `値 > 5`」。条件を満たさなければ次の腕へ落ちます。

> ⚠️ **お知らせ**：ガードの式には方言が書けます（`値 もし 値 > 5`）——`もし` は `if` に転訳されます。`もし` はパターン内では別の意味（`if let`）を持ちますが、ガード条件としては転訳後ただの `if` です。

### @ 束縛：マッチしながら名前を残す

「範囲マッチが成功して、かつ当たった値そのものも手元に欲しい」—— `@` はまさにそのためのもの：

```rust
宣言 数値 = 7;
マッチ 数値 {
    値 @ 1..=5 => 表示行!("1〜5：{}", 値),
    _ => 表示行!("範囲外"),
}
```

📖 **@ 束縛**：`名前 @ パターン` ——マッチした値を **同時に** `名前` にしまいます。`値 @ 1..=5` の読み方：「数が 1 から 5 の間なら、その数自身を `値` と呼ぶ。」

`@` がないと、`1..=5` は「範囲に入っているか」を判定できるだけで具体的な数を取れません—— `@` がこのすき間を埋めます。

### またはパターン：一腕で何役も

 **同型の** いくつかの値に同じ道を歩ませたい？ `|`（縦棒）で一つの腕にまとめます：

```rust
宣言 数値 = 7;
マッチ 数値 {
    1 | 2 => 表示行!("1または2"),
    _ => 表示行!("その他"),
}
```

列挙型も同様です：`成績::欠席 | 成績::履修免除(_) => 表示行!("具体的な点数がない")` ——「点がない」二通りが一つの腕を共用します。

### 構造体とタプル：まとめデータを解体する

パターンが解体するのは列挙型だけではありません。構造体もタプルも解体できます：

```rust
構造体 点 {
    横: 整数,
    縦: 整数,
}

宣言 点甲 = 点 { 横: 10, 縦: 20 };
マッチ 点甲 {
    点 { 横, 縦 } => 表示行!("横={} 縦={}", 横, 縦),
}

宣言 (甲, 乙) = (1, 2);
表示行!("{} {}", 甲, 乙);
```

- 構造体パターン `点 { 横, 縦 }`： **フィールド名** で解体。順番は問わない；
- タプルパターン `(甲, 乙)`： **位置** で解体。一対一で対応。

💡 **たとえ**：列挙型パターンは宅配便の箱を開ける（どこの便か見て、中身を取り出す）；構造体パターンは **ラベル** で物を取る；タプルパターンは **席番号** で点呼する。

### 完整例一：if let、while let、let else

```rust
関数 主関数() {
    // if let
    宣言 点数: オプション<整数> = あり(95);
    if let あり(値) = 点数 {
        表示行!("点がある：{}", 値);
    } そうでなければ {
        表示行!("点がない");
    }

    // while let
    宣言 可変 残り: オプション<整数> = あり(3);
    while let あり(値) = 残り {
        表示行!("残り {}", 値);
        残り = なし;
    }

    // let else
    宣言 入力: オプション<整数> = あり(7);
    宣言 あり(数) = 入力 そうでなければ {
        返す;
    };
    表示行!("let-else で取得 {}", 数);
}
```

出力：

```
点がある：95
残り 3
let-else で取得 7
```

### 完整例二：ガード、@、解体

ガード、`@`、`|`、構造体解体、タプル解体を一つのプログラムに詰め込んで回します：

```rust
構造体 点 {
    横: 整数,
    縦: 整数,
}

関数 主関数() {
    // マッチガード
    宣言 数値 = 7;
    マッチ 数値 {
        値 もし 値 > 5 => 表示行!("5より大きい：{}", 値),
        _ => 表示行!("5以下"),
    }

    // @ 束縛
    マッチ 数値 {
        値 @ 1..=5 => 表示行!("1〜5：{}", 値),
        _ => 表示行!("範囲外"),
    }

    // またはパターン
    マッチ 数値 {
        1 | 2 => 表示行!("1または2"),
        _ => 表示行!("その他"),
    }

    // 構造体解体
    宣言 点甲 = 点 { 横: 10, 縦: 20 };
    マッチ 点甲 {
        点 { 横, 縦 } => 表示行!("横={} 縦={}", 横, 縦),
    }

    // タプル解体
    宣言 (甲, 乙) = (1, 2);
    表示行!("{} {}", 甲, 乙);
}
```

出力：

```
5より大きい：7
範囲外
その他
横=10 縦=20
1 2
```

最初の三つは `7` がガード、範囲、`|` を順に通った結果；後の二つは構造体とタプルを一気に解体するデモです。

### 反駁可能と反駁不可能：パターンの二つの顔

最後に概念を一つ。パターンには二種類あります：

📖 **反駁可能**：当てはまらない可能性がある。例えば `あり(値)`——万一値が `なし` なら当てはまらない。
📖 **反駁不可能**： **必ず** 当てはまる。例えば `数`、`(甲, 乙)`——どんな値でも解体できる。

**使える場所に決まりがあります**：

- `宣言` の束縛、関数引数、`各` ループ： **反駁不可能** パターンが要求されます（コンパイラが検査してくれます）；
- `マッチ` 腕、`if let`、`while let`： **どちらでも可** （当てはまらなければ別の道か終了）。

逆もまた然り——`if let` に反駁不可能パターンを書くと、コンパイラは「蛇足だ」と注意してきます（「このパターンは必ず成功するので if let は不要」）。

**最もよくある落とし穴**：`宣言` に `宣言 あり(値) = 点数;` と書く——コンパイラは即座に **E0005** を出します：

```
エラー[E0005]: このパターンは失敗する可能性があるが、ここでは必ず成功するパターンが必要です
💡 `宣言` バインディングや関数引数などの位置は必ず成功するパターンを要求します。失敗しうるパターンは `マッチ` や `もし 宣言` で処理してください。
```

**解決**：「当てはまらないかもしれない」解体は `マッチ` / `if let` / `let else` に任せる；`宣言` は「必ずある」物を受け取るためだけに使う。

## 11.7 オプション：「ないかもしれない」に対処する

プログラムではよくあること： **値が存在しないかもしれない** 。たとえば「クラスの最高点」——万一クラスに誰もいなかったら？

多くの言語は「ヌルポインタ」で「なし」を表現し、その結果「十億ドルの過ち」が生まれました：空値のチェックを忘れると、プログラムはその場で崩壊です。Rust の答えは組み込みの列挙型一つ：

```rust
列挙型 オプション<物> {
    あり(物),    // 値あり。値が中に入っている
    なし,          // 値なし
}
```

（`<物>` はジェネリクス——第 12 章で詳しくやります。今は「どんな型の値を入れるオプションか」と読んでください。）

📖 **オプション**：「値があるかもしれないし、ないかもしれない」を表す型。`あり` = ある、`なし` = ない。

```rust
宣言 ある点: オプション<整数> = あり(95);
宣言 ない点: オプション<整数> = なし;

マッチ ある点 {
    あり(値) => 表示行!("点数あり：{}", 値),
    なし => 表示行!("点数なし"),
}
マッチ ない点 {
    あり(値) => 表示行!("点数あり：{}", 値),
    なし => 表示行!("点数なし"),
}
```

出力：

```
点数あり：95
点数なし
```

鍵となる思想： **「値がない」ことも一つの値であり、必ず明示的に処理されなければならない** 。`なし` の存在を無視することはできません——オプションから値を取り出したければ、`マッチ` で両方の場合に付き合うしかない（または第 16 章の便利メソッドを使う）。これ以降「空値のチェックを忘れる」ような事故は、Rust では **起きようがない** のです。

## 11.8 完整例：マークシートの採点

列挙型の配列 + マッチ + ループで、10 問のマークシートを採点します：

```rust
// 各問題の解答状況（Copy を派生：データなし列挙型は手軽に複製できる）
#[派生(コピー, クローン)]
列挙型 解答 {
    正解,
    誤答,
    無答,
}

// 問題ごとの得点ルール
関数 採点(題: 解答) -> 整数 {
    マッチ 題 {
        解答::正解 => 5,
        解答::誤答 => 0,
        解答::無答 => 0,
    }
}

// 総合評価
列挙型 評価 { 優, 良, 可, 不可 }

関数 評価判定(総点: 整数) -> 評価 {
    もし 総点 >= 45 { 返す 評価::優; }
    もし 総点 >= 35 { 返す 評価::良; }
    もし 総点 >= 20 { 返す 評価::可; }
    評価::不可
}

関数 主関数() {
    // 10 問のマークシート
    宣言 解答用紙 = [
        解答::正解, 解答::正解, 解答::誤答, 解答::正解, 解答::無答,
        解答::正解, 解答::正解, 解答::誤答, 解答::正解, 解答::正解,
    ];

    宣言 可変 総点 = 0;
    宣言 可変 正解数 = 0;
    各 番号 中 0..10 {
        総点 = 総点 + 採点(解答用紙[番号]);
        マッチ 解答用紙[番号] {
            解答::正解 => 正解数 = 正解数 + 1,
            解答::誤答 => {}
            解答::無答 => {}
        }
    }
    表示行!("正解{}問、総点{}", 正解数, 総点);

    マッチ 評価判定(総点) {
        評価::優 => 表示行!("総評：優、すばらしい！"),
        評価::良 => 表示行!("総評：良、なかなか！"),
        評価::可 => 表示行!("総評：可、もう少し"),
        評価::不可 => 表示行!("総評：不可、がんばろう"),
    }
}
// 预期输出: 正解7問、総点35
// 総評：良、なかなか！
```

## 11.9 一行ずつ

- **2 行目**：`#[派生(コピー, クローン)]`——`解答` はデータを何も持たないので、整数のように **手軽に複製** できます。ここが大事：配列の要素は標準では取り出せません（E0508 が出る）。`コピー` があれば `解答用紙[番号]` が自動で一部複製され、関数に自由に渡せます。
- **10〜16 行目**：`採点` はマッチで三つの場合を数値に写像します。マッチ腕の右側は式 `5`、`0` がそのまま。
- **19 行目**：`評価` は純粋なラベル列挙型。
- **21〜26 行目**：`評価判定` は第 5 章の `もし` 連鎖で総点を評価に換え、最後は `評価::不可` が受け皿。
- **30〜33 行目**：列挙型の配列。要素は 10 個。
- **37〜43 行目**：一つのループで二つの仕事——総点の累加と正解数の計上。`解答::誤答 => {}` と `解答::無答 => {}` は空の波括弧：マッチ腕は **必ず** 三つの場合を書き切る必要があり、「何もしない」二者も書いて席を確保しなければなりません。
- **46〜51 行目**：評価の列挙型をさらにマッチしてことばに換えます。四つのバリアント、一つも漏れなし。

## 11.10 見えるはずのもの

```
正解7問、総点35
総評：良、なかなか！
```

正解 7 問 × 5 点 = 35 点。35〜44 の帯に落ちるので → 良。

## 11.11 よくある失敗と直し方

### 失敗一：E0004 マッチが非網羅

バリアントの漏れ。**解決**：補うか、`_` を受け皿にする。エラーに「未カバーのパターン」が列挙されていたら、それを写しましょう。

### 失敗二：E0508 配列の中身を持ち出せない

`関数(配列[番号])` のように要素を **持ち去ろう** とすると、配列が応じません。**解決**：列挙型に `コピー` を派生する（データなしなら）、または参照を渡す `&配列[番号]`（関数の引数を変える）、または `.クローン()`。

### 失敗三：バリアントに `文字列参照` を入れて E0106

列挙型のバリアントに `履修免除(文字列参照)` と書くと寿命注釈が要求されます。**解決**：`文字列型` に変える：`履修免除(文字列型)`、値を作るときは `文字列型::から("...")`。

### 失敗四：列挙型を直接印刷

`表示行!("{}", 解答::正解)` はエラー。**解決**：`#[派生(デバッグ)]` ＋ `{:?}`（第 10 章の定番手）。

### 失敗五：オプションの中身を当然のように使う

`あり(95)` はそのまま `95` として使えません——外にまだ殻が一枚かぶっています。**解決**：`マッチ` で殻を剥く、または第 16 章の `期待` などのメソッド。

### 練習二：データ付きの図形

列挙型 `図形 { 円(整数), 四角(整数, 整数) }`（円は半径、四角は縦と横）を定義し、関数 `面積` を書いてください：円は `3 * 半径 * 半径` で近似、四角は縦×横。

<details>

    円(整数),
    四角(整数, 整数),

        図形::円(半径) => 3 * 半径 * 半径,
        図形::四角(縦, 横) => 縦 * 横,
    }

関数 主関数() {

}
```

</details>

<details>

    点数報告(あり(72));
    点数報告(なし);
}
```

</details>

## 11.14 よくある質問

**Q：列挙型と文字列のどちらを使うべきか判断するには？**

文字列は何でも書けてしまう——`"優"`、`"優 "`、`"ゆう"` はどれも別の値で、書き間違えてもコンパイラは見てくれません。列挙型は固定のいくつかの値しかなく、書き間違えればコンパイルが通らず、しかもマッチの網羅検査で全場合の処理が保証されます。 **ずっと安全** です。

**Q：データなしの列挙型に `コピー` を派生しないと配列から取れないのはなぜ？**

配列の要素は標準では「借りて見るのは可、持ち去るは不可」だからです。`コピー` はコンパイラに「この型の複製は極めて安い（ただのラベル）」と伝えます——取り出すとき自動で一部複製し、元の配列はそのまま。データ付きの列挙型は複製にコストがかかるかもしれないので、あなたの明示的な意思表示（`クローン` または `クローン` 派生）が要ります。

**Q：`オプション` は面倒。素直に「値がない」を許してはだめ？**

「空値チェックの忘れ」は歴史上もっとも高くついた過ちの源だからです。Rust は「なし」を **明示的に処理が必須の型** にして、面倒をコードを書く瞬間に前倒ししました——結果、崩壊がユーザーの目の前で起きることは永遠にありません。慣れれば殻剥きはたった二行です。

**Q：`マッチ` と `もし` の連鎖、どう選ぶ？**

離散的な場合（列挙型、少数の固定値）は `マッチ`；連続した区間（点数帯）は `もし` 連鎖のほうが手なれます。どちらも合法なので、分かりやすいほうで。

**Q：列挙型に構造体を入れられる？**

入れられます！バリアントの手荷物はどんな型でも構いません——構造体でも、別の列挙型でも。あとの章の実戦プロジェクトでこの「組み合わせ技」をふんだんに使います。

**Q：`リザルト` 型も列挙型なの？**

そうです！`リザルト` = `成功(値)` / `エラー(理由)` で、`オプション` と同じ仕組みの、「失敗するかもしれない操作」専門の型です。第 16 章《エラー処理》がその主场です。
