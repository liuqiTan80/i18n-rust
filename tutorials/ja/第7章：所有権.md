# 第 7 章：所有権

## 7.0 この章の目標

この章を終えると、あなたは次のことができるようになります：

1. **所有権の三つのルール** を言える；
2. **スコープ** の終わりで値に何が起きるか説明できる；
3. **複製**（整数などの小さなデータ）と **移動**（文字列などのヒープデータ）を区別できる；
4. **E0382**（移動後の値の使用）エラーを読んで直せる；
5. **`クローン()`** で独立した複製を作れる；
6. 値を **関数に渡すとき・関数から返すとき** に所有権がどこへ行くか言える。

> ✨ この章は Rust の最も特別な部分で、他の言語のほとんどにはありません。最初は読んでも分からなくて当たり前。二回三回と読み、例を全部実際に動かせば、ふっと開けます。

---

## 7.1 なぜ所有権が要るのか：誰が掃除するのか

💡 **物語**：学校で大掃除をすることになりました。 **分担がなかったら** 、二つの惨事が起きます：

1. **誰も掃除しない**：担当のない場所にゴミが溜まり続ける——プログラムでは **メモリリーク**（メモリを確保したのに返さないので、使い込むほど増え、最後には固まる）と呼ばれます；
2. **二人が同じ場所を同時に掃除する**：片方が拭き終わった直後に、もう片方が自分の流儀で書き直す——大混乱。プログラムでは **データ競合**（マルチスレッドの話のとき、二章先で詳しくやります）と呼ばれます。

Rust の解決策はシンプルかつ強烈です： **すべての物には、必ずちょうど一人の主人がいなければならない。主人が面倒を見て、主人が去るとき、物は自動的に片付けられる。**

📖 **所有権**：Rust の中核ルール——すべての値には唯一の「主人」（変数）がいて、主人がスコープを去ると値は自動的に解放される。

これが、Rust が「ガベージコレクタ」（他の言語が雇う自動清掃員）なしでメモリ安全を保証できる理由です： **全員に責任があり、責任は人ごとに明確** 。

---

## 7.2 所有権の三つのルール

この三つを覚えれば、この章は半分クリアです：

| 番号 | ルール | 平たく言うと |
|---|---|---|
| ルール一 | すべての値には **所有者**（変数）がいる | すべての物に主人がいる |
| ルール二 | 同じ瞬間に、所有者は **一人だけ** | 一物に二主なし |
| ルール三 | 所有者が **スコープ** を去ると、値は **自動的に解放される** | 主人が去ると、物は自動的に片付く |

📖 **スコープ**：ある名前が「有効」なコードの範囲。たいていは波括弧 `{ }` の内側です。「校庭」があなたの活動範囲のようなもの——校庭を出たら、校庭の中のことはもう管理できません。

---

## 7.3 スコープ：値の一生

このコードを見てください：

```rust
関数 主関数() {
    {
        宣言 一時 = 文字列型::から("ブロックの中だけ");
        表示行!("ブロック内：{}", 一時);
    }
    // 一時 はここで既に存在しない
    表示行!("ブロック外の続き");
}
```

出力：

```
ブロック内：ブロックの中だけ
ブロック外の続き
```

`一時` は内側の波括弧の中で生まれ、波括弧が終わった瞬間に **消滅** します——占めていたメモリは自動的に返却されます。ブロックの外で `一時` を使おうとすると、コンパイラが「そんな変数はない」とエラーを出します。

> 💡 **たとえ**：値の一生はホテルの宿泊のようなもの： **チェックイン**（宣言）→ 使用 → **チェックアウト**（スコープを去る）。チェックアウト時には部屋が自動できれいに掃除されます（メモリの解放）。あなたが気を配る必要もなければ、居座る人もいません。

> 📖 **解放**：値がスコープを去るときに自動で実行される後片付け。メモリはシステムへ返却されます。

## 7.4 二つの保管場所：ポケットと倉庫

なぜデータによって「複製」されたり「移動」したりするのか？ まず、データの保管場所が二つあることを知る必要があります：

📖 **スタック**：高速で容量の小さいメモリ領域。 **随身ポケット** のようなもの——出し入れは一瞬ですが、大きな物は入りません。
📖 **ヒープ**：やや遅くて容量の大きいメモリ領域。 **倉庫** のようなもの——大きな物を置けますが、取りに行くには足を運び、帳簿にも記帳する必要があります。

| 保管場所 | 何を入れるか | たとえ |
|---|---|---|
| スタック（ポケット） | 整数、浮動小数点数、ブール、文字——大きさ固定の小さな物 | 鍵、消しゴム |
| ヒープ（倉庫） | 文字列、ベクタなど——長さの決まっていない大きな物 | 本がぎっしりの一箱 |

`文字列型` の中身は **ヒープ** に置かれています：倉庫に一列に文字が並んでいて、変数そのもの（ポケットの中）は **引換券**（倉庫の場所と長さの記録）を握っているだけです。

これが分かれば、このあとの複製と移動はすんなり飲み込めます。

---

## 7.5 複製：ポケットの中身は手軽にもう一部写せる

```rust
宣言 甲 = 5;
宣言 乙 = 甲;
表示行!("甲：{}、乙：{}", 甲, 乙);
// 预期输出: 甲：5、乙：5
```

出力：`甲：5、乙：5`

整数は **ポケット** に住んでいるので、もう一部写すのにほとんど時間がかかりません。つまり `宣言 乙 = 甲` は **複製**：甲は元気なまま、乙は独立した別の一部。二つの変数はどちらも自由に使えます。

📖 **複製**：スコープを去るときに自動でビット単位に写される性質。整数、浮動小数点数、ブール、文字がこれに当たります。

**どの型が複製される？** 合言葉は **「数値・真偽・一文字」** ——整数（`整数`、`長整数`…）、浮動小数点数（`浮動小数点数`）、ブール（`真`/`偽`）、文字。これらは全部ポケット住まいなので、代入はそのまま一部写すことになります。

---

## 7.6 移動：引換券は一枚しかない

文字列は **倉庫** に住み、変数の手元にあるのは引換券だけです。ここで：

```rust
宣言 文甲 = 文字列型::から("こんにちは");
宣言 文乙 = 文甲;
表示行!("文乙：{}", 文乙);
```

`宣言 文乙 = 文甲` は複製ではなく **移動** です：引換券が文甲の手から文乙へ **手渡されました** 。引換券は一枚しかない——今の主人は文乙です。

💡 **たとえ**：映画のチケットを一枚友達にあげたら、あなたの手元にはもうない。入場したい？ 友達に返してもらうか、もう一枚買う（7.7 節のクローン）しかありません。

移動した後で古い変数名をまだ使おうとすると：

```rust
宣言 文甲 = 文字列型::から("こんにちは");
宣言 文乙 = 文甲;
表示行!("文甲：{}", 文甲);   // ❌
```

コンパイラは容赦なくエラーを出します：

```
エラー[E0382]: 移動後の値の使用：`文甲`
📌 変数 `文甲` は 3 行目で移動され、4 行目で再び使用されました。
💡 Rustでは移動後の値は使用できません。`参照`（&）や `クローン()` を使って移動を回避しましょう。
```

📖 **移動**：ヒープ上のデータの所有権をある変数から別の変数へ渡すこと。元の変数は即座に無効になります。

> 📖 **E0382**：エラーコード。「移動後の値の使用」という意味です。これを見たらこう判断します：値はすでに新しい主人のところへ行ったのに、あなたはまだ旧主人のところを訪ねている。

**なぜ Rust はこんなに「けち」なのか？** 本箱ごと複製したら（数百メガになることも）、プログラムが遅くなります；二人で一枚の引換券を共有したら、チェックアウト時（スコープを去るとき）に同じ部屋を二回掃除することになり——即崩壊です。Rust は最もあっさりした方案を選びました： **一物一主、渡したらもうない** 。

---

## 7.7 クローン：もう一枚買う

独立した二份が欲しい？ **`クローン()`**（「クローン、複写する」の意味）を使いましょう：

```rust
宣言 原本 = 文字列型::から("宝の地図");
宣言 複製 = 原本.クローン();
表示行!("原本：{}、複製：{}", 原本, 複製);
// 预期输出: 原本：宝の地図、複製：宝の地図
```

出力：`原本：宝の地図、複製：宝の地図`

クローンは **倉庫の中身を本当に一式コピー** します。二枚の引換券はそれぞれ別の倉庫を指すので、片方を変えてももう片方には影響しません。

> ⚠️ **注意**：クローンには時間がかかります（倉庫の中身を箱ごと複写する）。移動で済むならクローンしない。入門のうちは安心して使って大丈夫——性能の最適化はその先の話です。

**対比メモ**：

| 操作 | ポケットデータ（整数など） | 倉庫データ（文字列など） |
|---|---|---|
| `宣言 乙 = 甲` | 複製。どちらも使える | 移動。甲は無効 |
| `宣言 乙 = 甲.クローン()` | クローンも可（必要ない） | 複製。どちらも使える |

## 7.8 所有権と関数：出入りどちらも「名義変更」

値を **関数に渡す** ときも、 **関数から返す** ときも、同様に所有権が移ります。

### 引数として渡す：値が関数へ引っ越す

```rust
関数 受け取る(文: 文字列型) {
    表示行!("関数内で受領：{}", 文);
}

関数 主関数() {
    宣言 お祝い = 文字列型::から("お誕生日おめでとう");
    受け取る(お祝い);
    // お祝い はすでに関数へ引っ越したので、ここではもう使えない
}
```

`受け取る(お祝い)` はお祝いをまるごと関数の引数 `文` へ **名義変更** します。呼び出しが終わると `文` はスコープを去り、値は解放されます。主関数の中の `お祝い` はこの瞬間から無効です。

### 返り値：値が呼び出し元へ帰ってくる

```rust
関数 挨拶づくり(名前: 文字列参照) -> 文字列型 {
    文字列型::から(名前)
}

関数 主関数() {
    宣言 挨拶 = 挨拶づくり("太郎");
    表示行!("受け取った：{}", 挨拶);
}
// 预期输出: 受け取った：太郎
```

出力：`受け取った：太郎`

関数の中で新しく造った文字列が、`返す` によって `挨拶`——その新しい主人——へ **名義変更** されます。

> 💡 **たとえ**：関数は一つの宅配便の集配所。引数として渡す = 荷物を **送り込む**（あなたの手元にはもうない）；返す = 集配所が新しい荷物を **送り返してくれる**（これ以降はあなたの物）。

> ✨ **ここで「借用だけならだめなの？」と思ったあなた、正解です。** 第 8 章《参照と借用》はまさに「どうやって借りるか」の専門章——借りたら返す、所有権は移りません。

## 7.9 総合例：宅配便の集配所

所有権の知識ぜんぶを「荷物を送る」の物語につなげます：

```rust
// 派生(クローン)：構造体に自動的に クローン 能力を与える
// 派生括弧内のトレイト名は日本語（クローン）でもよい
#[派生(クローン)]
構造体 荷物 {
    中身: 文字列型,
    重量: 整数,
}

実装 荷物 {
    関数 作成(中身: 文字列型, 重量: 整数) -> 荷物 {
        荷物 { 中身: 中身, 重量: 重量 }
    }

    関数 紹介(&自己) {
        表示行!("荷物：{}、{}グラム", 自己.中身, 自己.重量);
    }
}

// 受け取り = 荷物の所有権を受け取る。受け取り終わると荷物は「使い切った」状態
関数 受け取り(件: 荷物) {
    件.紹介();
    表示行!("受領済み！");
}

関数 主関数() {
    // 荷物を一つ造る
    宣言 甲 = 荷物::作成(文字列型::から("おもちゃ"), 500);
    甲.紹介();

    // クローンして発送し、原本は手元に残す
    宣言 複製 = 甲.クローン();
    受け取り(複製);

    // 原本はまだ生きているので、使い続けられる
    甲.紹介();

    // 最後に原本も発送する
    受け取り(甲);
    // これ以降 甲 は無効
}
// 预期输出: 荷物：おもちゃ、500グラム
// 荷物：おもちゃ、500グラム
// 受領済み！
// 荷物：おもちゃ、500グラム
// 荷物：おもちゃ、500グラム
// 受領済み！
```

---

## 7.10 一行ずつ

- **3 行目**：`#[派生(クローン)]` は一枚の「シール」（正式名は **属性**）で、コンパイラに `荷物` 用の `クローン()` メソッドを自動生成させます。括弧の中には日本語のトレイト名（`クローン`、`デバッグ`）も書けるし、英語の原名を直接書いても構いません。
- **4〜7 行目**：構造体 `荷物` には二つのフィールドがあります。`中身` は `文字列型`（倉庫住まい）、`重量` は整数（ポケット住まい）。
- **10〜13 行目**：関連関数 `作成` は新しい荷物を返します（所有権は呼び出し側へ）。
- **15〜17 行目**：`紹介` は `&自己`—— **借りて眺めるだけ** で持ち去らないので、呼び出し後も荷物は無事です（借用の詳細は第 8 章で）。
- **21〜24 行目**：`受け取り` の引数型は `荷物`（`&` なし）——渡されてきた荷物の所有権は `件` のものになり、関数が終わると `件` ごと解放されます。差出人はこの荷物をもう失いました。
- **28 行目**：`文字列型::から("おもちゃ")` で文字列を造り、荷物と一緒に `甲` の所有になります。
- **32 行目**：`甲.クローン()` が完全に独立した `複製` を複写します（中の文字列ごと）。
- **33 行目**：`受け取り(複製)`——複製は取り上げられ、解放されます。
- **36 行目**：`甲` は無傷なので、まだ自己紹介できます。
- **39 行目**：`受け取り(甲)`——原本も取り上げられました。この行の後に `甲.紹介()` と書いたら E0382 です。

## 7.11 見えるはずのもの

```
荷物：おもちゃ、500グラム
荷物：おもちゃ、500グラム
受領済み！
荷物：おもちゃ、500グラム
荷物：おもちゃ、500グラム
受領済み！
```

照らし合わせると：1 行目は造り終わっての自己紹介；2〜3 行目はクローンの複製が受け取られる様子；4〜6 行目は原本が自己紹介してから、それも受け取られる様子。二つの荷物は中身が同じでも、 **独立した二つの値** です。

## 7.12 よくある失敗と直し方

### 失敗一：E0382 移動後の使用

```
エラー[E0382]: 移動後の値の使用：`文甲`
💡 Rustでは移動後の値は使用できません。`参照`（&）や `クローン()` を使って移動を回避しましょう。
```

**修理ルートは三つ**：

1. **見たいだけ** → 参照を渡す `&文甲`（第 8 章）；
2. **双方とも残したい** → `文甲.クローン()`；
3. **本当に一人だけに渡したい** → コードの順番を調整して、最後の使用が移動より前に来るようにする。

### 失敗二：整数の挙動を文字列に当てはめた

「なんで `甲` が使えなくなるの？ `乙 = 甲` のあとも整数は使えるよ！」——整数は **複製**、文字列は **移動** だからです。7.4 の合言葉を思い出しましょう：「 **数値・真偽・一文字** 」だけが複製されます。

### 失敗三：クローンしたのに「メソッドが見つからない」

自作の構造体で `.クローン()` を呼ぶとエラーになるのは、構造体は標準では **クローンされない** からです。構造体の定義の前にシール `#[派生(クローン)]` を貼りましょう。

### 失敗四：派生トレイト名の書き間違い

`#[派生(クーロン)]` は「派生マクロが見つからない」というエラーになります——`クローン` を `クーロン` のような音便間違いで書かないよう注意。日本語のトレイト名は `クローン`、`デバッグ`、`コピー`、`ハッシュ` などが使えます。

## 7.13 章末用語集

| 用語 | 一言でいうと |
|---|---|
| 所有権 | すべての値に唯一の主人がいて、主人が去ると値は解放される |
| スコープ | 名前が有効なコード範囲。たいてい波括弧一組の内側 |
| 解放 | 値がスコープを去るときにメモリを自動で片付けること |
| スタック | 速くて小さいメモリ領域。大きさ固定のデータ用。随身ポケットのたとえ |
| ヒープ | 大きくてやや遅いメモリ領域。可変サイズのデータ用。倉庫のたとえ |
| 複製 | スタックデータの代入方式。双方が独立した一份を持つ |
| 移動 | ヒープデータの代入方式。引換券を渡し、元の変数は無効になる |
| クローン | ヒープ上のデータの完全な複写を手動で作ること |
| E0382 | 「移動後の値の使用」のエラーコード |
| 属性 | コードに貼る「シール」。`#[...]` と書き、コンパイラへの追加指示 |
| 派生 | コンパイラに特定のトレイト実装を自動生成させること。`#[派生(クローン)]` など |

> 📖 **お知らせ**：分からない言葉が出たら、いつでも本の冒頭の《総用語表》に戻って引いてください。

## 7.14 練習問題

> 💪 まず自分で試してから、答えを覗いてください。

### 練習一：誰がまだ使えるか

次の各行のあとで、どの変数がまだ使えるか判断してください（まず紙に答えを書いてから）：

```rust
宣言 甲 = 10;
宣言 乙 = 甲;
宣言 丙 = 文字列型::から("こんにちは");
宣言 丁 = 丙;
宣言 戊 = 丁.クローン();
```

<details>
<summary>🔍 参考解答</summary>

- `甲`：使える（整数は複製）；
- `乙`：使える；
- `丙`： **使えない**（丁へ移動した）；
- `丁`：使える；
- `戊`：使える（クローンされた独立した複製）。

</details>

### 練習二：E0382 を修理する

次のコードはエラーになります。 **二通りの違う方法** で直してください（ヒント：一つはクローン、もう一つは使用順の調整）：

```rust
// 预期错误: E0382
関数 主関数() {
    宣言 お祝い = 文字列型::から("あけましておめでとう");
    宣言 バックアップ = お祝い;
    表示行!("{}", お祝い);
}
```

<details>
<summary>🔍 参考解答</summary>

方法一：クローン。

```rust
宣言 バックアップ = お祝い.クローン();
```

方法二：先に表示してから移動する。

```rust
宣言 お祝い = 文字列型::から("あけましておめでとう");
表示行!("{}", お祝い);
宣言 バックアップ = お祝い;
```

</details>

### 練習三：関数間の荷物

関数 `梱包`（整数の重量を受け取り、荷物を返す）と `開封`（荷物を受け取り、中身を印刷する）を書いてください。主関数で「ブロック」を梱包し、開封したあと、元の変数を使おうとしてみる——コンパイラがどう注意してくれるか見てみましょう。

<details>
<summary>🔍 参考解答</summary>

```rust
構造体 荷物 {
    中身: 文字列型,
    重量: 整数,
}

関数 梱包(重量: 整数) -> 荷物 {
    荷物 { 中身: 文字列型::から("ブロック"), 重量: 重量 }
}

関数 開封(件: 荷物) {
    表示行!("取り出した：{}", 件.中身);
}

関数 主関数() {

    開封(贈り物);

    // 表示行!("{}", 贈り物.重量);

```

## 7.15 よくある質問

**Q：所有権の検査は実行時？ コンパイル時？**

**コンパイル時** です。コンパイラはあなたが実行する前に所有権の行き来をすべて調べ上げ、合格しないプログラムはそもそもコンパイルが通りません。だから Rust のプログラムは実行時に所有権検査の負担がありません——「ゼロコスト」思想の実践です。

**Q：整数は本当に永遠に移動しないの？**

そうです。整数、浮動小数点数、ブール、文字という「ポケットデータ」は、代入時に常に複製されます。のちに正確な判定方法を学びます： `コピー` トレイトを実装した型はすべて複製される、と。

**Q：文字列リテラル `"こんにちは"` も移動するの？**

リテラルは **文字列参照** で、「借用」の一種です——借用した物の代入は借用証をもう一部写すだけで、双方とも使い続けられます。本当に移動するのは `文字列型` ——例えば `文字列型::から("こんにちは")` で造ったものです。両者の違いは第 9 章で詳しくやります。

**Q：クローンと複製の違いは結局何？**

複製はコンパイラが **自動で、安価に** 行う（ポケットの中の数バイトを写すだけ）；クローンは **あなたが手動で、やや高価に** 行う（倉庫へ行って箱ごと複写する）。複製できる型ならクローンもできますが無意味；移動する型で二份欲しければ、クローンが必須です。

**Q：すべての変数で所有権を考えるのは、疲れない？**

最初は確かに疲れます。これが Rust 学習最大の関門です。朗報は：二、三章分のプロジェクトを書き終える頃には「誰が誰を所有しているか」が直感になるということ。しかもコンパイラはタダの相棒です——あなたが忘れたらすぐ注意してくれて、修理の提案まで付けてくれます。

**Q：他の言語（Python や JavaScript など）にこれがないのはなぜ？**

たいていは「ガベージコレクタ」を使っています：プログラムの実行中に裏方の清掃員を雇い、定期的に巡回して誰にも使われていない値を掃除する。便利ですが、実行時の性能負担と不定性と引き換えです。Rust は所有権でコンパイル時に解決するので、実行時は速くて安定しています。

## 次は

所有権は安全ですが、「渡したらもうない」ばかりでは不便すぎます——自分のデータを人に見せたいだけなのに、名義変更が要るのでしょうか？

第 8 章 **《参照と借用》** は Rust の「貸し借りルール」をお伝えします：

- **参照** `&`：借りて眺めるだけ。元の主人に影響なし；
- **可変参照** `可変参照`：借りて変更できる。ただし厳しい制限つき；
- **一つの鉄律**：同時に可変借用は一つまで、または読み取り専用借用はいくらでも；
- なぜこのルールがデータの衝突を防げるのか。
