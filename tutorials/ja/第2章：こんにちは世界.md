> 💡 VS Code 拡張をまだ導入していない場合は、まず**第1章（VS Code 拡張を使いこなす）**をご覧ください — この章では `.ja` ファイルが開けることを前提に進めます。

## 2.1 プログラミングとは

### ロボットへのメモ

目の前にロボットがいると想像してください。とても従順 — でもとても不器用です。**言われたことを一語ずつ**実行するだけで、気持ちを推測してくれません。

「お水を一杯持ってきて」と言っても、「まずコップを取って」と言わなければ、その場で呆然と立ち尽くすかもしれません。

**プログラミングとは、ロボットへのメモを書くこと** — 手順をすべて書き残すことです：コップを取り、給水機の前まで歩き、ボタンを押し、コップが满ちたら止める……

> 💡 **比喩**：プログラミングは、極めて詳細なレシピを書くことに似ています。「麺を作る」とは書けず、「手順1：蛇口を開ける。手順2：鍋に水を半分入れる。手順3：……」と書かなければなりません。

書いたメモの一つ一つを**ソースコード**と呼びます。

> 📖 **ソースコード**：コンピュータに読ませるために書く文章のこと。

ソースコードを書くのに使う言語が**プログラミング言語**です。

> 📖 **プログラミング言語**：人間がコンピュータと対話するための言語。人間に中国語・英語・日本語があるように、プログラミング言語にも多くの種類があり、それぞれ特徴があります。

### この本で学ぶ言語：Rust

この本の言語は **Rust**（ラストと読みます）— 世界中で人気のプログラミング言語の一つです。

普通の Rust のキーワードは英語です。この本で書くのは**日本語 Rust** — キーワードがすべて日本語です：

| 日本語キーワード | 英語原名 | 意味 | 生活のたとえ |
|---|---|---|---|
| `関数` | `fn` | 繰り返し使える命令のかたまりに名前をつける | 一連の動作に名前をつけ、呼べば実行される |
| `宣言` | `let` | データをしまう「箱」を作る | 箱を用意し、ラベルを貼り、中に物を入れる |
| `もし` | `if` | 条件に応じて動作を変える | 雨なら傘を持っていく |
| `各` | `for` | 個々のものに対して繰り返す | かごの中のリンゴを一つずつ洗う |
| `表示行!` | `println!` | 画面に文字を表示する | 画面に向かって「叫ぶ」 |

書いたコードは日本語の文章に見えますが、それは**本当に動くプログラム**です：

```rust
関数 主関数() {
    表示行!("こんにちは、世界！");
}
```

> ✨ **ヒント**：今はこのコードの細部を理解しなくて大丈夫です。1.6 節で一語ずつ解説します。今は「この数行の日本語が、コンピュータが読めるプログラムだ」とだけ覚えてください。

> 🌍 **多言語教室の方へ**：英語話者にとっては、標準 Rust こそが「母語の Rust」です。中国語・日本語・ロシア語など 10 の言語の話者は、rzc という道具を通じて、同じ標準 Rust を自分の言葉で書きます。この章で出会う教育的な診断メッセージも、同じ道具が 10 言語に翻訳しています。

## 2.2 まずはパソコンと知り合う

コードを書く前に、基本の用語を数分かけて確認しましょう。すでにご存知なら 2.3 へ飛んでも構いません。

### ファイル：コンピュータの中の「紙」

> 📖 **ファイル**：コンピュータが情報を保存する基本の単位 — 一枚の紙のようなもの。紙に文章も書けるし絵も描けるように、ファイルにも文字も画像も保存できます。

ファイルには必ず**ファイル名**があります（例：`作文.txt`）。点の後ろの `txt` は**拡張子**と呼び、ファイルの種類を表します。

> 📖 **拡張子**：ファイル名の最後の点より後ろの部分。`.txt` は普通の文字ファイル、`.jpg` は画像ファイルです。この本で書くコードファイルの拡張子は **`.ja`**（日本語の ja）です。

### フォルダ：コンピュータの中の「引き出し」

> 📖 **フォルダ**：ファイルをしまう「引き出し」。「ディレクトリ」とも呼ばれます。多くのファイルを一つのフォルダにまとめられます。

### キーボードで最も重要なキー

コードを書くのは主にタイピングです。このキーは必ず使います：

| キー | 位置 | 役割 |
|---|---|---|
| `Enter`（改行キー） | メインキー区の右 | 改行する。ターミナルでは「このコマンドを実行」の意味 |
| `スペースキー` | 一番下の一番長いキー | 空白を一つ入力する |
| `Backspace` | Enter の上 | カーソルの前の一文字を消す |
| `Shift` | 左右に一つずつ | 押しながら字母キーで大文字や記号を入力 |
| `Ctrl` | 左右に一つずつ | 組み合わせキーに使う（例：`Ctrl+S` で保存） |

> ⚠️ **注意**：コードは**日本語入力モードをオフ**にして打ちます！全角のカンマ `，` はコードではエラーの元。（引用符の中の日本語の句読点は大丈夫 — それは人間に見せる文字だからです。）

### ファイルの保存

エディタで書いたコードは、最初は「メモリ」の中にしかありません。電源を切ると消えます。**保存**して初めてディスクに書き込まれます。

> 📖 **保存**：編集中の内容をディスクに書き込み、失われないようにすること。ほとんどのソフトで `Ctrl+S`（macOS は `Cmd+S`）で保存できます。

> ✨ **ヒント**：数行書くたびに `Ctrl+S` を押す習慣をつけましょう。

## 2.3 道具と知り合う

コードを書くには三つの道具が必要です。料理に台所・フライパン・レシピが必要なように。

### 道具一：ターミナル — コンピュータと対話する窓口

> 📖 **ターミナル**：文字だけの窓。打ち込んだ命令をコンピュータが実行し、結果も文字で返してきます。「コマンドライン」とも呼ばれます。

💡 **比喩**：ターミナルは文字の注文しか受けないウェイターのようなもの。「お水を一杯」と書けば、水を持ってきて「こちらです」と文字で返事します。

開き方：

- **Windows**：画面左下をクリックし、「PowerShell」と検索して Enter。
- **macOS**：`Cmd+スペース` を押し、「ターミナル」と入力して Enter。
- **Linux**：`Ctrl+Alt+T`。

開くと、点滅する縦線が見えます — それが**カーソル**で、「あなたの入力の番」という合図です。

> 📖 **コマンド**：ターミナルに打ち込む一行の命令。`rzc --version` と打てば、rzc がバージョン情報を表示します。

### 道具二：コンパイラ — あなたの翻訳者

ソースコードは人間が読める文章ですが、コンピュータは**バイナリ**しか理解しません。

> 📖 **バイナリ**：0 と 1 の二つの数字だけですべてを表す方式。電灯の「点く／消える」のように、コンピュータの内部も「電気あり／なし」の 1 と 0 だけです。

そこで、ソースコードを機械が実行できる命令に翻訳する**翻訳者**が必要です。

> 📖 **コンパイラ**：翻訳者プログラム。書いたソースコードを読み、間違いをチェックし、機械が実行できる命令に翻訳します。

> 📖 **コンパイル**：翻訳者がコードを翻訳する一連の動作。「コードをコンパイルする」＝「翻訳者に翻訳してもらう」。

```
あなたのソースコード（人間が読める文字）
    ↓  コンパイラが翻訳
マシンコード（01010101……コンピュータが読める）
    ↓  コンピュータが実行
出力（画面に表示される）
```

日本語 Rust には翻訳者が**二人**いて、リレーをします：

```
日本語ソースコード（.ja ファイル）
    ↓  一人目の翻訳者 rzc：日本語 → 英語
標準 Rust ソースコード（.rs ファイル）
    ↓  二人目の翻訳者 rustc：英語 → マシンコード
実行ファイル
    ↓  実行
出力
```

一人目の翻訳者は **rzc**（アルファベットで「アール・ゼット・シー」と読みます）。このプロジェクトの日本語コンパイラで、日本語のキーワードを英語に置き換えます。

二人目は **rustc**、Rust 公式のコンパイラで、英語コードをマシンコードに変えます。

二人に別々に指示する必要はありません。`rzc run` と一声かければ、二段階が自動で進みます。

> ✨ **ヒント**：rzc の「r」は Rust、「zc」はこのプロジェクトが中国語教育から始まったことに由来します。今では 10 の言語を話します。

### 道具三：テキストエディタ — 好きなだけ書けるノート

> 📖 **エディタ**：文章を書くためのソフト。コードを書く用のものは「コードエディタ」と呼ばれ、コードに色をつけて見やすくしてくれます。

この本が勧めるのは **VS Code**（ブイ・エス・コード）。無料で高機能、世界中のプログラマが使っています。

> 📖 **拡張機能**：エディタに「後付け」する小さな機能 — 自転車のかごのようなもの。VS Code には日本語 Rust 専用の拡張機能があり、導入すると日本語コードが色分け表示され、エラーをリアルタイムで教えてくれます。

## 2.4 道具のインストール

この節は手順書です。ターミナルを開いて、一緒に進めましょう。

### 手順一：Rust のインストール（rustup）

rzc や拡張機能は公式コンパイラ rustc と連携して動くので、先に Rust を入れます。

#### Windows：
ブラウザで https://rust-lang.org/learn/get-started/ を開き、
インストーラをダウンロードして指示に従います。

#### Linux / macOS：

ターミナルにこの一行を入力して Enter：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

> 📖 このコマンドの意味：ネットからインストーラをダウンロードして実行する。`curl` はダウンロード道具の名前で、後ろの URL はインストーラの場所です。全部分を理解する必要はなく、そのまま打ち込めば大丈夫です。

インストーラが質問をしてきたら、**そのまま Enter** で既定値を選びます。回線速度にもよりますが、通常は数分です。

> ⚠️ **注意**：インストールが終わったら、**ターミナルを一度閉じて、新しい窓を開いてください**。新しく入れたソフトは、新しく開いた窓でしか見つかりません。

開き直して、次のコマンドで確認します：

```bash
rustc --version
```

> 📖 `--version` は「あなたのバージョンを教えて」という意味。バージョン番号はソフトの誕生日タグのようなもの（例：1.85.0）です。

`rustc 1.85.0` のような表示が出れば成功です。数字が完全に同じでなくても構いません。

> **うまくいかないとき**：「コマンドが見つからない」と出たら、窓を開け直していないのが大半の原因。閉じて開き直してください。それでもだめならパソコンを再起動して再度試しましょう。

### 手順二：rzc のインストール

rzc は crates.io（Rust 公式のライブラリ倉庫）から一行で入れられます：

```bash
cargo install rzc
```

（cargo は Rust に付属の「ソフトの管家」です。初回は数分かかります。）終わったら `rzc --version` で確認しましょう。

> 💡 crates.io が使えない環境では、GitHub Releases からオフラインパッケージをダウンロードする方法もあります（rzc・言語サーバ・10 言語パック同梱、解凍するだけで使えます）。

### 手順三（任意）：VS Code 拡張機能

エディタでの色分け・リアルタイムチェック・ワンクリック実行が欲しいときは、第1章に従って i18n-rust 拡張を導入してください（`.vsix` オフラインインストール対応）。コマンドラインだけで進めたい方は、この手順は飛ばして構いません。

## 2.5 初めてのプロジェクトを作る

### プロジェクトとは

> 📖 **プロジェクト**：一つのことを成し遂げるために必要なファイルをすべてしまうフォルダ。プログラムを書くときは、まずプロジェクトフォルダを作ります。

ターミナルに入力：

```bash
rzc init ハローワールド --lang ja
```

> 📖 コマンドの分解：`rzc` は翻訳者を呼ぶ合図。`init` は「イニシャライズ（初期化）」の略で「新規に準備する」の意味。`ハローワールド` はプロジェクトの名前です。`--lang ja` は「日本語パックで」という指定です（システムの言語設定が日本語なら、指定しなくても自動で ja になります）。

このコマンドは `ハローワールド` フォルダを自動で作り、中身は：

```
ハローワールド/
├── Cargo.toml          ← プロジェクトの名刺（名前などの記録）
├── rust-toolchain.toml ← 必要な Rust バージョンの記録
├── README.md           ← プロジェクトの説明
└── src/
    └── main.ja         ← あなたのソースファイル（コードを書く場所）
```

> 📖 **ディレクトリツリー**：このように線でフォルダの階層を描いた図のこと。`src/` の後ろの斜線は「フォルダである」合図です。

注目するのは **`src/main.ja`** — コードを書く場所はここだけ。他のファイルは道具が自動管理するので、今は触りません。

### VS Code で開く

1. VS Code を開く。
2. 左上の「ファイル」メニュー →「フォルダーを開く」。
3. さきほどの `ハローワールド` フォルダを選ぶ。
4. 左側のファイル一覧で `src` → `main.ja` を開くと、コードが中央の大きな領域に現れます。

## 2.6 初めてのプログラム：一字一句解説

### 完全なコード

`src/main.ja` を開くと、すでにテンプレートが書かれています：

```rust
関数 主関数() {
    表示行!("こんにちは、世界！");
}
```

この三行が、あなたの初めてのプログラムです。

> ⚠️ **注意**：打ち込むときは —
> 1. `関数` と `主関数` の間には**半角スペース**が一つあります。
> 2. `()`、`{}`、`""`、`!`、`;` はすべて**半角（英語入力）**で入力します。
> 3. 引用符の中の「こんにちは、世界！」は人間に見せる文字なので、日本語の句読点で大丈夫です。

### 一行ずつ、一語ずつ

**第1行：`関数 主関数() {`**

この行の意味：「『主関数』という名前の命令のかたまりを定義します。入力は不要で、中身は `{` の後ろから始まります。」

| コード | 正体 | 役割 | 生活のたとえ |
|---|---|---|---|
| `関数` | キーワード | コンピュータに「これから命令のかたまりを定義します」と伝える | 「はい、これから一連の動作です」と宣言するようなもの |
| 空白 | 区切り | 二つの語を分ける。コンピュータは空白で語の境界を判別 | 「我爱学习」を「我 爱 学习」と分けて書くようなもの |
| `主関数` | 関数の名前 | この命令のかたまりの名前。プログラムは必ず「主関数」から実行が始まる | 本の「第1章」 — 必ずここから読む |
| `()` | 対の丸括弧 | 「引数」（関数が必要とする入力）を入れる場所。空なら入力不要 | 「この動作に道具は不要」と言うようなもの |
| `{` | 左波括弧 | 「命令の中身はここから」 | 「よーい、スタート！」 |

> 📖 **引数**：関数が必要とする入力。ジューサーは果物がないと動かない — 果物がジューサーの引数です。主関数は入力不要なので括弧は空です。第6章で詳しく扱います。

> 📖 **波括弧**：`{` と `}` の二つの記号。必ず対で現れ、内容を囲みます。`{` が始まり、`}` が終わり。

**第2行：`    表示行!("こんにちは、世界！");`**

この行の意味：「画面に『こんにちは、世界！』と表示する。」

| コード | 正体 | 役割 | 生活のたとえ |
|---|---|---|---|
| 先頭の 4 つの空白 | インデント | この行が主関数の「内側」であることを示す | 作文の段落冒頭の字下げ |
| `表示行` | 組み込み道具の名前 | 画面に文字を表示し、自動で改行する | 画面に向かって「叫ぶ」 |
| `!` | 感嘆符 | この道具が**マクロ**である印 | マクロの専用バッジ |
| `(...)` | 丸括弧 | 表示する内容を入れる | 叫ぶ内容 |
| `"こんにちは、世界！"` | 文字列 | 二重引用符で囲まれた一連の文字 | メモに書いた言葉 |
| `;` | セミコロン | この命令の終わり | 中国語の「。」のようなもの |

> 📖 **マクロ**：名前の後に感嘆符 `!` がつく特別な組み込み道具。今は「感嘆符があったらマクロ」とだけ覚えてください。マクロと普通の関数の違いは第23章で詳しく扱います。

> 📖 **文字列**：一連の文字。「一連」は文字通りです。二重引用符 `"` で囲んで「これは文字です」と示します。

> ⚠️ **注意**：`表示行` の「行」は「一行表示する」の意味。表示後に自動で**改行**します — 次の表示は次の行に現れます。

**第3行：`}`**

| コード | 正体 | 役割 | 生活のたとえ |
|---|---|---|---|
| `}` | 右波括弧 | 主関数の中身はここまで | 「はい、終わり！」 |

> ⚠️ **注意**：`{` と `}` は**必ず対で**現れます。始まりがあれば終わりが必要。片方欠けは初心者最大の定番ミスです（2.9 節で扱います）。

### 保存して実行

1. `Ctrl+S` で保存。
2. ターミナルで `ハローワールド` フォルダに入っていることを確認し、実行：

```bash
rzc run src/main.ja
```

> 📖 コマンドの分解：`rzc` は翻訳者を呼ぶ；`run` は「実行」；`src/main.ja` は「このファイルを翻訳して実行して」という指定。

うまくいけば、画面に現れます：

```
こんにちは、世界！
```

**おめでとうございます — 日本語 Rust の初めてのプログラムの実行に成功しました！** 世界中のプログラマが最初に書くのはこの「こんにちは、世界」。あなたも正式にこの伝統に加わりました。

> ✨ **ヒント**：コードを変えるたびに `rzc run src/main.ja` を打ち直せば新しい結果が見られます。ターミナルで**上矢印キー**を押せば前のコマンドを呼び出せます — 打ち直し不要です。

## 2.7 舞台裏：日本語コードはどう動くのか

コンピュータは日本語を理解しないのに、なぜ日本語コードが動くのか？

`rzc run` を打った裏側では、三つの段階が自動で進んでいます：

```
┌──────────────────────────────────┐
│ ① あなたの日本語ソース main.ja     │
│    関数 主関数() { ... }           │
└────────────┬─────────────────────┘
             │ rzc が日本語キーワードを英語に置換
             ▼
┌──────────────────────────────────┐
│ ② 標準 Rust ソースコード           │
│    fn main() { ... }              │
└────────────┬─────────────────────┘
             │ rustc が英語コードをマシンコードに
             ▼
┌──────────────────────────────────┐
│ ③ マシンコード（0 と 1）→ 実行 → 出力 │
│    画面に表示：こんにちは、世界！    │
└──────────────────────────────────┘
```

1. **翻訳**：rzc が「日英対照表」を引き、`関数` を `fn` に、`表示行` を `println!` に置き換えます。
2. **コンパイル**：rustc が英語コードをマシンコードに翻訳します。
3. **実行**：コンピュータがマシンコードを実行し、画面に結果が現れます。

> 📖 **マッピング表**：この「日英対照表」の正式な名前はマッピング表 — 日本語の語を英語の語に対応させる表です。プロジェクトの言語パックにあり、完全な内容は付録 A に収録されています。

すべて自動です。あなたは `.ja` ファイルを書くことに集中するだけ。

### 翻訳結果が見たい？eject コマンドで

翻訳後の英語コードを自分の目で確かめたければ：

```bash
rzc eject src/main.ja
```

> 📖 `eject` は「取り出す」という意味。このコマンドは `src/main.rs` ファイル（`.rs` は標準 Rust の拡張子）を生成します — 翻訳後の英語コードそのものです（標準 Rust なので通常のコードフェンスで表示します）：

```
fn main() {
    println!("こんにちは、世界！");
}
```

> ✨ **ヒント**：引用符の中の「こんにちは、世界！」は**翻訳されていません**。rzc が翻訳するのはキーワードと識別子（コード内で特別な意味を持つ語）だけ。引用符の中の文字はそのまま残ります。

> ✨ **ヒント**：`main.rs` は見るためのもの。普段は `main.ja` を編集し続ければ大丈夫です。

## 2.8 実験してみよう

プログラミング学習の最高の方法は**自分でコードを変えること**。次の三つの実験を、すべてやってみてください。

### 実験 1：表示内容を変える

**目的**：「コードを変える → 出力が変わる」を自分の目で確かめる。

`main.ja` を次に変えます：

```rust
関数 主関数() {
    表示行!("こんにちは、太郎です！");
    表示行!("日本語 Rust を学んでいます。");
}
```

一行ずつ：

- 第 1 行：主関数を定義。プログラムはここから始まる。
- 第 2 行：「こんにちは、太郎です！」を表示して改行。
- 第 3 行：次の行に「日本語 Rust を学んでいます。」を表示して改行。
- 第 4 行：主関数の終わり。

保存して実行すると、画面には：

```
こんにちは、太郎です！
日本語 Rust を学んでいます。
```

> **観察**：二つの文が二行に分かれて表示されるのは、`表示行!` が毎回自動改行するから。命令は上から下へ順番に実行されます — 先に書いたものが先に動く。

### 実験 2：改行なしで表示

**目的**：「改行あり」と「改行なし」の違いを理解する。

```rust
関数 主関数() {
    表示!("こんにちは、");
    表示!("世界！");
}
```

一行ずつ：

- 第 2 行：`表示!` と `表示行!` の唯一の違いは — **表示後に改行しない**こと。
- 第 3 行：前回の表示位置の続きから現れる。

実行すると画面には：

```
こんにちは、世界！
```

二つの文字が一行につながったのは、途中で改行がなかったからです。

### 実験 3：文字にデータを差し込む

**目的**：プログラムにデータを「覚えさせ》、必要なときに取り出せるようにする。

```rust
関数 主関数() {
    宣言 名前 = "太郎";
    宣言 年齢 = 12;
    表示行!("私は{}、{}歳です。", 名前, 年齢);
}
```

一行ずつ：

- 第 2 行：`宣言` はキーワードで「箱を作る」という意味。この行は：箱を用意し、「名前」ラベルを貼り、「太郎」を入れる。
- 第 3 行：同様に、「年齢」ラベルの箱に 12 を入れる。
- 第 4 行：`{}` は**プレースホルダ**（あらかじめ空けておく席）。`表示行!` が括弧の後ろに並べたデータを順番に空席へ埋め込みます。

> 📖 **変数**：ラベルの貼られた箱。ラベルが名前、箱の中身がデータ。`宣言 名前 = "太郎"` で「名前」という変数ができます。第3章で詳しく扱います。

> 📖 **プレースホルダ**：あらかじめ空けておいて、後で埋めるための席。`{}` がそれで、フォームの空欄のようなものです。

埋め込みの過程：

```
"私は{}、{}歳です。"     ← テンプレート、空席が二つ
      ↑       ↑
    名前     年齢        ← 順番に埋める
   "太郎"     12
      ↓       ↓
"私は太郎、12歳です。"   ← 最終結果
```

実行すると画面には：

```
私は太郎、12歳です。
```

## 2.9 コードスタイル

コードは動くだけでなく、読みやすくなければなりません。作文が丁寧で段落がはっきりしているように。

### インデント：半角スペース 4 つ

波括弧の中のコードは、右に 4 つの空白を下げて、外側の関数に「属する」ことを示します。

```rust
関数 主関数() {
    表示行!("正しいインデント");  // ✅ 4 つの空白
}
```

なぜインデントするのか？階層がひと目でわかるからです。手紙の段落の頭を空けるのと同じ — 構造を見た目で分かるようにするためです。

> ✨ **ヒント**：空白を数える必要はありません。VS Code 拡張を入れていれば、コード内で**右クリック → ドキュメントのフォーマット**で自動整列します。

### 命名

| 分類 | スタイル | 例 |
|---|---|---|
| 関数名 | 動詞または動詞句 | `合計を計算`、`入力を取得` |
| 変数名 | 名詞 | `名前`、`年齢`、`個数` |

> ⚠️ **注意**：名前はキーワードと衝突させないこと。また、言語パックの対応語（`結果`、`文字列型` など）と同じ名前も避けましょう — 別の用途があるため混乱のもとです。具体的な名前（`合計点`、`あいさつ`）が一番安全です。

### コメント：人間のための注釈

> 📖 **コメント**：コード内の人間のための説明文。コンパイラは完全に無視します。一行コメントは `//` から始まります（半角スラッシュ二つ）。

```rust
// これは一行コメント。コンパイラは無視する

関数 主関数() {
    表示行!("こんにちは"); // 行末にも書ける
    // 宣言 名前 = "太郎";  // コメントアウトされたコードは実行されない
}
```

なぜコメントを書くのか？コードはコンピュータに「何をするか」を伝え、コメントは人間に「なぜそうするか」を伝えます。数日後に自分のコードを読み返したとき、思い出す手がかりになります。

## 2.10 よくあるエラーと解決法

コードを書けば必ず間違えます — ごく普通のことです。コンパイラを**厳しいが親切な先生**と想像してください：採点しながら、**どこが・なぜ・どう直すか**を教えてくれます。

> 📖 **エラーメッセージ**：コンパイラが問題を見つけたときに出す文字。批判ではなく、間違い探しの手伝いです。

まず、実行せずにチェックだけするコマンドを覚えましょう：

```bash
rzc check src/main.ja
```

> 📖 `check` は「チェックする」の意味。翻訳と検査だけして、実行はしません。提出前に自分で見直すようなものです。

### エラー 1：括弧の閉め忘れ

```rust
関数 主関数() {
    表示行!("こんにちは"   // ❌ 閉じ括弧 ) とセミコロンがない
}
```

`rzc check` の報告：

```
error: mismatched closing delimiter: `}`
  --> main.ja:2:22
```

**読み方**：

- `mismatched closing delimiter`：「閉じ記号が合っていない」— 括弧が閉じられていない。
- `-->` の後ろは場所：`main.ja` の 3 行目 1 列目。
- この種の**構文エラー**（書き方の規則違反）にはエラーコードがなく、英語の原文で表示されます。

**直し方**：左括弧と右括弧の数を数える。口癖：**開いた括弧は必ず閉める**。

### エラー 2：道具名の打ち間違い

```rust
関数 主関数() {
    表示ギョウ!("世界");  // ❌ 「表示ギョウ」は存在しない。正しくは「表示行」
}
```

報告：

```
error: cannot find macro `表示ギョウ` in this scope
  --> main.ja:2:5
```

**読み方**：`cannot find` は「見つからない」、`macro` は「マクロ」。つまり：**この範囲に `表示ギョウ` というマクロは存在しない**。ほぼ間違いなく打ち間違いです。

**直し方**：本章の道具名と照らし合わせ、`表示行!` に直します。

### エラー 3：型の不一致（最頻出）

```rust
// 预期错误: E0308
関数 主関数() {
    宣言 個数: 整数 = 10;     // 個数 は数字を入れる箱
    個数 = "こんにちは";       // ❌ 数字の箱に文字を詰めようとしている
}
```

報告：

```
エラー[E0308]: 型の不一致：`整数` を期待しましたが、`文字列参照` が渡されました
💡 変数の型が文脈の要求と一致しているか確認してください。
```

**読み方**：

- `エラー[E0308]`：括弧内は**エラーコード**。各コードはよくある間違いの一種類に対応します。コード付きのエラーは日本語に翻訳されています。
- `型の不一致`：問題の本質 — 異なる種類のものが混ざった。
- `💡` の後ろは修正の提案です。

> 📖 **型**：データの「種類」。数字も文字も別の種類です。箱にはラベルの種類のものしか入れられません。第3章で詳しく扱います。

**この一文を覚えてください**：数字は数字、文字は文字 — 混ぜてはいけません。「リンゴ用」と書かれた箱にバナナを無理やり詰められないのと同じです。

## 2.13 よくある質問

**問 1：画面に「rzc は内部コマンドまたは外部コマンドとして認識されていません」と出ます。**

ターミナルが rzc を見つけられていません。窓を閉じて開き直す；だめならパソコンを再起動；それでもだめならインストールに失敗しています — 2.4 の手順に戻ってやり直しましょう。

**問 2：日本語で書いたのに、なぜコンピュータが分かるのですか？**

コンピュータは実は日本語を理解していません。rzc がまず日本語キーワードを英語に置き換え（マッピング表を参照）、その後 rustc がマシンコードにコンパイルします。あなたの見る「日本語コード」はあなたへのやさしい見た目で、実際に動くのは翻訳後の英語コードです。

**問 3：引用符の中の日本語も翻訳されますか？**

されません。引用符の中の文字はそのまま残ります。rzc が翻訳するのはコード本体のキーワードと識別子だけです。

**問 4：`表示` と `表示行` の違いは？**

`表示行!` は表示後に自動改行、`表示!` はしません。二つの文字をつなげたいときは `表示!` を使います。

**問 5：感嘆符 `!` は必須ですか？**

省略できます — 道具が自動で補います。ただし書いておくことを勧めます。感嘆符を見れば「これはマクロだ」と一目で分かるからです。

**問 6：VS Code を使わずメモ帳で書けますか？**

書けますが、お勧めしません。メモ帳には色分けも自動整列もワンクリック実行もなく、とても疲れます。仕事を始める前に道具を磨く、ということわざの通りです。

**問 7：コードの間違いでパソコンが壊れますか？**

絶対に壊れません。コードの間違いの最悪の結果は「プログラムが実行できない」ことだけ。直せば終わりです。思い切って実験しましょう。

**問 8：この章の単語が覚えられません！**

覚える必要はありません！用語集は調べるためのものです。使っているうちに自然と身につきます — 自転車の乗り方に「左足から」と覚える必要がないのと同じです。

## 次章の予告

**第3章《変数と型》**では、プログラムにデータを「覚えさせる」方法を学びます：

- **`宣言`** で変数を作る（「ラベル付きの箱」）完全なルール。
- **`可変`** で箱の中身を入れ替えられるようにする。
- データの種類：**整数**、**浮動小数点数**、**ブール**、**文字**。
- プログラムに計算をさせる：足し算、引き算、掛け算、割り算。

本当に「計算できる」プログラムを書けるようになります！
