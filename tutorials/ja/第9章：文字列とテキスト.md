# 第 9 章：文字列とテキスト

## 9.0 この章の目標

この章を終えると、あなたは次のことができるようになります：

1. **文字列参照**（`&str`）と **文字列型** の二つの文字型を区別できる；
2. 文字列を作り、追加し、つなげられる；
3. `長さ()`、`含む()`、`先頭一致()`、`検索()` で文字を調べられる；
4. **バイト** と **文字** の違いを説明し、日本語のスライスがなぜパニックするか分かる；
5. `置換()`、`トリム()`、`分割()` で文字を加工できる；
6. `文字ごと()` で一文字ずつたどれる。

> ✨ ここまでの章はずっと「文字」に専用の一章を貸していました。今日ついに返済です。文字列は日常のプログラミングで最もよく使う型——この章はゆっくり読む価値があります。

---

## 9.1 二つの文字型

Rust の「ひとつなぎの文字」には二つの型があり、初心者が最も混乱しやすい場所です。

💡 **たとえ**：
- **文字列参照** は **石碑に刻まれた文字** ——工場出荷の時点で決まっていて、誰にも変えられません；
- **文字列型** は **ノートに書いた文字** ——加えたければ加えられるし、直したければ直せる（ただしノートは「可変」と宣言する必要があります）。

| 型 | 書き方 | 特徴 | 住処 |
|---|---|---|---|
| 文字列参照 | `文字列参照`（&str） | 不変。書き込まれた文字 | 石碑（プログラム組み込み領域） |
| 文字列型 | `文字列型` | 伸びる、変わる | 倉庫（ヒープ） |

```rust
宣言 石碑 = "刻まれた文字";                 // 型：文字列参照
宣言 可変 ノート = 文字列型::から("書ける文字"); // 型：文字列型
```

📖 **文字列型**：伸び縮みできる文字型。ヒープに存在します。
📖 **文字列参照**：借り物の不変な文字。文字列リテラル（ダブルクォートで直接書いた文字）はこれです。

### どう選ぶ？

- 書き換えないもの（案内文、メニュー項目）→ リテラルのままでよい（文字列参照）；
- 変わるもの、つなげるもの（ユーザー入力、プログラムが組み立てるテキスト）→ `文字列型`。

---

## 9.2 石碑は変えられない

リテラルを変更してみましょう：

```rust
// 预期错误: E0599
宣言 可変 石碑 = "刻まれた文字";
石碑.追加('！');   // ❌ コンパイルエラー
```

エラーの大意：`文字列参照` に対して `追加` を呼べない。石碑は石碑です——`可変` を付けても救えません。 **型が能力を決める** のです。変えられる文字が欲しければ、`文字列型::から("...")` で碑文を **ノートへ書き写します** 。

---

## 9.3 文字列を作って育てる

```rust
// リテラルから文字列を造る
宣言 可変 日記 = 文字列型::から("きょうも文字列を学んだ");

// 追加：末尾に一文字足す（シングルクォート！）
日記.追加('、');

// 文字列追加：末尾にひとつなぎの文字を足す
日記.文字列追加("たのしい！");

表示行!("日記：{}", 日記);
// 预期输出: 日記：きょうも文字列を学んだ、たのしい！
```

出力：`日記：きょうも文字列を学んだ、たのしい！`

三つの要点：

| 書き方 | 意味 |
|---|---|
| `'、'` シングルクォート | **一文字**（文字型） |
| `"..."` ダブルクォート | ひとつなぎの文字（文字列参照） |
| `文字列型::から("...")` | 文字を書き写して可変な文字列にする |

> ⚠️ **注意**：シングルクォートとダブルクォートは混ぜられません。`追加` は一文字を受け取るのでシングルクォート；`文字列追加` はひとつなぎの文字を受け取るのでダブルクォート。

---

## 9.4 連結：`フォーマット!` 一発

📖 **フォーマット!**：値とテンプレートをつなげて新しい文字列を作るマクロ。テンプレートの中の `{}` は順に置き換えられます。`表示行!` とほぼ同じ姿ですが、違いは一つ： **`表示行!` は画面に表示し、`フォーマット!` は文字列を返す** 。

```rust
宣言 名前 = "太郎";
宣言 挨拶 = フォーマット!("こんにちは、{}さん！", 名前);
表示行!("{}", 挨拶);
// 预期输出: こんにちは、太郎さん！
```

出力：`こんにちは、太郎さん！`

文字の連結はこの一手だけ覚えておけば、場面の九割は足ります。

## 9.5 調べる

```rust
宣言 日記 = 文字列型::から("きょうも文字列を学んだ、たのしい！");

表示行!("バイト長：{}", 日記.長さ());
表示行!("「文字列」を含む？：{}", 日記.含む("文字列"));
表示行!("「きょうも」で始まる？：{}", 日記.先頭一致("きょうも"));
表示行!("「！」で終わる？：{}", 日記.末尾一致("！"));
```

出力：

```
バイト長：51
「文字列」を含む？：true
「きょうも」で始まる？：true
「！」で終わる？：true
```

> 📖 **表示の注意**：判定の結果はブール値です。コードでは `真`/`偽` と書けますが、印刷されるときは Rust 本来の `true`/`false` と出ます。

| メソッド | 役割 | 返り値 |
|---|---|---|
| `長さ()` | バイト数（文字数ではない！） | 整数 |
| `含む(小片)` | その部分が入っているか | ブール |
| `先頭一致(小片)` | それで始まるか | ブール |
| `末尾一致(小片)` | それで終わるか | ブール |
| `検索(小片)` | 最初に現れる位置（バイト番号） | オプション（第 16 章で扱います） |

## 9.6 バイトと文字：日本語の大きな罠

直感に反する数字を見ましょう：「きょうも文字列を学んだ、たのしい！」と数えてみると **17 文字** なのに、`長さ()` は **51** を返します。

📖 **バイト**：コンピュータが文字をしまう最小の単位。小さな箱一つ。
📖 **文字**：人間の目に見える「一字」。

💡 **たとえ**：コンピュータは UTF-8 という方式で文字を保存します——英数字は箱 1 個で済みますが、 **日本語の文字は 3 箱** 必要です。`長さ()` が数えているのは **箱の数（バイト）** であって、文字数ではありません。17 文字 × 3 箱 = 51。

### なぜ危険か：スライスのパニック

第 3 章でスライス `&配列[0..3]` を学びました。文字列も切れますが、切っているのは **バイト** です：

```rust
宣言 文 = "こんにちは世界";
宣言 前半 = &文[0..6];    // 先頭 6 バイト = 最初の二文字、✅
表示行!("前半：{}", 前半);
// 预期输出: 前半：こん
```

出力：`前半：こん`

しかし **文字のまんなか** を切ると：

```rust
// 预期行为: 运行失败
宣言 文 = "こんにちは";
宣言 半分 = &文[0..1];   // ❌ 「こ」の 1 箱目だけ切り取った
```

実行時にパニックします：

```
thread 'main' panicked at ...:
end byte index 1 is not a char boundary; it is inside 'こ' (bytes 0..3 of string)
```

（「バイト位置 1 は文字の境界ではない——それは『こ』の内部にある」。半箱では完全な文字が組み立てられないので、Rust はパニックしても文字化けをあなたに渡しません。）

> ⚠️ **ルール**：日本語の文字列を添字でスライスするとき、境界は **完全な文字と文字のすき間** に落ちなければなりません（一文字 3 バイトなので、0、3、6、9… が安全なすき間）。自信がなければ 9.8 の `文字ごと()` を使いましょう。

## 9.7 加工：置換・トリム・分割

```rust
// 置換：甲の部分を乙に換え、新しい文字列を返す
宣言 原文 = 文字列型::から("猫はかわいい");
宣言 新文 = 原文.置換("猫", "トラ");
表示行!("{}", 新文);          // トラはかわいい

// トリム：前後の空白を取る
宣言 汚いデータ = "  りんご,バナナ  ";
表示行!("[{}]", 汚いデータ.トリム());   // [りんご,バナナ]

// 分割：区切り文字でつなぎごとに切る
各 項目 中 "りんご,バナナ,みかん".分割(",") {
    表示行!("[{}]", 項目);
}
```

出力：

```
トラはかわいい
[りんご,バナナ]
[りんご]
[バナナ]
[みかん]
```

| メソッド | 役割 |
|---|---|
| `置換(古, 新)` | 一致した箇所をすべて換え、新しいものを返す |
| `トリム()` | 前後の空白（スペース、改行など）を取る |
| `分割(区切り)` | つなぎごとに切る。`各` と組み合わせて一つずつ処理 |

> ✨ **トリム + 分割** はユーザー入力処理の黄金コンビ：まず前後の空白を洗い流し、それからカンマやスペースで切り分けます。

## 9.8 一文字ずつたどる

一文字ずつ処理したいときは `文字ごと()` を使います：

```rust
各 字 中 "こんにちは".文字ごと() {
    表示行!("一文字：{}", 字);
}

```
出力：

```
一文字：こ
一文字：ん
一文字：に
一文字：ち
一文字：は
```

どの文字も分け隔てなく、毎回必ず完全な文字を一つ吐き出します—— **日本語の文字をまんなかで切ることは決してありません** 。これが添字スライスより安全な理由です。

---

## 9.9 総合例：日記アシスタント

```rust
関数 主関数() {
    // —— フォーマット! で文字をつなぐ ——
    宣言 名前 = "太郎";
    宣言 挨拶 = フォーマット!("こんにちは、{}さん！", 名前);
    表示行!("{}", 挨拶);

    // —— 可変な文字列は育つ ——
    宣言 可変 日記 = 文字列型::から("きょうも文字列を学んだ");
    日記.追加('、');
    日記.文字列追加("たのしい！");
    表示行!("日記：{}", 日記);

    // —— 調べる ——
    表示行!("バイト長：{}", 日記.長さ());
    宣言 可変 文字数 = 0;
    各 _ 中 日記.文字ごと() {
        文字数 = 文字数 + 1;
    }
    表示行!("文字数：{}", 文字数);
    表示行!("「文字列」を含む？：{}", 日記.含む("文字列"));

    // —— トリム + 分割 ——
    宣言 汚いデータ = "  りんご,バナナ,みかん  ";
    宣言 きれいなデータ = 汚いデータ.トリム();
    各 項目 中 きれいなデータ.分割(",") {
        表示行!("[{}]", 項目);
    }

    // —— 文字ごと ——
    各 字 中 "こんにちは".文字ごと() {
        表示行!("一文字：{}", 字);
    }
}
// 预期输出: こんにちは、太郎さん！
// 日記：きょうも文字列を学んだ、たのしい！
// バイト長：51
// 文字数：17
// 「文字列」を含む？：true
// [りんご]
// [バナナ]
// [みかん]
// 一文字：こ
// 一文字：ん
// 一文字：に
// 一文字：ち
// 一文字：は
```

## 9.10 一行ずつ

- **3〜5 行目**：`フォーマット!` が `名前` をテンプレートに流し込み、 **新しい文字列** を返して `挨拶` にしまいます。
- **8〜10 行目**：`文字列型::から` で可変な文字列を造る；`追加` はシングルクォートの文字、`文字列追加` はダブルクォートの文字を足します。
- **14 行目**：`長さ()` が数えるのは **バイト**：17 文字 × 3 = 51。
- **15〜18 行目**： **文字** を数える方法——`文字ごと()` でたどり、一つ吐くごとに `文字数` を一つ足す。14 行目と並べれば、バイトと文字の違いがはっきり見えます。
- **22〜26 行目**：まず `トリム()` で前後のスペースを洗い、それから `分割(",")` でカンマごとに切り、`各` で一つずつ印刷。
- **29〜31 行目**：`文字ごと()` はどの文字も正しく一つずつ吐き出します。

## 9.12 よくある失敗と直し方

### 失敗一：リテラルは変えられない

`"..."` に対して `追加` などの変更メソッドを呼ぶとエラー。**解決**：`文字列型::から("...")` で可変な複製を書き写してから変更する。

### 失敗二：E0308 型不一致：`文字列型` を期待したが `文字列参照` を得た

```rust
// 预期错误: E0308
関数 受け取る(話: 文字列型) { }
受け取る("こんにちは");   // ❌ リテラルは文字列参照
```

**解決**：`受け取る(文字列型::から("こんにちは"))` とするか、関数の引数を `文字列参照` に変える（読み取り専用の場面では後者がおすすめ——ずっと楽です）。

### 失敗三：スライスのパニック（バイト位置が文字の境界にない）

スライスの位置が文字のまんなかに落ちると、実行時にパニック。**解決**：境界は 3 の倍数（日本語の場合）、または `文字ごと()` でのたどりに切り替える。

### 失敗四：シングルとダブルの混同

`追加("！")` はエラー（一文字を受け取るのに文字を渡した）；`文字列追加('！')` も同様。**解決**：文字はシングルクォート、ひとつなぎはダブルクォート。

### 失敗五：`長さ()` を文字数だと思い込む

日本語の場面で `長さ()` はバイト数です。文字数を数めたいなら `文字ごと()` でカウントします。

## 9.15 よくある質問

**Q：なぜ Rust は文字型を二種類用意するの？ 一つではだめ？**

役割分担が資源の節約になるからです。石碑（リテラル）はコンパイル時にプログラムへ刻み込まれるので倉庫を占有しません；ノート（文字列型）は自由ですが維持費がかかります。読み取り専用なら参照でゼロコスト；加工が必要になって初めて `文字列型` を造ります。

**Q：`文字列参照` と第 8 章の「参照」はどういう関係？**

`文字列参照` は **参照** の一種——ひとつなぎの文字への不変借用です。第 8 章の `&文字列型` は「文字列型 への参照」、`文字列参照` は「文字そのものへの参照」。お互いに協力できます：`&文字列型` は `文字列参照` が必要な場所にそのまま渡せます（自動変換）。

**Q：数値を文字に変えるには？**

`フォーマット!("{}", 数)` が万能です。第 15 章の集合、第 16 章のエラー処理では、`解析()`（文字を数値に変える）の使い方もさらに見ていきます。

**Q：スライスがそんなに危険なら、学ぶ必要はある？**

あります。英数字だけのテキストやプロトコルデータの処理では、スライスは速くてよく使われます。ルールは一つだけ： **境界は文字のすき間に** 。日本語で自信がなければ `文字ごと()` 。

**Q：シングルクォートの `'あ'` は何バイト？**

文字型そのものは固定 4 バイトです（世界のどんな文字でも入る）。ただし UTF-8 のテキストとして保存すると、「あ」は 3 バイトです。入門のうちはこの細部にこだわらなくて大丈夫。

**Q：`分割` で出てきた断片は、そのまま保存して後で使える？**

断片は元の文字列への **借用** （文字列参照）なので、元の文字列が生きている間しか使えません。長期保存したいなら独立した文字列に変える必要があります（次の章以降の技）。まずは「分割しながら処理する」使い方を覚えましょう。

## 次は

ここまでのデータはみな「バラ売り」でした：名前が一つ、年齢が一つ、得点が一つ……現実の世界では、これらは **同じ一枚の名簿カード** に属しています。

第 10 章 **《構造体》** は、関連するデータをまとめる方法を教えます：

- 自分の型を定義する：`構造体 学生 { ... }`；
- 実体を作り、フィールドを読み、フィールドを変える；
- `実装` ブロックでメソッドを取り付ける（第 6 章の伏線がついに回収）；
- `#[派生(デバッグ)]` で構造体をそのまま印刷できるようにする。
