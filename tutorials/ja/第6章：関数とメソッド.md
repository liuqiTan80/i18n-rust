# 第 6 章：関数とメソッド

## 6.0 この章の目標

この章を終えると、あなたは次のことができるようになります：

1. **魔法の箱** のたとえで、関数とは何かを説明できる；
2. **引数つき・返り値つき** の関数を自分で書ける；
3. **文** と **式** を区別し、セミコロンがどう返り値を「飲み込む」か分かる；
4. **`返す`** キーワードで結果を先渡しできる；
5. **再帰** 関数（自分自身を呼ぶ関数）を書ける；
6. **`実装`** ブロックで型に **メソッド** を取り付け、**`自己`** の三つの書き方を知っている；
7. **空型** `()` を知っている。

---

## 6.1 関数とは：魔法の箱

💡 **たとえ**：あなたが **魔法の箱** を持っていると想像してください：

- 上の **入口** から物をいくつか差し込む（これを **引数** と呼びます）；
- 箱の中でひとりでにせわしなく働く（これが **関数本体** です）；
- 下の **出口** から結果を吐き出す（これが **返り値** です）。

例えば「ジューサー」の箱：りんご（引数）を差し込むと、中で絞って（関数本体）、りんごジュース（返り値）を吐き出します。

📖 **関数**：名前を付けられて、繰り返し使える命令の切れ端。本書では **`関数`** と書きます。

実はあなたはとっくに関数を使っています——`表示行!` もその一つです（感嘆符つきの特別な「マクロ」で、第 2 章で感嘆符の違いを学びました）。今から学ぶのは **自分で箱を造る** ことです。

### なぜ関数が要るのか

同じ五つ星の図形を三つの場所で表示したいとします。関数を知らなければ、同じコードを **三回書き写す** はめになります。三回の書き写しには二つの欠点があります：

1. **疲れる**：三回書くのは時間の無駄；
2. **直しにくい**：図形を変えたくなったら三つの場所を直すことになり、一つでも漏らせばプログラムの誤動作（業界用語で「バグ」）になります。

関数があれば：図形のコードを一つの箱にしまい、名前を付けます。使いたいときは **名前を呼ぶ** だけ。直すときも箱の中の一枚を直すだけです。

> 💡 **一言で**：関数 = 名前のついたコードブロック。**書き写しを減らし、修正を楽にする** ためのものです。

---

## 6.2 最も簡単な関数

まず、引数も返り値もない関数を見てみましょう：

```rust
関数 挨拶() {
    表示行!("こんにちは！");
}

関数 主関数() {
    挨拶();
    挨拶();
}
```

見えるはずのもの：

```
こんにちは！
こんにちは！
```

五つの部品に分解すると：

| 部品 | 例 | 説明 |
|---|---|---|
| `関数` キーワード | `関数` | コンピュータに「ここに箱を造る」と伝える |
| 関数名 | `挨拶` | 箱の名前。自由に付けられる（動詞がおすすめ） |
| 小括弧 | `()` | 引数を入れる場所。今は引数がないので空 |
| 波括弧 | `{ }` | 箱の「身体」。中に具体的な命令を書く |
| 呼び出し | `挨拶();` | 名前を呼ぶ ＋ 小括弧 ＋ セミコロンで、箱を働かせる |

> ⚠️ **注意**：関数を **定義** する（箱を造る）ことと、関数を **呼び出す**（箱を働かせる）ことは別物です。定義だけ書いて呼ばなければ、箱は永遠に働きません。プログラムの入口は常に `主関数` です。

---

## 6.3 引数：箱に物を差し込む

📖 **引数（パラメータ）**：関数が受け取る入力の、定義時に書く名前。
📖 **実引数（アーギュメント）**：呼び出し時に実際に差し込む値。

💡 **たとえ**：ジューサーの取説に「**果物** を入れてください」と書いてある——「果物」が **引数**（占位の名前）；実際に入れたそのりんごが **実引数** です。

### 引数一つ

```rust
関数 あいさつ(名前: 文字列参照) {
    表示行!("こんにちは、{}さん！", 名前);
}

関数 主関数() {
    あいさつ("太郎");
    あいさつ("花子");
}
```

> 📖 **文字列参照**：借り物の文字。`"..."` のようなリテラルのこと。第 9 章で詳しくやります——今は「ダブルクォートの中の文字はこの型に属する」だけ覚えてください。

引数の書き方は **`名前: 型`**——Rust は各引数に **型の記述を必須** とし、一つも省略できません。

### 引数複数

複数の引数は **カンマ** で区切ります：

```rust
関数 合計(甲: 整数, 乙: 整数) -> 整数 {
    甲 + 乙
}

関数 主関数() {
    宣言 和 = 合計(3, 7);
    表示行!("和：{}", 和);
}
// 预期输出: 和：10
```

出力：`和：10`

新しい記号 **`->`**（マイナス＋大于号……ではなく、マイナスより大きい。意味は「指し示す」）に注目：

- `-> 整数` は「この箱が吐き出す物は整数」；
- `->` を書かない関数は物を吐き出しません（正確には「空」を吐きます。6.8 節で扱います）。

> ⚠️ **注意**：呼び出し時の実引数の **個数と順序** は引数と一致させなければなりません。`合計(3)` は一つ足りず、`合計("三", 7)` は型が違う——どちらもエラーです。

## 6.4 返り値：箱が結果を吐き出す

関数に結果を渡させる方法は三つあります。

### 方法一：末尾式（セミコロンなし）

関数本体の **最終行** が **式**（値を計算できるもの）で、しかも **末尾にセミコロンがない** 場合、その値が返り値になります：

```rust
関数 二乗(数: 整数) -> 整数 {
    数 * 数
}
```

`数 * 数` にセミコロンがない → その値が「吐き出される」。

### 方法二：`返す` キーワード

📖 **返す**：すぐに値を渡し、関数はそこで終わる。

```rust
関数 最大値(甲: 整数, 乙: 整数) -> 整数 {
    もし 甲 > 乙 {
        返す 甲;
    }
    乙
}
```

読み方：「もし甲のほうが大きければ、**すぐに** 甲を渡す；そうでなければ最終行まで進み、乙を渡す。」

`返す` は **早期脱出** によく使われます：条件が満たされたら答えを渡してさようなら、残りは実行しない。

### 方法三：ブロック式

第 5 章で学んだとおり：波括弧のブロック自体も式で、その最終行（セミコロンなし）の値がブロックの値になります：

```rust
宣言 和値 = {
    宣言 甲 = 10;
    宣言 乙 = 20;
    甲 + 乙
};
表示行!("ブロックの値：{}", 和値);
// 预期输出: ブロックの値：30
```

出力：`ブロックの値：30`

### ⚠️ セミコロン罠：最もよくある間違い

`数 * 数` に **セミコロンを付けると** どうなるでしょう？

```rust
// 预期错误: E0308
関数 二乗(数: 整数) -> 整数 {
    数 * 数;    // ❌ セミコロンが余分
}
```

エラー：**E0308 型不一致：`整数` を期待したが `()` を得た**。

💡 **たとえ**：セミコロンは「句点」のようなもの——一文を「陳述」に変えてしまいます（言い終わったらおしまい、何も残らない）。関数は整数を吐くと約束したのに、実際には「陳述」一つ（空値 `()`）しか吐かない——コンパイラが抗議するのも当然です。

**合言葉**：**返り値がほしければ、最終行にセミコロンを書かない。**

## 6.5 関数はどこに書いてもいい

`主関数` を先頭に書き、呼び出される関数を後ろに書くこともできます：

```rust
関数 主関数() {
    表示行!("面積：{}", 長方形の面積(3, 4));
}

関数 長方形の面積(縦: 整数, 横: 整数) -> 整数 {
    縦 * 横
}
// 预期输出: 面積：12
```

出力：`面積：12`

第 5 章の `もし`、`ループ` とは違います——あちらは使う前に現れなければなりませんが、**関数は順序にこだわりません**。コンパイラがまず全関数を「一通り登録」してから、どこからでも呼べるようにしてくれます。

## 6.6 再帰：関数が自分を呼ぶ

📖 **再帰**：関数が自分の本体の中で自分自身を呼ぶこと。

💡 **たとえ**：お父さんに「これどうすればいい？」と聞くと、「おじいさんに聞いて」と言われ、おじいさんは「ひいおじいさんに聞いて」と……最も年長の方にたどり着くと、その方が直接答えをくれて、それが一层一层伝わって戻ってきます。

定番の例は **階乗**。5 の階乗 = 5 × 4 × 3 × 2 × 1 = 120。法則は：`階乗(5) = 5 × 階乗(4)`、これをどんどん押し進め、`階乗(1) = 1` で止まります。

```rust
関数 階乗(数: 整数) -> 整数 {
    もし 数 <= 1 {
        返す 1;          // 底に着いた、直接答えを渡す
    }
    数 * 階乗(数 - 1)    // まだ底でない、「一まわり小さい自分」に聞く
}

関数 主関数() {
    表示行!("階乗：{}", 階乗(5));
}
// 预期输出: 階乗：120
```

出力：`階乗：120`

> ⚠️ **注意**：再帰には必ず **停止条件** が必要です（上なら `数 <= 1`）。停止条件のない再帰は永遠に問い続け、プログラムは崩壊します。物語の中で誰も答えをくれず、問い合わせが永遠に伝わり続けるようなものです。

> ✨ 今は再帰が分からなくても大丈夫。ループ（第 5 章）で大部分の問題は解けますし、再帰は「上級の書き方」——後の章でもまた出会います。

---

## 6.7 メソッド：型にぶら下がった関数

これまで造った箱は「汎用」で、誰でも使えました。もう一種、**特定の物に専属** の箱があります——例えば「リモコン」は「テレビ」の専属です。ある型にぶら下がった関数を **メソッド** と呼びます。

📖 **メソッド**：ある型にぶら下がった関数。ある玩具が持っている専用ボタンのようなもの——ボタンは玩具の身体に付いていて、押す前にまずその玩具が必要です。

**構造体**（自作の型）は第 10 章で正式に学びます。ここでは最も簡単な構造体を一つ借りて、メソッドの姿を見てみましょう：

```rust
構造体 スコアボード {
    得点: 整数,
    回数: 整数,
}
```

（読み方：スコアボードという型には二つのデータがある——得点と回数。）

### `実装` ブロック

型にメソッドを付けるには **`実装`**（「実装する、機能を取り付ける」という意味）を使います：

```rust
実装 スコアボード {
    // 関連関数：自己 引数なし、「新しいのを一つ造る」ために使う
    関数 作成() -> スコアボード {
        スコアボード { 得点: 0, 回数: 0 }
    }

    // メソッド：&自己 = 読み取り専用で自分を借りる
    関数 平均点(&自己) -> 整数 {
        もし 自己.回数 == 0 {
            返す 0;
        }
        自己.得点 / 自己.回数
    }

    // メソッド：可変参照 自己 = 自分を変更できる
    関数 一局記録(可変参照 自己, 加点: 整数) {
        自己.得点 = 自己.得点 + 加点;
        自己.回数 = 自己.回数 + 1;
    }
}
```

新しい言葉が二つ出てきました：

📖 **自己**：メソッドの中で「この実体自身」を表す引数。`平均点` はスコアボードのメソッドで、メソッド内の `自己` は「それを呼んだあのスコアボード」のことです。

📖 **関連関数**：`実装` ブロックに書かれているが **`自己` 引数を持たない** 関数。既存の実体を相手にせず、主に **新しい実体を造る** ために使うので、**コンストラクタ** とも呼ばれます。

### `自己` の三つの書き方

| 書き方 | 意味 | たとえ |
|---|---|---|
| `&自己` | 読み取り専用の借用。見るだけで変えない | 友達の本を借りて眺める。書き込まない |
| `可変参照 自己` | 可変の借用。変更してよい | 友達のペンを借りて字を書く。使い終わったら返す |
| `自己` | そのまま持っていく（消耗） | このりんごを食べる。りんごはなくなる |

第 7 章《所有権》、第 8 章《参照と借用》で「借用」を詳しく解説します。今はこれだけ覚えてください：**自分を変えたいメソッドは `可変参照 自己`、読むだけなら `&自己`**。

### メソッドの呼び出し：ドット

```rust
宣言 可変 板 = スコアボード::作成();   // 関連関数は ダブルコロン で呼ぶ
板.一局記録(80);                 // メソッドは ドット で呼ぶ
板.一局記録(95);
板.一局記録(76);
表示行!("平均点：{}", 板.平均点());
```

出力：`平均点：83`

二つの呼び方の対比：

| 呼び方 | 例 | 対象 |
|---|---|---|
| `型::名前()` | `スコアボード::作成()` | 関連関数（`自己` なし） |
| `実体.名前()` | `板.平均点()` | メソッド（最初の引数は `自己`、呼び出し時に自動で渡される） |

> ⚠️ **命名の注意**：関連関数に名前を付けるとき、標準ライブラリがすでに占有している対応語は **使わない** でください（例えば `新規`——標準ライブラリの予約対応語で、定義側と呼び出し側の変換が食い違い、「メソッドが見つからない」エラーの原因になります）。自分の新しい名前（例えば `作成`）を付けるのが一番安全です。同様に、変数名も `リザルト`（`Result` 型の対応語）などを避けましょう。

## 6.8 空型：何も吐かない

`->` を書かなかった関数は、実は特別な値を吐いています：**空**。`()` と書きます。

📖 **空（ユニット型）**：何も入れていない型。`()` と書く。「すべての関数に返り値がある」ことを保証するために存在します。ほとんど気にする必要はありません。

```rust
宣言 何もなし: 空 = ();
表示行!("空：{:?}", 何もなし);
// 预期输出: 空：()
```

出力：`空：()`

6.4 のセミコロン罠を覚えていますか？ エラーは「`整数` を期待したが `()` を得た」——あの `()` が空です。これで面識ができました。

### 発散関数と「決して戻らない」型（`!`）

「何も吐かない空」のほかに、もっと特別な関数があります：**発散関数**——「吐く」という動作自体が発生しません。終わりにたどり着く前に「永遠に去って」しまうからです。

📖 **発散関数**：決して普通には戻ってこない関数。返り値の型は `!` と書きます。無限ループするか、直接パニックするか、プログラムを中断するか——いずれかです。

```rust
関数 永遠に止まらない() -> ! {
    ループ {
        表示行!("また来たよ！");
    }
}

関数 必ず終わる() -> ! {
    パニック!("これは必ず死ぬ関数です");
}
```

`!` 型には不思議な性質があります：**どんな型の代わりとしても使える**。例えば `マッチ` のある腕が `!` を返すとき、マッチ全体の結果の型は他の腕で決まります——コンパイラが許可するのは、`!` の腕が実際に値を生むことが決してないからです：

```rust
関数 記述(可能値: オプション<整数>) -> 文字列型 {
    マッチ 可能値 {
        あり(値) => 値.文字列へ変換(),
        なし => パニック!("ここに値はないはず"),   // この腕の型は !（決して戻らない）、どんな型としても使える
    }
}
```

`パニック!`、`後で!`、`返す` これらの「早めに去る」式の型はみな `!` なので、どんな型が必要な式の位置にも現れられます。

💡 **たとえ**：`()` は「空の箱を受取人に手渡す」ようなもの；`!` は「配達員が途中で消息を絶った」——箱は永遠に届かないので、中身が何であるか決める必要すらないのです。

## 6.9 総合例：三科目成績アナライザー

この章で学んだすべてを使います：普通の関数（引数・返り値・早期リターン）＋ 構造体メソッド（関連関数・`&自己`・`可変参照 自己`）：

```rust
// ============ 普通の関数 ============

// 合計：引数二つ、返り値一つ
関数 合計(甲: 整数, 乙: 整数) -> 整数 {
    甲 + 乙
}

// 最大値：早期の 返す を使用
関数 最大値(甲: 整数, 乙: 整数) -> 整数 {
    もし 甲 > 乙 {
        返す 甲;
    }
    乙
}

// 挨拶：返り値なし、第 5 章のループを使用
関数 挨拶(回数: 整数) {
    各 _ 中 0..回数 {
        表示行!("こんにちは！");
    }
}

// ============ 構造体 + メソッド ============

構造体 スコアボード {
    得点: 整数,
    回数: 整数,
}

実装 スコアボード {
    // 関連関数：まっさらなスコアボードを造る
    関数 作成() -> スコアボード {
        スコアボード { 得点: 0, 回数: 0 }
    }

    // メソッド：一局の成績を記録（自分を変えるので 可変参照 自己）
    関数 一局記録(可変参照 自己, 加点: 整数) {
        自己.得点 = 自己.得点 + 加点;
        自己.回数 = 自己.回数 + 1;
    }

    // メソッド：平均点を算出（読み取り専用、&自己）
    関数 平均点(&自己) -> 整数 {
        もし 自己.回数 == 0 {
            返す 0;    // 一局も遊んでいなければ、ゼロ除算を避けて直接 0 を返す
        }
        自己.得点 / 自己.回数
    }

    // メソッド：戦況を報告（メソッドの中から別のメソッドも呼べる）
    関数 報告(&自己) {
        表示行!("計{}局、合計{}点、平均{}点", 自己.回数, 自己.得点, 自己.平均点());
    }
}

// ============ 主関数 ============

関数 主関数() {
    表示行!("和：{}", 合計(3, 7));
    表示行!("大きいのは：{}", 最大値(5, 9));
    挨拶(2);

    宣言 可変 板 = スコアボード::作成();
    板.一局記録(80);
    板.一局記録(95);
    板.一局記録(76);
    板.報告();
    表示行!("平均点は：{}", 板.平均点());

    宣言 何もなし: 空 = ();
    表示行!("空：{:?}", 何もなし);
}
// 预期输出: 和：10
// 大きいのは：9
// こんにちは！
// こんにちは！
// 計3局、合計251点、平均83点
// 平均点は：83
// 空：()
```

## 6.10 一行ずつ

- **4〜6 行目**：`合計` は整数を二つ受け取り、最終行 `甲 + 乙` にセミコロンがないので、その値が返り値になります。

- **25〜28 行目**：構造体 `スコアボード` を定義。二つのフィールドはどちらも整数。
- **32〜34 行目**：関連関数 `作成` は `自己` 引数がなく、「0 点 0 局」の新しいスコアボードを返します。
- **37〜40 行目**：`一局記録` は `可変参照 自己` を使います——自分の二つのフィールドを変更するからです。
- **43〜48 行目**：`平均点` はまずゼロ除算を防ぎ（`回数 == 0` なら早期に 0 を返す）、それから整数除算をします。
- **51〜53 行目**：`報告` の中の `自己.平均点()` は **メソッドがメソッドを呼ぶ** 例です。

## 6.12 よくある失敗と直し方

### 失敗一：E0308 返り値の型不一致

```rust
// 预期错误: E0308
関数 倍にする(数: 整数) -> 整数 {
    "大きくなった"
}
```

エラー：

```
エラー[E0308]: 型不一致：`整数` を期待したが `文字列参照` を得た
```

**原因**：整数を返すと約束したのに、文字を渡した。**解決**：返り値と `->` の後ろの型が一致しているか確認。大抵は二種類——型を書き間違えたか、セミコロンを多く/漏らして書いたか（次の項参照）。

### 失敗二：セミコロンを取り忘れ（E0308 ＋ `()`）

```rust
// 预期错误: E0308
関数 二乗(数: 整数) -> 整数 {
    数 * 数;
}
```

エラー：`型不一致：整数 を期待したが () を得た`。

**解決**：返り値の行からセミコロンを削除。エラーに `()` が見えたら、まずセミコロンを疑いましょう。

### 失敗三：引数に型を書き忘れ

```rust
関数 二乗(数) -> 整数 {   // ❌ 数 の後ろに「: 整数」がない
```

エラーが型注釈の欠落を教えてくれます。**解決**：Rust では **関数の引数に必ず型を書く**。一つも省略できません：`(数: 整数)`。

### 失敗四：呼び出し時の引数が合わない

`合計(3)` は実引数が一つ足りず、`合計(3, 7, 9)` は一つ多い——どちらも「この関数は N 個の引数を受け取る」というエラーになります。**解決**：定義側の引数の数を数えて、呼び出し側も同じ数に。

### 失敗五：ゼロ除算はエラーにならないの？

`平均点` で `回数 == 0` を防がないと、初回の実行で **パニック** します（実行時の崩壊。第 3 章で見ました）。Rust の整数のゼロ除算は実行時エラーで、コンパイラは事前に止めてくれません。**解決**：割り算の前に必ず除数が 0 でないか調べる。

### 失敗六：メソッドが見つからない（名前の衝突）

`新規` を自分の関数名にすると、「定義側は変換されず、呼び出し側は `new` に変換される」という食い違いが起き、E0599「その型にメソッドが見つからない」になりがちです。**解決**：自作の関数・変数名は標準ライブラリの対応語（`新規`、`リザルト` など）を避け、自分の名前を付ける。

## 6.13 章末用語集

| 用語 | 一言でいうと |
|---|---|
| 関数 | 名前が付いていて繰り返し使える命令のブロック |
| 引数 | 関数定義時に書く入力の名前。型が必須 |
| 実引数 | 呼び出し時に実際に渡す値 |
| 返り値 | 関数の実行後に渡される結果 |
| 返す | 結果を先渡しして関数を終える |
| 式 | 値を一つ計算できる書き方（最終行のセミコロンを取れば返り値になる） |
| 文 | 物事をひとつ済ませる命令。セミコロンで終わり、値を生まない |
| 再帰 | 関数が自分を呼ぶこと。停止条件が必須 |
| メソッド | ある型にぶら下がった関数 |
| 実装 | 型にメソッドを取り付けるブロック |
| 自己 | メソッド内で「この実体自身」を表す引数 |
| 関連関数 | 実装ブロック内の自己引数なしの関数。新しい実体を造るのによく使う |
| コンストラクタ | 「関連関数」参照 |
| 空（ユニット型） | 何も入れていない型。() と書く |
| パニック | プログラムが誤ると即座に崩壊終了する（実行時） |

> 📖 **お知らせ**：分からない言葉が出たら、いつでも本の冒頭の《総用語表》に戻って引いてください。

## 6.15 よくある質問

**Q：関数名に日本語は使える？ 制限はある？**

使えます。本書はすべて日本語の関数名です。**動詞から始める**（`合計`、`表示`、`点検`）のがおすすめ——箱が何をするのか一目で分かります。対応表にある既存の語（`新規`、`表示行` など）を自分の関数名に使うと衝突するので避けましょう。

**Q：関数と第 5 章の `マッチ`、`ループ` はどういう関係？**

`もし`、`ループ` は **制御フロー**（実行順を決める）、関数は **コードの組織化**（命令を名前付きでまとめる）。関数の中で制御フローを自由に使えるし、制御フローの中で関数を呼んでもいい。協力関係です。

**Q：一つの関数で複数の値を返せる？**

厳密には返せるのは **一つ** だけ。でも複数の値を **タプル**（第 4 章で学びました）に包んで一緒に返せます。例：`-> (整数, 整数)`。第 10 章で構造体を学べば、構造体を返すこともできます。

**Q：`返す` と最終行式、どちらを使うべき？**

単純な計算なら最終行式（すっきり）； **先に立ち去りたい**（条件が満たされたら先へ進まない）ときは `返す`。どちらもよく使います。

**Q：メソッドの `&自己` の `&` はどういう意味？**

「借用」です——メソッドはこの実体を **借りて** 見たり変えたりするだけで、使い終わったら返す。食べたりしません。第 7 章《所有権》、第 8 章《参照と借用》の二章まるごとかけて詳しくやります。今は決まり文句として覚えてください。

**Q：再帰とループ、どちらが速い？**

多くの場合、ループのほうが速くてメモリも節約できます。再帰の強みはコードの優雅さと分かりやすさ（特に「何層にも入れ子」になる問題）。入門のうちは両方書けるようになれば十分で、性能を気にする必要はありません。

**Q：なぜ `挨拶` の中でループ変数に `_` を使うの？**

`_` は「この値は使わない」という意味です。ループは `回数` 遍繰り返すだけで、今が何遍目かに関心がないなら、`_` で名付けを飛ばします。これで「変数を定義したのに使っていない」警告も避けられます。

## 次は

あなたの造った箱はどんどん増えていきます。でも、箱に入れたデータには大きな問題があります：**誰がそれを所有する？ 使い終わったら誰が片付ける？**

第 7 章 **《所有権》** では、Rust 最も独特なルールを学びます：

- すべての値にはただ一人の **主人**（所有者）がいる；
- 主人がいなくなると、値は自動的に **片付けられる**（解放される）；
- 値を他人に渡すと、自分は **もう使えない**（移動）；
- `クローン` なら独立した複製を作れる。

これは Rust が他の言語と最も違うところであり、メモリ安全の秘密兵器でもあります。次の章でお会いしましょう！
