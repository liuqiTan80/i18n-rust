# 附录D：常见问题与学习路线

学完整个教程后，你可能还有很多疑问。本附录回答最常见的问题，并给你一条继续前进的路线。

---

## D.1 常见问题

### "我完全看不懂怎么办？"

回头重新读前面的章节。每章的比喻和解释是独立的——你可以只看某一章，不用从头开始。

最重要的是**动手写代码**。光看不练永远学不会——就像光看菜谱不会做菜一样。

### "编译器报错了怎么办？"

先别慌。编译器报错不是"你做错了"，而是"编译器在帮你"。

Rust 的编译器是出了名的友好——它会告诉你：
1. 哪里出了错
2. 为什么错了
3. 怎么修

仔细阅读错误信息，大部分问题都能自己解决。

### "什么时候用结构体，什么时候用枚举？"

- **结构体**：当你需要把**多个数据打包**时——比如一个人的姓名、年龄、身高
- **枚举**：当一个值**只能是几种情况之一**时——比如方向（东南西北）、选项（有/无）

### "什么时候用引用，什么时候用克隆？"

- **引用**：你只是想"看看"数据，不需要修改——借来看，看完还回去
- **克隆**：你需要一份独立的副本——复印一份，各改各的

克隆会消耗更多内存。如果数据很大，优先考虑引用。

### "什么时候用 `结果`，什么时候用 `恐慌`？"

- **`结果`**：错误是**可以预见的**——文件可能不存在、用户可能输入错误
- **`恐慌`**：错误**不应该发生**——发生了就说明程序有严重问题

经验法则：如果错误是"正常的"（用户经常遇到的），用 `结果`。如果错误是"不可能发生的"（发生了就是 bug），用 `恐慌`。

## D.2 学习路线

学完本教程后，推荐按以下路线继续学习：

### 第一阶段：巩固基础（1-2 周）

- 重新阅读你不确定的章节
- 做每章的练习题
- 写几个自己的小项目（计算器、猜数字游戏、待办事项列表）

### 第二阶段：实战项目（2-4 周）

选择一个小项目来做：

1. **命令行工具**：文件搜索、文本处理、批量重命名
2. **小游戏**：猜数字、贪吃蛇、21 点
3. **网络工具**：简单的网页服务器、聊天室

### 第三阶段：深入学习（持续）

1. 阅读标准 Rust 的官方教程
2. 学习 Rust 的异步生态
3. 学习 Rust 的嵌入式开发
4. 参与开源项目

## D.3 编程思维建议

### 先想清楚再写代码

拿到一个问题后，不要急着写代码。先用自然语言描述解决步骤：

```
问题：计算一组成绩的平均分

步骤：
1. 把所有成绩加起来
2. 数一数有多少个成绩
3. 总分除以个数
```

想清楚步骤后，再翻译成代码。

### 从小处开始

不要试图一次写 1000 行代码。每次只写一小部分，确认它能运行，再继续。

```
第一步：写一个能打印"你好"的程序 → 运行 ✅
第二步：加一个变量 → 运行 ✅
第三步：加一个循环 → 运行 ✅
...
```

### 多读错误信息

编译器的错误信息是你的朋友。它告诉你：
- **哪里**错了（文件名和行号）
- **什么**错了（错误类型）
- **怎么**修（建议的修复方式）

### 善用文档

遇到不认识的功能时，查文档。文档里有：
- 功能的说明
- 使用示例
- 注意事项

## D.4 编程习惯建议

### 给变量取有意义的名字

```rust
// ❌ 看不出是什么
让 x = 25;

// ✅ 一看就知道
让 学生年龄 = 25;
```

### 写注释解释"为什么"

```rust
// ❌ 没用的注释——代码已经说了
让 总分 = 甲 + 乙;  // 甲加乙

// ✅ 有用的注释——解释了"为什么"
// 因为满分是 100，超过 100 按 100 算
让 总分 = (甲 + 乙).最小(100);
```

### 保持函数简短

一个函数只做一件事。如果函数太长了，考虑拆成多个小函数。

```rust
// ❌ 一个函数做了太多事
函数 处理用户() {
    // 读取用户信息...
    // 验证用户信息...
    // 保存到数据库...
    // 发送欢迎邮件...
}

// ✅ 每个函数只做一件事
函数 处理用户() {
    让 用户 = 读取用户信息();
    验证用户信息(&用户);
    保存到数据库(&用户);
    发送欢迎邮件(&用户);
}
```
