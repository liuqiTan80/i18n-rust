# 第二十二章：闭包与迭代器

## 22.0 学习目标

读完这一章，你将能够：

1. 用**随身小工具**比喻解释闭包；
2. 写出 **`|参数| 表达式`** 形式的闭包；
3. 解释闭包如何**抓住**周围的数据（包括可变数据）；
4. 用**流水线**比喻解释迭代器；
5. 熟练使用 **`迭代`→`过滤`→`映射`→`收集`** 四段链；
6. 用 `求和` 等快捷方法一步到位；
7. 理解迭代器的**懒惰**特性（不收集不开工）。

---

## 22.1 闭包：揣兜里的匿名函数

第六章教过定义函数——得起名字、住在文件顶层。可有时你只想**现场造一个小工具**，用完就扔：

```rust
让 加 = |甲: 整数, 乙: 整数| 甲 + 乙;
打印行!("加(2,3) = {}", 加(2, 3));   // 5
```

📖 **闭包（closure）**：没有名字的函数，可以存在变量里、当参数传、从函数返回。语法：

```
|参数1, 参数2| 表达式        // 参数类型常可省略
|| 表达式                    // 无参数
```

💡 **比喻**：正式函数像**挂牌门店**（有地址有招牌）；闭包像**揣兜里的瑞士军刀**——不挂牌，掏出来就用。

第二十章的 `线程::生成(|| { ... })` 传的就是闭包——把一段活打包交给线程。

## 22.2 闭包的背包：抓住环境

闭包最神奇的本事：能**抓住**定义它时周围的数据。

```rust
让 可变 计数 = 0;
让 可变 加一 = || 计数 = 计数 + 1;
加一();
加一();
加一();
打印行!("计数 = {}", 计数);   // 3
```

`加一` 这个闭包没写参数、没写捕获清单，却自动"看见"并抓住了旁边的 `计数`。

💡 **比喻**：闭包出门带个**背包**，把它需要的周围变量装进去随身带走。要改背包里的东西，闭包本身也得 `可变`（`让 可变 加一`）。

三种抓法（编译器自动挑，知道有即可）：借来读（&）、借来改（可变引用）、整个搬走（移动，见第二十章）。

## 22.3 迭代器：数据流水线

处理一串数据，笨办法是 `对于` 循环一步步挪。迭代器给出**流水线**写法：

💡 **比喻**：工厂流水线——原料（数据）上去，每站干一件事（筛选、加工），末端装箱（收集）。**每个站不碰原料本身，只描述加工规则**。

```
数列.迭代().过滤(...).映射(...).收集()
   原料     筛选站     加工站     装箱
```

📖 **迭代器（iterator）**：一个"知道下一个元素是谁"的传送装置。`迭代()`（= iter）把数组、向量变成传送带。

## 22.4 四段链逐站拆解

```rust
让 数列 = [1, 2, 3, 4, 5, 6];
让 偶数放大: 向量<整数> = 数列.迭代()
    .过滤(|数| *数 % 2 == 0)
    .映射(|数| 数 * 10)
    .收集();
```

| 站 | 方法 | 干什么 | 产物 |
|---|---|---|---|
| 原料 | `迭代()` | 把数组上传送带 | 1,2,3,4,5,6 |
| 筛选 | `过滤(闭包)` | 留下闭包说"真"的 | 2,4,6 |
| 加工 | `映射(闭包)` | 每个过一遍变换 | 20,40,60 |
| 装箱 | `收集()` | 传送带末端收成容器 | 向量 [20,40,60] |

两个细节：

- **`*数`**：迭代器递出来的是**借用**，比较前先 `*` 拆包；
- **`: 向量<整数>`**：`收集` 能装进好几种容器，必须说清楚要哪种——这是新手最常忘的标注。

## 22.5 快捷终点：不止收集

流水线的终点不一定装箱：

```rust
让 总和: 整数 = 数列.迭代().求和();   // 21
```

`求和`（= sum）直接把传送带上的数加起来。（`总和: 整数` 的标注同理——说清结果类型。）还有 `折叠`（累加器自定义起点和规则）等，用到再查。

## 22.6 懒惰的流水线

迭代器是**懒惰**的：

```rust
让 带 = 数列.迭代().映射(|数| 数 * 10);
// 此时什么都没算！
```

只搭链子不干活，**直到遇到终点站**（`收集`、`求和`、`对于` 循环消费）才真正启动。好处：中间不产生临时容器，省内存、方便优化。

## 22.7 完整示例：数据加工车间

闭包三态 + 迭代器两链，合在一个车间里：

```rust
函数 主函数() {
    // —— 匿名函数，揣兜里随叫随到 ——
    让 加 = |甲: 整数, 乙: 整数| 甲 + 乙;
    打印行!("加(2,3) = {}", 加(2, 3));

    // —— 闭包抓住周围的可变数据 ——
    让 可变 计数 = 0;
    让 可变 加一 = || 计数 = 计数 + 1;
    加一();
    加一();
    加一();
    打印行!("计数 = {}", 计数);

    // —— 迭代器流水线：过滤偶数、放大十倍 ——
    让 数列 = [1, 2, 3, 4, 5, 6];
    让 偶数放大: 向量<整数> = 数列.迭代()
        .过滤(|数| *数 % 2 == 0)
        .映射(|数| 数 * 10)
        .收集();
    打印行!("流水线产物：{:?}", 偶数放大);

    // —— 直接求和 ——
    让 总和: 整数 = 数列.迭代().求和();
    打印行!("总和 = {}", 总和);
}
```

## 22.8 逐行解释

- **第 3–4 行**：现场造 `加`——两个参数、一条表达式，随造随用。
- **第 7–12 行**：`加一` 抓住可变的 `计数`；三次调用，背包里的值真真切切涨了三次。两个 `可变` 缺一不可。
- **第 15–19 行**：四段链一气呵成。`过滤` 里的 `*数 % 2 == 0` 是"偶数判断"；`%` 是取余运算。
- **第 22–23 行**：`求和` 终点站，不装箱直接出总数。

## 22.9 运行结果

```
加(2,3) = 5
计数 = 3
流水线产物：[20, 40, 60]
总和 = 21
```

`{:?}` 打印向量时会带上方括号——这是调试格式（第十章见过）。

## 22.10 常见错误与解决

### 错误一：`收集` 不知道往哪装

```
错误：无法推断收集的目标类型
```

**解决**：给变量标类型 `让 结果: 向量<整数> = ...`。

### 错误二：闭包里改不了捕获的变量

```
错误：无法借用为可变
```

**解决**：被捕获的变量和闭包变量**都要** `可变`。

### 错误三：比较借用和数值

`|数| 数 % 2 == 0` 报类型不匹配——`数` 是借用。**解决**：`*数 % 2 == 0`，或先 `映射(|数| *数)` 统一拆包。

### 错误四：链子搭了没干活

光 `.迭代().映射(...)` 没输出？迭代器是懒惰的。**解决**：补上终点站（`收集`/`求和`/循环消费）。

## 22.11 本章术语表

| 术语 | 一句话解释 |
|---|---|
| 闭包 | 匿名函数，可存变量、可捕获环境 |
| 捕获 | 闭包把周围数据装进背包 |
| 迭代器 | 逐元素传送数据的装置 |
| 迭代 | 把集合上传送带（iter） |
| 过滤 | 留下满足条件的元素（filter） |
| 映射 | 逐个变换元素（map） |
| 收集 | 把传送带收成容器（collect） |
| 求和 | 终点站快捷方法（sum） |
| 惰性求值 | 不到终点不开工 |

## 22.13 常见问题（FAQ）

**问：闭包和普通函数有啥实质区别？**

答：闭包能**捕获环境**，函数不能；闭包不用起名、随写随用；闭包的类型是编译器生成的独一份，写不出来也读不出来（所以第二十章用 `移动 ||` 直接传给线程，而不是先存变量传来传去）。

**问：迭代器链比 `对于` 循环快吗？**

答：通常不慢，常常更快。编译器能把链子优化成紧凑的循环，还省了中间容器。可读性上，链式写法把"做什么"一行说清。

**问：`过滤` 里为什么是借用？**

答：因为 `迭代()` 借出元素（不搬走）。想搬走元素用 `消费迭代`（= into_iter）——之后原集合就空了，慎用。

**问：链子能写多长？**

答：随便长，每站只是"加一道工序"，不多占内存。实战中三四站最常见；太长就拆开起名，保持可读。

**问：`映射` 和第十章结构体的方法重名吗？**

答：不冲突。方法按类型归属找——`数列.迭代()` 后的对象才认 `映射`；你在结构体上定义叫 `映射` 的方法也互不干扰。

**问：闭包能当函数参数传来传去吗？**

答：能，这正是它的大用途（`线程::生成`、`过滤`、`映射` 都在收闭包）。签名里接收闭包要用特征约束（`实现 Fn(整数) -> 整数`），等你需要时再学不迟。
