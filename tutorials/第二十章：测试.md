# 第二十章：测试

代码写完了，怎么知道它是对的？你可以运行看看——但如果代码有一万行呢？你不可能每次都手动检查。

**测试**就是让程序自己检查自己——你写好"正确答案"，每次修改代码后，程序自动对比"实际结果"和"正确答案"。

---

## 20.1 为什么要测试

> **生活类比**：测试就像**考试后的对答案**。你做完题后，拿出标准答案一道道对——发现错了就改。测试就是给代码"对答案"。

```
不测试：
  写代码 → 运行 → "看起来对" → 上线 → 💥 出错了！

测试：
  写代码 → 对答案（自动） → 全对 ✅ → 上线
```

**为什么要自动化测试？** 因为手动测试太慢太容易漏。自动化测试一秒钟能检查几百个情况。

---

## 20.2 写第一个测试

```rust
函数 加(甲: 整数, 乙: 整数) -> 整数 {
    甲 + 乙
}

#[测试]
函数 测试加法() {
    断言相等!(加(2, 3), 5);
    断言相等!(加(0, 0), 0);
    断言相等!(加(-1, 1), 0);
}
```

逐行解释：

- 第 1-3 行：定义一个普通的加法函数
- 第 5 行：**`#[测试]`** 标记这是一个测试函数——告诉编译器"这不是普通函数，是考试题目"
- 第 6 行：**`断言相等!(加(2, 3), 5)`** 意思是"2+3 应该等于 5，如果不等就报错"
- 第 7-8 行：更多测试——检查各种情况

```
测试的执行过程：

运行测试
    │
    ├── 加(2, 3) = 5？   → 5 == 5 ✅ 通过
    ├── 加(0, 0) = 0？   → 0 == 0 ✅ 通过
    └── 加(-1, 1) = 0？  → 0 == 0 ✅ 通过

    全部通过！✅
```

### 运行测试

在终端输入：

```bash
cargo test
```

它会找到所有标记了 `#[测试]` 的函数，逐个运行。

## 20.3 断言——检查答案

> **生活类比**：断言就是"对答案"——"我认为答案是 X，如果不是就告诉我错了"。

### 断言相等

```rust
#[测试]
函数 测试相等() {
    断言相等!(2 + 2, 4);  // 2+2 应该等于 4
}
```

### 断言不等

```rust
#[测试]
函数 测试不等() {
    断言不等!("你好", "世界");  // "你好" 不等于 "世界"
}
```

### 断言条件为真

```rust
#[测试]
函数 测试条件() {
    断言!(5 > 3);      // 5 大于 3 应该是真的
    断言!("abc".包含("b"));  // "abc" 包含 "b" 应该是真的
}
```

## 20.4 测试应该失败的情况

有时候你想测试"这个函数应该报错"——比如传入非法参数时：

```rust
函数 安全除法(甲: 整数, 乙: 整数) -> 结果<整数, 字符串> {
    如果 乙 == 0 {
        结果::错误("除数不能为零".转字符串())
    } 否则 {
        结果::成功(甲 / 乙)
    }
}

#[测试]
函数 测试除以零() {
    让 除法结果 = 安全除法(10, 0);
    断言!(除法结果.是错误());  // 除以零应该返回错误
}

#[测试]
函数 测试正常除法() {
    让 除法结果 = 安全除法(10, 2);
    断言相等!(除法结果.解包(), 5);  // 10 ÷ 2 = 5
}
```

逐行解释：

- 第 12 行：测试除以零的情况——应该返回错误
- 第 13 行：调用函数
- 第 14 行：检查结果是不是"错误"类型
- 第 18 行：测试正常情况——10 ÷ 2 应该等于 5

## 20.5 测试组织

> **生活类比**：测试代码和正式代码应该分开——就像"考试卷"和"课本"分开。测试代码只在"考试"（运行测试）时才用，不会出现在最终发布的程序里。

### 内联测试

在同一个文件里，用 `模块 测试` 把测试代码放在一起：

```rust
函数 加(甲: 整数, 乙: 整数) -> 整数 {
    甲 + 乙
}

函数 减(甲: 整数, 乙: 整数) -> 整数 {
    甲 - 乙
}

// 测试模块——只在运行测试时编译
#[cfg(测试)]
模块 测试 {
    使用 超级::*;  // 引入上面所有函数

    #[测试]
    fn 测试加() {
        断言相等!(加(1, 2), 3);
    }

    #[测试]
    fn 测试减() {
        断言相等!(减(5, 3), 2);
    }
}
```

逐行解释：

- 第 9 行：**`#[cfg(测试)]`** 意思是"只在运行测试时才编译这个模块"
- 第 10 行：`模块 测试` 把所有测试放在一起
- 第 11 行：**`使用 超级::*;`** 引入上面定义的所有函数
- 第 14、20 行：每个测试函数用 `#[测试]` 标记

```
代码结构：

src/lib.rs
├── 正式代码
│   ├── 加()
│   └── 减()
│
└── 测试模块（只在测试时编译）
    ├── 测试加()
    └── 测试减()
```

### 集成测试

如果你想测试整个项目（不只是单个函数），在 `tests/` 目录下创建文件：

```
项目/
├── src/
│   └── lib.rs
└── tests/
    └── 集成测试.rs
```

## 常见错误

### 测试函数忘记标记

```rust
// ❌ 忘记加 #[测试]
fn 测试加法() {
    断言相等!(2 + 2, 4);
}
// 修复：加上 #[测试]
```

### 断言写反了

```rust
#[测试]
函数 测试() {
    // ❌ 断言不相等的东西相等
    // 断言相等!(2 + 2, 5);  // 测试失败！

    // ✅ 正确断言
    断言相等!(2 + 2, 4);
}
```

## 本章小结

| 概念 | 一句话 |
|------|--------|
| 测试 | 对答案——让程序自己检查自己 |
| `#[测试]` | 标记测试函数——"这是考试题目" |
| `断言相等!` | 检查两个值是否相等 |
| `断言!` | 检查条件是否为真 |
| `cargo test` | 运行所有测试 |
| `#[cfg(测试)]` | 只在测试时编译的模块 |
