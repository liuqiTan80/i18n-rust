# 第十七章：包管理与构建

前面的代码都是一个个小程序。但真正的项目需要用到别人写好的工具库，也需要把自己的代码组织好。

这一章学习如何**管理项目**和**使用第三方库**。

---

## 17.1 什么是包管理器

> **生活类比**：包管理器就像一个**购物平台**。你想做蛋糕，但家里没有烤箱——你不用自己造一个，直接"下单买"就行。包管理器帮你"下载"别人写好的工具库，安装到你的项目里。

```
做蛋糕需要烤箱 ──→ 不用自己造 ──→ 在购物平台下单 ──→ 快递送到家
写程序需要随机数 ──→ 不用自己写 ──→ 在包管理器添加 ──→ 自动下载到项目
```

Rust 的包管理器叫 **Cargo**。它同时负责：
- 下载第三方库（购物）
- 编译你的代码（组装）
- 运行你的程序（启动）

---

## 17.2 项目配置文件

> **生活类比**：`Cargo.toml` 就像一份**快递单**——告诉快递公司（编译器）你是谁、你要寄什么、需要哪些配件。

每个 Rust 项目都有一个 `Cargo.toml` 文件：

```toml
[项目信息]
名字 = "我的项目"
版本 = "0.1.0"
版本集 = "2021"

[依赖]
```

逐行解释：

- 第 1 行：**`[项目信息]`** 是"项目的基本信息"部分
- 第 2 行：项目的名字
- 第 3 行：版本号——`0.1.0` 表示"还在早期开发"
- 第 4 行：用哪套语法规则
- 第 6 行：**`[依赖]`** 是"我需要哪些第三方库"部分

```
Cargo.toml 就像快递单：

┌── Cargo.toml ──────────────────────┐
│  [项目信息]                         │
│  名字 = "我的项目"     ← 你是谁     │
│  版本 = "0.1.0"        ← 版本号     │
│                                     │
│  [依赖]                             │
│  随机数 = "0.8"        ← 需要哪些库 │
└─────────────────────────────────────┘
```

## 17.3 添加第三方库

> **生活类比**：添加第三方库就像在购物平台**下单**——告诉包管理器"我要这个东西"，它就会自动下载并安装。

### 方法一：直接编辑配置文件

打开 `Cargo.toml`，在 `[依赖]` 下面添加：

```toml
[依赖]
随机数 = "0.8"
```

### 方法二：用命令添加

在终端输入：

```bash
cargo add 随机数
```

两种方法效果一样。

### 使用第三方库

添加好依赖后，就可以在代码中使用了：

```rust
使用 随机数::随机特征;

函数 主函数() {
    让 随机数: 整数 = 随机数::线程随机数();
    打印行!("随机数：{}", 随机数);
}
```

逐行解释：

- 第 1 行：引入"随机数"库中的"随机特征"——告诉编译器"我要用随机数功能"
- 第 4 行：生成一个随机整数
- 第 5 行：打印出来

## 17.4 常用命令

| 命令 | 作用 | 生活类比 |
|------|------|---------|
| `cargo build` | 编译项目 | 把材料组装好 |
| `cargo run` | 编译并运行 | 组装好并启动 |
| `cargo check` | 只检查不编译 | 检查图纸有没有错 |
| `cargo test` | 运行测试 | 质量检验 |
| `cargo clean` | 清除编译产物 | 清空工作台 |
| `cargo update` | 更新依赖 | 更换新配件 |

```
cargo check  vs  cargo build
┌──────────────┐    ┌──────────────┐
│ check        │    │ build        │
│ 检查语法     │    │ 检查语法     │
│ 检查类型     │    │ 检查类型     │
│ ✅ 到此为止  │    │ 生成程序     │
│              │    │ ✅ 可以运行  │
└──────────────┘    └──────────────┘
  更快（不生成）       较慢（生成文件）
```

**为什么要区分 `check` 和 `build`？** 因为 `check` 只检查代码有没有错，不生成最终程序。它比 `build` 快很多。写代码时经常用 `check` 来快速检查，确认没问题了再用 `build`。

## 17.5 中文 Rust 的构建流程

中文 Rust 在 Cargo 的基础上增加了一个**翻译步骤**：

```
你写的中文代码 (.zh 文件)
    ↓
翻译器把中文关键字翻译成英文
    ↓
标准 Rust 代码 (.rs 文件)
    ↓
编译器编译成程序
    ↓
可以运行的程序
```

```
┌── 构建流程 ──────────────────────────┐
│                                      │
│  中文源码 (.zh)                       │
│      ↓                               │
│  ┌─────────────┐                     │
│  │ 翻译器       │  中文关键字 → 英文  │
│  └─────────────┘                     │
│      ↓                               │
│  标准代码 (.rs)                       │
│      ↓                               │
│  ┌─────────────┐                     │
│  │ 编译器       │  编译为程序         │
│  └─────────────┘                     │
│      ↓                               │
│  可执行文件                           │
│                                      │
└──────────────────────────────────────┘
```

### 中文 Rust 命令

| 命令 | 作用 |
|------|------|
| `rzc init 项目名` | 创建新项目 |
| `rzc run 文件.zh` | 翻译并运行 |
| `rzc check 文件.zh` | 翻译并检查错误 |
| `rzc eject 文件.zh` | 导出为标准 Rust |

## 17.6 项目结构

一个典型的中文 Rust 项目长这样：

```
我的项目/
├── Cargo.toml          ← 项目配置（快递单）
├── rust-toolchain.toml ← 编译器版本
├── 语言包/              ← 中文翻译规则
│   └── 中文/
│       ├── 关键字.toml
│       ├── 标准库.toml
│       └── 错误消息.toml
└── src/
    ├── main.zh         ← 你的中文代码（主文件）
    └── lib.zh（可选）   ← 库代码
```

**为什么有这么多文件？** 因为中文 Rust 需要知道"怎么把中文翻译成英文"。语言包文件夹里装的就是翻译规则——哪个中文关键字对应哪个英文关键字。

## 常见错误

### 忘记初始化项目

```bash
cargo build
# ❌ 找不到 Cargo.toml
# 修复：先用 rzc init 或 cargo init 初始化项目
```

### 依赖版本冲突

```toml
# 两个库依赖同一个库的不同版本
# 修复：用 cargo tree 查看冲突，或用 cargo update 解决
```
