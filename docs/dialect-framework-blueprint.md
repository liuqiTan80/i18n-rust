## 1. 范式选择

### 1.1 核心决策：源码到源码转译（Transpile-and-Delegate）

方言框架有两条路线：

| 路线 | 做法 | 代价 |
|---|---|---|
| ❌ 重写编译器 | 为方言实现完整的解析/类型检查/代码生成 | 工作量巨大、与官方语义漂移、生态全部丢失 |
| ✅ 转译代理 | 方言源码 → 官方源码 → 官方工具链编译 → 诊断反向翻译 | 仅需维护映射数据与薄转译层 |

**本项目选择转译代理，且被验证成立**。三条支撑理由：

1. **生态零成本继承**：编译、优化、依赖管理、测试全部由官方工具链（cargo/rustc）完成，
   方言代码与标准生态完全互通。
2. **语义永远正确**：方言不引入新语义——母语代码与标准代码是同构的，
   差别只在标识符文本，因此不存在"方言编译器自己的 bug"。
3. **渐进过渡**：`eject` 命令一键导出标准源码，学习者随时可以"毕业"，
   这消除了方言工具最大的顾虑（被锁死）。

### 1.2 成立的前提条件（移植到其他语言前先核对）

宿主语言必须满足：

1. **标识符允许非 ASCII 字符**（Unicode XID）——Rust/Python 3/Go/JS/Swift/Kotlin 均满足；
   C/C++/Java（16 前）不满足，需改用拼音/转写方案或放弃词内映射。
2. **官方工具链可被脚本驱动**：能用命令行编译单文件/项目并拿到退出码与诊断输出
   （最好是结构化 JSON，见 §6）。
3. **词法边界可靠可得**：有官方/权威词法器（本项目用 `rustc_lexer`），
   否则需自实现保守词法器（字符串/注释不可误改是底线）。

### 1.3 教学三支柱

- **母语可执行**：`函数 主函数() { 打印行("你好") }` 直接编译运行。
- **母语诊断**：错误码、消息、类型名、help 短语、cargo 进度行全部翻译，并附教学提示。
- **母语生态**：标准库与第三方库 API 也有母语别名（`向量::新建()` → `Vec::new()`）。

## 2. 总体架构四层模型

```text
┌────────────────────────────────────────────────────────────┐
│  ④ IDE 层        编辑器扩展：语法高亮 / 全角转换 / 右键运行     │
│                  LSP 代理：方言 ↔ 官方 LSP 双向翻译            │
├────────────────────────────────────────────────────────────┤
│  ③ 工具链层      CLI：init / run / check / eject / add /      │
│                  lang / mapping —— 驱动官方构建工具            │
├────────────────────────────────────────────────────────────┤
│  ② 引擎层（语言无关）                                          │
│     词法转译 → 模块路径替换 → 别名替换 → 增量缓存               │
│     诊断翻译（错误码表 + 消息表 + 类型本地化 + 教学提示）        │
│     源映射（双向位置还原）/ Unicode 安全检查 / 自身界面国际化     │
├────────────────────────────────────────────────────────────┤
│  ① 数据层        语言包（每自然语言一个目录）：                 │
│                  关键字 / 模块路径 / 标准库别名 / 第三方库别名   │
│                  / 错误翻译 / 界面文案 / 元信息                 │
└────────────────────────────────────────────────────────────┘
```

**关键不变式**：引擎层不硬编码任何具体自然语言与宿主语言知识；
一切语言相关内容都在数据层（语言包）与宿主适配层（词法器、构建工具驱动）。

**模块依赖方向**（严格单向）：

```text
语言包(数据) → 引擎 → CLI / LSP → IDE 扩展
```

## 3. 核心执行管线

### 3.1 正向：方言 → 可执行程序

```text
main.zh 源码
   │  ① Unicode 混淆检查（零宽/双向控制符/同形字符，仅告警不阻断）
   │  ② 词法转译：token 级关键字替换（注释与字符串内容绝不误改）
   │     └─ 宏感叹号自动补充（宿主特有阶段，见 §5.1）
   │  ③ 模块路径替换：仅 use/import 语句内的路径段
   │  ④ 别名替换：标准库/第三方标识符（声明位保护 + 用户声明名全文件豁免）
   ▼
标准宿主语言源码（写入项目源文件原位或临时目录）
   │  ⑤ 调用官方工具链（cargo build/run --message-format=json）
   ▼
编译产物运行 / JSON 诊断行
```

**管线顺序不可调换**：先关键字（`使用`→`use` 让模块路径阶段能识别语句起点），
再模块路径（限定在 use 内），最后别名（兜底处理 use 内未命中的末段与表达式中的限定调用）。

### 3.2 反向：诊断 → 母语教学信息

```text
官方工具链 --message-format=json 诊断行
   │  ① 解析（兼容两种格式：编译器直出 / 构建工具包装行）
   │  ② 查翻译表：错误码表优先 → 消息表兜底（精确 → 最长前缀 → ~后缀键）
   │  ③ 提取期望/实际类型（label 优先，消息内反引号兜底）
   │  ④ 类型名本地化（三段式：路径前缀 + 中间段 + 类型后缀）
   │  ⑤ help 子消息翻译 + 教学提示拼接
   ▼
母语教学诊断（级别/错误码/消息/位置/📌叙事/💡提示）
```

### 3.3 增量缓存

缓存键 = **内容哈希 + 语境指纹**（全部映射表的哈希）。
源码不变但语言包更新时语境指纹变化 → 自动失效重译。
缓存同时保存**源映射**（被替换标识符的源偏移与前后文本），供 LSP 位置还原复用。

## 4. 语言包数据规范

一个语言包 = 一个目录（目录名即语言代码，如 `zh`、`vi`）。
全部使用 TOML；**非 ASCII 键必须双引号包裹**（TOML 裸键仅允许 ASCII）。

```text
lang-packs/<语言代码>/
├── lang_info.toml      # 必需：元信息
├── keywords.toml       # 必需：关键字映射
├── module_paths.toml   # 可选：use/import 路径段映射
├── stdlib.toml         # 可选：标准库模块路径 + 标识符别名
├── errors.toml         # 可选（强烈建议）：诊断翻译
├── ui.toml             # 必需：工具自身界面文案
└── crates/             # 可选：第三方库映射（每库一文件）
    └── <库名>.toml
```

### 4.1 lang_info.toml —— 元信息

```toml
["语言包"]
"名称" = "中文"
"扩展名" = "zh"     # 方言源码文件扩展名（不含点），决定 rzc run 的文件识别
"版本" = "1.0"
```

### 4.2 keywords.toml —— 关键字映射

按语义分节组织；**键 = 母语词，值 = 官方原词（不可改）**。
节名可自定义，但 `宏` 节有特殊语义（若宿主语言有宏系统，见 §5.1）：

```toml
["声明"]
"函数" = "fn"
"让" = "let"
"可变" = "mut"
"主函数" = "main"

["控制流"]
"如果" = "if"
"如果让" = "if let"      # 多词关键字合法，词法器需支持连续 token 合并
"对于" = "for"
"在" = "in"

["类型"]
"整数" = "i32"
"字符串" = "String"
"选项" = "Option"
"有些" = "Some"

["逻辑值"]
"真" = "true"

["宏"]
"打印行" = "println"     # 宏名后跟括号时自动补感叹号
```

设计要点：

- 枚举变体/构造器（`有些`/`无`/`成功`/`错误`）也进关键字表——
  它们出现频率极高且语义稳定，是教学体验的关键。
- 同一词允许映射多词短语（`如果让` → `if let`），词法器按最长匹配处理。
- 常用类型（`字符串`/`向量`/`哈希映射`）放关键字表保证处处可写；
  更细的标准库 API 放 stdlib.toml（见下）。

### 4.3 module_paths.toml —— 导入路径映射

```toml
["模块路径"]
"标准库" = "std"
"标准集合" = "std::collections"
"格式化" = "fmt"
```

仅在 `use`/`import` 语句内生效（`使用 标准集合::哈希映射;` → `use std::collections::HashMap;`）。
表达式中的 `类型::关联函数` 不走此表，交给别名表。

### 4.4 stdlib.toml —— 标准库别名

与第三方库映射同格式，两节：

```toml
["模块路径"]
"线程" = "std::thread"
"文件系统" = "std::fs"

["标识符"]
"字符串" = "String"
"新建" = "new"
"长度" = "len"
```

**加载顺序即优先级**：`crates/*.toml` 先按文件名排序合并，`stdlib.toml` 最后加载并覆盖同名键
——标准库通用词（如 `发送`）不应被某个第三方库的撞名词条污染。

### 4.5 crates/<库名>.toml —— 第三方库映射

格式与 stdlib.toml 完全相同；文件名即库的展示名。
由 `mapping auto`（提取公开 API + AI 命名）或 `mapping scaffold`（骨架 + 人工）生成，
质量由 `mapping check` 把关（重复键/关键字碰撞/跨文件冲突）。

### 4.6 errors.toml —— 诊断翻译（教学价值核心）

两类条目共存于同一文件：

```toml
# ① 错误码表：顶层节名为官方错误码
[E0308]
"消息模板" = "类型不匹配：期望 `{期望}`，实际得到 `{实际}`"
"教学提示" = "请检查变量类型是否与上下文要求一致。尝试使用 `作为` 进行类型转换。"

[E0382]
"消息模板" = "值在移动后被使用：`{变量名}`"
"教学提示" = "值被移动后不能再使用。考虑使用引用（&）或克隆()来避免移动。"

# ② 消息表：节名固定 ["消息翻译"]，键为官方英文消息原文
["消息翻译"]
# 最长前缀匹配：动态后缀自动拼回
["消息翻译"."did you mean "]
"消息模板" = "你是否想用 {q0}？"

# ~ 后缀键：动态名在消息中间时用后缀锚定（~ 为机制标记，非消息内容）
["消息翻译"."function `"]
"消息模板" = "函数 `{q0}` 从未被使用"
"教学提示" = "删除未使用的函数，或添加 #[allow(dead_code)] 临时抑制。"

["消息翻译"."~ is never used"]
"消息模板" = "`{q0}` 从未被使用"
```

**匹配顺序**：错误码表 → 消息表精确 → 消息表最长前缀 → 消息表最长后缀（`~` 键）。

**占位符体系**：

| 占位符 | 来源 |
|---|---|
| `{期望}` / `{实际}` | 从 `expected X, found Y` label（或消息反引号对）提取 |
| `{变量名}` / `{名称}` 等 | 专用解析逻辑（如所有权错误从 span label 提取） |
| `{q0}` / `{q1}` | 从动态残段的引号内容自动填充：反引号取最后一对（`rsplit`），单引号按序取 |

**关键约束**：消息表里不得出现**英文键反向修正条目**（如 `"format" = "fmt"`，
那是转译管线内部用途）；构建反向映射（英文→母语）时必须过滤纯 ASCII 键，
否则会污染诊断翻译（详见坑 ②，§13）。

### 4.7 ui.toml —— 工具界面文案

```toml
["界面消息"]
"success_compile" = "✅ 编译成功，没有错误。"
"cargo_progress_compiling" = "正在编译 {}"
```

键为稳定英文标识（或语义键），`{}` 为顺序占位符。
**构建时嵌入二进制**（build.rs 扫描语言包目录生成 `include_str!` 清单），
运行时按界面语言路由，未知语言回退 `zh`。CLI 帮助文本（clap）同样经此表本地化。

## 5. 引擎模块详细设计

### 5.1 词法转译（lexer）

**输入**：方言源码 + 关键字映射 + 宏映射。**输出**：官方源码 + 源映射。

实现要求（按重要性排序）：

1. **token 级替换**：使用权威词法器（本项目：`rustc_lexer`）。
   注释、字符串字面量、原始字符串中的同形文本绝不允许被替换。
2. **整词匹配**：仅替换完整标识符 token，`读取全部字符串` 中的 `字符串` 不得被误替换。
3. **原始标识符透传**：`r#让` 形式需剥离前缀查表后复原（`r#let`）。
4. **宏感叹号自动补充**（宿主特有）：宏名后跟 `(`/`[`/`{` 且前无 `::` 时自动补 `!`；
   宏名的英文替换必须用**独立的宏映射表**，不能用全局关键字表
   （`向量` 在类型节映射为 `Vec`、在宏节映射为 `vec`，全局表会被类型节覆盖）。
5. **多词关键字**：`如果让` → `if let` 需要连续 token 前瞻合并。
6. **源映射记录**：每次实际替换记录 `(源偏移, 长度, 原文, 替换文)`，
   是 LSP 双向位置还原的唯一依据；自动补 `!` 不产生映射条目。
7. **反向转译**：同一机制反转映射表即得 官方源码 → 母语源码（供 `eject` 反向展示与文档生成）。

### 5.2 模块路径替换

状态机极简：遇 `use`（或母语关键字转译结果）进入语句态，遇 `;` 退出；
语句态内每个标识符 token 查路径表，命中即替换。
**语句外的 `类型::段` 一律不碰**——那是别名表的职责（`引用计数::新建` → `Rc::new`），
越界替换会把 `Rc` 误还原成 `rc`。

### 5.3 别名替换（最易出错的模块）

**声明位保护**：紧跟声明关键字（`fn/struct/enum/trait/type/mod/let/const/static`）
的标识符是用户自己的定义，不替换。两遍扫描：

1. 第一遍收集全部用户声明名（`mut` 在声明态内透明传递；空白/注释不打断声明态）；
2. 第二遍逐 token 替换：**用户声明名在整个文件的所有裸使用处全部豁免**
   （保守近似，不做作用域分析），但 `::` 限定后的路径段（`字符串::新建`）照常替换——
   用户变量不可能经 `::` 访问。

移植到其他语言时，需替换的只是 `DECL_KEYWORDS` 常量（该语言的声明关键字集合）。

### 5.4 Unicode 混淆安全检查

转译前扫描：零宽字符（U+200B 等）、双向控制符（RLO 等）、高置信同形字符。
**仅告警不阻断**（教学场景宽容），但必须报告位置。这是母语编程框架的安全底线——
防止"看起来一样、实际不同"的恶意标识符。

### 5.5 工具自身国际化（自举）

引擎/CLI 的所有用户可见文案同样走语言包（`语言::f(键, 参数)`），
界面语言由系统区域检测 + 环境变量覆盖。框架"自己说的每一句话"都是母语，
这是与一般翻译工具的本质区别。

## 6. 诊断翻译系统

### 6.1 前提：结构化诊断输出

最优路径是官方工具链的 JSON 诊断（`cargo --message-format=json` / `rustc --error-format=json`）。
解析器需兼容两种行格式：编译器直出行、构建工具包装行（诊断嵌在 `message` 字段）。
若宿主工具链无 JSON（见 §11），退而求其次解析文本输出，但会损失 span/children/help 信息。

### 6.2 翻译决策链

```text
诊断(code, message, spans, children)
 ├─ code 命中错误码表 ──────────────→ 模板 + 教学提示
 ├─ message 命中消息表(精确/前缀/后缀) → 模板（含 {q0} 捕获填充）+ 动态残段拼接
 └─ 均未命中 ──────────────────────→ 回退原文（仅做类型名本地化）
```

### 6.3 类型名本地化（三段式）

诊断中出现的类型路径 `std::fmt::Display` 按 `::` 分段本地化为 `标准库::格式化::可显示`：

1. **类型后缀段**：末段查类型词表（`Display` → `可显示`）；
2. **路径前缀完整匹配**：从长到短尝试多段前缀（`std` → `标准库`）；
3. **中间段单段映射**：首尾之外的段逐段查表（`fmt` → `格式化`）。

反向映射表由引擎从语言包自动构建，合并源 = 类型节反转 + 别名表反转 + 模块路径表反转，
**全程过滤纯 ASCII 键**，模块路径源用覆盖式合并（消除第三方库撞名的不确定性）。

### 6.4 教学增强

- **教学提示**（💡）：每个错误条目可附一条面向初学者的下一步建议，用母语关键字书写示例。
- **所有权叙事**（📌）：针对移动/借用类错误，从 span label 定位
  "移动点/借用点/再次使用点"，生成一句话故事线（宿主特有，可选）。
- **依赖提示**：未解析导入错误自动提取候选库名，提示 `rzc add <crate>`
  （LSP 侧同时注入快捷修复代码动作）。
- **构建进度行翻译**：`Compiling/Checking/Finished/Running` 等前缀行进消息表
  （注意行首可能有缩进，匹配前先 `trim_start`）。

### 6.5 run/check 的 JSON 模式集成

`run` 命令用 `官方构建工具 --message-format=json` + 管道：
stdout 中含 `reason` 字段的行是诊断（收集后批量翻译），其余行是程序输出（透传）；
stderr 逐行做进度翻译。编译成功时静默（不重复打印成功消息）。
这保证警告/错误**实时、全量、母语化**，且不引入二次编译。

## 7. CLI 设计

命令树（宿主无关部分照抄，构建命令替换为宿主工具链）：

| 命令 | 职责 |
|---|---|
| `init <项目> --lang <代码>` | 生成项目骨架（构建清单 + 主源文件模板） |
| `run <文件>` | 转译 → 官方构建工具 run（JSON 模式，诊断母语化） |
| `check <文件>` | 转译 → 官方构建工具 check（诊断母语化） |
| `eject <文件>` | 导出标准宿主语言源码（渐进过渡出口） |
| `add <库>[@版本]` | 封装官方包管理器（`cargo add`），附母语映射提示 |
| `lang list / install / remove` | 语言包管理：内置 + 用户目录（`~/.rz/lang-packs`） |
| `mapping auto / check / scaffold` | 第三方映射生成 / 质量校验 / 跨语言翻译骨架 |
| `install lsp` | 安装配套语言服务器 |

实现要点：

- **文件扩展名 → 语言包**路由：扫描所有已安装语言包的 `lang_info.toml` 扩展名；
  未知扩展名报错并列出可用扩展名；`--lang-pack` 可显式指定目录。
- **项目根定位**：从源文件向上查找构建清单（`Cargo.toml`）；找不到给出 `init` 引导。
- **语言包加载优先级**：用户安装目录覆盖内置（内置经 `include_str!` 编译期嵌入，
  由 build.rs 自动扫描生成清单，新增语言包零代码改动）。
- **界面语言**：系统区域检测 → 环境变量覆盖 → 回退默认语言。
- **工具链版本锁定**：`init` 生成的 `rust-toolchain.toml` 应**动态探测本机工具链版本**
  （解析 `rustc --version`），不可硬编码——硬编码版本会随时间过时，
  导致 IDE 报"工具链过于陈旧"；components 需含 `rust-analyzer`、`rust-src` 供 IDE 使用。

## 8. LSP 代理设计

不自研语言服务器，**代理官方 LSP**（本项目：rust-analyzer；
其他宿主对应 pyright/gopls/tsserver 等）：

```text
编辑器 ──方言文件──▶ 方言 LSP 代理 ──翻译后 .rs──▶ 官方 LSP（子进程）
编辑器 ◀──母语诊断── 方言 LSP 代理 ◀──位置/文本还原── 官方 LSP
```

核心机制：

1. **正向**：`didOpen/didChange` 收到方言文本 → 转译 → 以虚拟官方文件喂给子进程。
2. **反向位置还原**：官方响应的行列位置经源映射逆向折算回方言坐标
   （替换前后等宽则零成本；不等宽需按映射条目做列偏移模拟）。
3. **响应映射器**：转发请求使用自增 ID，维护 `代理ID → 原始请求` 映射，
   响应到达时还原 ID 并翻译内容；**设超时清理**（如 60s），防止条目无限累积。
4. **诊断翻译**：复用引擎诊断翻译系统（与 CLI 同一套）。
5. **代码动作增强**：`codeAction` 请求上下文中提取未声明库名，
   响应时注入"添加依赖"快捷修复。
6. **扩展名可配置**：默认清单与内置语言包一致，`--extensions` 参数覆盖。

**注意**：语义着色（变量/参数颜色）完全依赖本链路——官方 LSP 启动失败
（如工具链版本被项目锁定文件钉到过时版本）时，方言文件只剩 TextMate 关键字着色。

## 9. IDE 扩展设计

以 VS Code 扩展为例，职责清单：

1. **语言注册**：每语言包一个 language id + 文件扩展名关联；
   tmLanguage 语法高亮由**脚本从语言包自动生成**（关键字/类型/宏分节注入正则），
   保证映射表与高亮永不漂移。
2. **全角符号自动转换**：中文输入法的全角标点（`（），；：`）在代码上下文自动转半角，
   词法状态机区分字符串内外（字符串内保留原文，但配对引号场景需特判）。
3. **右键运行/检查**：终端发送 `rzc run <文件>`；
   **Windows 必须处理 PowerShell 语法**：带引号的可执行路径需 `& ` 调用操作符前缀
   （`& "C:\...\rzc.exe" run "文件"`），否则报"意外的标记"语法错误；
   参数按平台做引用转义（双引号加倍/反引号加倍/% 转义），防命令注入。
4. **依赖添加命令**：封装 `rzc add`。
5. **LSP 客户端**：启动方言 LSP 代理（可执行文件解析需跨平台：
   PATH 扫描 + PATHEXT 后缀探测 + 用户主目录回退）。
6. **AI 辅助翻译**（可选增值）：选中文本调用 LLM 提供方把标准代码译为方言。

## 10. 映射质量工具链

母语映射是社区共建的，质量门禁必须自动化：

| 工具 | 检查项 |
|---|---|
| `mapping check` | ① 同文件重复键 ② 母语词与关键字碰撞（`让` 不能再当库别名）③ 跨文件同键不同值 ④ 跨语言条目数一致性 |
| `mapping auto <库>` | 提取已安装库的公开 API → 规则/LLM 生成母语名与解释 → 写 `crates/<库>.toml`，可 `--install` 顺带加依赖 |
| `mapping scaffold <源语言> <目标语言>` | 以成熟语言包为源，生成目标语言翻译骨架（英文值不动，键待译）；支持 LLM 批量翻译 + 冲突改名重试，重跑自动补齐残留 |

**确定性要求**：多文件合并必须排序（文件名字典序），否则同键冲突时结果随
HashMap/目录迭代顺序漂移（真实事故，见坑 ①）。

## 11. 宿主语言移植清单

把本框架落到另一门宿主语言时，逐层核对：

### 11.1 逐模块适配点

| 模块 | Rust 实现 | 移植时需替换为 |
|---|---|---|
| 词法器 | `rustc_lexer` crate | 宿主官方词法器；无则自实现保守词法器（必须正确跳过字符串/注释/模板串） |
| 宏感叹号补充 | `打印行(...)` → `println!(...)` | 宿主无宏系统则整段删除；有类似机制（如 Lisp 系）则照模式适配 |
| 模块路径替换触发 | `use ... ;` 语句态 | 宿主 import 语法（Python `import x.y` / JS `import ... from` / Go import 块） |
| 声明关键字表 | `fn/struct/let/...` | 宿主声明关键字（Python `def/class` / Go `func/type/var` / JS `function/class/const/let`） |
| 构建工具驱动 | `cargo check/run --message-format=json` | 见 §11.2 诊断接口表 |
| 包管理器封装 | `cargo add` | `pip install` / `npm install` / `go get` |
| LSP 代理目标 | rust-analyzer | pyright / gopls / tsserver 等 |
| 项目骨架（init） | Cargo.toml + main.<ext> | 宿主项目清单 + 入口文件模板 |
| 所有权叙事 | 移动/借用三点定位 | 宿主无此概念则删除；GC 语言可换成空指针/越界类叙事 |

### 11.2 结构化诊断接口现状（决定诊断翻译上限）

| 宿主 | 结构化诊断 | 备注 |
|---|---|---|
| Rust | ✅ cargo/rustc JSON | 本项目基线，信息最全（spans/children/help） |
| Go | ✅ `go build -json`、`go vet -json` | 字段简单但够用 |
| TypeScript | ⚠️ `tsc --pretty false` 文本解析 | 格式稳定，正则可解析；错误码体系完善 |
| Python | ⚠️ 无官方结构化诊断 | 方案：`ast.parse` 捕获语法错误（有行列）；类型错误靠 pyright --outputjson |
| C/C++ | ✅ `clang -fdiagnostics-format=json` | clang 可用；gcc 较弱 |
| Java | ⚠️ javac 文本 + `-Xstdout` | 可借道 Eclipse JDT 批处理接口 |
| Swift/Kotlin | 部分 | 需实测 |

**没有 JSON 诊断的宿主**：诊断翻译降级为"文本模式"——按错误码正则锚定 +
消息表前缀/后缀匹配仍可覆盖大部分教学场景，但失去 span 级叙事增强。
建议优先选有结构化诊断的宿主，或为其接入第三方静态检查器（pyright/eslint）作为诊断源。

### 11.3 语言包迁移工作量估算（以中文 Python 为例）

| 文件 | 工作量 | 说明 |
|---|---|---|
| keywords.toml | 小 | Python 关键字约 35 个 + 内置常量（True/False/None） |
| module_paths.toml | 小 | `import os` → `导入 操作系统` 之类的段映射 |
| stdlib.toml | 中 | 内置函数（print/len/range）+ 常用类型方法 |
| errors.toml | 中 | Python 异常类名 + 常见 SyntaxError 消息；无错误码体系，主要靠消息表 |
| ui.toml | 可直接复用结构 | 键不变，仅译文案 |
| crates/（PyPI 库） | 按需 | `mapping auto` 需适配为解析 .pyi stub / `inspect` 提取 API |

## 12. 分阶段实现路线

按依赖顺序切分，每阶段独立可交付、可验证：

### 阶段 0：最小可运行（约 1 周）

- **验收**：`函数 主函数() { 打印行("你好") }` 运行成功；字符串内的母语关键字不被误改

### 阶段 1：项目模型与检查（约 1-2 周）
- `init` 骨架、项目根定位、`check` 命令接入官方工具链退出码与文本诊断
- `eject` 导出（反向映射表，注意单向多对一碰撞）
- **验收**：完整项目可 init → run → eject → 用官方工具直接编译 eject 产物

### 阶段 2：标准库母语化（约 2 周）
- module_paths.toml + stdlib.toml + 别名替换（声明位保护 + 用户声明名豁免）
- **验收**：`向量::新建()` / `使用 标准集合::哈希映射;` 编译通过；
  `让 新建 = 5` 不误替换且后续使用处豁免（回归用例必写）

### 阶段 3：教学诊断（核心价值，约 2-4 周）
- JSON 诊断解析、错误码表、消息表（精确/前缀/~后缀）、{q0} 捕获、

- **验收**：构造覆盖类型错误/未使用变量/命名规范/借用冲突的样例文件，全中文输出；
  未收录消息优雅回退原文不崩溃

### 阶段 4：IDE 集成（约 2-3 周）
- LSP 代理（双向位置还原 + 响应映射 + 诊断翻译）
- 扩展：语法高亮生成脚本、全角转换、右键运行、LSP 客户端、可执行文件跨平台解析
- **验收**：编辑器内补全/跳转/悬停/诊断全部可用；诊断位置与方言源码严格对齐

### 阶段 5：生态与规模化（持续）
- `mapping auto/check/scaffold` 工具链、第三方库映射积累
- 第二自然语言包（验证语言无关性）、语言包热安装（`lang install`）
- Unicode 安全检查、增量缓存、离线发布包、双平台 CI

## 13. 实战坑清单（本项目真实事故，逐条可复现）

| # | 坑 | 症状 | 规避 |
|---|---|---|---|
| ① | HashMap 迭代顺序不确定 | 同一英文词在不同运行映射到不同母语词 | 多源合并强制排序；撞名时按固定优先级覆盖（后载覆盖先载，并在文档声明） |
| ② | 英文键反向条目污染 | 转译修正用的 `"format" = "fmt"` 混入诊断反向映射，`fmt` 被译成 `format` | 构建反向映射时过滤纯 ASCII 键（`是中文键` 判别）；内部修正条目与教学条目物理分离 |
| ③ | 别名误伤用户标识符 | `让 新建 = 5` 之后 `新建` 被替换成 `new` | 两遍扫描：收集声明名 → 全文件裸使用处豁免；`::` 限定段除外 |
| ④ | PowerShell 带引号路径 | 右键运行报"意外的标记 run" | Windows 终端命令名统一加 `& ` 调用操作符前缀（cmd 亦兼容），并写单测 |
| ⑤ | 宏名与类型名碰撞 | `向量` 类型节 `Vec` 覆盖了宏节 `vec`，宏调用被译错 | 宏替换走独立宏映射表（宏节），不查全局关键字表 |
| ⑥ | 多词关键字 | `如果让` 被拆成 `如果` + `让` 各自替换 | 词法阶段支持最长匹配/连续 token 合并 |
| ⑦ | 编译器消息格式随版本漂移 | 新版 rustc 把算术错误的类型信息从 label 挪进 message，提取失败 | 提取逻辑双通道：label 优先、消息反引号兜底；每个编译器大版本跑回归 |
| ⑧ | 进度行翻译失效 | `strip_prefix("Compiling ")` 失败——行首有缩进 | 前缀匹配前先 `trim_start` |
| ⑨ | 缓存只按内容哈希 | 语言包更新后旧译文被复用 | 缓存键 = 内容哈希 + 映射表语境指纹 |
| ⑩ | 字符串/注释被误改 | 注释里的母语关键字被替换，破坏原文 | 词法器必须 token 级；上线前用"字符串内含全部关键字"的对抗样例测试 |
| ⑪ | 并行测试锁竞争 | 多个集成测试并发跑构建工具偶发失败；并发测试互相污染环境变量 | 构建类测试串行化或各用独立临时项目目录；环境变量测试共用进程级互斥锁 |
| ⑫ | 零宽字符注入 | 源码混入零宽空格导致隐晦编译错误 | 转译前扫描告警（不阻断），报告精确位置 |
| ⑬ | 硬编码工具链版本 | `rust-toolchain.toml` 钉死旧版本，IDE 报"工具链过于陈旧"、语义着色失效 | `init` 动态探测本机 `rustc --version`；components 含 rust-analyzer/rust-src |
