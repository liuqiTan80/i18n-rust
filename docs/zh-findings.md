# zh 分支摩擦台账（可行性验证与问题排查）

`zh` 分支不与 main 合并。它的产出不是"更好看的后端"，而是**用 ~55K 行真实 Rust 当语料，
把 rzc 方言管线在工程场景下的问题一个个撞出来**。本台账按发现顺序累加，每条都附
可复现证据（哪个文件、哪次转译、什么现象），供后续判断"是工具缺陷、词库缺口，还是用法错误"。

编码约定（同时由 `tools/check-zh-artifacts.py` 把守）：

- 真源是 `.zh`，同目录同名 `.rs` 是 `rzc transpile | rustfmt --edition 2024` 的提交产物；
- **排除一切一词多译**：中文词 → 多个英文值的歧义词不得进入代码区，
  仅 `tools/zh-ambiguity-exemptions.json` 登记的核心语法位（函数/字符串/向量/路径/格式化）
  豁免，且每条豁免必须附**实测取值证据**（见 F17）；
- **命名位不用关键字表词形**：`让` 的名字、参数名、字段名、闭包参数、`对于` 的循环变量、
  模式内变量，以及**函数名/常量名/结构体名/模块名等声明名**，撞上 `keywords.toml` 的词形
  都会被词条顶掉（见 F12；测试模块因此一律叫 `母语测试`，不叫 `测试`，已由门禁把守）；
- **重构而非对译**：逐句把英文代码换成中文词发现不了问题，只有重新设计数据结构与
  控制流，才会持续踩到缺词条、守卫失效、静默改名这类真实边界（F20 的随机序缺陷就是
  这样被撞出来的——只翻译会把它当"历史行为"原样搬过去）；
- **取证一律用 `target/debug/rzc`**：PATH 里装的是发布版，行为可能落后 HEAD 好几个
  版本，用它跑探针会把旧版缺陷记到主线账上（见 F18）。
- **if-let 必须写 `如果让`**：`如果 有值(x) = y` 会产出非法的 `if Some(x) = y`，
  transpile 与 lint **零提示**，只能靠 rustc 事后报错（见 F22）。
- **新方言文件的声明名要避开全部词表词形**：`rzc` 的项目声明豁免**按目录聚簇**，
  同目录任一 `.zh` 声明过的词形，会让同目录**所有** `.zh` 的方法位停止替换（见 F21）。
  因此每次新增/删除同目录方言文件后，必须重转该目录**全部** `.zh` 验漂移。
- **门禁脚本必须逐字照 Makefile/CI 的调用口径**：参数漏一项（如教程门禁漏 `--dir`）
  会造出整片假失败（见 F25）。
- **豁免不止声明名，`let` 绑定名也算**：同文件里一个 `让 调试 = 2` 能让另一处无关函数
  的 `T: 调试` 停止替换（见 F28）。所以命名位的禁令范围是「声明名 + 绑定名 × 全目录」，
  不是「只有声明名」；核查脚本 `decl_audit.py` 按这个范围分层判级。
- **`自身::X` 的 `X` 要走全表核查**：`Self::` 前缀后的变体名/关联函数名是 stdlib、
  `module_paths`、第三方三张表**唯一会命中的关联项位**（见 F27）；`类型名::X`、
  字段访问位、绑定位都不命中。用枚举变体做方言命名前必须过一遍这三张表。
- **依赖模块的英文声明要改**声明**侧，不是改引用**：`.zh` 里剩下的英文绝大多数不是"我没查表"，
  而是同仓某个英文模块把它的项目自己的项名（类型/字段/方法/模块名）泄漏进了方言消费侧。语言包
  救不了这类词（它们是本项目符号，不该进词条表）。口径见 F32；改名批之后必须回查字面量（F33）。
- **平台钉死的名字走「声明位有意替换」豁免表**：`impl Display` 的方法名必须是 `fmt`，方言侧
  只能用词形 `格式化方法` 换出；`tools/zh-decl-exemptions.json` 只对**声明名位**放行，同一词形
  用作绑定名/字段名仍判红（见 F36）。
- **产物格式不跟着源码改名**：磁盘缓存 JSON 的键是对外契约，字段名中文化时用 `#[serde(rename)]`
  定住旧键，省掉一次全量缓存失效（见 F37）。

- **注释区的英文同样判红**：`tools/check-zh-ascii.py` 对注释区**零容忍**——只有三条出口：
  按形状自动豁免（路径/文件名、连字符名、编号、`VS Code` 这类带空格专名、反引号里的**逐字**
  产物/命令引用）、`tools/zh-comment-allowlist.json` 逐条附理由的专名、以及改写为中文术语。
  「代码区 0、注释里全是英文」不叫达标（见 F34）。
- **`len<2` 豁免只适用于泛型与闭包参数**：声明名/导入名哪怕只有一个字母也是没中文化的英文
  （`t`/`f`/`K`）。外部模块的英文名走 `.zh` 侧导入别名，本模块的声明直接改名（见 F38）。

- **特征约束位与属性参数位只能照抄英文**：`T: 调试 + 克隆` → `T: debug + clone`（非法），
  `#[允许(死代码)]` → `#[allow(死代码)]`（原样落进产物）——只有 `#[派生(...)]` 的参数位
  吃 `派生特征` 表（见 F26）。

## 台账

### F1 中文模块名必须手写 `#[path]`（Rust 限制，非 rzc 缺陷）

`pub mod 反译重生;` 直接报 **E0754**：Rust 不为非 ASCII 模块名推断文件名。
每个中文模块的声明位都得配 `#[path = "反译重生.rs"]`。
**影响**：方言源转译出来的产物不能自带模块声明，接线这一步无法全自动，`rzc` 若要支持
整crate 重构，需在 `mod` 声明生成处补 `#[path]`。

### F2 产物口径必须是 `rustfmt ∘ transpile`

`rzc transpile` 的输出未经 rustfmt 规范化：直接提交则 `cargo fmt --check` 红，
跑了 `cargo fmt` 则与转译产物漂移。门禁最初按"裸转译字节比对"写，被这条打架打红。
**口径**：产物 = `rzc transpile x.zh | rustfmt --edition 2024`，两边同一口径才可复现。

### F3 教学 lint 对工程代码是噪音

`rzc transpile` 默认输出教学提示（嵌套过深、建议把 `sort` 写成 `排序` 等），
工程路径需 `--no-lint`。**缺口**：lint 目前没有"教学/工程"分档开关，只有全开/全关。

### F4 单词中文标识符会被**静默改名**（最值得修的一条）

实测两次：

- `让 字节 = 名字.转为字节()` → `let u8 = ...`（`字节` 是 `u8` 的词条，替换后左值名变成类型名）；
- `让 可变 游标: usize = 0` → 侥幸保留（`游标` 属派生特征表 `Cursor`，不进词法替换）——
  同一个"单词名"在不同表归属下行为不同，靠的是运气而非规则。

替换本身按 token 精确整词命中，**复合词安全**（`字节串`/`名字槽位`/`取或解析` 透传），
**单词名危险**（`字节`/`文本`/`游标`/`映射`/`排序`/`克隆`/`长度`/`位置`/`指针` 等会被换掉）。
**建议**：`rzc` 在 lint 层加"标识符命名撞词条"预警——这是纯改名事故，编译器只会
在少数场合（类型不符）报错，多数情况会静默产出错误代码。

### F5 一词多译只能靠**改写代码**绕开，位置守卫不足以支撑工程

语言包转译面共 31 个歧义词。本工程采用的替代：
`排序`（Ord/sort）→ 用 `有序映射` 的数据结构性质或方法位守卫；
`克隆`（Clone/clone）→ `克隆值`；`匹配`（match/matches）→ 改 `如果 让`；
`复制`（Copy/copied）→ `可复制`；`循环`（cycle/loop）→ `当`（while）；
`相等`（Eq/PartialEq）→ 不用；`切片`（slice/as_slice）→ 用 `..` 范围语法。
方法位让位守卫能救 `排序`（`.排序()`→`.sort()`），但同一词在**变量位/类型位**取值不同，
工程代码不能靠守卫赌一把，所以本分支一律改写。**豁免表只留三个核心语法位**。

### F6 语言包**方法位缺口**（实测无词条，只能留英文或改设计）

工程代码常用而 zh 包没有唯一中文词条的：
`from_le_bytes`、`rotate_left`、`copy_from_slice`、`inline`（属性位）、
`FnOnce`/`FnMut`（闭包特征位，`函数` 被 `Fn`/`fn` 占用）、
`match`（`匹配` 歧义）、`loop`（`循环` 歧义）、`format!`（`格式化` 歧义 fmt/format）、
`Vec::from_iter`、`extend`。**现象**：写中文则产物是未定义方法名（编译错误），
写英文则"全中文"在方法维位不达。`名字缓存` 是靠**重构**（逐字节散列）消掉前三个，
`FnOnce` 与 `#[inline]` 无处可躲，保留英文并在文档注释里标注原因。
**建议**：按"工程代码实际用量"补齐词条，优先补属性位与闭包特征位。

### F7 `self` / `super` 的词形易错（教学侧真问题）

接收者要写 `自我`（→`self`），`super` 要写 `超级`；而 `自身` 是 `Self`（类型位）。
本模块实测：写 `&mut 自身` 转译出 `&mut Self`（成了类型而不是接收者），
只能靠人工读产物发现；方言源、产物两侧都不会有任何提示。
**建议**：方言在参数/接收者位对 `自身` 给出定向提示；或为 `self` 增补一个不易混的词。
**已升级为机器检查**：见 F12（接收者/绑定位同属“词条在任意位置替换”这一条规则）。

### F8 一词多译审计需要**等长剥离**字面量与注释

审计直接把 `.zh` 全文切 token 会假报警（文档注释里出现 `文本`、字符串里出现 `映射`）。
门禁的做法是等长剥离注释/字符串/字符字面量后再比代码区，
并对「词条 + ASCII 缩写」拼接（NFKC 分解后重合）先做归一化。
**这是工具自身要解决的问题，不是用法问题**：任何基于词表的扫描都会撞上。

### F9 自动 `rzc relocalize --to zh` 只能当脚手架

探针实验（`/tmp/rlz-proj`）：反译取"排序最小候选"会选错，
`.filter()` → `.日志过滤器()`、`.bytes()` → `.字节响应()`，项目自定义标识符一律保留英文。
产物能编译，但既非"全中文"也非"正确中文"。要得到可信的方言源，必须手写 + 正向转译验证。

### F10 若改引擎行号，`ui-keys-index` 必红（既有坑，本轮复现）

接线导致 `lib.rs` 等行号位移，`docs/ui-keys.en.md` 判陈旧。
改引擎源码后必跑 `python3 tools/ui-keys-index.py --write`。

### F11 与 MSRV 卡线交互的一条 lint 修复

`如果 让 … { 如果 … }` 被 clippy `collapsible_if` 判折叠（本仓 clippy 警告视为错误），
改成 `如果 让 … && …` 链式判断，而 let_chains 恰好是 **Rust 1.88** 稳定——
即本仓声明的 MSRV 上沿。方言写法本身没问题，但"改写产物以迁就 clippy"这条路径
未来会反复出现，值得在 rzc 侧考虑：转译产物是否内置 lint 抑制策略。

### F12 关键字表词条**劫持绑定位**（已从文档条目升级为机器检查）

`keywords.toml` 的替换在词法层做、**不区分位置**，所以连 `let` 绑定名、参数名、
模式内变量都会被词条顶掉。一次 `rzc transpile` 一次复现四种：

```
让 无 = x            -> let None = x       （语法错误）
让 文本 = "t"         -> let str = "t"      （同上）
让 列 = 1             -> let column = 1     （静默改名：产物能编译，名字换成英文）
如果 让 成功(自身) = …  -> if let Ok(Self)    （模式内变量被顶成 Self）
```

对比实验：stdlib / 别名表词条（`路径`、`组件`、`版本`、`名字`）在绑定位**透传**，
只在方法位、类型位替换——即**劫持范围由词条属于哪张表决定**。F4、F7 都是这条
规则的具体表现。

**处置**：`tools/check-zh-artifacts.py` 的 `check_binding_hijack` 把 keywords.toml 的
126 个词形当禁名集，扫 let 绑定名 / 参数名 / 字段名 / 闭包参数 / `对于` 循环变量 /
模式内变量六类位置，命中即判红。反向验证：植入 `让 列`、`让 无`、`让 文本`、
`成功(自身)` 的坏例被判红 5 处、退出码 1；现存三个方言源零命中。
语法前缀词形（`让`/`对于`/`可变`/`有值`…）按英文原名从表里反查，语言包改名时
检查跟着走，不会悄悄失效。

**给 rzc 的建议**：这类劫持应在**转译期**报警，而不是靠外接门禁。方言作者的心智模型是
“中文名字是我自己定的标识符”，而词法替换把这条直觉打破了——编译器只会以“找不到变量”
的形式间接提示，不告诉你是哪个词条干的。

同一批实测还确认**声明名位同样被顶**：`函数 格式化(&自我, …)` → `fn format(&self, …)`、`模块 测试` → `mod test`（模块名被换成英文，`cargo test` 报告里的母语路径就此丢失）。据此两件事：绑定位审计从 5 类模式扩到 6 类（新增「声明名」）；四个已转模块的测试模块名统一改成无词条的 `母语测试`，让测试路径保持母语。

**机制修正（`界面消息` 轮，F21 取证带出）**：上文「对比实验：stdlib / 别名表词条在绑定位透传，只在方法位、类型位替换」容易被读成“stdlib 词形当名字是安全的”。逐位实测结论更窄也更要紧：

- keywords 词表：词法层全局替换，**含声明名位与绑定位**（`让 匹配 = 1` → `let match = 1`）；
- stdlib / module_paths / 第三方表：只在**方法位、类型位、关联函数位**替换，**定义位不替换**
  （`函数 解析` → `fn 解析`，而 `.解析()` → `.parse()`）——于是定义与调用不一致，报 **E0599**；
- 所以此前“`排序` 撞 `Ord` 导致方法位不可用”的说法要改口：真正拦住“用 stdlib 词形做方法名”的是
  **定义位不替换** 与 **项目声明豁免**（F21），不是歧义词优先级。

### F13 语言包里有**混血词形**：中文里塞 ASCII 尾巴

排查 `column_map` 时翻 stdlib 表发现：`最后一个_mut` = `last_mut`、`取值或_else` =
`unwrap_or_else`、`取成功值_or_else` = `unwrap_or_else`。这类词形在中文代码里读不通
（母语读者不会在中文词后面写 `_mut`），等于把"全中文"的门槛又抬回英文；而且它们让
`unwrap_or_else` 同时有 `解包或用否则` 与 `取值或_else` 两种写法，术语表的一致性
也破了。**同表内还有 `复制` = copied 与 `可复制` = Copy、`取值或`/`解包或`/`取成功值或`/
`解包或用` 四个词形同指 unwrap_or**——多写法并存时，"看代码猜原意"与"由产物反推母语"都会分叉。
**建议**：`last_mut` 一类按本项目既有的 `可X` 构词法补纯中文词形（`可克隆`/`可复制` 已经是成
功例子），并把同义词收敛到一个规范词形上、其余标为别名。

### F14 重构会把**隐含不变量**变成正确性依赖，而 rzc 没有表达契约的位置

`列位映射` 把 `HashMap` 偏移索引换成升序游标归并，前提是那表本来就按 `source_offset`
升序（`TranspileOutput::pipeline_map` 的文档这么写，但代码里没有任何地方校验）。
英文版对乱序**不敏感**（哈希表与顺序无关），中文版乱序就**漏替换**——一个只有方言实现
才会踩的坑。更麻烦的是：这种依赖在 Rust 类型系统里没有落点，只能写在文档注释里。
同一处还暴露了行为差异：同一偏移上有两条编辑时，`HashMap` 倒表是**后写覆盖**，
游标是**取首条**。我用测试把这个差异钉死（`同偏移多条编辑取第一条`），而不是让它静默漂移。
**建议**：管线输出的这类不变量（升序、不重叠、同偏移唯一）应由 engine 提供一个
`校验过的编辑表` 类型或 debug 断言入口，方言实现才有地方"声明"而不是"假设"。

### F15 clippy 抓到了中文声明式改写的**复杂度退化**（正例）

`回译坐标` 我按中文直觉写成 `迭代().过滤(…).最后一个()`，clippy
`double_ended_iterator_last` 直接判红："在 DoubleEndedIterator 上调 last() 会无谓地
迭代整个迭代器"——英文原版靠 `for … { if … { point = *p } else { break } }` 提前退出，
换成声明式后这个提前退出就丢了。本模块每行分段点很少、且只在诊断路径调用，可以接受，
但**"母语表达更直白 ↔ 悄悄丢掉提前退出"这个模式会在每个转方言的模块上重演**。
最终写法改成「满足条件者构成前缀 → 前缀长度减一即所求」，既不违反 clippy，又把
"升序"这个前提写进了式子本身。附带一条：`unnecessary_lazy_evaluations` 会把
`解包或用否则(|| x)` 判成多余闭包（该用 `取值或`），方言作者按英文习惯写 `unwrap_or_else`
的中文对应物时会撞上。
**建议**：`bench-check` 之外，方言侧值得有一条"控制流改写"提示——声明式改写丢 break 时给个信息。

### F16 生命周期位不吃关键字表：`'静态` 原样落进产物

`静态` = `static` 属 `["声明"]` 节的词法层词条，但 `'静态` 是**整体一个生命周期 token**，
不参与词条匹配：`结构体 分类<'a> { 标题: &'静态 文本 }` 转译得
`struct 分类<'a> { 标题: &'静态 str }` —— 生命周期名成了 `'静态`，与声明的 `'a` 对不上。

- 影响面：凡需要 `&'static str` 的字段/返回类型，中文源只能写 `&'static 文本`
  （生命周期留英文、类型用中文的混排）。`指南.zh` 的
  `样本分类们() -> 向量<词条分类<'static>>` 即如此，源注释里点名了本条。
- 要覆盖需让词法层把 `'X` 的 `X` 也过一遍表，但得先回答「同名词形出现在生命周期位时
  是否只有唯一解」（`'文本`、`'向量` 这类生命周期一旦存在就会撞类型词条），不是加条规则就行。

### F17 词库标注的多值可能只是**静态形态**，实测只命中一个取值

`格式化` 同时挂 `fmt` 与 `format`，在「一词多译」审计里是在册歧义词；四个位置实测**恒取 `format`**：

| 中文源写法 | 产物 |
| --- | --- |
| `格式化!("{}x", 1)` | `format!("{}x", 1)` |
| `让 格式化 = …` | `let format = …` |
| `结构体 甲 { 格式化: 整数 }` | `struct 甲 { format: i32 }` |
| `函数 格式化(&自我, …)` | `fn format(&self, …)` |

`fmt` 那条来自方法别名表（`impl Display` 的 `fn fmt`），而关键字表同名且先行，
zh 语言包的实际渲染永远取不到它。审计只看表的静态形态就会把 20 处 `格式化!` 全判红。

- 处置：进豁免表，但条目里写的是**上面这四行实测**而不只是"某位置允许"，并顺带约束
  「绑定名/字段名/方法名一律禁用本词」——它照样被顶成 `format`，属 F12 家族。
- 口径提醒：豁免的成立条件是"实测取值唯一"，不是"该处看起来安全"。

### F18 拿 PATH 里的发布版 rzc 取证，结论会串到旧版本上

本轮先用 shell 里的 `rzc`（`~/.cargo/bin/rzc`，**0.8.4**）跑探针，得到
`#[配置(测试)] 模块 测试` → `#[cfg(test)] mod test! {` 这种非法产物，
差点记成主线缺陷；换工作区 `target/debug/rzc` 复跑，同一输入得到合法 `mod test`
——**该缺陷属于 0.8.4，主线已修**。

- 反向价值：它仍是一条**发布版真实缺陷**（装着 0.8.4 的用户会撞上），值得进发布说明，
  只是不能记在 HEAD 账上。
- 纪律：方言取证一律用 `target/debug/rzc`。`tools/check-zh-artifacts.py` 的默认口径
  本来就是它（只有 `--rzc` 能覆盖），所以门禁结论没被污染，出错的只是手工探测。

### F19 中文源里「英文 + 空格 + 中文」的混合标识符不会被修，直接产出语法错误

测试函数写成 `函数 markdown 转义竖线与换行()`，转译原样给出
`fn markdown 转义竖线与换行()` —— 标识符内含 ASCII 空格，rustfmt 立刻报
`missing parameters for function definition`。转译器**不做标识符规范化**，只能源侧避免
（本轮改名 `转义竖线与换行`）。

可给上游提的 lint：`.zh` 源里声明/引用位的标识符若同时含 ASCII 与 CJK 且中间有空格，
在转译阶段报错，而不是把语法错误留给 rustc 去猜。

### F20 `rzc cheat` 的行序每进程都不同（真缺陷，本轮已修）

`guide.rs` 的模块注释自己写着「同一分类内行的先后顺序沿用原实现（来自 HashMap 迭代序，
不保证稳定，历史行为同样如此）」——等于把问题当既成事实接受了。实测 `rzc cheat zh` 连跑两次
**相差 2908 行**（两侧各自排序后才零差异）。后果落在用户身上：`rzc init --ai` 与
`rzc relocalize` 写出的 `AGENTS.md` 每次全表重排，读者仓库里出现与语言包变化无关的 git diff。

转 `指南.zh` 时真修：分类内改用 `有序映射`（`std::collections::BTreeMap`）按母语词形归集，
迭代序即码位序，因而不需要 `sort_by`——顺带避掉 `排序_by`（F13 式混血词形）与 `排序` 撞
`Ord`（keywords `["派生特征"]` 优先）两个坑。

- 等价性凭证：改动前基线与改动后输出**排序后零差异**（内容一字未动）；改动后两次运行
  **原始零差异**（改动前 2908）；markdown 版与 0.8.4 基线排序后亦零差异。
- 上锁：测试 `同一输入渲染两次逐字节一致` 直接断言两次渲染相等，旧实现下这条必然 flaky。
- 这条是「重构而非对译」产出的第一例用户可感知修复：逐行翻译会把那段 HashMap 迭代序
  原样搬进中文源，还要多加一句"沿用历史行为"的注释。

### F21 项目声明豁免**按目录聚簇**：一个词形当声明名，同目录所有 `.zh` 的该词方法位集体失效

转 `界面消息.zh` 时，产物里 `.长度()` 原样留中文；而同一段代码复制到没有声明过的目录就正常
转成 `.len()`。一轮隔离变量对照定位到根因：

- 机制：`rzc transpile` 默认加载 `ProjectContext`（`crates/engine/src/alias.rs` 94-103 行），
  它扫描**同目录全部方言源文件**的声明名汇总；`names`/`items` 一旦含某词形，
  同目录**任何** `.zh` 里该词的方法位不再替换（1154-1156 行：`is_method_pos` 分支含
  `project.items.contains(text)`）。
- 取证对照：探针7 在 `crates/engine/src/` 声明过 `长度`/`是否为空`/`解析`/`取` 四个方法名
  → 同目录所有 `.zh` 的这四个词方法位均不替换；把同一文件复制到 `.rz/probe2/`（空目录）
  → 四个词全部正常替换。差异只来自目录内的声明集。
- 注释与行为不符：同文件 1145-1146 行自己写着「`编辑表.长度()` 的 `长度` 是 `Vec::len` 调用，
  **字段名豁免不适用于方法位**」，但实测有项目上下文时 `project.items` 在方法位照样豁免。
  读注释推不出这个行为，只能实测。
- 工程后果：这是**目录级隐式耦合**——新增一个方言文件就能静默改掉同目录其他文件的产物
  （名字恰好撞词形时）。本分支已把“转换后重转同目录全部 `.zh` 验漂移”定为纪律，
  `界面消息` 轮实测 6 个源**零漂移**。
- **给 rzc 的建议**：①豁免集只收“真实参与链接的 crate 内方言源”，并提供 `--no-project-context`
  供取证与排查；②声明名撞词表词形时在转译期给一条信息（现在是静默影响整个目录）。

### F22 `如果 有值(x) = y` 产出非法的 `if Some(x) = y`，transpile 与 lint 零提示

方言里 `如果让` = `if let`、`当让` = `while let`，但写成 `如果 有值(甲) = 文案` 时，
转译器只做词形替换，产出一行 `if Some(甲) = 文案`（Rust 语法错误），`--no-lint` 以外的
默认 lint 路径也**不给任何提示**，只能靠事后 `cargo build` 看 E0308/语法错发现。
本分支写法均已改为 `如果让` / `当让`。
**建议**：`如果`/`当` 后紧跟模式形（`有值(`、`成功(`…）且跟 `=` 时，转译期直接报错并提示
该用 `如果让` / `当让`——这是方言特有的高频误写，比让使用者面对一句英文 rustc 报错便宜得多。

### F23 歧义 keywords 词形用在命名位有**两种失败形态**，信号强度完全不同

同一类误用，得到的反馈差一截：

| 写法 | 产物 | 失败形态 |
| --- | --- | --- |
| `让 匹配 = 1` | `let match = 1` | 撞**保留关键字**，编译期硬失败 |
| `结构体 甲 { 匹配: 布尔 }` | `{ match: bool }` | 同上 |
| `函数 格式化(&自我, …)` | `fn format(&self, …)` | **静默改名**，能编译，产物与源码不同名 |
| `让 结果 = …` | `let Result = …` | 静默改名，能编译但把库类型名用作局部名 |

前者靠编译器能定位，后者**只有读产物才能发现**（本分支靠 `check-zh-artifacts.py` 的
声明名/绑定位审计把 126 个 keywords 词形当禁名集）。两条一起进豁免表条目：
`匹配`（仅语句位与方法位）、`错误`（仅模式位与路径位），现共 7 条，均附逐位置实测。

### F24 重写引入的 char-boundary panic 被 **729 例穷举差分**当场抓住（差分测试的正向价值）

`代入参数` 第一版按“手写边界用例全过”的姿态落地：`当 游标+1 < 模板.长度()` 配
`&模板[游标..游标+2]`，在纯 ASCII 手写用例上行为正确，一旦模板是中文（`"已导出到 {}"`）
就把字节游标切在多字节字符 `已` 内部 → panic。18 条手写用例没抓住（都是 ASCII 模板），
**抓住它的是以 `['a','{','}']` 三字符表、长度 5 穷举的 243 个模板 × 0..2 参数共 729 例与
旧实现对跑**。
更值得记的一笔：这个 buggy 版本已被 `cargo build --bin rzc` 编进二进制，导致随后跑
`check-zh-artifacts` 时**整个门禁 panic**（`end byte index 2 is not a char boundary`，
5 个 `.zh` 全报“转译失败”）——引擎缺陷会冒充工具链缺陷。
**可复用做法**：“重构而非对译”的改写必须留下旧实现作差分基准（本模块把它放在测试里叫
`旧代入`，注释点名“只活在测试里”），差分要么逐例、要么穷举；手写边界只能验证“我想到的形状”。

### F25 教程门禁漏 `--dir` 会造成 en/ja/ru 三语**假失败**（F18 同类第二次重演）

自查时跑 `verify-tutorials.py` 没带 `--dir tutorials/<lang> --lang <lang>`，脚本默认拿 **en 方言包**
去编中文代码块，报 314 个代码块失败、“对齐对数低于下限 37 → 0”，一度像真回归；按 Makefile 72-74 行
的完整口径重跑 → zh/en/ja/ru 分别 77/37/37/51 全绿。
与 F18 同根：**取证口径错→结论全错**。纪律：门禁脚本调用逐字照 `Makefile`/CI，包含所有
`--allowlist tools/expected-failures.json --ctx --outputs` 类参数；手写命令只用于探针，不用于结论。

### F26 属性位只认 `#[派生(...)]`：同一个 `调试` 在三处取三个值

转 `映射管理器.zh` 时逐形态实测（`.rz/probe8/属性位.zh`，干净目录）：

| 中文源写法 | 产物 | 判定 |
| --- | --- | --- |
| `#[派生(调试, 克隆)]` | `#[derive(Debug, Clone)]` | 可用（走 `keywords.toml` 的 `["派生特征"]` 节） |
| `#[派生(默认)]` | `#[derive(Default)]` | 可用 |
| `#[派生(调试, 克隆, PartialEq)]` | `#[derive(Debug, Clone, PartialEq)]` | 混写安全：英文项透传 |
| `#[配置(测试)] 模块 X测试` | `#[cfg(test)] mod X测试` | 可用 |
| `#[允许(死代码)]` | `#[allow(死代码)]` | **不可用**：属性参数位不走任何表，`dead_code` 无中文词条（`stdlib.toml` 自己也注明「如 non_snake_case/dead_code 直接写英文」） |
| `函数 戊<T: 调试 + 克隆>` | `fn 戊<T: debug + clone>` | **不可用**：约束位取的是 stdlib（`克隆`→`clone`）与第三方表（`调试`→`debug`，来自 `crates/日志.toml`），拿到的全是被小写化的、不存在的特征名 |

- 最坏的一面：`调试` 在属性位得 `Debug`（对）、在约束位得 `debug`（错），两处都不给提示；
  而约束位是泛型代码常客，等价于「特征名不可方言化」。既有台账 F17 只说过「取值分歧」，
  本条是它后果最重的一次。
- 同一轮还撞出一个纯语法错：测试函数写成 `函数 空()` → `fn ()()`（`空` = `()` 是 keywords
  词条，声明名被换成单元类型），属 F12/F23 家族。
- **建议**：`派生特征` 节同时喂约束位与 `impl 特征名` 位；`allow`/`deny`/`cfg` 的属性参数位
  至少补常见 lint 名词条，或在转译期对「属性参数位留中文」给一条提示。
- 顺带证实可写形式：`实现 特征 对于 类型` → `impl Trait for Type` ✅（写成 `实现 ... 为 ...`
  会把 `为` 原样漏进产物 → 非法，方言介词是 `对于`）。

### F27 `自身::X` 是 stdlib / module_paths / 第三方三张表唯一会命中的关联项位

`映射管理器` 的枚举变体与关联函数按后缀区分，一次撞中两个（都是真编译错误）：

| 中文源 | 产物 | 位置判定 |
| --- | --- | --- |
| `枚举 源类别 { 关键词, 标准库 }` 定义位 | `标准库` 保留 | 定义位不替换 |
| `自身::标准库 => 真` | `Self::std => 真` → **E0599** | `Self::` 前缀后 → 替换 |
| `类别::标准库` | `类别::标准库` 保留 | `类型名::` 前缀 → 不替换 |
| `函数 装配() -> 自身` + `自身::装配()` | `Self::hoop()` → **E0599**（第三方表 `装配` = hoop） | 同上 |
| `机器::装配()` | 保留 | `类型名::` 前缀 |
| `结构体 记录 { 条目路径: 字符串 }`、`r.条目路径`、`自我.条目路径` | 全部保留（`条目路径` = path） | 字段定义位与访问位 |
| `让 项路径 = ...` | `let 项路径` 保留 | 绑定位 |
| `哈希集合::新建()` | `HashSet::new()` | **前缀类型名自己被替换 → 后面关联项名跟着走表** |
| `懒算表::新建()` | 保留 | 本地声明的类型名前缀 → 整条不换 |

- 机制图景：关联项名不是独立判定位，而是**跟着前缀走**——前缀是 `Self`（由 `自身` 得来）
  或一个已被替换成英文的类型名时，表才作用到第二级；前缀是本地类型名时整条透传。
- 工程后果：**枚举变体名与关联函数名是命名位里唯一需要过全表核查的那类**，撞
  stdlib/第三方词形时定义处不改、引用处改，必然成对 E0599。本轮据此改名：
  `标准库`→`标准源`、`装配`→`组装`、`新建`→`空白`、`条目路径`→`项路径`、`源`→`入料`。
- **建议**：转译期发现「本文件定义位有 X，而 `Self::X` 被换成英文」时应直接报错——
  它不会静默出错而是必然编译失败，本可零成本拦住。

### F28 同文件同名的豁免范围：声明名盖住方法位，`let` 绑定名只盖住类型位

F21 只说了「声明名按目录聚簇」。本轮同一词形在两个位置拿到相反结果，隔离变量重跑
（`.rz/probe8/{y1,y2,y3,z1,z2,x4,x5,u1}/`）：

| 本文件里的同名项 | `T: 调试`（约束位） | `x.调试()`（方法位） |
| --- | --- | --- |
| 没有任何叫 `调试` 的名字 | → `debug`（替换） | → `debug`（替换） |
| `让 调试 = 2;` | → `调试`（**不替换**） | → `debug`（仍替换） |
| `实现 甲 { 函数 调试(&自我) }` | → `调试`（不替换） | → `调试`（不替换） |
| 同目录另一 `.zh` 写了 `函数 调试()` | → `调试`（不替换） | → `调试`（不替换） |

- 两个新事实：① **`let` 绑定名也进豁免集**，不仅声明名；② 豁免是**整文件级而非作用域级**
  ——在 `主()` 里写 `让 调试 = 2`，会关掉同一文件中另一个函数 `戊<T: 调试>` 的替换，
  哪怕 `戊` 写在 `主` 之前、二者不同层作用域。对照实验：绑定名换成无关的 `游标`
  时替换照旧发生，排除了「有 let 就整体停摆」。
- 危险面：一个局部变量名能静默改掉同文件无关代码的产物（不报错，只把中文留进约束位
  → E0412/E0405）；而 keywords 词条不受这层保护（`让 枚举 = 1` 仍先被换成 `let enum`，F23）
  ——同一条规则对两张表给出相反后果，只能逐表实测。
- 处置：`.rz/gen/decl_audit.py` 把命名位审计分三级（高危＝keywords 词形 × 任意命名位；
  中危＝非 keywords 词形 × 声明位；提示＝非 keywords 词形 × 局部绑定），退出码卡高/中危，
  本轮据此在入场前拦掉 3 处真问题。
- **潜伏项记账**：已发货的 `列位映射.zh` L46 字段 `全部行` 属「中危」（stdlib 词形做声明名），
  实测当时未发作（字段位不在替换范围），但按本条机制它是同目录方法位豁免的潜在注入点，
  下次动该目录时应一并改名。
- **建议**：豁免集只应收「本 crate 内真实参与链接的项名」，不应含局部 `let` 名；至少提供
  `--no-project-context` 与逐文件声明清单，让作者看得见自己在跟哪些词形抢名字。

### F29 宏名位走 keywords 表：`matches!` 没有可用方言形态，但 `拼接!`/`崩溃!` 有

`.rz/probe7/探7.zh`：`匹配!(值, 类别::甲 | 类别::乙)` → `match!(值, 类别::甲 | 类别::乙)`。
宏名 `匹配!` 被 keywords 的 `匹配`→`match` 顶掉，而 `match` 不是宏 → 产物直接非法。
同一位置实测 `拼接!("甲", "乙")` → `concat!("甲", "乙")` ✅、`崩溃!` → `panic!` ✅：
区别在于 `拼接`/`崩溃` 在表里取到的就是宏名，而 `匹配` 取到的是关键字。
叠加 F5（`匹配` 是 match/matches 歧义词），结论：**`matches!` 在 zh 方言里写不出来**，
只有 `如果 让` / `匹配` 语句两种替代。本轮实际影响：clippy `match_like_matches_macro`
把 `匹配` 语句判成应该用 `matches!`，而 `matches!` 写不了中文——只能改数据结构绕开
（把 `报错带来源名` 整个方法删掉、路径改为无条件带上，反而修掉一个真 wart：
读盘路 stdlib 解析失败时报的是空路径）。
**建议**：宏名位应优先查宏表（`标准库成员` 节或专用宏节）而不是 keywords 表，
否则「clippy 鼓动的写法」与「方言可写的写法」持续互斥。

### F30 歧义词在方法位可能取到**类型形态**：`临时.路径()` → `临时.Path()`

`.rz/probe8/v1/t.zh`：`路径` 同时挂 `path`（stdlib 方法）与 `Path`（module_paths 类型），
方法位实测取 **`Path`**（首字母大写那个），产出 `临时.Path()` 这种非法方法名。
同一条言改写成表里另一个词形 `条目路径`（stdlib.toml「条目路径」= path）实测得
`临时.path()` ✅——所以这不是缺口，而是**歧义词的取值恰好选了错的那一支**。
- 与 F5 同族但方向相反：F5 说「方法位让位守卫能救 `排序`」，本条说**方法位不保证拿到方法形态**。
- 口径意义：判断一个词能不能用，不能只看「在不在歧义表」，必须**逐位实测取到哪个值**；
  豁免表证据栏只记实测行，不记推定。

### F31 全中文残量第一次可量化：224 → 195 处，其中多数是「词条在表里、我却写了英文」

用户指出「zh 代码里还有很多英文」。清点方式落到新门禁
`tools/check-zh-ascii.py`（口径：等长剥离注释与字面量 → 剥数字字面量 → **剥掉语言包里

残量分三类，处置不同：

| 类别 | 实例 | 处置 |

| **表里有词条，我没查表**（本轮清零 29 处） | `std::`→`标准库::`、`collections`→`集合`、`crate::`→`包::`、`concat!`→`拼接!`、`.as_str()`→`.作为字符串()`、`.path()`→`.条目路径()`、`impl `→`实现 `、`&mut `→`&可变 `、`pub(crate)`→`公开(包)`、`FnOnce`→`一次函数`、`u32`→`无符号整数`、`rustc_lexer::tokenize`→`词法解析器::切分令牌`、`toml::from_str::<toml::Value>`→`TOML处理::解析字符串::<TOML处理::TOML值>` | 全部改写；7 个 `.zh` 重转**产物零漂移**（证明只是源侧中文度提升、语义未动） |

### F32 `.zh` 里剩下的英文，主力不是「没查表」，是依赖模块把英文声明漏进方言消费侧

F31 把残量分成三类，第三类（161 处）最大也最难：**同仓某个英文模块把它自己的项名
（类型 / 字段 / 方法 / 模块名）泄漏进了 `.zh` 的消费位**。语言包救不了它们——它们是
本项目符号，不该进词条表；补词条只会让「本项目名字」和「Rust 生态名字」混在一张表里。

所以这一轮的口径是**改声明侧，不是改引用**：

| 改名前（main 侧） | 改名后（zh 分支） | 性质 |
| --- | --- | --- |
| `error.rs` | `故障.zh` → `故障.rs` | 整模块转方言源（`LoadError`→`载入故障`、`LoadTarget`→`载入目标`、`SourceLocation`→`位置信息`） |
| `mapping_manager.rs` | `映射管理器.zh` → `映射管理器.rs` | 整模块转方言源（`MappingManager`→`映射管理器`） |
| `mapping_source.rs` | `映射源.rs` | 英文模块内改声明（`ParsedDocument`→`已解析文档`、`SectionMap`→`节表`、`DangerInfo`/`DangerLevel`→`危险详情`/`危险等级`、`flatten_sections`→`摊平节表`、`is_always_panic_target`→`恒恐慌目标`、`is_native_key`→`是母语词条`、`danger_from_sections`→`危险从节表`） |
| `lint.rs` | `校验.rs` | 同上（`WordBuckets`→`词形分桶`） |
| `cache.rs` | `缓存.rs` | 同上（`SourceMapEntry`→`源码映射条目`、`TranslationCache`→`转译缓存`） |
| `lexer.rs` | `词法器.rs` | 同上 |
| `语言.rs` | 原地改（`current_language`/`set_language`/`builtin_message_table`/`reverse_transpile`→`当前语言`/`设定语言`/`内置消息表`/`反译重生`） | 同上 |

- `lib.rs` 一次接线 339 行：六个 `#[path = "…"]` 模块声明 + 全部重导出路径。
- **判据是「方言消费侧要不要写它」，不是「它是不是英文」**。`compute_content_hash`、
  `lint_teaching*`、`eject_hints`、`with_language`、`builtin_file` 这些只有英文侧
  （cli / lsp / 未转换的 engine 模块）在调，留在英文声明——它们是**还没轮到的模块**的
  账，不是漏网（滚动顺序见文末）。
- 改名批的接线不能用全文替换：不同接收者上有同名方法（`mapper`/`loader`/`cache` 三类），
  一把梭会连带误改。本轮用**接收者白名单脚本**（`.rz/gen/wire_mm.py`）逐接收者改写 +
  32 个消费侧文件逐处复核，改后 debug/release 全绿。
- 教训一句话：看到 `.zh` 里有英文，先问「这是 std / 第三方 API，还是本仓某个模块的声明」。
  前者查表（表里没有就补词条，见 F31 第二类的 3 条），后者只能改声明侧。

### F33 改名批之后必须回查字面量与注释引用——门禁对这两区都视而不见

三道门禁（`check-zh-artifacts`、`check-zh-ascii` 代码区、注释区）**都是等长剥离字面量**
之后才开始找英文，注释区门禁又额外豁免路径/文件名形状。于是旧名字的残留**永远不会判红**，
但它照样误导读者、照样能在运行时读不到东西：

- 本轮实测抓到 3 处「指向已不存在的文件」的注释引用：`crates/engine/build.rs` 两处写
  「见 `cache.rs`」、`crates/engine/tests/differential_lex.rs` 写「把 `alias.rs`/`lint.rs` 里的…」——
  文件都已改名，指路人扑空。已全部改指新名。
- **该保留的旧名引用只有一类**：溯源注明。`故障.rs`/`故障.zh` 首行的「（`error.rs` 的中文
  原生重构）」是有意保留的历史坐标，不是残留。
- 收尾清单（改名批必跑，脚本抓不到就得靠这条命令）：
  `grep -rn "<旧名>" --include=*.rs --include=*.zh --include=*.toml crates/ tools/`，
  命中分两类处置——① 指向已不存在的东西 → 改；② 协议字面量（serde 键、`#[path]`、

- 字面量区本身也有一笔账：9 个 `.zh` 的字面量区实测 **392 处 / 160 词**英文（`"err_line_col"`

  （`check-ui-keys` 把守），改它等于改协议 + 改 11 份语言包，属跨分支决策，不该在清注释
  这一轮顺手做掉。

### F34 注释里的英文此前完全不可见：注释区改为零容忍（578 → 0）

用户两次指出「zh 代码里还有很多英文」，而 `check-zh-ascii` 报的是「代码区残余 0」——
两者不矛盾：**主门禁等长剥离注释与字面量**，注释里的英文一行都看不见。而注释恰恰是
读者主要在读的东西，「代码没英文、注释全是英文」不叫达标。

- 先把残量测出来：9 个 `.zh` 的注释区 **578 处 / 166 词**。拿语言包做 en→zh 反查分类，
  只有 **6 词**在表里有词形（TOML / PATH / Windows / IO / API / Unix），其余 **98 词无词形**
  （`stdlib` 24、`rzc` 22、`lint` 16、`crates` 15、`token` 14、`ui` 14、`HashMap` 13、
  `markdown` 12、`keywords`/`module_paths` 各 11、`Display` 10…）。
  结论：注释区的问题**不是查表能解决的**，是要用中文把事实重述一遍。
- 落进门禁（`tools/check-zh-ascii.py` 新增 `scan_comments`）：注释区**零容忍**，只留三条出口——
  1. **按形状自动豁免**（不接受就地豁免）：路径/文件名（含 `/` 或带 `rs|zh|toml|md|json|…|exe|cmd`
     扩展名、`~/.rz`、`<名>` 尖括号）、连字符小写名（`rust-analyzer`）、编号（`F16`/`E0308`/`B9`）、
     带空格专名（`VS Code`）、**逐字引用区间**（反引号内含代码标点 `;()[]{}=!|&*<>#:` 或以
     `rzc`/`cargo`/`rustc`/`git`… 开头）；
  2. **专名登记表** `tools/zh-comment-allowlist.json`：43 词，逐条附理由（`rzc`、`rustc`、`TOML`、
     `JSON`、`Rust`、`Windows`、`FNV`、`SipHash`、`anyhow`、`rustdoc`…）；
  3. 其余一律判红 → 改写为中文术语。
- 术语定稿（本轮统一，逐文件改写 248 处后注释区归零）：`token`→令牌、`lint`→校验、
  `stdlib`→标准库、`crates`→三方包表、`panic`→恐慌、`unwrap`→取成功值、`HashMap`→哈希映射、
  `BTreeMap`→有序映射、`Display`→可显示、`Self`→自身、`Box`→盒子、`Option`/`None`→选项/无、
  `Copy`/`Clone`/`PartialEq`/`Eq`/`Ord`→可复制/可克隆/部分相等/全等/全序、`0-based`/`1-based`→
  从零起算/从一起算、`toolchain`→工具链、`standalone`→独立发行版、`cheat`→速查、`AI`→人工智能、
  `emoji`→表情符号、`BMP`→基本多文种平面、`leak`→泄漏、`OnceLock`→一次性锁、`crate`→本包、
  `IO`→输入输出。
- **注释是描述，不是术语表**：同一个英文名在不同文件可以有不同的中文写法——`load_from_dir`
  在装配段叫「从目录载入」（那是方言函数名），在讲合并顺序的散文里叫「读盘路」。强行统一
  反而把散文写成对译。判据只看「有没有把事实说清楚」，不看「有没有一词一译」。
- 门禁输出同时管两区：`✅ 全中文棘轮达标：9 个方言源，代码区残余英文 0 处与基线一致，
  注释区残余英文 0 处`（注释区**不写基线**，因为它按定义是 0）。

### F35 反引号区间用正则配对会跨区间误抹；施工脚本的三次事故

- **正则事故**：rustdoc 链接 `[`渲染分类表`]` 与相邻的 `` `rzc cheat --markdown` `` 之间，
  「上一个区间的结束反引号」正好被当成「下一个区间的开始反引号」，于是把中间的**真实中文
  内容**整段抹空 → 门禁**假达标**（漏报）。同理，跨行断裂的命令引用（`` `rzc cheat `` 在
  L14、`` --markdown` `` 在 L15）会把整行 `//!` 前缀吞掉。
  处置：`strip_spans()` 按反引号**奇偶配对剖开**逐段判定，命令引用改成单行。
  教训：**任何「配对剥壳」都不能用正则扫整行**，正则不数配对，跨区间合并是必然。
- **按行号改写的事故**：一次批量给 20 行拆成两段，把原 L21 的一条 bullet 覆盖掉了。
  批量编辑里行号一定漂。之后一律改成**唯一片段替换 + 命中数断言**（`.rz/gen/textfix.py`），
  多行片段带上下文整块替换。
- **零命中仍写盘的事故**：批量规则里两条在注释里一次都没命中，脚本却继续写盘 → 半份改动。
  之后 `zh-comreplace.py` 先全量校验、有不命中即中止不写。
- **替换后留下的空格**：`load_from_dir` 换成中文后，两侧原本隔开英文的空格变成「两个汉字
  之间的空格」。用 `--despace`（CJK 前后看断言）抹掉，且**只作用于注释区间**——代码区
  多一个空格 rustfmt 会吃掉，注释区 rustfmt 不管。
- **凭记忆写片段必翻车**：`故障.zh` 一条多行片段命中 0 次，实际文件里是
  `` `&可变 格式化参数<'_> ` ``——反引号内多一个尾空格。用 `repr()` 读原文再写片段。

### F36 平台钉死的名字走「声明位有意替换」豁免表，不放行引用位

`impl Display` 的方法名**必须是** `fmt`（rustc 规定，写错等于没实现该 trait 方法），
而方言侧不许写英文（F34 之后连注释都不许）。唯一出路是让转译器**故意**把中文词换成
那个英文短名：词形 `格式化方法` = `fmt`（`keywords.toml` 的「标准库成员」节）。

- 登记表 `tools/zh-decl-exemptions.json` 的边界写死为**只对声明名位放行**：同一个词形
  用作绑定名 / 参数名 / 字段名仍按 F28 的绑定位劫持判红——那才是静默改名的事故位。
  表内附实测证据：`让 格式化方法 = 甲::乙` → `let fmt = 甲::乙`（绑定位也被换），
  所以绑定名一律禁用该词。
- 新增条目必须附 `rzc transpile` 实测证据，不接受「看起来该豁免」。
- 与之相邻的另一条硬约束（同文件实测）：方法名写「显示」会被换成**类型** `Display`，
  特征方法名就成了类型名；词形「结果」同时是 `Result` 与 `fmt::Result`，格式化侧那个
  一律写全路径 `标准库::格式化模块::结果`，不把短名使用进来顶掉成功结果。

### F37 产物格式不跟着源码改名：serde 键用 `#[serde(rename)]` 定住

`缓存.rs` 的字段中文化后，磁盘缓存 JSON 的键**沿用 v1 拼写**：

```rust
#[serde(rename = "source_offset")]   // 源码字段：源偏移
```

- 理由：JSON 键是**对外契约**，跟着源码改名会让全部存量缓存失效（一次全量重转译），
  而改名本身对用户零收益。定住旧键 = 缓存继续命中、不需要版本号升级。
- 判据推广：**任何改名批都要先问一遍**「这个名字有没有出现在序列化格式 / 命令行参数名 /
  跨语言对齐的键表里」。有 → 定住；没有 → 直接改。
- 同一机制的反向教训见 F10：引擎行号一变，`docs/ui-keys.en.md` 里的
  `main.rs:2842 → 2837` 就陈旧，`ui-keys-index` 必红——本轮实测 230 行整批漂移，
  靠 `python3 tools/ui-keys-index.py --write` 重生成解决。**索引/产物不自动跟着源码动**，
  改完必须显式重生成，这是同一类「对外契约」问题。

### F38 门禁的「长度 ≥2」豁免让单字母英文 API 名隐身

`scan_file()` 跳过长度 <2 的 ASCII 标识符（本意是放过泛型参数 `T`、闭包参数 `x`），
结果把三类东西一起藏了：`语言.rs` 的 `pub fn t`/`pub fn f`、`界面消息.zh` 自己声明的
`函数 t`/`函数 f`，以及方言侧对它们的全部调用（`故障.zh` 10 处、`界面消息.zh` 11 处）。
泛型与闭包参数是**结构性 ASCII**，而**有名字的公开 API** 就是没中文化的英文——
同一条 len<2 规则盖不住两种情况。

本轮两条处置路径（按「改名代价」分）：

1. **外部模块的英文名 → `.zh` 侧导入别名**：`语言.rs` 还没方言化，`f(` 在全仓 316 处
   （cli 221 / engine 60 / lsp 35），改不起。于是在 `.zh` 侧起中文名：
   `使用 包::语言::{f 作为 带参消息};`（与 `指南.zh` 既有写法一致，零外部改动）。
2. **本模块自己的声明 → 直接改声明名**：`界面消息.zh` 的 `t`/`f` 改 `取消息`/`取带参消息`。
   先过 F21 核查（两个名字都不是任何词表的词形），消费侧只有 3 处（`cli/src/ui.rs` 一处、
   `lsp/src/ui.rs` 两处），改得起：产物重转 + workspace 全绿（engine 459 例）。
3. 顺带清掉一个同类：`名字缓存.zh` 的 `常量 K` → `常量 散列质数`。

**门禁侧同步升级**：`check-zh-ascii.py` 新增 `scan_single_names()`，专扫**声明位 / 导入位**
的单字母 ASCII 名并打印计数（现阶段只报不判红）。当前读数是 3 处，全部落在路径 1 的
别名导入行（`指南.zh` L226、`故障.zh` L38）——那是「必须点名英文源项」的机制成本，
账挂在滚动顺序里：等 `语言.rs` 方言化，别名行自然消失。
