# 四维分析：面向全球用户的 rzc 现状评估与改进路线

> 日期：2026-09-05 · 视角：资深架构师 × 产品专家 · 战略前提：**主要目标从"服务中文用户"升级为"让全球用户都能用母语编写 Rust"**
> 技术基线：v0.7.0 + 13 个整改提交 + crate-registry 合并（bee6c41），392 测试全绿

---

## 〇、战略前提变化带来的评估口径调整

此前结论"冻结非中文语言包"**作废**。全球用户目标下，架构的最大优势——"新增语言 = 新增语言包目录，零代码改动"——从锦上添花变成**核心竞争力**。相应地，评估重心从"功能是否够"转为三问：

1. 一个不懂中文的德国/日本/巴西用户，能否在 10 分钟内完成安装并看到母语报错？（易用性）
2. 他能否找到母语的学习材料？（易学性）
3. 中文社区之外，这个项目靠什么被看见？（可推广性）
4. 第 11、20 种语言加入时，边际成本是否仍然趋近于零？（可扩展性）

---

## 一、易用性：现状、问题与建议

### 现状

命令面克制（init/run/check/eject/lang/mapping/install/doctor）；文件扩展名自动匹配语言；UI 语言跟随 `LC_ALL/LANG` 自动检测；三平台 CI 构建；`rzc doctor` 环境自检。

### 具体问题（按摩擦大小排序）

| # | 问题 | 影响 |
|---|---|---|
| U1 | **无零门槛安装路径**：README 明言"不提供在线预编译安装"，全球用户必须先装 rustup 再源码编译 1-3 分钟——而目标用户恰恰是还没装过 Rust 工具链的新手，鸡生蛋 | 致命摩擦，全球推广第一障碍 |
| U2 | **VS Code 扩展仅手动 .vsix 安装**：未发布 Marketplace/OpenVSX，全球用户（含 VSCodium/Cursor 用户）装不上 IDE 体验 | IDE 是核心体验载体 |
| U3 | **init 后无下一步引导**：项目骨架生成后，新用户不知道该看教程第 1 章还是先装扩展 | 首次会话流失点 |
| U4 | **RTL/字体未标注**：ar（阿拉伯语）在多数终端的方向与字体问题会让首批阿拉伯用户体验"坏掉"，却没有任何实验性标注 | 口碑风险 |

### 改进措施（优先级从高到低）

- **U1（P0，1 天）**：① 发布 crates.io（release.yml 已接线，配 token 即可），使 `cargo install rzc` 成为全球标准安装方式；② CI 已产出的三平台二进制挂到 GitHub Release 下载页——这两步是纯运营动作，工程零改动
- **U2（P0，半天）**：扩展发布 VS Code Marketplace + OpenVSX（后者覆盖 VSCodium/远程开发用户）；package.json 补充 `repository`/`keywords` 元数据
- **U3（P1，半天）**：`rzc init` 完成后打印与用户语言一致的"下一步"（教程第 1 章链接 + `rzc install lsp` 提示）；中期做交互式语言选择（`init` 不带 `--lang` 时列出全部 10 语言供选择，而非仅依赖系统语言）
- **U4（P2，2 小时）**：README 与 `lang list` 中为 ar/hi 标注"终端支持有限，推荐 VS Code 扩展内使用"

## 二、易学性：现状、问题与建议

### 现状

25 章教程（CI 逐块编译验证，全球罕见的教程质量护栏）、附录 A 映射表、总术语表、first-run 引导、`--help` 全面本地化。

### 具体问题

| # | 问题 | 影响 |
|---|---|---|
| L1 | **教程仅中文**：全球目标下这是最大短板——德/日/韩/西语用户没有任何母语学习材料 | 目标人群无法转化 |
| L2 | **映射速查表无英文/多语言版**：学习者最需要的"我的语言 ↔ Rust 对照卡"只有中文附录 A | 记不住映射时无处可查 |
| L3 | **无文档站点**：教程散在仓库 md 文件里，GitHub 网页阅读体验割裂，无语言切换 | 阅读摩擦 |
| L4 | **贡献指南仅中文**：全球用户想贡献第 11 种语言时读不懂贡献流程 | 生态增长依赖的贡献者路径断裂 |

### 改进措施

- **L1（P0，2-3 天）**：英文教程优先——AI 辅助翻译正文、**代码块保持原样**（`verify-tutorials.py` 会逐块验证编译，翻译安全有护栏）；英文版是事实上的"世界语版本"，其他语言后续复用同一流水线
- **L2（P1，半天）**：新增 `rzc cheat` 命令，按当前语言输出"母语 ↔ Rust"对照速查表（数据全在语言包里，纯展示逻辑）；README 附英文版速查卡
- **L3（P1，1-2 天）**：mdBook + GitHub Pages 文档站，聚合教程/附录/命令参考，顶栏语言切换；md 文件仍在仓库，站点自动构建
- **L4（P1，半天）**：`contributing-lang-pack.md` 英文化，并补一节"AI 辅助翻译 + 人工审校"的 SOP（这是全球用户贡献第 11 种语言的标准路径）

## 三、可扩展性：现状、问题与建议

### 现状（架构强项，直接支撑全球目标）

引擎语言无关、语言包数据驱动（新语言零代码）、跨语言一致性 CI 门禁、crate-registry 共享映射（本次合并）、核心模块已完成拆分（mapping_gen/diagnostic/response_map）、392 测试 + 覆盖率/基准/MSRV 门禁。

### 具体问题

| # | 问题 | 影响 |
|---|---|---|
| E1 | **ui.toml 键无英文释义字典**：每个键的含义只存在于使用处代码，全球贡献者补第 11 种语言时靠猜 | 新语言贡献的最大隐性门槛 |
| E2 | **Rust 侧 AI 提供商单一**：`mapping auto` 仅 DeepSeek；扩展侧已三提供商。全球用户多数没有 DeepSeek 账号 | 映射自动生成对新语言用户不可用 |
| E3 | **engine 全局语言状态**（`语言::set_language`）：作为库被嵌入其他工具时，多语言并发使用会互相污染 | 限制第三方集成（低频场景） |
| E4 | **无 CHANGELOG**：扩展有，workspace 级没有；全球贡献者无法追踪版本变化 | 发布透明度 |
| E5 | server.rs/main.rs 大文件（既有结论：server.rs 维持不拆；main.rs 诊断管线区可抽离） | 长期可维护性 |

### 改进措施

- **E1（P0，1 天）**：建立"键字典"——以 zh/en 双语注释生成 `docs/ui-keys.md`（脚本从 zh/ui.toml + 使用处提取），作为语言包贡献的权威参考
- **E2（P1，1 天）**：CLI 侧 `mapping auto` 抽象出 OpenAI 兼容 provider（base_url + key + model 三环境变量），与扩展侧对齐——DeepSeek 变成预设之一而非唯一
- **E4（P1，1 小时）**：workspace CHANGELOG.md，从 v0.7.0 起补记
- **E3（P2，大改）**：显式 locale API（`with_locale(...)`），仅当出现第三方嵌入需求时做
- **E5（P2）**：main.rs 诊断管线区抽模块沿用既有模式；server.rs 维持不拆

## 四、可推广性：现状、问题与建议

### 现状

双平台仓库（GitCode/GitHub）、crates.io/Marketplace 均未发布、无文档站、无演示素材、中文推广方案已就绪（docs/strategy/推广方案.md）、**品牌名三处不一致**：仓库名 zrRust（GitCode）/ i18n-rust（GitHub）/ 产品名 rzc。

### 具体问题与措施

| # | 问题 | 措施 | 优先级 |
|---|---|---|---|
| M1 | **品牌不统一**：全球传播必须一个名字 | 统一为 **i18n-rust**（仓库）/ **rzc**（产品），tagline：*"Write Rust in your native language."*；GitCode 仓库名对齐或注明镜像关系 | P0 |
| M2 | **英文是全球传播的通行证**：现有材料几乎全中文 | README.en 升级为全球门面（三语言示例切换 + GIF）；首篇英文文章投 dev.to + r/rust + Show HN（标题：*"Rc: A compiler that lets you learn Rust in your native language"*）；注意 r/rust 对"中文编程"有历史争议——**叙事必须多语言并举**，中文只是 10 种语言之一 | P0 |
| M3 | **无可视化 demo**：全球传播 GIF/短视频是转化核心 | 录制三段 15 秒 GIF（中文/日文/西文报错对照），放 README 顶部 | P0 |
| M4 | **This Week in Rust / 社区简报未触达** | 英文文章发布后自荐投稿；r/ja・r/ko 等 Rust 本地社区同步 | P1 |
| M5 | **竞品叙事缺失**："AI 时代为什么需要它" | 定位语：*"AI explains errors in your language — we make the code itself speak it."*（确定性 + 离线 + 编辑器闭环是 AI 的短板，详见 docs/strategy/项目存续评估.md） | P1 |
| M6 | **国内渠道**（docs/strategy/推广方案.md 已完整规划） | 按该方案执行，全球目标下降级为并行支线 | P1 |

## 五、按优先级汇总的可落地路线

### 立即实施（第 1 周，全部为运营/轻改动，合计约 3 天工作量）

1. **crates.io 发布 + Release 挂三平台二进制**（U1，解除全球安装摩擦）
2. **扩展发布 Marketplace + OpenVSX**（U2）
3. **品牌统一**：GitCode 仓库对齐 i18n-rust 命名，README 三语言 tagline + 三段演示 GIF（M1/M3）
4. **英文版映射速查卡 + `rzc cheat` 命令**（L2，全球学习者的第一工具）
5. **CHANGELOG.md**（E4）

### 短期（第 2-4 周）

6. **英文教程**（L1，AI 翻译 + CI 验证护栏）——全球易学性的关键一跃
7. **mdBook 文档站 + GitHub Pages**（L3）
8. **contributing-lang-pack 英文化 + 键字典**（L4/E1）——打开"第 11 种语言由社区贡献"的通道
9. **init 交互式语言选择 + 下一步引导**（U3）

### 中期（第 2-3 个月）

10. **CLI 侧 OpenAI 兼容 provider**（E2）
11. **英文全球渠道分发**（M2/M4：dev.to → r/rust → Show HN → TWiR）与中文方案并行
12. **RTL/南亚语言终端体验标注与改进**（U4）

### 长期（按需）

13. 显式 locale API（E3）；main.rs 诊断管线抽模块（E5）；第 11 种语言由外部贡献者按新 SOP 完成接入——**这将是"全球用户用母语写 Rust"目标的第一次架构级验证**

## 六、一句话结论

**架构已经为全球做好了准备（语言无关引擎 + 数据驱动语言包 + 质量门禁），真正的差距全在"最后一公里"：安装摩擦（crates.io/Marketplace）、英文通行证（教程/文档/品牌）、可视化素材。这三件事合计约一周工作量，做完之前不要开始任何全球推广；做完之后，项目就从"中文个人项目"变成了"任何母语者都可进入的产品"。**
