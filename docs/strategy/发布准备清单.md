## 2. GitHub Release + GitCode Release 双平台（~15 分钟 + 离线包打包）

前置（GitCode 侧，仅需一次）：仓库 Secrets 配置 `GITCODE_TOKEN`
（GitCode 头像 → 设置 → 私人令牌，需 releases 权限）；未配置时
workflow 仅告警跳过 GitCode Release，其余产物不受影响。

```bash
git push origin main && git push github main              # 双平台同步（先 GitCode 后 GitHub）
git tag v0.8.3 && git push origin v0.8.3 && git push github v0.8.3   # 版本按实际替换
# 推 tag 触发两平台各自 CI 的 release.yml：GitHub 侧建 GitHub Release、
# GitCode 侧建 GitCode Release，vsix 与 SHA256SUMS 随 Release 自动上传；
# 手动触发（workflow_dispatch）只构建 vsix 上传为 Artifact（不建 Release），
# 勾选「发布到 crates.io」可额外发布三 crate
```

补挂离线包（审计：v0.7.1 起各版 Release 仅挂 vsix，离线包与 SHA256SUMS
均缺——rzc 离线包不随 CI 构建，内置 rust-analyzer 且体积大，由发行方在各
平台本机打包后手动上传）：

1. 构建：在各平台机器执行 `./release-offline.sh`（Windows 用
   `.\release-offline.ps1`），产物 `release/rzc-<版本>-<平台>-<架构>.tar.gz`
   （Windows 为 `.zip`）；本机 Linux 包已就绪：
   `release/rzc-0.8.2-linux-x86_64.tar.gz`（已核验：内含 rzc 0.8.2、
   `i18n-rust-lsp`、rust-analyzer、11 语言包与教程）
2. 校验和：三平台包与 vsix 收集到同一目录后执行 `sha256sum * > SHA256SUMS`
   （Windows：`Get-FileHash * -Algorithm SHA256`）
3. 上传：GitHub Release（https://github.com/liuqiTan80/i18n-rust/releases）
   与 GitCode Release（https://gitcode.com/tan80/i18n-rust/releases）的编辑页
   分别拖拽上传；GitCode 侧 v0.8.0 / v0.8.1 / v0.8.2 三个 Release 尚缺，
   需先补建再传

发布后核验（维护者，~5 分钟）：
- [ ] GitHub Release：vsix + `SHA256SUMS` 齐全（离线包补挂后一并列出）
- [ ] GitCode Release（https://gitcode.com/tan80/i18n-rust/releases）：
      vsix 与 `SHA256SUMS` 附件齐全
- [ ] 下载任一产物执行 `sha256sum -c SHA256SUMS` 校验通过
- [ ] 若 GITCODE_TOKEN 未配置：补配后在 Actions 页重跑 publish job（或重推 tag）
