# rzc（母语 Rust）推广方案

> 日期：2026-09-04 · 目标：用 8 周时间、接近零预算，验证"母语 Rust 入门"是否有人真的需要
> 原则：不吹不黑——诚实定位为"入门坡道"，用真实数据决定项目去留（对应存续评估的 D1 路径）

---

## 一、先想清楚：卖给谁、卖什么

### 1.1 三类目标人群（按优先级）

| 人群 | 规模 | 动机 | 触达渠道 |
|---|---|---|---|
| **A. 想学 Rust 的中文自学者**（有其他语言基础） | 最大盘 | 被所有权+英文报错双重劝退过 | 知乎/掘金/教程 SEO |
| **B. 编程零基础学生 / 教学机构** | 小但深 | 需要成体系、可离线、免费的教材 | B站/公众号/教师社群 |
| **C. Rust 中文社区围观者** | 中 | 对"中文编程"话题有天然立场（正反皆有） | V2EX/Rustcc/即传播即检验 |

### 1.2 一句话定位（所有内容统一口径）

> **"用中文写 Rust，报错也是中文的——写的是真 Rust，随时毕业。"**

三层卖点，按说服力排序：
1. **报错是中文的 + 教学提示**（所有权叙事、引用层数提示）——最强的差异化，demo 冲击力最大
2. **不是伪代码**：逐 token 转译 → 官方工具链编译，宏/泛型/异步全支持，生态 100% 真实
3. **`rzc eject` 一键毕业**：导出标准 Rust，无锁定——直接回应"中文编程是围墙花园"的质疑

**诚实红线（所有内容必须遵守）**：不宣称"替代英文学习"，定位为**入门坡道**；教程双栏对照（中文/英文）。主动承认争议反而赢得信任。

### 1.3 预设质疑 FAQ（写进文章、评论区置顶）

- **"学 Rust 该直接学英文关键字"** → Rust 核心词汇量很小，第一周的流失大多发生在"看不懂报错"而非"背不下 let"。坡道存在的意义是让你活到能理解所有权的那一天；`eject` 保证坡道不变成围墙。
- **"转译器是玩具/伪代码"** → 架构图 + 官方工具链事实 + 宏/泛型/生命周期全支持 + CI 门禁列表。
- **"AI 时代直接问 ChatGPT 就行"** → 完全同意，所以扩展里内置了三提供商的 AI 讲解；rzc 补的是 AI 给不了的：编辑器内 1 秒确定性反馈与离线可用。

## 三、Phase 1：种子内容（第 1-2 周，3 篇 + 1 视频）

### 3.1 知乎首发长文（主攻人群 A + C）

**标题**：《我写了一个编译器，让你用中文学 Rust》
**结构**（AI 可代拟初稿，人工加个人经历）：
1. Hook：Rust 的第一道门槛不是所有权，是英文报错（放 GIF）
2. Demo：让 x: 长整数 = "你好" → 中文 E0308 + 两条教学提示（实拍）
3. 为什么不是伪代码：架构图（母语源码 → 逐 token 转译 → 官方工具链 → 诊断回译）
4. **主动列出反对意见并回应**（"为什么不直接学英文"三连问）——知乎生态里自黑式写作效果最好
5. `eject` 毕业机制：现场演示导出标准 Rust
6. 25 章教程链接 + 问卷/讨论区入口

### 3.2 掘金/V2EX/Rustcc 技术版（主攻人群 C，放大器）

**标题**：《rzc：把 Rust 关键字和报错翻译成中文的转译器——原理与三个技术难点》
**内容**（项目已有的干货，几乎零写作成本）：
- rustc_lexer 逐 token 转译为何不用正则
- 难点 1：行号恒等、列偏移回放（column_map，字符列 vs UTF-16 列）
- 难点 2：LSP 双向代理 + 虚拟项目 + 符号链接防护
- 难点 3：教学诊断三层管线（错误码表/消息表/所有权叙事）
- CI 门禁展示（MSRV/覆盖率/基准回归/教程逐块编译验证）——工程质量本身是传播点

### 3.3 B 站演示视频（3-5 分钟，主攻人群 A/B）

脚本：0:00 中文报错画面 hook → 0:30 安装（一行命令）→ 1:00 init/run 全流程 → 2:00 报错变中文 + AI 讲解命令 → 3:00 eject 导出 → 3:30 教程与链接。
成本：AI 写脚本 + 免费剪辑工具，半天。

### 3.4 发布节奏

知乎首发（周五晚流量高峰）→ 48 小时后掘金/V2EX → 第 2 周内 B 站 + Rustcc。**每篇末尾统一：安装命令 + 问卷 + 讨论区链接。**

## 四、Phase 2：内容矩阵与社区运营（第 3-6 周）

1. **教程连载**（长期 SEO 主力）：25 章教程每周发 2-3 章到知乎专栏《用中文学 Rust》，AI 辅助改编、人工校对。教程是独立资产——**就算不用 rzc，教程本身也能引流**。
2. **响应纪律**：issue/评论/讨论区 24 小时内回复；被吐槽的点记入清单。
3. **快速迭代一次**（v0.7.x）：把前两周最高频的吐槽修掉并发版，"反馈→修复"的闭环本身就是最好的传播素材（发一条"你们要的 X 做好了"）。
4. **精准触达**：私信 2-3 个做 Rust/编程教育的 B 站 UP 主或公众号作者，送体验 + 请求评测（不要求好评，要求真实）。
5. **教学机构试探**：找 1-2 所职校/培训机构教师提供离线包 + 教程打包（这是唯一能产生"课堂使用数据"的主动动作）。

## 五、Phase 3：数据复盘与去留决策（第 7-8 周）

| 指标 | 8 周现实目标 | 数据来源 |
|---|---|---|
| crates.io 下载量 | 300+ | crates.io 页面 |
| GitHub+GitCode stars | 30+ | 两平台 |
| 教程专栏累计阅读 | 5000+ | 知乎/掘金后台 |
| 深度反馈（问卷/issue/讨论） | 10+ 条，其中 1-3 条来自真实学习者 | 问卷/讨论区 |

**决策门**（对应存续评估的信号）：
- 下载与反馈达标 → 转入正式运营（加大教程产出、做教学机构合作）
- 有下载但无深度反馈 → 转向教程资产，编译器降级为教程配套
- 全面冷淡 → 归档，项目以作品集价值收尾（已付清）

## 七、风险与预案

| 风险 | 预案 |
|---|---|
| 被批"伪需求/中文编程引战" | FAQ 预埋 + 自黑式写作 + 不参与立场论战，只回应技术问题 |
| 教学法被质疑无数据支撑 | 文章里明说"这是待验证的假设，欢迎实践者反馈"——把质疑者变成数据来源 |
| 用户报 rustc 兼容问题 | CI 门禁已覆盖 MSRV/多平台；issue 快速响应 |
| 推广内容本身有错 | 教程有 CI 验证；文章发布前对照 README 逐条核对命令 |
| 热度后继乏力 | 教程连载是长尾流量，不依赖单次爆点 |
