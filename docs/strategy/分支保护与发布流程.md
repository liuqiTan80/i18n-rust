# 分支保护与发布流程

> 适用范围：GitHub `liuqiTan80/i18n-rust`（唯一写入源）。
> Gitee / GitCode 为只读镜像，不接收人工提交。
> 本文件是分支保护的**唯一事实来源**；规则以 [`.github/rulesets/`](../../.github/rulesets/) 下的 JSON 为准。

## 1. 分支角色

| 分支 / 引用 | 角色 | 谁能写 | 保护 |
|---|---|---|---|
| `main` | **发布树**：`zh` 方言源执行 `rzc eject` 后的标准 Rust 代码 | 只能通过 PR 合并 | 禁止直接推送、强推、删除；线性历史；必须评审 + 状态检查 |
| `zh` | **日常开发唯一分支**：只保留 `.zh` 方言源 | 所有开发者直接推送 | 禁止强推、删除 |
| `release/eject-<版本>` | 发布候选：由 `zh` eject 生成，向 `main` 开 PR | 发布负责人临时推送 | 临时分支，合并后删除 |
| `v<版本>` 标签 | 已发布版本 | 仅发布负责人 | 禁止删除、移动 |

**核心约束**

1. `main` 上的每一个 `.rs` 都必须来自 `rzc eject`，不接受手写或直接合入 `zh`。
2. `zh` 是唯一日常提交分支；功能、修复、文档、语言包、CI 改动都先在 `zh` 完成并验证。
3. `zh` **不能直接 merge 到 `main`**。必须先生成 `release/eject-<版本>` 候选树，再走 PR。
4. `main` 上不回写代码；如需修改，回到 `zh` 改，再重新 eject。

## 2. `main` 的保护规则

对应 [`.github/rulesets/protect-main-release.json`](../../.github/rulesets/protect-main-release.json)：

| 规则 | 效果 |
|---|---|
| `deletion` | 禁止删除 `main` |
| `non_fast_forward` | 禁止强制推送（含 `--force`、`--force-with-lease`） |
| `required_linear_history` | 禁止 merge commit；配合仓库只允许 **Squash / Rebase** 合并 |
| `pull_request` | **所有变更必须走 PR**；直接 push 一律被拒 |
| 评审参数 | 至少 1 人批准；必须 CODEOWNERS 批准；新推送会驳回旧批准；最后一次推送需他人批准；评审对话必须解决 |
| `required_status_checks` | 必须通过 `test`、`windows-gates`、`msrv`、`eject-verify`；且分支必须是最新的（strict） |

`eject-verify` 是新增的发布树校验（[workflow](../../.github/workflows/eject-verify.yml)）：
在 PR 上构建候选树的 `rzc`，对 `origin/zh` 执行 eject，逐文件比对
`crates/`、`Cargo.toml`、`Cargo.lock`。**不一致就阻断合并**，并提示重新 eject。
文档、脚本、CI 配置不参与该比对，但仍须走 PR + 评审。

> 评审人数说明：默认要求 1 人。团队只有一名有写权限成员时，PR 无法满足
> CODEOWNERS 审批；应尽快增加第二名维护者。**不建议**把评审人数改成 0；
> 如确需临时降低，改完后必须记录在团队通知里并尽快恢复。

## 3. `zh` 的保护规则

对应 [`.github/rulesets/protect-zh-dev.json`](../../.github/rulesets/protect-zh-dev.json)：

- 允许开发者直接 push（这是日常唯一提交分支）；
- 禁止强推与删除，保证提交历史可追溯；
- 每次 push 触发 [`zh-gates.yml`](../../.github/workflows/zh-gates.yml)：
  全中文棘轮 + 方言源纪律（可转译性、一词多译、绑定位）。
- 推送前本地必须通过：

```bash
make zh-build ARGS='test --workspace --locked'
make zh-artifacts
make zh-ascii
```

## 4. 标准发布流程

### 第 1 步：在 zh 开发与验证

```bash
git switch zh
git pull --ff-only
# 改 .zh / 语言包 / 文档 / 工具…
make zh-build ARGS='test --workspace --locked'
make zh-artifacts
make zh-ascii
git add -A && git commit -m "feat(engine): …"
git push github zh
```

### 第 2 步：生成发布候选分支

> 前置：`zh` 工作树干净、版本号已在三 crate / 扩展 / CHANGELOG 中统一。

```bash
scripts/prepare-eject-branch.sh 0.9.1
```

脚本会：在 `.zh-build/` 生成 eject 产物 → 从 `main` 新建
`release/eject-0.9.1` → 整体替换为产物树（删除 `.zh`，保留 zh-pure 夹具）→
`cargo fmt` + 重生成 `docs/ui-keys.en.md` → 提交。

### 第 3 步：推送并开 PR

```bash
git push -u github release/eject-0.9.1
# GitHub 网页：base = main，compare = release/eject-0.9.1
```

PR 描述必须写清：

- 源分支与提交：`zh@<sha>`
- 版本号与变更摘要
- 本地已跑的门禁命令

### 第 4 步：等待必需检查

| 检查 | 内容 |
|---|---|
| `eject-verify` | 候选树 == 当前 `zh` 的 eject 产物 |
| `test` | fmt / clippy / 全量测试 / 各脚本门禁 |
| `windows-gates` | Windows 构建与测试 |
| `msrv` | 最低 Rust 版本（1.88）编译 |

任何一项红 → 回到 `zh` 修复，重新执行第 2 步（不要手工改候选分支上的 `.rs`）。

### 第 5 步：评审与合并

- 至少 1 名 CODEOWNERS 批准；
- 评审通过后使用 **Squash merge**（或 Rebase），禁止 merge commit；
- 合并后删除 `release/eject-*` 分支。

### 第 6 步：打标签与发布

```bash
git switch main && git pull --ff-only
git tag -a v0.9.1 -m "rzc 0.9.1"
git push github v0.9.1
# tag 触发 release.yml：构建三平台产物、vsix、GitHub Release、crates.io
scripts/mirror.sh v0.9.1   # 镜像到 Gitee / GitCode（已存在标签自动跳过）
```

### 第 7 步：清理

```bash
git worktree remove .zh-tmp/eject-0.9.1
git branch -d release/eject-0.9.1
```

## 5. 禁止事项

- ❌ 直接 `git push github main`（会被 ruleset 拒绝）
- ❌ `git push --force` 到 `main` / `zh`
- ❌ 把 `zh` 直接 merge / rebase 到 `main`（缺少 `.rs`，`eject-verify` 必红）
- ❌ 在 `main` 上手工改 `.rs` 后提交（下次 `eject-verify` 会比对失败）
- ❌ 绕过 PR 用管理员权限强推（规则集未配置 bypass；如遇紧急情况先停手，联系维护者）
- ❌ 删除或移动已发布 `v*` 标签

## 6. 平台配置（维护者一次性操作）

### GitHub

```bash
# 需要 repo admin 权限
gh auth login
scripts/setup-github-rulesets.sh liuqiTan80/i18n-rust
```

或在网页 `Settings → Rules → New ruleset → Import` 逐个导入：

- `.github/rulesets/protect-main-release.json`
- `.github/rulesets/protect-zh-dev.json`
- `.github/rulesets/protect-release-tags.json`

再确认：

1. `Settings → General → Pull Requests`：只保留 **Squash merging**（或 Rebase），关闭 merge commits；
2. `Settings → Rules`：`main` 的必需检查显示为 `test`、`windows-gates`、`msrv`、`eject-verify`；
3. `.github/CODEOWNERS` 中的 `@liuqiTan80` 是有效账号。

### Gitee / GitCode

- 默认分支设为 `zh`；
- `main` / `zh` 仅允许镜像账号写入（开发者无写权限）；
- 关闭网页端直接编辑与强推；
- 镜像由 GitHub Actions 的 `mirror.yml` 单向推送，不接收人工提交。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `push main` 被拒：`protected branch` | main 已启用 PR 规则 | 走第 2–5 步开 PR |
| PR 卡在 `eject-verify` | 候选树不是当前 `zh` 的 eject 产物 | 在 `zh` 修复并 push，重跑 `prepare-eject-branch.sh` |
| `eject-verify` 报 `origin/zh` 不存在 | 分支未 fetch 或仓库改名 | `git fetch origin zh`；确认仓库地址 |
| `test` / `windows-gates` / `msrv` 红 | 代码或环境问题 | 回 `zh` 修复；不要在 main 上改 |
| 所有检查绿但无法合并：`Review required` | 缺 CODEOWNERS 批准 | 联系维护者评审；不要绕过 |
| 规则集未生效 | 只提交了 JSON，没应用 | 运行 `scripts/setup-github-rulesets.sh` |
| `prepare-eject-branch.sh` 报工作树脏 | 有未提交改动 | 先提交/清理 `zh` |

## 8. 可追溯性

每次发布应能回答：**哪个 `zh` 提交、用哪个 `rzc`、生成了哪个 `main` 提交、由谁评审、对应哪个 tag。**

- `zh` 提交：PR 描述中的 `zh@<sha>`；
- `main` 提交：squash merge 后的 SHA；
- `eject-verify` 运行记录：GitHub Actions 日志；
- 评审记录：PR 的 Approvals；
- 版本：`v<版本>` 标签 + `CHANGELOG.md`。

审计命令：

```bash
git log --oneline --decorate main
git show v0.9.1 --stat
gh pr list --base main --state merged --limit 20
```
