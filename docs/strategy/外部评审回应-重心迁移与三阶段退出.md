## 二、混写实测（2026-11-03，`target/debug/rzc`，本地探针工程 `.rz/probe9/` 不入库，样本内容见下）

样本：`.zh` 文件内中英结构词混写（`fn`/`let`/`vec!`/`for`/`in`/`println!` 与
`让`/`向量!`/`打印行!` 同篇共存），入口名 `主函数`、标识符中文。

1. **转译层放行**：词法替换按 token 命中词条，未标记英文原样保留；产物为合法标准
   Rust，`rzc check` ✅ 编译成功、`rzc run` 输出正确（和是：6）。
2. **与全中文写法零行为差异**：英文 `let` 不享受 `让` 的任何特殊机制，同缺 `mut`
   同报 E0596、译文一致——混写不是二等语法。
3. **纯英文内容进 `.zh` 同样可编**（第三阶段证据）：全英文源码 `rzc check` ✅，
   仅教学告警不阻断。
4. **唯一阻力是英文回落 lint 的姿态**：每个英文结构词位刷屏
   「`fn` 有母语词条 `函数`，建议使用母语写法」——方向与"退出路径"相反；
   且纯英文文件里该提示永远无法满足。现有静默手段只有两种：`--no-lint`
   全局关**所有**教学 lint（魔法数字等一并静默）、行注释「教学忽略」逐行豁免——
   都没有细到"只关英文回落一类"的粒度。
5. 顺带复证两条已知墙：入口产物名非 `main` 时 Cargo 认不到 bin 目标（"没有编译
   目标"，同 zh-findings 口径）；探针工程需 `[workspace]` 空表隔离。

## 三、三阶段退出路径（方案主体）

把"离开工具也写得了代码"从隐含承诺变成显式规约：

| 阶段 | 形态 | 工具行为 |
|---|---|---|
| ① 母语全量 | 结构词、标识符全母语 | 现默认形态，教学 lint 全开 |
| ② 中英混写 | 逐文件把高频结构词换回英文，标识符可保留母语 | 转译层已开箱支持；回落 lint 从"建议改回母语"**翻转方向**为进度信号（"N 处已回归英文，还剩 M 处"） |
| ③ 纯英文标准 Rust | 方言文件退场 | `eject` 产物即终点；诊断中文化仍可保留（对英文源码 `rzc check` 已可用） |

### 工程清单（按依赖排序）

1. **回落 lint 类别开关**（小）：`--no-lint` 之外给单类别静默粒度（env 或 `lang_info`
   /项目配置，待定），这是混写目前唯一的硬摩擦；
2. **迁移进度读数**（中）：`rzc doctor` 增一项，复用回落表按文件统计英文化比例——
   把 lint 噪音升级为"阶段定位"数据，教学叙事有了仪表；
3. **教程叙事**（文档）：附录 E 学习路线加"三阶段桥"一节；README 加一行"与
   rust-lang 官方 i18n 无关"免责；
4. **姿态钉测试**（小）：混写可编 / 纯英文可编各一条 CLI 集成用例进 `crates/cli/tests`，
   防止未来收紧策略时无声破坏退出路径；
5. **双栏对照视图**（大，独立候选）：两栏渲染 source_map；与阶段②天然配套，排在其后。

### 明确不做

- 不迁移重心到"纯诊断工具"：`rzc check` 对英文源码已可用，受众入口已含；
  放弃方言即放弃全链路控制，等于拆掉 LSP/补全/gaps/漂移看守的立足点。
- 不在学习者端运行时调 LLM（维持 2026-10-28 否决结论）。
