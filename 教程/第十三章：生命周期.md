# 第十三章：生命周期

在第七章我们学了引用——借用数据而不转移所有权。但编译器怎么知道一个引用是否仍然有效？

答案是**生命周期**（lifetime）。生命周期是 Rust 确保引用安全的机制。

---

## 13.1 什么是生命周期？

生命周期就是引用**保持有效的作用域**。

```rust
函数 主函数() {
    让 r;                // r 的生命周期从这里开始
    {
        让 x = 42;       // x 的生命周期从这里开始
        r = &x;          // r 引用了 x
        打印行!("{}", r); // ✅ x 还活着
    }                     // x 的生命周期到此结束
    // 打印行!("{}", r);  // ❌ r 指向了已释放的 x
}
```

Rust 编译器会自动推断大多数引用的生命周期。但有时候它推断不出来，需要你手动标注。

---

## 13.2 生命周期标注

用 **`'a`** 这样的语法标注生命周期（读作"生命周期 a"）：

```rust
// &'a 整数 表示"一个引用，它的生命周期是 'a，指向整数"
函数 取较长<'a>(x: &'a 整数, y: &'a 整数) -> &'a 整数 {
    如果 x > y { x } 否则 { y }
}

函数 主函数() {
    让 数字1 = 10;
    让 数字2 = 20;
    让 结果 = 取较长(&数字1, &数字2);
    打印行!("较大值：{}", 结果);
}
```

- **`<'a>`** 声明了一个生命周期参数。
- **`&'a 整数`** 表示"引用指向的整数，生命周期为 `'a`"。
- 返回值的生命周期 `&'a` 告诉编译器："返回的引用和输入参数活得一样长"。

> **通俗理解**：生命周期标注不改变引用的实际寿命，只是告诉编译器"这些引用的关系是什么"。

---

## 13.3 生命周期省略规则

大多数时候你不需要手动标注，因为编译器有三条省略规则：

1. **每个引用参数都有自己的生命周期**
2. **如果只有一个输入引用，返回值的生命周期和它一样**
3. **如果有 `&自我`，返回值的生命周期和 `自我` 一样**

```rust
// 编译器自动推断：
// 函数 首词(s: &文本) -> &文本
// 规则2：只有一个输入引用，返回值和它一样
函数 首词(s: &文本) -> &文本 {
    // ...
    s
}
```

只有当编译器推断不出来时，才需要手动标注。

---

## 13.4 结构体中的生命周期

如果结构体持有引用，必须标注生命周期：

```rust
结构体 摘要<'a> {
    文本: &'a 文本,
}

函数 主函数() {
    让 小说 = "很久很久以前...".转字符串();
    让 摘要 = 摘要 { 文本: &小说 };

    打印行!("摘要：{}", 摘要.文本);
}  // 摘要 在 小说 之前被释放，安全
```

**`摘要<'a>`** 告诉编译器：`摘要` 实例不能比它引用的 `文本` 活得更久。

---

## 13.5 动手实验

### 实验 1：最长子串

```rust
函数 最长子串<'a>(s1: &'a 文本, s2: &'a 文本) -> &'a 文本 {
    如果 s1.长度() >= s2.长度() { s1 } 否则 { s2 }
}

函数 主函数() {
    让 字符串1 = "你好".转字符串();
    {
        让 字符串2 = "你好世界".转字符串();
        让 结果 = 最长子串(&字符串1, &字符串2);
        打印行!("较长的：{}", 结果);
    }
}
```

---

## 本章小结

1. **生命周期** 是引用保持有效的作用域
2. **`'a`** 语法标注生命周期
3. 编译器有三条省略规则，大多数时候不需要手动标注
4. 结构体持有引用时必须标注生命周期
5. 生命周期标注不改变实际寿命，只是帮助编译器验证安全性
