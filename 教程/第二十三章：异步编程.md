# 第二十三章：异步编程

现代程序经常需要同时做多件"等待"的事——下载文件、查询数据库、等待用户输入。**同步**方式是一个接一个等，**异步**方式是同时开始所有等待，哪个先完成就先处理哪个。

---

## 23.1 同步 vs 异步

> 🎯 **生活类比**：
> - **同步**：你在餐厅点了 3 道菜，服务员一道一道上——做完第一道才做第二道。
> - **异步**：你同时点了 3 道菜，厨房同时做，哪道好了先上哪道。

```
同步（一个接一个）：
时间线 ──────────────────────────────→
  下载A: ████████████
  下载B:              ████████████
  下载C:                           ████████████
  总耗时：30 秒

异步（同时进行）：
时间线 ──────────────────────────────→
  下载A: ████████████
  下载B: ████████████
  下载C: ████████████
  总耗时：10 秒
```

### 为什么不用多线程？

多线程也能并行，但每个线程占用约 **2-8MB** 栈内存。如果你需要同时处理 10 万个连接，多线程方案需要 200GB+ 内存。

异步任务只需要 **几百字节**——10 万个异步任务只需几十 MB。

| 对比 | 多线程 | 异步 |
|------|--------|------|
| 内存开销 | 大（每线程 MB 级） | 小（每任务 KB 级） |
| 适合场景 | CPU 密集计算 | IO 密集（网络、文件） |
| 编程难度 | 需要处理锁 | 需要处理生命周期 |
| 并发量 | 千级 | 十万级 |

## 23.2 异步函数

用 **`异步`**（`async`）标记一个函数为异步函数：

```rust
// 异步函数返回一个"未来"（Future）
异步 函数 获取用户信息(用户ID: 整数) -> 字符串 {
    // 模拟网络请求（需要等待）
    等待 睡眠(持续时间::从秒(1));
    格式化!("用户{}的信息", 用户ID)
}
```

异步函数不会立即执行，它返回一个 **`未来`**（`Future`）——代表"将来某个时刻会完成的值"。

```
┌─────────────────────────────────────┐
│  异步 函数 获取用户信息(用户ID)       │
│  ↓ 调用时不执行，返回一个"未来"       │
│  未来<字符串>                        │
│  ↓ 等待"未来"完成                    │
│  等待 获取用户信息(1)                │
│  ↓ 完成后得到结果                    │
│  "用户1的信息"                       │
└─────────────────────────────────────┘
```

### 等待关键字

用 **`等待`**（`await`）等待一个异步操作完成：

```rust
异步 函数 主函数() {
    打印行!("开始下载...");

    让 结果 = 等待 下载页面("https://example.com");

    打印行!("下载完成：{} 字节", 结果.长度());
}
```

`等待` 不会阻塞线程——它会**让出控制权**，让运行时去处理其他任务，等结果回来再继续。

## 23.3 并发执行多个异步任务

### 顺序执行（慢）

```rust
异步 函数 主函数() {
    // ❌ 一个接一个，总耗时 = A + B
    让 a = 等待 任务A();  // 等 3 秒
    让 b = 等待 任务B();  // 再等 3 秒
    打印行!("总耗时 6 秒");
}
```

### 并发执行（快）

```rust
异步 函数 主函数() {
    // ✅ 同时开始，总耗时 = max(A, B)
    让 (a, b) = 等待 连接(
        任务A(),
        任务B(),
    );
    打印行!("总耗时 3 秒");
}
```

```
顺序执行：
任务A: ████████████
任务B:              ████████████
总计: 6 秒

并发执行：
任务A: ████████████
任务B: ████████████
总计: 3 秒
```

## 23.4 异步运行时

Rust 标准库**不包含**异步运行时——它只定义了 `未来` 特征。你需要选择一个运行时库：

| 运行时 | 特点 | 适用场景 |
|--------|------|---------|
| **tokio** | 最流行，功能全面 | Web 服务、通用异步 |
| **async-std** | 模仿标准库 API | 喜欢标准库风格 |
| **smol** | 极简轻量 | 小型项目 |

本教程以 **tokio** 为例。在 `Cargo.toml` 中添加依赖：

```toml
[依赖]
tokio = { 版本 = "1", 特征 = ["full"] }
```

### tokio 入口

```rust
// tokio 提供的宏来标记主函数为异步
#[tokio::主函数]
异步 函数 主函数() {
    打印行!("你好，异步世界！");

    // 生成异步任务
    让 句柄 = tokio::生成异步(异步 {
        等待 tokio::睡眠(持续时间::从秒(1));
        打印行!("任务完成！");
        42
    });

    让 结果 = 等待 句柄;
    打印行!("结果：{}", 结果);  // 42
}
```

## 23.5 异步通道

异步通道用于在异步任务之间传递消息，类似于第十九章的多线程通道，但专为异步设计：

```rust
使用 tokio::同步::mpsc;

#[tokio::主函数]
异步 函数 主函数() {
    // 创建异步通道（容量 100）
    让 (发送端, 可变 接收端) = mpsc::通道(100);

    // 生成生产者任务
    tokio::生成异步(异步 move {
        对于 i 在 1..=5 {
            发送端.发送(i).等待.解包();
            打印行!("已发送：{}", i);
        }
    });

    // 主任务消费消息
    等待 一些(|| 异步 {
        如果 让 有些(值) = 接收端.接收().等待 {
            打印行!("已接收：{}", 值);
            真
        } 否则 {
            假
        }
    });
}
```

## 23.6 异步中的共享状态

在异步任务间共享数据，仍然用 `原子引用计数<互斥锁<T>>`：

```rust
使用 标准库::同步::原子引用计数;
使用 tokio::同步::互斥锁;

#[tokio::主函数]
异步 函数 主函数() {
    让 数据 = 原子引用计数::新建(互斥锁::新建(向量::新建()));

    // 生成 3 个异步任务，每个往共享向量中添加数据
    让 可变 句柄们 = 向量::新建();
    对于 i 在 0..3 {
        让 数据克隆 = 数据.克隆();
        让 句柄 = tokio::生成异步(异步 move {
            让 可变 锁 = 数据克隆.加锁().等待;
            锁.推(i);
        });
        句柄们.推(句柄);
    }

    // 等待所有任务完成
    对于 句柄 在 句柄们 {
        等待 句柄.解包();
    }

    让 结果 = 数据.加锁().等待;
    打印行!("{:?}", 结果);  // [0, 1, 2]
}
```

> ⚠️ **注意**：异步中使用 `互斥锁` 时，`.加锁()` 返回的是 `未来`，需要 `.等待`。不要用标准库的 `互斥锁`（会阻塞整个异步线程），要用 `tokio::同步::互斥锁`。

## 23.7 超时处理

网络请求不能无限等待——用 `超时` 设置时间上限：

```rust
使用 tokio::time::{超时, 持续时间};

#[tokio::主函数]
异步 函数 主函数() {
    让 结果 = 超时(持续时间::从秒(5), 慢速请求()).等待;

    匹配 结果 {
        有些(成功) => 打印行!("成功：{:?}", 成功),
        无 => 打印行!("超时了！"),
    }
}

异步 函数 慢速请求() -> 字符串 {
    等待 tokio::睡眠(持续时间::从秒(10));  // 模拟慢请求
    "数据".转字符串()
}
```

## 常见错误

### ❌ 在异步中使用同步阻塞

```rust
// ❌ 这会阻塞整个异步线程！
异步 函数 坏例子() {
    标准库::线程::线程休眠(持续时间::从秒(5));  // 阻塞！
}

// ✅ 用异步睡眠
异步 函数 好例子() {
    等待 tokio::睡眠(持续时间::从秒(5));  // 不阻塞
}
```

### ❌ 在异步闭包中忘记 move

```rust
让 数据 = 向量![1, 2, 3];
tokio::生成异步(异步 {
    // ❌ 编译器报错：data 可能被释放
    打印行!("{:?}", 数据);
});

// ✅ 用 move 获取所有权
tokio::生成异步(异步 move {
    打印行!("{:?}", 数据);
});
```

### ❌ 混用标准库和 tokio 的同步原语

```rust
// ❌ 标准库的 Mutex 在异步中会阻塞线程
使用 标准库::同步::互斥锁;

// ✅ 用 tokio 的异步互斥锁
使用 tokio::同步::互斥锁;
```

## 练习题

### 练习 1：并发下载模拟

写一个异步程序，同时"下载" 3 个页面（用 `tokio::睡眠` 模拟延迟），计算总耗时。

<details>
<summary>参考答案</summary>

```rust
使用 tokio::time::{睡眠, 持续时间, 即时};

异步 函数 下载页面(名字: &字符串, 延迟秒: u64) -> 字符串 {
    睡眠(持续时间::从秒(延迟秒)).等待;
    格式化!("{} 的内容", 名字)
}

#[tokio::主函数]
异步 函数 主函数() {
    让 开始 = 即时::现在();

    让 (a, b, c) = 等待 tokio::连接!(
        下载页面(&"首页".转字符串(), 2),
        下载页面(&"关于".转字符串(), 3),
        下载页面(&"联系".转字符串(), 1),
    );

    打印行!("a: {}", a);
    打印行!("b: {}", b);
    打印行!("c: {}", c);
    打印行!("总耗时：{:?}", 开始.经过时间());  // 约 3 秒
}
```
</details>

### 练习 2：异步消息传递

创建一个生产者-消费者模式：生产者每秒发送一条消息，消费者接收并打印，5 秒后停止。

<details>
<summary>参考答案</summary>

```rust
使用 tokio::同步::mpsc;
使用 tokio::time::{睡眠, 持续时间};

#[tokio::主函数]
异步 函数 主函数() {
    让 (发送端, 可变 接收端) = mpsc::通道(32);

    // 生产者
    tokio::生成异步(异步 move {
        对于 i 在 1..=5 {
            发送端.发送(格式化!("消息{}", i)).等待.解包();
            睡眠(持续时间::从秒(1)).等待;
        }
    });

    // 消费者
    等待 一些(|| 异步 {
        匹配 接收端.接收().等待 {
            有些(消息) => {
                打印行!("收到：{}", 消息);
                真
            }
            无 => 假,
        }
    });
}
```
</details>

## 本章小结

| 概念 | 一句话 |
|------|--------|
| `异步` | 标记函数为异步函数 |
| `等待` | 等待一个异步操作完成 |
| `未来` | 代表"将来会完成"的值 |
| 异步运行时 | 执行异步任务的引擎（如 tokio） |
| 异步通道 | 异步任务间的消息传递 |
| 超时 | 限制异步操作的最大等待时间 |
