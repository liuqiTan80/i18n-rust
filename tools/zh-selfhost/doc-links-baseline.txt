# zh 自举 intra-doc 失效链接 —— 已审定的合法保留基线
#
# 用途：tools/zh-selfhost/doc-links-check.sh 把 cargo doc 报出的每个未解析
#   链接符号与本表逐行全量比对；本表之外的任何未解析符号一律判为「失效引用回潮」
#   （AI/人改 .zh 时冒出的对不存在符号的引用），退出码 1。故本表是「地板」不是「免死」：
#   新增条目须像其余 zh 门禁一样附带人工审定理由，不能为图省事把真漏网塞进来。
#
# 本表 15 项的保留理由（逐类，勿泛化）：
#
# ① .zh 源真相的惯用路径写法，改成英文/具名反破坏源真相自洽（eject 到 .rs 才不匹配）：
包::工具链::安装根目录
包::映射管理::映射管理器::取别名映射表
包::映射管理::映射管理器::取方法延迟词
包::映射管理::映射管理器::取使用延迟词
#    —— `包::` 是 .zh 对 `crate::` 的刻意惯用前缀；目标函数（安装根目录/取…延迟词/
#       取别名映射表）均在 .zh 真实定义、链接名与定义自洽，属双语言模型必然伪报。
源码转译并项目
#    —— lib.zh 定义了同 crate 公开函数 `源码转译并项目`，裸名链接却报失效，
#       同为 eject 链接名映射伪报（.zh 名正确）。
# ② 模块 `//!` 文档里列举兄弟子模块的惯用裸链接（指真实存在的子模块，非失效引用）：
响应集合
诊断文本
消息翻译
# ③ 非符号引用（指向配置节名 / 错误码格式示例，本就不该解析成 item）：
语言包
E0xxx
# ④ 外部类型 / Cargo target / Rust 关键字白名单（合法英文，见 guide §3 三层判据）：
TextEdit
bin
lib
# ⑤ .zh 字段/静态自洽名（eject 改名伪报，改动反使 .zh 链接指错）：
原子u64
