# zh-demo —— 方言能力演示项目

展示 rzc 方言改写能力的最小示例 crate，重点演示**模块路径替换**：源文件里
`使用 标准库::集合::哈希映射;` 会转译为 `use std::collections::HashMap;`，
程序本身就在演示同一类替换（真实实现见 `crates/engine/src/module_path.rs`）；
顺带演示全中文写法下声明位、调用位、字段访问位各自的映射规则。

运行方式：在工作区根目录执行

```bash
rzc run .zh-demo/src/main.zh
```

三处值得注意的写法（本文件已纳入 `tools/check-zh-ascii.py` 门禁，代码区与
注释区残余英文均为 0）：

- **三方 crate 也有母语词形**：`rustc_lexer` 在中文语言包 `stdlib.toml` 的
  「三方 crate 标识符」节里登记了 `词法解析器`、`切分令牌`、`令牌种类`、
  `令牌类别` 等词形，于是导入行和令牌字段访问都能写中文；
- **构造方法写中文名**：`函数 新建` 的声明位与 `源码映射项::新建` 的调用位
  同属本项目的声明集合，两侧一起保留中文，产物自洽可编译，不必退回英文原名；
- **字段名不要撞词表词**：本文件一旦把结构体字段命名为 `长度`（它是 `len` 的
  词形），`长度` 就进入项目声明名，`令牌.长度` 会被当作项目自己的字段而保留
  中文，产物报「无此字段」。所以演示把字段取名 `字节数`（不在任何词表里），
  把 `长度` 让给词表使用——这正是「声明集合豁免」与「词表替换」相互作用的实例。
